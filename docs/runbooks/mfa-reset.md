# 手順書: 認証アプリを無くした人の二段階認証を外す(回復)

> 仕組みは [specs/0006-account-security.md](../specs/0006-account-security.md)・設計書の U-3(作者 @attumkwg の承認 2026-10-20)。
> **アプリの中に回復の道は作っていない**(Cognito に予備のコードが無い・「管理者が外す画面」は管理者が乗っ取られると全員の二段階認証を外せてしまう)。
> 外すのは運営が手で、**本人であることを確かめてから**だけ。ここをだまされると乗っ取られる(サポートをだます攻撃)。

## 1. 依頼を受ける

- 依頼は**その組織の管理者から**受ける(本人からの直接の依頼だけでは外さない)。管理者が本人に会う・電話するなどで確かめた、と書いてもらう。
- 管理者が1人だけで、その人が無くしたとき: **契約のときに登録された連絡先**(請求の担当など、アプリの外の連絡先)に電話して、本人と依頼を確かめる。メールだけで済ませない(メールが乗っ取られているかもしれない)。
- 依頼・確かめた方法・確かめた人を、作業の記録(#support など)に残す。

## 2. 外す(本番の Cognito への書き込み。2人で)

```bash
aws cognito-idp admin-set-user-mfa-preference \
  --user-pool-id <プール> \
  --username <その人のメールアドレス> \
  --software-token-mfa-settings Enabled=false,PreferredMfa=false
```

- アプリの DB は触らない。本人が次にログインすると、コードを聞かれずに入れ、写し(`users.mfa_enabled`)も「未設定」にそろう。
- その組織が二段階認証を必須にしていれば、本人はログインした後に設定の画面へ回されるので、新しい端末で設定し直してもらう。
- 乗っ取りが疑われるときは、外す前にパスワードも替えさせる(`aws cognito-idp admin-reset-user-password` → 本人が再設定のコードで新しいパスワードを決める)。

## 3. 後で確かめる

- その組織の監査ログに、本人の「ログインした」と「二段階認証を有効にした」が出ていること(管理者に見てもらう)。
- 同じ人・同じ組織から何度も依頼が来るなら、乗っ取りの試みを疑う([incident.md](incident.md))。
