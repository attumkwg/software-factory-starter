# 手順書: 引き継ぎの置き場(どこに何のアカウントがあり、誰が持ち、どう取り戻すか)

> 1人(か2人)で回している間の備え。管理者が1人しかいないとき(点検の `acct-two-admins` で「今は1人しかいない」)に作り、半年ごとに見直す(点検の `emergency-access`)。
> 想定の場面は [../scenarios/11-people-leave.md](../scenarios/11-people-leave.md) の 11-5。辞める日の手順は [joiner-leaver.md](joiner-leaver.md)。
> **ここに書くのは型と置き方だけ。中身の一覧は、このリポジトリに書かない**(公開のリポジトリになりうる・AI が読む・履歴から消せない)。

## 1. なぜ要るか

1人のエンジニアが抜けた会社で一番困るのは、コードより**アカウントの持ち主**。「ドメインの更新の通知が辞めた人のメールに届いていた」「AWS の root の二段階認証が辞めた人のスマホに入っていた」が起きると、パスワードが分かっていても入れない。

残すのは中身(パスワード・鍵)ではなく、**どこにあり・誰が持ち・どう取り戻すか**。

## 2. 一覧の型(1行 = 1つのアカウント)

| 道具 | 何のアカウントか | 持ち主(ログインのメール) | 二段階認証の機器・予備のコードの置き場 | 取り戻し方(持ち主がいないとき) | 請求の先 |
|---|---|---|---|---|---|
| 例: AWS | 本番の組織の管理(root) | 会社の共有のメール(個人のメールにしない) | 物の鍵(2本。1本は金庫)・予備のコードは紙で金庫 | AWS のサポートに、登録の電話と請求のカードで本人確認 | 会社のカード |

埋める物(どれも、あれば1行):

- **AWS**: 組織の管理アカウントの root(メールと二段階認証)・IAM Identity Center の管理者
- **GitHub**: 組織の持ち主(Owner)・二段階認証の予備のコード・課金の担当
- **ドメイン**: 登録の業者のアカウント・更新の通知の先のメール・自動更新の支払い
- **メール・DNS**: 会社のメールの管理者(Google Workspace など)・DNS の管理(Route 53 なら AWS の行)
- **Claude**(Anthropic): 組織の持ち主・API の鍵の管理・請求
- **Sentry・Slack・そのほか外のサービス**: 組織の持ち主・Webhook を作った人([../compliance/vendors.yaml](../compliance/vendors.yaml) の委託先が漏れの無い一覧になる)
- **アプリのストア**(Apple・Google の開発者アカウント): 持ち主・更新の支払い(使っていれば)
- **パスワードの金庫そのもの**: 誰が開けられるか・持ち主が倒れたときに開ける人(下の 4)

## 3. 置き場

- **パスワードの管理の道具**(1Password・Bitwarden など)の、会社の保管庫に置く。一覧の1枚と、各アカウントの中身を同じ所に。
- **このリポジトリ・Issue・Slack・チャットの AI に書かない**。ここにあるのは型だけ。
- 紙が要る物(物の鍵・予備のコード)は、金庫か封をした封筒で、置いた場所だけを一覧に書く。
- 持ち主のメールは**会社の共有のアドレス**にする(個人のメールにすると、辞めたときに通知が消える)。

## 4. 持ち主が急にいなくなったとき(1人の間)

1人の間は、持ち主が倒れると誰も入れない。前もって**開けられる人を1人決める**(家族・共同の創業者・顧問など。社員でなくてよい)。

- パスワードの管理の道具の**緊急のアクセス**(決めた人が申し込み、持ち主が一定の日数のうちに断らなければ開く機能)を、その人に向けて設定する。道具に無ければ、金庫の場所とその開け方を封をした封筒で渡す。
- その人に渡すのは**開け方だけ**。中身は渡さない(開けるのは本当に要るときだけ)。
- 開けた後にすることを一覧の頭に1行書く: 「まず [incident.md](incident.md) を開き、本番を止める・戻すのは手順書のとおりに」「2人目の管理者を足す([joiner-leaver.md](joiner-leaver.md) の 1)」。

## 5. 見直す(半年ごと・人が変わったとき)

- 点検の `emergency-access` が半年ごとに聞く。そのとき:
  1. 一覧の行と、[../compliance/vendors.yaml](../compliance/vendors.yaml) の委託先・実際に払っている請求を見比べ、足りない行を足す・使わなくなった行を消す。
  2. 二段階認証の機器が、今もある物か(機種を替えて古いスマホに残っていないか)。
  3. 緊急のアクセスの相手が、今も頼める人か。
- 人が入る・辞めるとき([joiner-leaver.md](joiner-leaver.md)): 持ち主の列を書き直す。辞める人が持ち主の行は、辞める日の前に移す。
- 2人目の管理者ができたら(`acct-two-admins` で「2人目を決めた」): この一覧はそのまま残し、2人とも開けられるようにする。
