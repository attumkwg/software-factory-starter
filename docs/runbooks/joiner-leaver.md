# 手順書: 人が入る・辞める・役割が変わる日のアカウント

> **入る日に要る物だけ作り、辞める日に全部止める。** 四半期ごとの棚卸し(点検の `access-review`)は「漏れを見つける」物で、その日にやる手順はここ。点検の `people-changes` が毎月「入った・辞めた人はいたか」を聞く。
> 決まりの元は基本方針の「人の出入り」([compliance/policies/basic-policy.md](../compliance/policies/basic-policy.md) の 8)。仕様は [specs/0034](../specs/0034-joiner-leaver.md)、既定の値の未確定事項は設計書 [0034](../designs/0034-joiner-leaver.md) の U-1・U-2。
> **本番の DB と AWS に書き込む操作は人が打つ**(AI は打たない。手順のコマンドを確かめて渡すまで)。

## 0. 道具の一覧(最初に、自社の物に直す)

このキットの既定で、人ごとのアカウントがある所。**ほかに使っている道具があれば行を足す**(委託先の台帳 [compliance/vendors.md](../compliance/vendors.md) の会社と、社内の道具)。

| 道具 | 何ができるか | エンジニア | CS・営業 |
|---|---|---|---|
| **AWS**(IAM Identity Center) | dev・stg・prod の操作。prod は本番のデータに届く | dev と stg。prod は当番か、要るときだけ | なし |
| **GitHub**(組織とリポジトリ) | コード・PR・Issue・本番へのデプロイの承認(Environments) | 書き込み | Issue だけ(要るなら) |
| **運営の組織**(本番のアプリ。Cognito と DB の行) | お客さんが許可したときに、お客さんの画面を見る(代理ログイン) | 問い合わせを受ける人だけ | 問い合わせを受ける人だけ |
| **Sentry** | 失敗の記録(ID とスタック) | あり | なし |
| **Slack** | `#alerts-prod`・`#incident`・知らせ | あり | あり |
| **Claude(Claude Code)** | AI。本番の個人データは渡さない(AI-6) | あり | 要るなら |
| 会社のメール | 上の道具のログインと、パスワードの再設定の宛先 | あり | あり |

- どれも**人ごとのアカウント**(共有しない)・**二段階認証**(点検の `acct-mfa`)。
- 会社のメールを止めても、ほかの道具は止まらない(パスワードと二段階認証で入れてしまう)。**道具ごとに止める**。

## 1. 入る日

前提: 秘密を守る誓約を交わし、教育([compliance/policies/training.md](../compliance/policies/training.md))を受けた(基本方針の 8)。

1. 上の表の「役割」の列で、要る道具だけを決める。**prod の権限は最初は渡さない**(当番になるとき・要るときに足す)。
2. 道具ごとに作る:
   - AWS: Identity Center に利用者を作り、役割のグループに入れる(dev・stg)。アクセスキー(長く使える鍵)は作らない。
   - GitHub: 組織に招待し、チームに入れる。危険度「高」を見る人なら CODEOWNERS のチームにも。
   - 運営の組織: 問い合わせを受ける人だけ。[support-access.md](support-access.md) の 1 の SQL で社員の行を足す(2人で確かめる)→ 本人がアプリで登録 → 二段階認証の設定。
   - Sentry・Slack・Claude: 招待する。
3. 本人に、二段階認証をすべての道具で設定してもらう。設定するまで prod と運営の組織は使わせない。
4. 記録(下の 4)に、作った道具と日付を書く。

## 2. 役割が変わる日

- 増える物は 1 と同じ。**減る物は 3 と同じ手順で、その日に外す**(「念のため残す」をしない)。
- CS からエンジニアへ・エンジニアから営業へ、のように変わったら、上の表の列を入れ替えて差分を出す。

## 3. 辞める日

**いつ止めるか**: 本番に届く物(AWS の prod・運営の組織・GitHub の本番の承認)は、**辞めると決まった日に**外す。ほかは**最終日の業務の終わり**に全部止める(U-1)。急な退職・解雇は、告げる前に全部止める。

上から順に(届く範囲の広い物から):

1. **AWS**: Identity Center の利用者を「無効」にし、グループから外す。IAM のユーザーやアクセスキーがあれば消す(使っていた鍵は点検の `key-rotation` の手順で)。
2. **GitHub**: 組織から外す(チーム・CODEOWNERS・Environments の承認者からも外れる)。個人のアクセストークンは組織から外せば効かなくなる。Environments の承認者に名前で入っていたら `.github/setup.yml` を直す PR。
3. **運営の組織**: Cognito の利用者を止める(次からログインできない)→ DB の行を消す(関所が毎回「いまも運営の組織の人か」を確かめるので、ログインしたままでも次のリクエストから入れない):

   ```bash
   POOL=<ユーザープールの ID>
   name=$(aws cognito-idp list-users --user-pool-id $POOL --filter "email = \"<社員のメール>\"" --query 'Users[0].Username' --output text)
   aws cognito-idp admin-disable-user --user-pool-id $POOL --username "$name"
   ```

   DB の行は [support-access.md](support-access.md) の 1 の「社員が辞めたら」(2人で)。
4. **Sentry・Slack・Claude**: 組織から外す(Slack は「無効」。書いた物は残る)。
5. **会社のメール**: 止める(自動の転送を置くなら、上の道具のパスワードの再設定が届かない宛先に)。
6. **その人が見られた秘密を替える**: GitHub の秘密・AWS の Secrets Manager の値を、その人が読める権限を持っていたなら(管理者だった・prod の役割を持っていた)。点検の `key-rotation` の手順。
7. **管理者が2人いるか**: 辞めた人が GitHub・AWS の管理者なら、残りが1人になっていないか(点検の `acct-two-admins`)。点検の台帳の担当者・相談先(`docs/checkup/todo.yaml` の `owners`)だったら、次の人に替える。
8. 端末と資料を返してもらう(基本方針の 8)。
9. 記録(下の 4)。

- **止めたアカウントは 90日後に消す**(U-2)。その間に「誰が何をしたか」を調べられるように。監査ログ・管理操作の記録の「誰が」は ID のまま残る。

## 4. 記録(1人1回1枚)

**名前が入るので、公開のリポジトリには置かない**(置き場は [compliance/records/README.md](../compliance/records/README.md) の表に書く)。

```markdown
# 入社 / 退職 / 役割の変更: <社内の ID>(名前は書かない形でもよい)

- 日付: YYYY-MM-DD(辞めると決まった日: YYYY-MM-DD)
- 役割: エンジニア / CS / 営業 → (変更なら、変更後)
- やった人: @   確かめた人: @

| 道具 | 作った / 外した | 日時 | 備考 |
|---|---|---|---|
| AWS | | | |
| GitHub | | | |
| 運営の組織 | | | |
| Sentry | | | |
| Slack | | | |
| Claude | | | |
| 会社のメール | | | |
| 秘密の入れ替え | | | 要らなければ「権限なし」 |
| 90日後に消す | | YYYY-MM-DD | |
```

## 5. 困ったとき

| こんなとき | どうするか |
|---|---|
| 辞めた人のアカウントが、棚卸し(`access-review`)で見つかった | その日に 3 をやる。記録が無かった理由を書き、この手順書のどこで抜けたかを直す |
| 辞めた人の鍵・トークンが、どこかで使われている(CloudTrail・GitHub の監査ログ) | [secret-leak.md](secret-leak.md) |
| 辞めた人しか分からない設定がある | 止める前に引き継ぐ(点検の `handover`)。止めるのは遅らせない |
| 辞めた人がアカウントの持ち主だった(root のメール・二段階認証の機器・ドメインの業者・請求) | 辞める日の前に、引き継ぎの置き場([emergency-access.md](emergency-access.md))の持ち主の列を書き直し、持ち主を移す |
