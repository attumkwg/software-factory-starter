# ペルソナ: タスク管理(見本)

> **見本**。題材はこのキットの TODO アプリ(組織 → プロジェクト → タスク)。**中身は架空**(「(架空)」と書いた所)。
> 自分のプロダクトでは、`/kickoff` が `_template-personas.md` の形で書き直す(見本の賭け B-0001・B-0002 を残すなら、ここの P-1・P-2 も残す)。
> 賭け・KPI(`kpi.yaml`)・仕様は、ここの `P-n` を指す。番号は変えない。考え方は [../guides/kpi.md](../guides/kpi.md)。
> 最終更新: 2026-10-28

## P-1 進み具合を見て、催促する人

- 使う人: 10〜30人の会社の、プロジェクトを見ている人(現場監督・制作進行など)(架空)
- 買う人: 社長(10人まではほぼ同じ人)
- 決める人: 社長と、P-1 本人
- 状況: 事務所のパソコンで朝に一覧を見て、日中は外からスマホで確かめる
- やりたいこと(用事): 期限に遅れそうな仕事を早めに見つけ、誰に声をかけるかを決める
- 困りごと: 「終わったかは画面を開かないと分からない」「期限が近いのを毎朝探している」(架空)
- 欲しい成果(数で言える形): 催促の電話・チャットが週5回 → 1回。毎朝の確認が15分 → 2分(架空)
- いまの代わり: Excel の表とチャットで「終わりましたか?」と聞く
- 確からしさ: 話を聞いた5組織のうち4つが、自分から「毎朝探している」と話した(架空。B-0002 の cpf)
- 北極星の指標とのつながり: 期限の前に終わったタスクが増える = 催促しなくて済む(K-0)

## P-2 タスクを片づける人

- 使う人: P-1 の会社で、割り当てられたタスクを片づける人(職人・作業者)(架空)
- 買う人: (P-1 の会社が買う。本人は選ばない)
- 決める人: (同上)
- 状況: 現場でスマホ。手が空いたときに少しだけ見る
- やりたいこと(用事): 自分の分を終えて、終わったことを伝える
- 困りごと: 「終わったのに、また電話で聞かれる」(仮説)
- 欲しい成果(数で言える形): 終わったことを伝える手間が1回の電話 → 1回のタップ(仮説)
- いまの代わり: 電話・チャットで「終わりました」と送る
- 確からしさ: (仮説)まだ話を聞いていない
- 北極星の指標とのつながり: 完了にするのが手早いほど、P-1 に早く届く(K-2)
