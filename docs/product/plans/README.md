# 2つ目からの客層の計画

> 本業(1つ目の客層)の計画は [../plan.md](../plan.md)。**新しい客層・新しい用途**(例: 診療所の次に介護施設)を、本業と並べて別の計画として確かめるときは、ここに1つずつ置く。
> 書くのは `/kickoff`(「新しい客層の計画」を選ぶ)。形は本業と同じ [../_template.md](../_template.md)。考え方は [guides/bets-and-assets.md](../../guides/bets-and-assets.md) の「2段の入れ子」。

- ファイル名は `<英語の短い名前>.md`(例 `care-facilities.md`)。1つの客層に1つ。
- 賭けの「親」には、どの計画のどの仮説かを書く(例 `親: plans/care-facilities.md の仮説1`)。本業の賭けは今までどおり `plan.md`。
- 予算と止める線(「半年・月◯万円まで」「半年で有料の施設が20」)は、計画の「合格と撤退の線」に書き、金額の枠は非公開の置き場の `budgets.csv` に賭けごとに置く(費用のページが超えそうなときに知らせる。[guides/cost-dashboard.md](../../guides/cost-dashboard.md) の 10)。
- **共通の基盤は要るまで作らない**(新しい客層のために、会社と店舗の階層・別の画面の枠組みを先に作らない)。確かめが進んでから、仕様と設計で決める。
- やめたら、ファイルは消さずに「これまでの判断」に `やめる` を書く(何が分かったかを残す)。
