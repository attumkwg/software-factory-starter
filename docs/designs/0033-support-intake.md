## 1. 設計方針

- 手引き1枚。`/report-bug` のスキルは変えない(すでに個人情報を貼らせない決まりがある。手引きはその手前の仕分けと、渡す物をそろえるだけ)。
- AI に渡す範囲は `ai-data.md` が正。手引きの表は、その行を問い合わせの仕事に広げた物で、`ai-data.md` の行から手引きを指す。
- 道具の AI の機能は切る(ADR 0044)。

## 4. 状態遷移

## 5. システム間連携

該当なし(この PR では外へ出さない)。入れたら、受け口の道具は `委託`・`personal` で委託先の台帳に1件。受け口 ↔ Issue は番号で結ぶ(Issue には受け口の番号だけ、受け口には Issue の番号)。

## 6. 業務ルール

- 段階: 共有の受信箱(兼任)→ ヘルプデスクの道具とヘルプの記事(2人目)→ 検索(数百社)。電話は最初は受けない・個人の受信箱で受けない(U-2)。
- 選び方: 番号と履歴・担当と状態・置き場所の国・AI の機能は切る・アカウントは人ごとに二段階認証・費用。
- 仕分け(最初の返事の前): 他社のデータ → tenant-data-leak(Issue にしない)/ 漏えい → personal-data-breach(受けた時刻が起点)/ 何社も → 障害の宣言 / 不具合 → `/report-bug` / 使い方 → 答えて3回でヘルプの記事 / 契約・解約 → 責任者・書面 / 中を見てほしい → 管理者の許可 / 本人の求め → 責任者(G-06)。
- `/report-bug` へは ID・requestId・時刻・再現の手順だけ。スクショは受けた人が見るだけ。
- 2人目の目安(U-1): 兼任でよい = 週10件まで・最初の返事1営業日以内・開発の時間の2割まで / 2人目 = 週20件超か、2営業日を超える週が続くか、休むと止まる。

## 8. 非機能

- セキュリティ: 本文・スクショを AI と Issue に渡さない。受け口のアカウントは人ごと・二段階認証。
- 運用: 件数と最初の返事までの時間は受け口の道具で数える。
- 費用: 0円(文書だけ)。道具を入れたら月額。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 道具の AI の機能を切る — AI-6 と委託先の台帳の決まり(AI の会社に personal を預けない)に従う。変えるなら決まりの側を人が見直す(ADR 0044)。
- `/report-bug` のスキルは変えない — すでに「個人情報を貼らせない・ID に置き換える」がある。手引きで手前をそろえれば足りる。
- 仕分けの最初に「他社のデータが見えた」を置き、Issue にしない — `/report-bug` の最初の1問と同じ理由(公開の Issue に書くと広がる)。
- 同じ質問が3回でヘルプの記事にする — 書く手間と答える手間の釣り合いの目安。数は使う人が変えてよい(業務の問いではない)。
- `docs/README.md` の手引きの行とカタログには足していない — 並行の PR が同じ行を直していてぶつかる。手引きは `ai-data.md` から指す。キットの中に部品を足していない。
- 想定の場面(`docs/scenarios/`)は直さない — 場面の持ち主が直す。
