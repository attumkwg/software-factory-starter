## 1. 設計方針

- 手引き1枚。LP のタグの決まりは `landing-page.md` を正にして指すだけ(2か所に同じ決まりを書かない)。
- 委託先の台帳の例は手引きの中(台帳は使っている物だけ。設計書 0032 と同じ理由)。
- 道具の AI の機能は切る(AI-6・台帳の決まり。問い合わせの受け口と同じ)。
- ADR は足さない(既存の決まりの当てはめ)。

## 2. データモデル

該当なし(DB に触らない)。CRM の会社の記録に、アプリの組織の ID を書いて結ぶ(アプリの側は変えない)。

## 3. API

該当なし。アプリから CRM への連携は作らない。

## 4. 状態遷移

該当なし。お客さんの担当者の記録: 商談中 → 契約中 → 解約(1年後に消す。U-2)。

## 5. システム間連携

該当なし(この PR では外へ出さない)。入れたら委託先の台帳に1件(`委託`・`personal`)。

## 6. 業務ルール

- 区分: CRM・MA・名刺は personal。広告のタグは LP の決まり。
- そろえる物: 台帳・人ごとのアカウント・入社退職の一覧・AI の機能を切る・越境。
- 守ること: アプリの中にタグを入れない・アプリの利用者のデータを宣伝に回さない(U-1)・組織の ID で結ぶ・利用の記録を CRM に送らない・リポジトリに商談の中身を書かない。
- AI: 組織の ID・段階ごとの件数・受注の率・来た所ごとの数・人が分類した理由ごとの数(数社以上の束)まで。
- 解約: 担当者の記録は1年後に消す(U-2)。道具をやめたら書き出して閉じ、台帳を ended に。

## 8. 非機能

- セキュリティ: アプリの画面に外のタグを入れない。道具のアカウントは人ごと。
- 法令: 外部送信・個人関連情報・広告のメール・越境は専門家に(手引きの 6・landing-page.md)。
- 費用: 0円。

## 10. 観点ごとの扱い

| 観点 | 扱い | 理由 |

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- アプリの中(ログインの後)に広告・MA・解析のタグを入れない — 利用者の業務の画面の情報が外の会社に渡る。LP の決まり(landing-page.md)とそろえる。
- 道具の AI の機能を切る — AI-6 と台帳の決まり(問い合わせの受け口と同じ。ADR 0044)。
- CRM とアプリは組織の ID で結び、自動の連携を作らない — 利用者の個人データを宣伝の道具に写さない。
- 委託先の台帳の例を手引きに置く — 台帳は使っている物だけ(設計書 0032 の 1)。
- `ai-data.md` に1行足した — AI に渡す範囲の正は ai-data.md。
- ADR は足さない — 既存の決まりの当てはめ。
- 想定の場面(`docs/scenarios/`)は直さない — 場面の持ち主が直す。
