## 1. 設計方針

- 新しいスキル・コマンドは足さない。ひな形の節と、`/kickoff` の B の段を1つ。
- 1社あたりの原価は費用のページが正。plan.md には割合か「足りる / 足りない」だけ(金額をリポジトリに置かない。費用のページの決まりと同じ)。
- 線は目安(ADR 0035)。届かなければ意思で進むの既存の流れ。
- ADR は足さない(既存の考え方に段を1つ足すだけ)。

## 2. データモデル

該当なし。plan.md の節: 手作業の裏方の表・1社あたり(手間・原価・値段との比べ)・誰が回すか・SPF の線。

## 3. API

## 4. 状態遷移

該当なし(段の進み方は今の B の判断と同じ: 進む・変える・やめる・意思で進む)。

## 5. システム間連携

該当なし。費用のページの出力(非公開の置き場)を人が見せる。

## 6. 業務ルール

- 聞く時期: PSF の後か、有料の顧客が付いたら。それより前は「まだ」。
- 聞く順: 手作業の裏方 → 置き換え → 1社あたりの原価 → 誰が回すか → 線と比べる。1回に1つ。
- キットにある運営のコマンド・手順書で置き換えられる物は「すでにある」と書く。
- 仕組みにする置き換えは `/bet` の候補(勝手に始めない)。
- 金額・人の名前を書かない。
- 線の例(U-1): 1社あたりの毎月の手間 60分以内・原価が料金の3割以内・1人休んでも止まらない。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 新しいスキルを足さず、`/kickoff` の B に段を足した — 結果を持ち帰ったときに一緒に見るのが自然。呼ぶ所を増やさない。
- 金額を plan.md に書かない — 費用のページの決まり(時給・売上は非公開の置き場だけ)とそろえる。
- 担当は役割で書く — plan.md はリポジトリにある。
- ADR は足さない — 1. の理由。
- 想定の場面(`docs/scenarios/`)は直さない — 場面の持ち主が直す。
