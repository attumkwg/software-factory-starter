## 1. 設計方針

- 新しい仕組みを作らず、今ある3つ(観点の台帳・レビュー役・VRT の画像)をつなぐ。仕様 0096 と同じ作り。
- 画像は VRT の基準の画像を使う。画面を変えれば撮り直しが要る(撮り直さないと VRT が赤)ので、変わった画像は PR に必ずある。
- 見方の知識は手引きに置き、レビュー役の定義には「🎨 のときの守ること」だけを書く(知識は人が読んで足せる所に)。

## 2. データモデル

- 該当なし(DB は触らない)。

## 3. API

- 該当なし。足すスクリプト:

| 道 | 入力 | 出力 |
|---|---|---|
| `scripts/ux-screens-lib.mjs` の `shotOf(path)` | ファイルの道 | 基準の画像なら `{ width, screen }`、違えば null |
| 同 `touchesScreens(changed)` | PR で変わった道 | 画面の道に触るか(テストだけは入れない) |
| 同 `planShots(changed, headShots)` | PR で変わった道・PR の版の基準の画像 | `{ changedShots, files: [{ side, path, name }] }` |
| `scripts/ux-screens.mjs <番号>`(`pnpm ux:screens`) | PR の番号 | 一時フォルダに画像を書き、場所を並べる。当てた版も出す |

## 4. 状態遷移

- 該当なし(PR のレビューの流れは仕様 0096 のまま。呼ぶ人格が1人増えるだけ)。

## 5. システム間連携

- GitHub: `gh pr view`(head の版)・`gh pr diff --name-only`。git: `fetch origin main pull/<番号>/head`・`ls-tree`・`show`。書くのは一時フォルダだけ

## 6. 業務ルール

- 🎨 を呼ぶ: 画面の道(`apps/web/src/`・`packages/ui/`・`apps/site/`)に触る PR。危険度によらない。「中」「高」の5人には入れない
- 🎨 は画像を見てから所見を出す。撮られていなければ ⚠️ の所見(VRT に足す)
- 好みは提案へ。所見には困る人と場面。直し方は `@app/ui` の中。新しい色・余白は ❓

## 8. 非機能

- 費用: 画面を変える PR で、レビュー役の呼び出しが1回増える(並べて呼ぶので時間は増えにくい)。画像は1枚あたり数百 KB を十数枚まで
- セキュリティ: 画像は種データだけ(VRT の決まり)。書くのは一時フォルダだけ

## 9. このプロダクト特有

- 該当なし(画面の使いやすさの観点は、どのプロダクトにも当たる)。

## 10. 観点ごとの扱い

| 観点 | 扱い | 理由 |
|---|---|---|
| 設計方針 | 最重要 | 今ある台帳・レビュー役・VRT の画像をつなぐだけにした。新しい道具は足さない |
| 要求との対応 | 機械で検証 | 台帳の形と画像の選び方はテスト。AI の手順は今の画面で1回回して確かめた |

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 🎨 は「中」「高」の5人に入れず、画面を変える PR に危険度によらず呼ぶ — 画面に触らない「高」の PR で呼んでも見る物が無い。画面の変更は「低」でも迷うかどうかが変わる
- 画像は VRT の基準の画像 — 画面を変えれば撮り直しが要るので、変わった画像は PR に必ずある。その場で撮る仕組みは作らない(VRT に無い画面は「VRT に足す」所見に寄せる)
- 知識は手引き、守ることはレビュー役の定義 — 見方は人が読んで足す物、守ることは変えにくい所(守る場所)に置く
- 10の目安は Nielsen の10の目安をこのキットの言葉に — 世間で定番の物差しに寄せる(持ち主「世間一般的に優れている UX デザイナーが指摘するようなこと」)
