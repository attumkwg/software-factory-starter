## 1. 設計方針

- 業界の前提(Markdown)→ ペルソナ(Markdown)→ 合議の記録(Markdown)→ KPI(YAML)。機械が読むのは、立場・決める力・根拠・客層の行と、合議の記録の見出しと表だけ
- 合議の中身(AI の呼び方・問いの形)はスキルに書き、機械は記録の形だけを見る
- 確かめは今までどおり `pnpm kpi` 1本(立場の地図と合議の記録も見る)

## 2. データモデル

- `docs/product/industry.md`(客層が2つ以上なら `industries/<名前>.md`): 自由な Markdown(機械は読まない)
- `docs/product/personas.md`: `## P-n …` と `- 立場:`(使う人・買う人・決める人・止める人・周りの人・失う人・運営)・`- 決める力:`(拒否権・予算・影響・なし)・`- 根拠:`(記録・公開の事例・推測で始める)・`- 客層:`(任意)・`- 状態: やめた`(任意)
- `docs/product/councils/YYYY-MM-DD-<名前>.md`: 見出し 1〜7 と、1 の表(ペルソナ・立場・賛否・自分の成功・一番の懸念・根拠)
- `kpi.yaml` の指標に `council:`(記録のパス)

## 3. API

## 4. 状態遷移

- 合議の記録の「7. 人の判断」: 未定 → @名前 日付 何を決めたか(書き直さず、やり直しは新しい記録)
- 指標の `status`: 仮説(合議の結論が推測だけ)→ 確か(本物の人に確かめた・人が決めた。council が要る)

## 5. システム間連携

- 合議は Claude Code の Agent(1人1つ・並べて同時に)。議論の回は、同じエージェントに続けて頼む(最初の答えを覚えている)
- Web の調べ物は、人が見ている手元のセッションでだけ(`docs/guides/unattended-ai.md`)

## 6. 業務ルール

- 立場のそろい: 客層ごとに、やめていない人で7つの立場が1人以上
- 合議の記録: 7つの見出し・賛否(賛成・条件つき・反対・拒否)・根拠(記録・事例・推測)・出席の立場が7つそろう・拒否した人は 4 に名前・6 に問いが1つ以上・7 は「未定」か「@名前」
- 「確か」の指標は council が要り、その記録が存在する
- 追う数の上限: 入力 1〜2・守り 1〜2(`LIMITS`)。`watch:` は数えず、目標・線を見ない。番号は候補のまま(`K-n` か `K-Gn`)
- レビューは周ごとに議長が案を直し、新しい拒否・満たしていない条件が出なくなるか3周で止める(スキルの決まり。機械では見ない)

## 8. 非機能

- 合議の費用: 10人なら1回目 10・反論役 1・議論の回 10 のエージェント(軽いモデルでよい)。見本では1人あたり数十秒で返った

## 9. このプロダクト特有

- 見本は工務店・制作会社向けのタスク管理(架空)。業界が違えば `/persona` で作り直す

## 10. 観点ごとの扱い

| 観点 | 扱い | 中身 |
|---|---|---|
| 合議の質 | 最重要 | 1人ずつ別に・根拠の強さ・推測だけの賛成は数えない・拒否は多数決で消さない・反論役・議論の回 |
| 立場の偏り | 採用 | 7つの立場を機械で見る |
| 業界の差 | 採用 | 業界の前提を先に・客層ごとにそろえる |

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 立場は7つ(使う人・買う人・決める人・止める人・周りの人・失う人・運営)。持ち主が選んだ案の中身のまま
- 合議の記録の見出しは7つで固定(機械が読む)
- 「確か」の指標だけ合議を必須にし、「仮説」は知らせるだけ(作りかけの木を止めない)
- 議論の回は、最初の答えを覚えている同じエージェントに頼む
