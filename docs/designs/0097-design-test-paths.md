## 1. 設計方針

- **要求との対応**: `scripts/design-tests-lib.mjs`(読む・判定・選ぶ。git もファイルも触らない)と `scripts/design-tests.mjs`(入口。git で変えた物を拾い、ファイルを読む)。CI の速い検査(`ci.yml` の `fast`)に1段足す。新しい依存は足さない(node の標準と git だけ)。
- **数えるのはテストのファイルだけ**。ファイル名に `.test.` か `.spec.` がある物。テストにならない受け入れ条件(文書の中身など)は「(手で確かめる: 理由)」と書けて、落ちずに出力に並ぶ(持ち主の判断「テストだけ数え、手も書ける」)。
- **変えた設計書だけを見る**。今の設計書のうち、ほとんどは、どこかの行がパスを書いていない(通り名か「画面の単体テスト」)。全部を見ると CI が落ちたままになる。見るのは「新しい設計書」「7 の節か状態の頭の言葉を変えた設計書」「この PR で『完了』にした仕様を指す設計書」。リンクの付け替えなどの文の直しで触れただけなら見ない(その PR が昔の表を直す羽目にならないように)。この緩めは持ち主が承認した(「仕様が完了なら見る・緩めは承認」)。
- **無いファイルは「完了」で落とす**。設計書は仕様の PR で実装より先に入る(`/design` の 6)。その時点ではテストのファイルはまだ無い。最初はパスを書くことだけを求め、設計書か指す仕様の状態を「完了」にした PR で、ファイルがあることを求める(作り終えた PR は仕様だけを「完了」にすることが多いので、仕様でも見る)。
- **検査の中身は守る場所**。`scripts/design-tests*.mjs` を `.claude/hooks/protected-paths.json`・`.github/labeler.yml` の risk:high・`.github/CODEOWNERS` に足す(緩めると作り忘れが通る。`scripts/test-weakening*.mjs` と同じ扱い)。
- **監査ログの画面の文**: 画面の単体テスト(`audit-labels.test.ts`)に1件。API のコードは画面から import しない(別のサービス。ADR 0003)ので、ファイルを文字として読む。正規表現は使わない(Semgrep の regex_dos)。読むファイルが画面のパッケージの外なので、`turbo.json` の画面のテストの入力に `actions.ts` を足す(変えたらキャッシュを使わずに流し直す)。

## 6. 業務ルール

- 確かめる設計書: `docs/designs/` の直下の `.md`(`_template.md`・README を除く)のうち、
  - 元から変えた物(作業中の物・git にまだ無い物も。消した物は見ない)で、元に無い(新しい)か、「要求との対応」の節か状態の頭の言葉が元と違う物
  - 元から変えた仕様(`docs/specs/` の直下)のうち、状態の頭の言葉が「完了」になった物を、「> 仕様:」の最初のリンクで指す設計書
- 状態: 「> 状態:」の行の頭の言葉(下書き・承認済み・完了)だけを読む・比べる(承認した人の書き換えでは見ない)。新しい設計書で、行が無い・頭の言葉が読めない(全角の「：」など)なら落とす。
- 元: 引数 `--base`(CI は `HEAD^1`)。無ければ `origin/main`。元との分かれ目(merge-base)から比べる。git の呼び出しの失敗だけを受け、ファイルが読めない失敗はそのまま落とす。
  - 元が読めない・最初のコミット(親が無い・浅くない)→「比べる元が無い」と出して通す(`ci-scope.mjs` と同じ向き)
  - 元が読めない・浅い checkout か、親がある(手元で fetch していない)→ 落とす
- git の名前の一覧は `-z`(「\0」区切り。空白や日本語の名前も崩れない。`gaps.mjs` と同じ)。
- 引数にファイルを渡すと、変えたかどうかに関わらず、その設計書を見る(手元で昔の設計書を見るとき)。
- 表: 「## 」で始まり「要求との対応」を含む見出しから、次の「## 」まで。最初の表の頭の行から「テスト」の列を探す。区切りの行は飛ばす。
- パス: テストの欄の「`」で囲んだ物のうち、「/」を含み、空白が無く、ファイル名に `.test.` か `.spec.` がある物。ファイル名だけ・通り名・コマンド・テストでないファイルは数えない。「/」で始まる物・「..」を含む物はリポジトリの外を指すので落とす。
- 手で確かめる: テストの欄に「(手で確かめる: 理由)」(半角の括弧と「:」)。理由が空なら書いていないのと同じ。
- ある: リポジトリの根か、`apps/*`・`packages/*` の中から見てあれば、ある(昔の設計書は `test/integration/…` と `apps/api` の中から書いている)。
- 落とす物: 新しい設計書の状態が読めない / 節・表・「テスト」の列・行が無い / テストのパスも「手で確かめる」も無い行 / リポジトリの外を指すパス / 設計書か仕様が「完了」なのに無いファイル。出すだけの物: 「完了」でないときの無いファイル・「手で確かめる」の行。
- 監査ログの名前: `actions.ts` の、コメントでない行の「"」で囲んだ物のうち、点を含み、空白と「/」を含まない物。行の終わりの `//` の後ろは見ない。画面の文の一覧に無い名前があれば落ちる。拾った中に `project.create`・`auth.login`・`support.read` が無ければ落ちる(拾い方が壊れて0件で通るのを防ぐ)。
- 足した画面の文(11件): `organization.task_mail_on`「タスクが完了したメールを送るに戻した」・`organization.task_mail_off`「タスクが完了したメールを止めた」・`tenant.delete`「組織を消した(解約)」・`data.export`・`sso.update`「SSO の必須と緊急用の管理者を変えた」・`sso.connect`・`sso.disconnect`・`pre_registration.purged`・`deleted`・`converted`「事前登録を組織にした印を付けた」・`found`「…見つけた」(見つかったときだけ残る)。
- 運営のコマンドが残す名前(`sso.connect`・`sso.disconnect`・`pre_registration.deleted`・`pre_registration.found`)は、文に「運営が」と書く。行為者の記録(誰が残したか)は変えない(持ち主の判断「文に『運営が』・記録は別の穴」)。
- 対象の種類の文に `pre_registration`「事前登録」・`file`「ファイル」を足した(無いと種類の名前がそのまま出る)。

## 8. 非機能

- 性能: 変えた設計書の数だけ確かめる。仕様を変えた PR では全部の設計書の頭を読む(100本ほど。1秒未満)。git を数回呼ぶだけ。
- セキュリティ: 外へ出ない。git の引数は配列で渡す(シェルを通さない)。パスはリポジトリの中だけを見る。
- 運用: 落ちたときの文に、どの行か・何を書けばよいかを出す。手引きはひな形の 7 と `docs/reference.md`。
- 費用: 増えない。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

> 持ち主が決めた2つ(変えた物だけ・仕様の「完了」でも見る / テストだけ数え、手も書ける)は仕様の「決めたこと」。

- パスは根からでもパッケージの中からでもよい — 昔の設計書(0089 など)は `apps/api` の中から書いている。根からだけにすると、その表に触れたときに全部書き直しになる。ひな形は根から書くように直した
- ファイル名だけ(`mail.int.test.ts`)はパスに数えない — 同じ名前が複数の場所にありうる。どれか分からない物は名指しにならない
- 状態は頭の言葉だけを比べる — 「承認済み(承認した人: …)」の書き換えで昔の表まで見る羽目にならないように
- 比べる元は CI では `HEAD^1` — PR を合わせたコミットの1つ目の親が PR の元(`ci-scope.mjs` と同じ)。main への push・マージキューでも1つ目の親と比べれば、入った差分だけを見る
- 最初のコミット(親が無い)は見ずに通す。浅い checkout は落とす — 前者は比べる物が無い(`ci-scope.mjs` と同じ向き)。後者は設定の誤りで、黙って通すと検査が飛ぶ
- テストのファイルを消す PR は見ない(設計書を変えなければ) — 消したテストを設計書の側から探すには全部の設計書を見る要がある。テストを消した PR には印 tests:weakened が付き、人の目に出る(`test-weakening.yml`)
- 画面のテストは API のコードを import せずに文字で読む — 画面と API は別のサービス(ADR 0003)。名前の一覧は文字の形が決まっている(`action: "…"` と `名前: "…"`)
- 足りなかった画面の文は、#187 の2件のほかに9件も足した — 全部の名前に文があることを確かめるので、足さないと通らない。文は今ある文の言い回しに合わせ、何をしたかが分かるように直した(`found` は見つかったときだけ・`converted` は印を付けるだけ・`sso.update` は必須と緊急用の管理者)
- `tenant.delete` を `MANUAL_AUDIT_ACTIONS` に移した — 一覧の外に文字で書くと、画面の文の確かめから漏れる
- `actions.ts` のコメントが画面の文の場所を `messages.ts` と書いていたのを `audit-labels.ts` に直した
