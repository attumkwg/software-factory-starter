## 0. 全体像

3つを足す。① 量: 背景の AI の前の段(`claude.yml` の `authors`)で、Claude のアプリが開いた PR を数え、`AI_OPEN_PR_LIMIT` に達していたら動かない。② 費用: モデルの会社の側(Claude の管理画面)で鍵を分けて、ワークスペースと組織に月の上限を置く手引きと、毎月の点検 `ai-spend`。③ 見える化: 費用のページに「AI の回数と時間」(金額なし)。

## 1. 設計方針

- **費用はモデルの会社の側で止める**。キットは使用量を自動で取らない(管理用の鍵を置かない)ので、Actions の側で数えるより、上限に届いたら呼び出しが止まる方が確か。キットは手順と点検を足す。
- **量は前の段で止める**。秘密を持たないジョブで数え、達していたら AI のジョブを動かさない(`needs`)。
- **見える化は金額を出さない**。回数・分数・本数だけ。金額は人が書き写す行(saas.yaml)のまま。
- 数え方は依存の無い Node のスクリプト(`.github/scripts/ai-open-prs.mjs`・中身は `-lib.mjs`)。

## 2. データモデル

該当なし(DB を使わない)。費用のページの `summary.json` に `ai`(`background_runs`・`background_minutes`・`ai_prs`・`prs`)を足す(読めなければ `null`)。

## 3. API

該当なし(アプリの API は変えない)。GitHub の REST を `gh api` で読むだけ: `pulls?state=open`(作った人と種類)。費用のページは集めている物(`github-actions`・`people-prs`)を使い、新しく読まない。

## 4. 状態遷移

該当なし(上限に達したら止まり、PR が閉じたら次から動く)。

## 5. システム間連携

- 前の段の手順を1つ足す(権限はそのまま。`pull-requests: read` で足りる)。上限は workflow の `env` の `AI_OPEN_PR_LIMIT`。
- モデルの会社の側の上限は人が管理画面で置く(キットからは触らない)。

## 6. 業務ルール

- 数える PR: 開いている(下書きも)・作った人が Bot で名前が `claude` で始まる。手元の AI の PR(人のアカウント・`ai:assisted`)は数えない(U-1)。
- 上限: 既定 5(U-1)。数でない・0 以下は 5 とみなす。
- 点検 `ai-spend`: 毎月。上限を置いていない・8割を超えた、は次の週にまた聞く。
- 費用のページ: 背景の AI はワークフローの名前 `Claude` の行。AI が手伝った PR は、人の時間の目安と同じ見分け方(本文の印・ラベル `ai:assisted`)。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- **月の上限はモデルの会社の側に置き、Actions では数えない** — 使用量を取る鍵を置かない(ADR 0032)。上限で呼び出しが止まる方が、数えて止めるより漏れが無い。
- **背景の AI 用のワークスペースと鍵を分ける** — 既定のワークスペースには上限を置けない。手元の Claude Code と同じ上限だと、背景の AI の暴走で手元も止まる。
- **費用のページに金額を出さない** — 公開のリポジトリのログ・ページに金額を残さない(今の決まり)。回数と分数で「1回が重くなった」を見る。
- **点検は8割で知らせる** — 月の途中で上限に届く前に、頼み方か上限を見直す時間を残す。
