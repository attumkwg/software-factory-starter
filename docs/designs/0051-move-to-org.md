## 0. 全体像

リポジトリを個人のアカウントから組織に移すときに洗う物・移す日の手順・マージキューを入れる手順を、手順書 `docs/runbooks/move-to-org.md` に置く。コード・設定・Terraform は変えない(手順だけ)。

## 作業の前に読んだ物(ガイド)

- 想定の場面 `docs/scenarios/07-grow.md` の 7-4、`gaps.md` の G-15。`docs/guides/ci-speed.md`(待ちの内訳)。
- `.github/setup.yml`(`template_repository`・`strict: true`・必須のチェック・「取り組みと作業の種類」はキューで流れない注・Environments の承認者 `@me`)・`scripts/setup/areas-ruleset.mjs`(`mergedRules`: キットが扱わない規則は残す)。
- `.github/workflows/ci.yml`・`vrt.yml` に `merge_group:` がある。
- `infra/terraform/modules/github-oidc/main.tf`(信頼の条件 `repo:${var.github_repository}:…`)・`envs/{stg,prod,preview/base,preview/prototypes}/variables.tf` の `github_repository`。
- ワークフローが使う秘密と変数の名前(`secrets.*`・`vars.*`)。
- GitHub の公式の文書(2026-10-25 に読んだ): リポジトリを移すと、Issue・PR・設定・秘密・Webhook・デプロイの鍵は付いたまま移り、古い URL は転送される(同じ名前を古い場所に作ると消える)。非公開を Free に移すとブランチの守りが使えなくなる。マージキューは `merge_group` の出来事でワークフローを動かす。使えるのは組織の公開のリポジトリと、Enterprise Cloud の組織の非公開のリポジトリ。

## 1. 設計方針

- 手順書1枚。setup のスクリプト・Terraform・ワークフローは変えない(どれも危険度「高」。移す人が手順の中で PR にする)。
- マージキューの規則は画面から足す(`pnpm setup:github` は扱わない規則を消さずに残すので、後で `--apply` しても消えない)。setup に扱わせるのは次の一歩。
- GitHub の仕様は変わるので、確かめた日を書き、移す前に確かめ直すと書く。
- ADR は足さない(仕組みの選び方ではなく手順)。

## 4. 状態遷移

個人のリポジトリ → (止める → 移す → OIDC・App・承認者を直す → 確かめる → 戻す)→ 組織のリポジトリ → マージキューあり。逆に移すこともできる(同じ手順で)。

## 5. システム間連携

- AWS(OIDC): 信頼の条件の `owner/repo` を新しい名前に。広げない。
- GitHub App(Renovate・Claude・Slack): 組織に入れ直す。
- 組織の Actions の決まり: リポジトリの設定より強い。

## 6. 業務ルール

- 2人で・デプロイを止めてから・OIDC は移した直後に apply(人)。
- 秘密と変数は名前だけを控え、値は控えない。
- マージキューの既定の案: squash・同時に流す数 5・1回にまとめる数 最大5・失敗した PR は入れない・チェックの待ち 60分。落ちる PR が多ければまとめる数を下げる。`strict` は外す。
- キューで流れないチェック(PR の本文を見る「取り組みと作業の種類」)は必須から外す。
- プラン(U-1): 公開なら Free の組織でよい・非公開でキューが要るなら Enterprise Cloud。

## 8. 非機能

- セキュリティ: OIDC の条件を広げない・組織の Actions の決まりを緩めない・古い場所に同じ名前を作らない。
- 費用: 非公開でキューを使うなら Enterprise Cloud の席の費用(U-1)。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 手順だけにし、setup・Terraform・ワークフローを変えない — どれも危険度「高」で、移すときに移す人の PR で直す物。
- マージキューは画面から足す — `mergedRules` が扱わない規則を残すので、後の `--apply` で消えない。
- キューの既定の数(同時 5・まとめる 5・待ち 60分) — CI の長さ(数分〜十数分)と、週数百本の PR を見た目安。始めてから落ちる数で直す(手順書の 3 の 6)。
- 秘密は名前だけ控える — 値は GitHub から読めず、控えると漏れる。
- 想定の場面(`docs/scenarios/`)は直さない — 場面の持ち主が直す。
