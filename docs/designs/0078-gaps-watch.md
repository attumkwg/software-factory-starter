## 0. 全体像

`scripts/gaps.mjs`(入口)が `docs/scenarios/gaps.md` の穴の行と「🎯」の節の段の表を読み、行の形・段の抜け・済みの行の仕様の状態を確かめ、`docs/`(仕様・設計書・ADR を除く)と `README.md` から済んだ穴を「まだ無い」と書いた所を探す。数の要約を出し、`--write` で gaps.md の頭の表を作り直す。CI の速い検査(「Biome・型・単体」)で流す。

## 1. 設計方針

- 依存を足さない。Node の標準だけ(`node:fs`・`node:child_process`)。テストは `node --test`(`pnpm test:scripts` に足す)。
- Semgrep の regex_dos に当たらないよう、正規表現を使わずに文字で読む(キットのほかの検査と同じ)。
- 段の正は gaps.md の「🎯」の節の表(人が読む形のまま、機械も読む)。別の YAML は作らない(正を2つにしない)。
- 「古い書き方」は決まった形だけを拾う(❌・「穴 G-xx」・「G-xx が埋まるまで」・「G-xx を入れるとき」)。「無い」「未」は広すぎるので拾わない(仕様のやらないこと)。

## 2. データモデル

DB は使わない。読む物:

- 穴の行: gaps.md の表の行で、1列目が `G-` と2〜3桁。2列目の頭で状態を決める: `→ ` と「に束ねた」= 束ねた(最初の番号が親)/ `✅ 済み` / `✅ ほぼ済み` / `🔧`(PR の番号 `#数字` が要る)/ 🔴🟡🟢 = 残り。済みの行の「仕様 NNNN(・NNNN)」を集める。
- 段の表: 「## 🎯」の節の表で、1列目が `今すぐ`・`使える前に`・`使えた後で` の行。2列目の「(」より前の番号(「〜」は間も)。
- 仕様の状態: `docs/specs/NNNN-*.md` の「> 状態:」の行。
- 今の数の表: gaps.md の `<!-- gaps:summary:start -->` と `<!-- gaps:summary:end -->` の間。

## 3. API

該当なし(アプリの API は変えない)。

- `pnpm gaps`: 問題があれば `場所 文` を並べて 1 で終わる。無ければ 0。数の表はいつも出す。
- `pnpm gaps --write`: 今の数の表を作り直す(ほかの問題は出して 1 で終わる)。
- `gaps-lib.mjs` の関数: `checkGaps(text, specStates)` → `{ rows, stageOf, problems }`・`summarize` → 全部と段ごとの数・`renderSummary`・`currentSummary`・`replaceSummary`・`staleRefs(text, done, { scenario })` → `[{ line, message }]`・`shouldScan(path)`・`isScenario(path)`。

## 4. 状態遷移

穴の行: 残り(🔴🟡🟢)→ 作業中(🔧 #番号)→ ほぼ済み → 済み。束ねた子は親に従う。済みの行の仕様: 下書き → 完了(作り終えた PR で直し、マージする人が見る。状態の言葉は増やさない)。承認済みの仕様は、作り終えても承認済みのままでよい。

## 5. システム間連携

- CI(`.github/workflows/ci.yml` の「Biome・型・単体」)の1段として流す。ジョブの名前は変えない(必須のチェックの名前。`pnpm setup:check`)。
- GitHub には聞かない(🔧 の PR が開いているかは見ない。番号があるかだけ)。

## 6. 業務ルール

| 見ること | 落ちる条件 |
|---|---|
| 番号の重なり | 同じ番号の行が2つ |
| 形の崩れ | 2列目の頭が上の6つのどれでもない(5つに ⛔ やらない を足した。2026-10-29) |
| 作業中 | 🔧 なのに `#数字` が無い |
| 束ねた | 親が一覧に無い・自分・束ねた行 |
| 済みの仕様 | 指す仕様が `docs/specs` に無い・状態が「下書き」で始まる |
| 段 | 段の表の番号が一覧に無い・束ねた子を段の表に書いた・やらない行を段の表に書いた・2つの段に入っている・残っている行(ほぼ済み・作業中・残り・束ねた。親がやらない子は除く)がどの段にも無い |
| 今の数の表 | 印が無い・中身が作り直した物と違う |
| 古い書き方 | 下の表 |

古い書き方(済んだ穴だけ。表の行はセルごと、表でない行は行ごとに見る):

| 形 | 例 |
|---|---|
| 前に「穴」 | 「穴 G-01」「穴 G-01・G-02」 |
| 後ろに「が埋まるまで」「を入れるとき」(閉じかっこの後も) | 「G-01・G-02 が埋まるまでは」「CSP(G-17)を入れるときは」 |
| 同じかたまりに ❌ | 「❌ … 無い(G-41)」 |

- 見ない: 「済」「足す前」を書いたかたまり・台本の「- 足す前の判定」の行とその下の字下げした行・`docs/specs/`・`docs/designs/`・`docs/adr/`・gaps.md そのもの。
- 読むファイル: `README.md` と、`docs/` の下の `.md`・`.yaml`(`git ls-files` の一覧から)。

## 8. 非機能

- 速さ: 文書は数百件・1秒ほど。CI の速い検査に置ける。
- 正規表現を使わない(regex_dos)。ファイルの長さと関数の複雑さは Biome の上限の中。
- 運用: 落ちたら出た場所を直すか、穴の一覧の行と段を直す。直し方は gaps.md の「🎯」の節。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 段の正を gaps.md の表に置き、別の YAML を作らない — 人が読む所と機械が読む所を1つにする(正を2つにしない)。
- 仕様の状態の言葉は増やさない — 済みの行が「下書き」の仕様を指すと落とす決まりにし、作り終えた PR で「完了」に直す(マージする人が見る)。途中の状態(「完了待ち」)も考えたが、言葉が1つ増えるだけなので持ち主がやめた(2026-10-28)。0061・0062・0066・0067・0068 と 0078 は持ち主が「完了」と答えた(0060 も同じ)。
- 「無い」「未」は拾わない — 今も無い物と区別できず、誤って落とす数が多い。決まった4つの形だけにした。
- 「済」「足す前」を書いたかたまりは見ない — 済んだと分かって書いた文(「穴 G-14 は済み」)を落とさないため。
- 🔧 の PR が開いているかは GitHub に聞かない — CI で外に出ない・トークンを使わないため。
- 段の表の「(」の後ろの番号は数えない — 「G-116(G-72 を束ねた)」のように、表の中で子を書けるようにするため。
- 古い書き方を探すのは `README.md` と `docs/` の `.md`・`.yaml` — 外の人と質問票のスキルが読むのはここ。スキル(`.claude/`)とコードの注記は対象にしない(必要になったら足す)。
