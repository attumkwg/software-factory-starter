# 設計: 作る前に決めること(買う人・使う人・決める人/創業者の腹落ち/意思で進む)

> 仕様: [specs/0021](../specs/0021-before-build-decisions.md)。判断の記録: [ADR 0035](../adr/0035-fit-journey-is-a-guide.md)

## 0. 全体像

`/kickoff`・`plan.md` の型・話の記録の型に、買う人・使う人・決める人と、なぜ自分たちか(FPF)の欄を足す。賭けに判断 `意思で進む(@名前)` と `## 意思で進んだ判断` の表を足し、`pnpm bets` が残っているかを確かめ、⚑ で一覧に出す。止めない。

## 作業の前に読んだ物(ガイド)

- `docs/guides/before-pmf.md`・`docs/guides/bets-and-assets.md`・`.claude/skills/kickoff/SKILL.md`・`.claude/skills/bet/SKILL.md`・`scripts/bets-lib.mjs`
- `docs/scenarios/fit-journey.md`(決めることの地図)・`docs/scenarios/00-best-case-run.md`(通しの試し)

## 1. 設計方針

- **止めない・残す**: 線は目安。進むかは本人が決める。キットは「残っているか」だけを確かめる。
- 名前を残す判断(`線を動かす`・`意思で進む`)は同じ扱い(`@名前` が要る)。
- 計画(`plan.md`)は型と対話の手順だけ。機械で確かめるのは賭けだけ(これまでどおり)。

## 2. データモデル

賭けのファイルに表を1つ足す(書いたときだけ要る):

| 日付 | 段階 | 引き受けた危なさ | 止める線 | 期限 | 決めた人 |
|---|---|---|---|---|---|

- 日付と段階は、`意思で進む` の小石と同じ値(小石の段階 = 進む前の段階)。
- `plan.md` の「これまでの判断」の判断の列に `意思で進む(@名前)` を書け、同じ形の `## 意思で進んだ判断` を置く。

なし。

## 4. 状態遷移

- `意思で進む` は `進む` と同じく次の段階へ(idea → cpf → psf → rollout → adopted)。この段階の線が先に決まっていることが要る(結果を見て決める判断)。
- 段階が変わるので、会計区分の案の行も要る(これまでどおり)。

## 5. システム間連携

なし。

## 6. 業務ルール

- `意思で進む` の小石に `@` が無ければ落とす。
- 小石ごとに、`## 意思で進んだ判断` に同じ日付と段階の行が要る。列は6つ・引き受けた危なさと止める線は空にしない・期限は YYYY-MM-DD・決めた人は `@名前`。
- 期限を過ぎた行は、賭けが終わっていなければ(dropped・retired でなければ)⏰ で知らせる。落とさない。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- 判断の名前は `意思で進む`(`進む` と頭が重ならず、読んだ人に意味が通る)。
- 止める線の期限を過ぎても落とさない(止めないため)。⏰ で知らせるだけ。
- FPF の問いは3つ(なぜ自分たちか・何年やるか・やめる条件)。選択肢は出さず、一言で答えてもらう(本人のことなので案を出さない)。
