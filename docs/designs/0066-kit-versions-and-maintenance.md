## 1. 設計方針

- 置き場所は GitHub がそのまま見つける所: `SECURITY.md` はルート(Security のタブに出る)、`CHANGELOG.md` もルート(慣例)。保守の方針はキットの持ち物なので `docs/kit/`(部品のカタログと同じ所)。
- **キットの物と、使う側の物を分ける**: `SECURITY.md` の頭に「これはキットの窓口。作ったら自分の連絡先に置き換える」。`CHANGELOG.md` は使う側では「キットの記録」で、`kit/main` の側で読める(`git show kit/main:CHANGELOG.md`)。
- 版は `v0.Y.Z`。0 の間は「作成中」(README の頭と同じ)。Y は「取り込むときに手が要るか」で上げる(使う側が取り込みの重さを版の数字で分かるように。G-42 の取り込みの手引きがこれを使う)。
- CHANGELOG は**版を切るときに PR の一覧から書く**(PR ごとに書かない)。並べた PR(このキットはセッションを分けて並行で PR を出す)が同じ行でぶつかるのを避ける。
- 新しい依存・ワークフロー・コードは足さない。

## 3. API

## 4. 状態遷移

版: `未リリース` → タグ `v0.Y.Z`(持ち主が打つ)。タグは付け替えない・消さない(戻さない。直すのは次の版)。

## 5. システム間連携

- GitHub の非公開の報告(Private vulnerability reporting)と勧告(Security Advisories)。設定は `.github/setup.yml` で既に有効。新しく足す連携は無い。

## 6. 業務ルール

- Y を上げる: 部品の増減・ファイルの移動・設定ファイルの形の変化・取り込むときに手が要る。Z を上げる: 穴・守りの抜け・文書の直しで手が要らない物。
- 直すのは最新の版だけ。
- 日数も期限も約束しない(U-1・U-2 は変更)。やめるときは README と CHANGELOG に書いて archive。
- タグ・リリースは持ち主。AI は作らない(手元のフックが止めるのは main への push・強制・ブランチの削除で、タグの push は止めないので、決まりとして文書に書く)。

## 11. 決めたこと(AI が決めた。人に聞かなかった)

- `SECURITY.md`・`CHANGELOG.md` はルート、保守の方針は `docs/kit/` — GitHub が見つける所と、キットの持ち物の置き場所に合わせた。
- 版の形は `v0.Y.Z`、Y は「取り込むときに手が要るか」 — README の「作成中」と合い、取り込む側が数字で重さを分かる。
- CHANGELOG は版を切るときに PR の一覧から書く — 並行の PR がぶつかるのを避ける。`/release-notes` と同じく `gh pr list` から下書きできる。
- 直すのは最新の版だけ — 持ち主1人で古い版を保つのは無理がある。
- 最初の版の中身は「これより前は git の履歴」とだけ書く — 214件の PR を並べ直しても読む人がいない。
