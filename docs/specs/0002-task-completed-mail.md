# 仕様: タスクが完了したら、プロジェクトを作った人にメールで知らせる

> 状態: 完了(メールの最初の使い道。仕組みの使い方の例。仕組みは [guides/mail.md](../guides/mail.md))

## なぜ作るか

プロジェクトを作った人(多くは進み具合を見ている人)が、画面を開かなくても「終わった」に気づけるようにする。

## 受け入れ条件

- [x] タスクが「未完了 → 完了」になったら、そのプロジェクトを作った人にメールが届く
- [x] 自分で完了にしたものは、自分には届かない
- [x] 送るまでの間に「未完了」に戻された・タスクやプロジェクトが消された・作った人が消されたら、送らない
- [x] メールには、プロジェクトの名前・タスクの題名・プロジェクトの画面へのリンクがある
- [x] メールの送り先(Postfix)が止まっていても、タスクの完了は成功する。メールは送り先が戻ってから届く
- [x] まれに同じメールが2通届くことがある(アウトボックスは「少なくとも1回」)。2通は同じ Message-ID を持つ

## 権限の表に足した行

なし(API は増えない。完了にする `PATCH /api/tasks/{taskId}` が出来事を積むだけ)。

## 悪用のされ方(STRIDE)

| 観点 | どう悪用されうるか | どう防ぐか |
|---|---|---|
| なりすまし | 中継(Postfix)に別のドメインを名乗るメールを渡す | Postfix は決めたドメインの送り元だけ受け取る。SES の資格情報もそのドメインだけ |
| 改ざん | 題名に改行を入れて、宛先(Bcc)を足す | 件名を1行にそろえる。結合テスト「ヘッダーの注入」 |
| 情報漏えい | 他社の人にメールが届く | 宛先は出来事のテナントの文脈(RLS)の中で読む。出来事の中身はメールを持たない(ID だけ) |
| 情報漏えい | メールのリンクから他社の画面が見える | リンクの先も通常の認可(他社なら 404) |
| 妨害 | タスクを大量に完了にして、メールを大量に送らせる | (今後)宛先ごとのまとめ送り・テナントごとの流量の上限。SES の送信の上限で頭打ち |
| 中継の悪用 | 外から Postfix を使って迷惑メールを送る | Postfix は VPC の中だけ・API のセキュリティグループからだけ受ける(mynetworks も VPC だけ) |

## やらないこと

- 知らせを受け取らない設定・まとめて1通にする(次の一歩)
- HTML のメール(プレーンテキストだけ)
- 担当者への知らせ(担当者がまだ無い)
