# 仕様: SSO(SAML)・SCIM・組織ごとの IP の制限・強制ログアウト・監査ログの書き出し

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。会話で: 設計書 0056 の U-1〜U-8 を「全部おすすめどおり」)
> 設計: [docs/designs/0056-sso-scim-ip-audit-export.md](../designs/0056-sso-scim-ip-audit-export.md)・ADR: [0067](../adr/0067-sso-via-cognito-saml.md)
> 穴 G-14(`docs/scenarios/gaps.md`)。実装は段ごとに別の PR: 段1a(会社のドメインの確認・IP の制限・強制ログアウト)→ 段1b(SSO のログイン・必須・緊急用)→ 段2(SCIM)→ 段3(監査ログの書き出し)。
> 決まり: `docs/security.md` の T-8(SSO は会社のドメインを DNS で確かめてから)・L-8。

## なぜ作るか

100人を超えるお客さん(病院・大きな会社)の情シスは、「職員は院内の ID(SAML)でログイン」「院外の IP からは入れない」「辞めた職員はすぐ止める(SCIM)」「監査ログを自分たちの道具に取り込む」を契約の条件にする。いまはどれも無く、決まり(T-8)だけが「未」のまま。強制ログアウトが要るなら、サーバー側のセッション保存も話に上がる(ADR 0017 は作らないと決めた)。

## 作る順(段)

1. **SSO**: 会社のドメインの確認・SAML の IdP のつなぎ・SSO を必須にする・SSO の外に残る緊急用のアカウント・組織ごとの IP の制限・管理者による強制ログアウト
2. **SCIM**: 情シスの道具から人を作る・止める(止めたらすぐログアウト)
3. **監査ログの書き出し**: 期間を選んで、管理者が自分たちの道具に取り込める形で受け取る

## 受け入れ条件

段1 SSO:

- [ ] 組織の管理者は、会社のドメインを登録し、DNS の TXT レコードで持ち主だと確かめられる。確かめるまで、そのドメインで SSO を有効にできない(T-8)。1つのドメインは1つの組織だけ
- [ ] 運営は、確かめたドメインを持つ組織に、お客さんの IdP(SAML のメタデータ)をつなげる(運営のコマンド。試し → 本番)
- [ ] 利用者は、ログインの画面でメールアドレスを入れると、そのドメインが SSO の組織なら IdP へ回り、戻ってくるとその組織に入る。パスワードは入れない
- [ ] IdP から戻った人は、**その IdP をつないだ組織**にだけ入れる。メールのドメインが、その組織の確かめたドメインでなければ入れない(他社の IdP から自社の人として入れない。L-8)
- [ ] IdP の人がその組織にまだいなければ(招待も SCIM も無ければ)、入れない(設計書 U-2)
- [ ] 組織の管理者は SSO を**必須**にできる。必須の組織では、そのドメインの人はパスワードでログインできない。ただし**緊急用のアカウント**(管理者が選ぶ。2人まで。二段階認証が必須)はパスワードで入れる(IdP が止まったときのため)
- [ ] 組織の管理者は、その組織に入れる IP の範囲(CIDR)を **20 個まで**登録できる。登録があると、ほかの IP からの API とログインは止まる(403)。自分を締め出さないよう、いまの IP が入っていない一覧は保存できない
- [ ] 組織の管理者は、人を**強制ログアウト**できる(その人の全部の端末が、次のリクエストから入れない)
- [ ] ドメイン・SSO・必須・緊急用・IP・強制ログアウトの変更は、その組織の監査ログに残る

段2 SCIM:

- [ ] 組織の管理者は、SCIM の鍵を作れる(画面に1回だけ出る・取り消せる)。鍵で組織が決まる
- [ ] 情シスの道具は SCIM 2.0 の `Users` で、その組織の人を作る・名前を直す・止める(`active: false`)・消すができる。作った人のメールのドメインは、確かめたドメインでなければならない
- [ ] 止めた人は、次のリクエストから入れない(強制ログアウトと同じ)。消した人は止めた人と同じに扱い、行は残す(監査ログの「誰が」を残す)
- [ ] SCIM の操作は、その組織の監査ログに「SCIM が」として残る

段3 監査ログの書き出し:

- [ ] 組織の管理者は、期間(最長 1年)を選んで、監査ログを1行1件の JSON(JSON Lines)で受け取れる。書き出したことも監査ログに残る

共通:

- [ ] どの設定も、組織の管理者だけ(代理の社員は見るだけ・変えられない)。他社の設定は見えない
- [ ] キットの部品のカタログに、`sso`・`scim`・`ip-allowlist`・`audit-export` を足す(使わない会社は消せる)

## 要配慮個人情報

- 当たらない(メール・名前・IP の範囲・監査ログ)。監査ログの書き出しには、もともと値が入っていない。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 他社が自分の IdP で、こちらの組織の人を名乗る | IdP は1つの組織にだけつなぐ。戻った人のメールのドメインが、その組織の確かめたドメインでなければ入れない(T-8・L-8) |
| なりすまし | 確かめていないドメインを登録して、他社の人を集める | DNS の TXT で確かめるまで SSO に使えない。1つのドメインは1つの組織だけ |
| なりすまし | SCIM の鍵が漏れて、人を作られる | 鍵はハッシュだけを持ち、画面に1回だけ出す。作れるのは確かめたドメインの人だけ。取り消せる。操作は監査ログに残る |
| 改ざん | IdP の答え(SAML の主張)を書き換える | 署名の確かめは Cognito が行う。API は Cognito の ID トークンの署名と発行元・宛先を確かめる |
| 否認 | 「止めた・入れた覚えがない」 | 設定の変更・SCIM の操作・強制ログアウト・書き出しを監査ログに残す |
| 情報漏えい(他社のデータ) | 監査ログの書き出しに他社の物が混ざる | 組織の文脈(RLS)で1ページずつ読む(データの書き出しと同じ形) |
| 妨害 | IP の制限で管理者が締め出される・IdP が止まって誰も入れない | いまの IP を含まない一覧は保存できない。緊急用のアカウントはパスワードで入れる。運営は手順書で制限を外せる |
| 妨害 | IP の一覧が長くて関所が重い | 20 個まで。組織ごとにリクエストの中で1回だけ読む |
| 権限昇格 | 緊急用のアカウントを増やして SSO を避ける | 2人まで・管理者だけ・二段階認証が必須・選んだことが監査ログに残る |

## やらないこと

- OIDC の IdP(まずは SAML だけ。Cognito は OIDC もつなげるので、要る会社が出たら)
- SCIM の Groups(グループからロールを決める)。ロールは管理者が画面で
- 端末を選んでログアウトさせる(サーバー側のセッション保存。ADR 0017 は変えない)
- 監査ログを相手の道具(SIEM)へ自動で送る(まずは書き出し)
- 国・地域での制限(WAF の仕事)

## 決めたこと

- SAML は Cognito の SAML の IdP でつなぐ(ADR 0067)。トークンは API の中だけ(ADR 0007 のまま)。
- 強制ログアウトは、いまある「これより前のセッションを切る」(`users.sessions_valid_after`)で行い、サーバー側のセッション保存は作らない(ADR 0017 のまま)。
- 人に聞く判断は、設計書の「未確定事項」に仮決めで置く。
