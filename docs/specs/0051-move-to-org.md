# 仕様: 組織に移してマージキューを使う手順

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。U-1 はキットの既定として承認し、導入時に決める)
> 設計: [docs/designs/0051-move-to-org.md](../designs/0051-move-to-org.md)

## なぜ作るか

- AI の PR が増えると、スカッシュ+「最新に追いついてから」で、1本ずつ追いつかせては CI を回し直す待ちが直列に並ぶ(想定の場面の 7-4)。マージキューで解けるが、個人のリポジトリでは使えない。
- 組織に移すと、AWS への入口(OIDC の信頼の条件)・アプリ(Renovate など)・Environments の承認者・Actions の決まりが切れたり変わったりする。洗う物と順番が無いと、移した日にデプロイが止まる。

## 受け入れ条件

- [ ] 手順書 `docs/runbooks/move-to-org.md` に、先に決めること(移す先・プラン・日・人)がある。プランとマージキューが使える条件は、確かめた日つきで書いてある
- [ ] 移す前に洗う物の表(OIDC の信頼の条件・URL とリモート・template_repository・秘密と変数・Environments・ルールセット・Actions の設定・Renovate・ほかの App・Webhook・CODEOWNERS・点検の担当者・費用と証跡の取り込み)に、移すとどうなるか・やること・いつ、がある
- [ ] 移す日の手順(2人で・マージとデプロイを止める・移す・リモート・OIDC の apply・App・setup:github・確かめる・戻す)がある
- [ ] マージキューを入れる手順(`merge_group` で流れるか・キューで流れないチェックを必須から外す・ルールセットにキュー・`strict` を外す・見る数)がある
- [ ] 困ったときの表がある
- [ ] キット自身は移さない、と書いてある
- [ ] `docs/guides/ci-speed.md` から指す

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 古い場所に同じ名前のリポジトリを作られ、転送が消えて古い URL が他人の物になる | 古い場所に同じ名前を作らない(手順書の 4)。リモートを新しい URL に直す |
| 改ざん | 組織の Actions の決まりが緩く、SHA で固定していない Action が流れる | 組織の Actions の設定を setup.yml と同じかそれより厳しく(移す前) |
| 否認 | 該当なし | — |
| 情報漏えい(他社のデータ) | OIDC の信頼の条件を広げすぎる(組織の全部のリポジトリから引ける) | 条件は新しい `owner/repo` だけに直す(広げない) |
| 妨害(重い処理・大量の要求) | 移した日にデプロイが止まる | デプロイを止めてから移し、OIDC を直してから戻す |
| 権限昇格 | 共同作業者が組織の広い権限を持つ | 組織の既定の権限は最小にし、チームで渡す |

## やらないこと

- キット自身を移す
- `pnpm setup:github` にマージキューを扱わせる(キットが扱わない規則は消さずに残るので、いまは画面から足す)
- 想定の場面(`docs/scenarios/`)の判定と穴の一覧の書き換え(場面の持ち主が直す)
