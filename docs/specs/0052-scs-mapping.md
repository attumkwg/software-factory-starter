# 仕様: 国のサプライチェーンの評価制度(★3・★4)への対応表

> 状態: 下書き(想定の場面の穴 G-25 から AI が書いた。2026-10-25。承認は PR で)
> 設計: [docs/designs/0052-scs-mapping.md](../designs/0052-scs-mapping.md)

## なぜ作るか

- 国のサプライチェーンのセキュリティ評価制度(SCS 評価制度。★3 は専門家の確認つきの自己評価・★4 は第三者評価)が 2026年度下期に始まる見込みで、大企業や病院の質問票の一部がこの制度で置き換わりうる(想定の場面の 2-5)。
- キットの管理策の一覧(附属書 A)・仕組み・手順は揃っているが、制度の要求事項との対応が無く、取引先に「★3 は取れますか」と聞かれたときに、何がキットにあり何を自社で整えるかが分からない。

## 受け入れ条件

- [ ] `docs/compliance/scs.md` に、制度の要求事項43件(★3 は26件・★4 は全43件)の1件1行で、要求事項の番号・★3/★4・要旨・対応する管理策(controls.yaml の番号)・キットの扱い(◎ ○ △ 委)・キットのどこ・使う人がやること、がある
- [ ] 頭に、準備の表で評価の結果ではないこと・確かめた日・出どころ(公的な一次資料だけ。リンクは IPA と経済産業省のページ)・評価基準の細目は写していないことがある
- [ ] 点検の台帳に「開始の後に見直す」項目(`scs-review`。半年ごと)があり、`refresh_sources` に IPA の制度のページがある。`docs/checkup/README.md` と適用宣言書が作り直してある
- [ ] `docs/compliance/README.md` と `/security-questionnaire` の対応の表から指す
