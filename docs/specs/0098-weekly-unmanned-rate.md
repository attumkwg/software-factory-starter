## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM・代表)
- 動かす KPI: (キットの物差し: 無人化率。守り: 事故 0件・センサーが正しいかの判定が回っていること)
- 無人化率(1 − 人が使った工数の割合)は、毎週いちばん目に見る入力の数と決めた。ところが出しているのは README と roi.md の手で数えた値だけで、週ごとに出す物が無い。`pnpm metrics` には人の介在率(問い・手直し)はあるが、工数の割合には直していない。

### 業務の要求

- 毎週の週の数字(`pnpm metrics`・Actions の要約)を開くと、週ごとの無人化率が1つの数(幅)で見える
- その数を何が動かしたか(PR の本数・人が答えた問い・コメント・人の手直し)が同じ所に並ぶ
- 測った数と、決まった分を掛けた見込みが見分けられる

### 業務ルール

- 式は roi.md の 2 と同じ — 手で数えた値と、毎週の数を突き合わせられるように
- 分は `docs/cost/people.yaml` の分(費用のページと同じ)— 自分たちの実感で直せる所を1か所にする
- 無人化率は【推定】と書く — 分は測った時間ではない
- 幅で出す(問い1つに別に5分かかったとき・かからなかったとき)— roi.md と同じ置き方
- 人ごとの数は出さない — 週の数字の決まり(仕様 0035)のまま

### 受け入れ条件(業務の言葉で)

- [x] `pnpm metrics` を打つと、決裁用の表に週ごとの「無人化率【推定】」の列(78〜86% の形)が出る
- [x] その下に、週ごとの無人化率・人の工数・全部を人が書いたらの工数【推定】と、PR(AI・人・ボット)・問い・コメント・人の手直し【実測】の表と、N 週の合計の行が出る
- [x] キット自身の数え(PR 149本・ボット 4本・コメント 99件・問い 305)を入れると、roi.md の 2 と同じ 78〜86% になる
- [x] 式の分は `people.yaml` から読み、表の下に式として出る

### 要配慮個人情報

- 当たらない(PR の数・コメントの数・レビューの数だけ。レビューした人の名前は分を数えるのにだけ使い、出さない)。

### やらないこと

- 人の時間を測る(Claude Code への指示と会話の時間は PR に残らないので入らない。注に書く)
- 「AI が手伝った」の列の見分け方(ラベルだけ)を変える(無人化率だけ、費用のページと同じ「ラベルか本文の印」で見分ける)
- README・one-pager の頭の数を、この数に置き換える(数え直すときの突き合わせに使う)
- 新しい日付の計算を足す(`scripts/checkup/phase.mjs` の `mondayOf`・`todayInTokyo` を使う)

### 決めたこと

- (持ち主 @attumkwg 2026-10-29 会話)無人化率は「作る(pnpm metrics に1列)」
- (AI が決めた)1列に加えて、何が動かしたかの表を決裁用の下に置く — 1つの数だけだと、上がり下がりの理由が分からない

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

- 該当なし(状態を持たない。毎回 GitHub から読んで数える)

### 境界値

- PR の無い週: 無人化率は —、時間は 0
- 問いが多く、人の工数(上の端)が全部を人が書いたらを超える週: 低い方の端を 0% で止める
- 今週(数え終わっていない週)の PR: 週の行にも合計にも入れない
- ボットの PR: 5分で数える。全部を人が書いたらでも 5分のまま
- 日本時間の月曜 0:00 の前後: 前の週・次の週に分ける(今までの週の数え方のまま)

### 権限の組み合わせ

- 該当なし(アプリの API は変えない)。読むのは今までと同じ `gh` の GraphQL(マージした PR のコメントの数とレビューを足した)
