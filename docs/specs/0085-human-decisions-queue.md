## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM・代表)
- 動かす KPI: (キットの物差し: 北極星 = 意義があると判断した物が使う人に届いて使われた数 ÷ 人の工数。毎週見る入力は無人化率。[../kit/roadmap.md](../kit/roadmap.md) の 4 の「工場の KPI」)
- 人が決めることが、CLAUDE.md・スキル・手引き・CI に散らばり、どれが仕組みで止まり、どれが頼みなのかが分からない。判断待ちがどこに溜まっているかも見えない。
- 危険度「高」の PR は「人が GitHub で押してください」で止まり、会話で答えても GitHub を開く手間が残る(#159・#160 は手で記録してマージした)。

### 業務の要求

- 人が決めることを1か所に集め、強制か頼みかを書く
- 判断待ちを古い順に、毎朝1枚で見られる(種類・待ちの日数・いちばん古い待ち)
- 人への問いは端的に(1問1行・選択肢つき・PR 1本で多くて2問)
- 人はチャット・Slack で答え、工場がその言葉を記録して実行する。「GitHub で押してください」をやめる

### 業務ルール

- 1人の間は、持ち主の会話の答えを PR にコメントで残し(言葉そのまま・答えた日時・当てた版・人の答えが要った理由・領域の問い)、必須のチェックが全部緑なら危険度「高」も AI がマージする — #152 の「高は人が GitHub で押す」を1人の間だけ置き換える
- 人が増えたら(承認数が 1 以上)、AI のマージは止まる。答えは押した人を確かめられる Slack のボタンで(G-133)
- 本番に出す承認(GitHub の環境 prod)は会話で代えない — 戻せない操作の最後の関所
- 問いが3つ以上になる PR は、AI が決められる所を決めて理由を書き、問いを2つまでに絞る — 多いと形だけの承認に戻る

### 受け入れ条件(業務の言葉で)

- [x] `docs/concepts/human-decisions.md` に、人が決めることの全部の行に強制か頼みか・止める物・1人の間に答える場所がある(行の形はテストが見る)
- [x] `pnpm queue` が、人の答えを待つ PR・Issue・意義の判断を古い順に出す。`human-queue.yml` が毎朝「🧑‍⚖️ 判断待ち」の Issue を1つだけ直す(Slack は任意)。無くなったら閉じる
- [x] 会話の答えの記録(「## 持ち主の承認(会話で…」)がある PR は、積み場から外れる
- [x] PR の「🧑‍⚖️ 人に判断してほしい所」の問いが3つ以上なら、CI「取り組みと作業の種類(PR の本文)」が落ちる。長い問いは知らせる
- [x] `pnpm pr:merge-when-green` が答えた日時(タイムゾーンつき)を求め、持ち主の言葉を PR に残してからマージする。1人の間は危険度「高」も断らない
- [x] `/slack-request` が、危険度「高」の PR で領域の問いを先に会話で聞き、答えを得てからマージに進む

### 要配慮個人情報

- 当たらない(積み場に出すのは PR・Issue の番号と題・待ちの日数・問いだけ)。

### やらないこと

- Slack のボタンで押した人を確かめる(人が増えたら。G-133。Slack の署名を確かめる受け口と、Slack の利用者と GitHub の名前の対応表が要る)
- 本番の承認を会話で代える
- 人が答えた回数・待ちの時間から無人化率を出す(足りない物 6 で `pnpm metrics` とそろえる)

### 決めたこと

- 人が決めることを1か所に集めた一覧と、判断待ちを古い順に毎日出す積み場を作る。PR の問いは端的に(1問1行・選択肢つき)(@attumkwg 2026-10-29。会話で回答「全部アグリー」)
- 「GitHub で押してください」をやめ、人がいる場所(チャット・Slack)で決めた答えを記録して工場が実行する。1人の間は会話の承認の言葉を PR にコメントで残して危険度「高」もマージ。人が増えたら押した人を確かめられる Slack のボタン(@attumkwg 2026-10-29。会話で回答)
- (AI が決めた)積み場は Issue 1つを直し続ける(毎日 Issue を増やさない)。毎朝 8:10(点検の後)
- (AI が決めた)テストを弱めた印の PR も、危険度「高」と同じく会話の答えで進める(センサーの判定は人が会話で答える物。記録に理由として残る)
- (AI が決めた)答えた日時は会話の時刻で、ISO 8601 のタイムゾーンつきだけ。先の時刻は断る
- (AI が決めた)同じ版に当てた記録があれば、コメントを足さない(やり直しで記録が増えない)

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 状態 \ 操作 | `pnpm queue` | `pnpm pr:merge-when-green` |
|---|---|---|
| 1人の間・低・中の PR・答えあり | 載らない | 記録を残し、緑ならマージ |
| 1人の間・危険度「高」・テストを弱めた・守りの場所に触る PR・答えなし | 載る | (呼ばない。先に会話で問いに答えてもらう) |
| 同じ PR・会話の答えの記録あり | 載らない | 理由と領域の問いを記録に書き、緑ならマージ |
| 人が増えた(承認数が 1 以上) | 載る | 断る(人がレビューしてマージ) |
| 下書きの PR | 載らない | 断る |
| 答えた日時が無い・形が違う・先の時刻 | — | 断る |
| 印 needs-human の Issue | 載る | — |
| 期限を過ぎて人の判定が未定の意義の判断 | 載る | — |
| 判断待ちが0件 | Issue を閉じる | — |

### 境界値

- 問いの数: 2 で通る・3 で落ちる。「なし」・空の行は数えない
- 問いの長さ: 160 文字を超えたら知らせる(落とさない)
- 待ちの日数: PR・Issue は開いた日から、意義の判断は期限の日から。切り捨ての日数
- 答えた日時: いまより5分先までは認める(時計のずれ)

### 権限の組み合わせ

- `human-queue.yml`: contents read・issues write・pull-requests read。秘密は SLACK_WEBHOOK_URL(任意)だけ
- `pnpm pr:merge-when-green`: 持ち主が環境に入れた KIT_AI_MERGE=slack と、gh のログインの権限

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | AI が持ち主の答えをでっち上げて、危険度「高」をマージする | 1人の間だけ・言葉と日時と版を PR に残す・持ち主が依頼の場所を自分だけにする(ADR 0082 の割り切り)・人が増えたら止まる。本番の承認は会話で代えない |
| 改ざん | PR の中でマージのスクリプトを緩め、その版で自分をマージする | スクリプトを変える PR も守りの場所なので、記録に「人の答えが要った理由」が出る。本番は環境 prod の承認で止まる |
| 否認 | 「そんな答えはしていない」 | 記録に言葉そのもの・答えた日時・当てた版が残る(`human-queue.test.mjs`) |
| 情報漏えい | 積み場に PR の本文を貼る | 題・番号・問いだけ(問いは 160 文字で切る) |
| 妨害 | 問いを3つ以上書いて CI を止める | AI が決めて2つに絞る(落ちた文に直し方を書く) |
| 権限昇格 | 該当なし | — |
