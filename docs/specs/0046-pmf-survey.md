# 仕様: 「無くなったら困るか」を画面の中で聞く(PMF の兆し)

> 状態: 下書き
> 設計: [docs/designs/0046-pmf-survey.md](../designs/0046-pmf-survey.md)・ADR: [0057](../adr/0057-pmf-survey-counts-only.md)
> 穴 G-39(`docs/scenarios/gaps.md`)。場面は `00-best-case-run.md`・`fit-journey.md` の PMF の行(「無くなったら困る」の割合)。

## なぜ作るか

- PMF の兆しの目安は「このサービスが無くなったら、どう感じますか」に「とても困る」が40%以上(`docs/guides/before-pmf.md`)。キットには、それを聞いて数える仕組みが無い(穴 G-39)。
- 外の道具(フォーム)で聞くと、答えた人の連絡先や名前が外に出る・使っている人だけに絞れない・何度も聞いてしまう。
- 利用者を測る仕組み(機能フラグ・利用の記録)はキットにあるので、その上に「聞く」を足す。

## 受け入れ条件

- [ ] 運営が機能フラグ `pmf-survey` を入れた組織の人だけに聞く(入れていない組織では、画面に出ず、答えても 404)
- [ ] 聞くのは使い始めて14日たった人だけ。代理ログインの社員(答えると 403)・運営の組織の人には聞かない
- [ ] 1人に聞くのは四半期(組織の時間帯)に1回まで。答えるか「答えない」を押すと、その四半期はもう聞かない(2回目の答えは 409)
- [ ] 答えは「とても困る / 少し困る / 困らない / もう使っていない / 答えない」の5つ。ほかは 400
- [ ] **答えは数だけを数える**: 組織・回・答えごとの数を1つ足すだけ。だれが何と答えたかは DB にも監査ログにも残さない(答え終えた印は答えを持たず、数は人を持たない)
- [ ] 画面(プロジェクトの一覧)に、問いと選択肢と「答えは数だけを数えます(だれが何と答えたかは残りません)」を出す。答えたらお礼を出して消える
- [ ] 運営のコマンド `pmf-survey-report` が、回ごとに全部の組織を足した数・「とても困る」の割合(分母はとても困る・少し困る・困らない)・線(40%)・答えが30件より少ないかを出す。組織と人の ID は出さない
- [ ] 答え終えた印(人の ID を持つ)は400日で消せる(`pmf-survey-purge`。試し → 本番)。解約で組織を消すと、印も数も消える
- [ ] 他社の数は読めない・増えない(RLS。2社のテスト)

## 権限の表に足す行

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `GET /api/pmf-survey` | 200 | 200 | 200 | —(パスに ID が無い) | 401 |
| `POST /api/pmf-survey` | 204(聞ける人)/ 404 | 204 / 404 | 204 / 404 | — | 401 |

## 要配慮個人情報

- 当たらない(答えは「困るか」の5択の数だけ。病歴・信条などは聞かない)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 代理ログインの社員が、お客さんの代わりに答える | `pmf_survey:answer` は代理の最中は使えない(403。結合テスト) |
| 改ざん | 同じ人が何度も答えて割合を動かす | 1人1回(印の一意の制約・409。同時に押しても1回だけ数える) |
| 否認 | 答えたかどうかが分からない | 監査ログに「答えた」(中身は無し)。数の表 |
| 情報漏えい | 管理者や運営が、だれが「困らない」と答えたかを知る | 印は答えを持たず、数は人も時刻も持たない(表の形を結合テストで確かめる)。監査ログに答えを入れない。集計は全部の組織を足した数だけ |
| 妨害 | 何度も聞かれて使いにくくなる | 四半期に1回・使い始めて14日たった人だけ・「答えない」でもその回は終わり |
| 権限昇格 | 他社の数を増やす・読む | 数は自分の組織の行だけ(RLS・tenantId で絞る) |

## やらないこと

- 自由記述の答え(「なぜ困るか」)。個人が分かる文が入るので、まずは数だけ。理由は話を聞いて確かめる
- 組織ごとの割合を運営や管理者に見せること(組織が少ないと、だれが答えたかが分かる)
- 答えをメールや外の道具で集めること

## 決めたこと

- 穴 G-39 と、`before-pmf.md` の「PMF の兆し」(Sean Ellis のテスト。40%)を、この仕様の要求にした。人に聞くこと(仮決め)は設計書の「未確定事項」に書く。
