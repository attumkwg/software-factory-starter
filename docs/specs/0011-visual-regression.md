# 仕様: 画面を見える化する(PR ごとのスクショ・見た目の回帰テスト・部品の一覧)

> 状態: 下書き(作者のメモ 2026-10-21〜22「実際どんな画面なのかがわからない」「VRT の仕組みが無い」から。2026-10-24 に作者が並行のセッションで1本ずつ PR にすると決めた。承認は PR で)
> 設計: [docs/designs/0011-visual-regression.md](../designs/0011-visual-regression.md)
> 判断: [ADR 0024](../adr/0024-vrt-browser-in-docker.md)

## なぜ作るか

1. **どんな画面なのかが分からない**: 画面を見るには、手元で `docker compose up` してログインして回るしかない。PR を読む人(作者)は、AI が作った画面を見ないまま判断している。
2. **見た目が壊れても気づかない**: E2E(Playwright)はスクリーンショットを撮っている(`screenshot: "on"`)が、前と比べていない。部品(`packages/ui`)の CSS を1行直したとき、どの画面がどう変わったかを誰も見ない。
3. **部品の見本が無い**: デザインシステム(`docs/design-system.md`)の部品が、どんな見た目か・どんな種類があるかを1か所で見られない(「ログイン → プロジェクト → タスクで全部の部品が出る」と書いてあるだけ)。

## 受け入れ条件

### PR ごとのスクショ

- [ ] 画面に関わる PR(同じリポジトリのブランチから)を開く・push すると、主な画面のスクショ(パソコンの幅とスマホの幅)が、PR のコメントに画像で並ぶ
- [ ] コメントは PR に1つだけ(push のたびに増やさず、書き換える)
- [ ] 写るのは種データ(架空の2社・`.test` のメールアドレス)と固定の文だけ。秘密・本物の個人情報・日によって変わる値(作った日など)は写さないか、塗りつぶす
- [ ] フォーク(外の人)からの PR ではコメントしない(書き込みの権限を渡さない)。比べる検査は流す

### 見た目の回帰テスト(VRT)

- [ ] 主な画面の見た目を、リポジトリに置いた基準の画像と比べ、違えば CI が落ちる
- [ ] 違ったときは、どの画面が変わったかと、基準・今回・差分の3枚の画像を PR から開ける(コメントに画面の名前と、画像の入った成果物へのリンク)
- [ ] 手元(Windows・Mac・Linux)と CI で同じ画像になる: ブラウザは Playwright の公式イメージ(版とダイジェストを固定)の Docker の中で動かす
- [ ] 基準の画像は「変える」と明示したときだけ変わる
  - 手元: `pnpm vrt:update`(Docker の中のブラウザで撮り直す)→ コミット
  - GitHub だけで: PR にラベル `vrt:update` を付けると、CI が撮り直した基準を成果物にし、取り込む1行のコマンドをコメントに出す(取り込んでコミットするまでは赤のまま)
- [ ] ふつうの E2E(`pnpm test:e2e`)は今までどおり動く(VRT は別のコマンド `pnpm vrt`・別の CI のジョブ)

### 部品の一覧ページ

- [ ] `/design-system` を開くと、`@app/ui` の部品が種類ごと(ボタンの4種と大きさ・押せない状態、入力の説明・エラー、選択、チェック、表、一覧、お知らせ、札、確認のダイアログ、QR コード、並べ方)に並ぶ
- [ ] 部品の一覧ページも VRT の対象(パソコンとスマホの幅。確認のダイアログを開いた状態も)
- [ ] 本番(`APP_ENV=prod`)では 404(利用者に見せる画面ではない)。手元・プレビュー・stg では、ログイン無しで開ける
- [ ] 部品の一覧ページも axe を通り、幅 320px で横にはみ出さない(ふつうの E2E)

## 権限の表に足す行

なし(API を足さない・変えない)。画面 `/design-system` は API を読まない。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし(ログインの仕組みを変えない) | — |
| 改ざん | フォークの PR のコードが、書き込みの権限つきで動いて、リポジトリや PR を書き換える | `pull_request_target` を使わない。PR のコードを動かすジョブは読む権限だけ。コメントを書くジョブは PR のコードを動かさず、フォークでは動かない(zizmor が CI で見張る) |
| 否認 | 該当なし | — |
| 情報漏えい(他社のデータ) | スクショ(公開のリポジトリのコメント・成果物・基準の画像)に、秘密・本物の個人情報が写る | 写すのは種データだけ(架空の2社・`.test`)。VRT は種データの人でだけログインする。日付などは塗る。基準の画像は人が PR の差分で見る |
| 妨害(重い処理・大量の要求) | 該当なし(CI のジョブが1つ増えるだけ。本番の画面には部品の一覧ページを出さない) | — |
| 権限昇格 | 部品の一覧ページから、ログインの後ろの画面やデータに届く | 部品の一覧ページは API を読まず、固定の見本だけを描く。本番では 404 |

## やらないこと

- Storybook などの部品の見本の道具を入れること(画面の中の1ページで足りる。`docs/design-system.md`)
- 全部の画面・全部の状態を VRT にすること(主な画面だけ。監査ログのように中身が時刻で変わる画面と、Cognito のときだけ出る画面は撮らない)
- CI が基準の画像を自分でコミットすること(GitHub の鍵で push すると、その commit で CI が動かない。取り込みは人か AI が1行のコマンドで)
- Firefox・Safari(WebKit)での見た目(CI に入れてあるのは Chromium だけ)
- プレビュー環境(`preview.yml`)での VRT
