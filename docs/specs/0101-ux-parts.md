## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: P-2 タスクを片づける人・P-3 入ったばかりの人・P-5 導入を進める事務の長
- 動かす KPI: (キットの物差し: 初見の利用者テストで終えられた仕事・手数・「怖かった」の数。守り: 事故 0件)
- 🎨 の棚卸しで ❌ が2つ(タスクの「消す」が押した瞬間に消える・設定のカードに主ボタンが複数)。初見の利用者テストでは、3人とも各行の「消す」が怖いと書き、現場の人は「完了にしても伝わったか分からない」と書いた。
- 持ち主(2026-11-13):「デザインシステムはもう少し凝れる」。デザインシステムは「壊れない」(a11y・崩れ)までで、使いやすさの型(元に戻す・空のとき・行の操作・いまここ)が無かった。

### 業務の要求

- 戻せない操作(消す・止める)は、押し間違えにくい所にあり、実行の前に何が・どこまで・戻せるかを確かめられる
- 戻せる操作(完了にする)は、確かめずにすぐ効き、結果が知らされ、その場で元に戻せる
- 一覧が空のとき、何をすれば増えるかが分かる
- いまどの画面にいるか・どこへ戻るかが分かる

### 業務ルール

- 戻せない操作は「…」の奥(行の操作のメニュー)にしまい、選んだら確認を出す — 主な操作(完了のチェック)の隣に同じ強さで並べると、手袋・初めての人が押し間違える
- 戻せる操作は確認しない。代わりに「元に戻す」を付ける — 毎回の確認は手数を増やし、読まずに押す癖をつける
- 1つの画面に並ぶカードの中では主ボタンを使わない — 組織の状態で主ボタンが3〜6個になり、重い操作(全員に必須にする)も軽い操作と同じ見た目になる
- 新しい色は足さない(いまここは下線、押せないチェックは薄く) — 色を決めるのは人(トークン)。今あるトークンで足りる

### 受け入れ条件(業務の言葉で)

- [x] タスクとプロジェクトの「消す」は「…」の奥にあり、選ぶと確認が出る
- [x] タスクを完了にすると「「○○」を完了にしました」と出て、「元に戻す」で戻せる
- [x] メールの「止める」は確認が出る
- [x] プロジェクト・タスクが空のとき、何をすれば増えるか(見るだけの人には、誰ならできるか)が出る。タスクは絞り込みに合わせた文
- [x] ナビで今の画面が分かる(設定から開く画面は「設定」)。設定から開く画面と規約の画面に戻る道がある
- [x] 設定のカードに主ボタンが無い
- [x] 機械の検査の外れの一覧(仕様 0100 のラチェット)が全部空になった
- [x] 招待の状態が「返事待ち」(「受けていない」は「断られた」と読めた)

### 決めたこと

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| タスクの行 \ 操作 | チェック | 「…」→ 消す |
|---|---|---|
| 未完了(書ける人) | 完了にして「完了にしました」+元に戻す | 確認 → 消す |
| 完了(書ける人) | 未完了に戻して「未完了に戻しました」+元に戻す | 確認 → 消す |
| 見るだけの人 | 押せない(薄い) | 出ない |
| 送っている間 | 押せない | 押せない |

### 境界値

- 「元に戻す」のトーストは 8秒(ふつうは 4秒)。押したらトーストは消え、反対の操作を送る
- 空の文: 絞り込み「すべて」で書ける人 → 足し方、見るだけの人 → 誰ならできるか。「未完了」「完了」→ 絞り込みを外せばよい
- いまここ: `/`・`/projects/*` → プロジェクト。`/settings`・`/members`・`/invitations`・`/audit`・`/support-access` → 設定。`/support`・`/account`・`/organizations` はそれぞれ

### 権限の組み合わせ

- 変えない(画面の出し分けだけ。API・権限の表はそのまま)
