# 仕様: AI の費用と量に、月と同時の上限を置く

> 1つの仕様 = 1つ以上の Issue。大きければ親 Issue → 子 Issue に割ってから AI に渡す。
> 状態: 完了(実装済み。作り終えた PR で「完了」にした。マージする人が見る)

## なぜ作るか

AI の費用と量の上限は「1回の実行」にしか無い(`claude.yml` の60分・60ターン)。背景の AI を `@claude` で動くようにした翌月に請求が見込みの3倍になる・AI の PR が1週間で40本開いてレビューがあふれる、が起きうる(台本 [10-ai-incidents.md](../scenarios/10-ai-incidents.md) の 10-6・10-7・穴 G-62)。費用のページの AI の費用は人が書き写すので、気づくのは請求の後。

## 受け入れ条件

- [ ] 背景の AI は、自分(Claude のアプリ)が開いた PR が上限(`claude.yml` の `AI_OPEN_PR_LIMIT`)に達していると動かない。止めたときは何本開いているか(番号)と直し方を出す。数えるのは秘密を持たない前の段
- [ ] 手引き(`docs/guides/cost-dashboard.md` の「AI の上限」)に、モデルの会社の側で鍵を分け、ワークスペースと組織に月の上限を置く手順がある
- [ ] 毎月の点検 `ai-spend` が、上限を置いたか・今月の使用が上限の何割かを聞く
- [ ] 費用のページに「AI の回数と時間」(背景の AI の実行の回数と分数・今月作った PR のうち AI が手伝った数)が出る。金額は出さない
- [ ] 上限の数と数え方はテストで確かめる(`pnpm test:scripts`)

## 権限の表に足す行

該当なし(アプリの API は変えない)。

## 要配慮個人情報

- 当たらない(PR の作った人の種類と数・Actions の実行の数と分数だけ)

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 人のアカウントで claude に似た名前を付けて、数を増やす・減らす | 数えるのはボット(`user.type === "Bot"`)で名前が claude で始まる物だけ(`ai-open-prs.test.mjs`) |
| 改ざん | PR の中で上限を上げる | `claude.yml` は危険度「高」。背景の AI は main のワークフローで動く |
| 否認 | 何で止まったか分からない | 止まった理由に開いている PR の番号を出す |
| 情報漏えい(他社のデータ) | 費用のページに金額が出る | AI の行は回数と分数と本数だけ(金額は人が書き写す saas.yaml) |
| 妨害(重い処理・大量の要求) | AI に頼み続けて費用を跳ねさせる | モデルの会社の側の月の上限で止まる・同時の PR の上限・1回の上限(60分・60ターン) |
| 権限昇格 | 該当なし | 前の段は読むだけ |

## やらないこと

- モデルの会社の使用量を API で取る(管理用の鍵を GitHub に置かない。ADR 0032)
- 手元の AI の PR を数えて止める(人が作って見ている。週の数字の AI の割合で見る)
- 月の回数の上限を Actions の側で数える(上限はモデルの会社の側で止まる方が確か)
