# 仕様: サポートの代理ログイン(お客さんの許可・見るだけ・全部記録)

> 状態: 承認済み(承認した人: @attumkwg。2026-10-18 の選択「お客さんの管理者が期限つきで許可・社員は見るだけ」)

## なぜ作るか

問い合わせ(「この画面がおかしい」)に答えるには、社員がお客さんの画面を見る必要がある。かといって、社員が DB を直接見たり、全社を一覧できる管理画面を作ったりすると、他社のデータが見える穴になる(my-life の security.md 4.3 の 7)。**お客さんが許した間だけ・見るだけ・全部お客さんから見える**、の形でだけ入れるようにする。

## 受け入れ条件

お客さんの管理者:

- [ ] 画面「サポートへの許可」で、期限(1時間・24時間・3日)を選んで許可すると、**サポート番号**(例 `K7QM-2XPA-9DNE`)が1回だけ出る。番号は保存されない(ハッシュだけ)ので、二度と出ない
- [ ] 許可の一覧(いつ・誰が許可・いつまで・状態)を見られ、**いつでも取り消せる**。取り消すと、入っている社員も次のリクエストから入れない
- [ ] 許可した・取り消したが、監査ログに残る
- [ ] メンバー・閲覧者は許可できない・一覧も見られない(403)

社員(運営の組織の人。`SUPPORT_TENANT_ID` の組織の管理者・メンバー):

- [ ] 画面「サポート」でサポート番号を入れると、その組織を**閲覧者と同じ権限で**見られる。画面の上に「サポートとして ○○ を見ています(見るだけ・何時まで)」と「終わる」が出る
- [ ] 書き込みはできない(403。ボタンも出ない)。試みた記録が「拒否」で残る
- [ ] 1回の入室は最長1時間。許可の期限・取り消しが先に来れば、そこで終わる
- [ ] 入った・見た(どの画面のどの物か)・出た、が**お客さんの監査ログ**に「サポート(運営)」として残る
- [ ] 番号が違う・期限切れ・取り消し済みなら入れない(どれかは言わない)
- [ ] 運営の組織の人でなければ、番号を入れても入れない(403)
- [ ] 全社を一覧する画面・API は無い(番号が無いと、どの組織にも入れない)

## 権限の表に足す行

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `GET /api/support-grants` | 200 | 403 | 403 | — | 401 |
| `POST /api/support-grants` | 201 | 403 | 403 | — | 401 |
| `DELETE /api/support-grants/{grantId}` | 204 | 403 | 403 | 404 | 401 |
| `POST /api/support/sessions`(社員が入る) | 403(運営の組織でない) | 403 | 403 | — | 401 |
| `POST /api/support/end`(社員が出る) | 204 | 204 | 204 | — | 401 |

運営の組織の管理者・メンバーが `POST /api/support/sessions` で入れることは、結合テストで確かめる(表のテストの組織は運営ではないため)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 社員でない人が番号を手に入れて入る | 入れるのは運営の組織の人だけ(番号を知っているだけでは入れない) |
| なりすまし | 番号を当てずっぽうで試す | 番号は約59ビットのランダム(紛らわしい字を除いた30文字 × 12桁)・社員だけが試せる・WAF の流量の上限 |
| 改ざん | 代理の社員が書き換える | 代理のときのロールは閲覧者に固定。書き込みは 403(権限の表と同じ関所) |
| 否認 | 社員が「見ていない」と言う | 入った・見た・出たを、お客さんの監査ログに残す(足すだけの表) |
| 情報漏えい(他社のデータ) | 許可された組織から、別の組織に移る | 代理の文脈は許可の組織に固定(Cookie の中の組織と、DB の入室の記録の両方)。他社の物は 404 |
| 情報漏えい | 番号が漏れる | 番号は保存しない(ハッシュだけ)。期限つき・取り消せる・社員しか使えない |
| 妨害 | 許可を大量に作る | 管理者だけ・一覧は最新20件 |
| 権限昇格 | 代理のまま、許可の API やほかの社員向けの API を叩く | 代理のときは閲覧者なので、管理者向け・社員向けの API は 403 |

## やらないこと

- 書き込みもできる代理(本人の選択で「見るだけ」)
- 社内のもう1人の承認(本人の選択で「お客さんの許可」)
- 許可の通知(メールで「サポートが入りました」)。監査ログで見る
- 運営の組織の作り方の画面(手順書の SQL で1回だけ作る)

## 決めたこと・人に判断してほしいこと

- 許可と入室の記録は、領域「組織」(organizations)の表。運営の組織は環境変数 `SUPPORT_TENANT_ID` で決める。ADR 0014。
- 代理のときの Cookie は「社員の本来の組織」と「見ている組織・入室の ID」の両方を持ち、関所が毎回 DB の入室の記録(期限・取り消し)を確かめる。終われば本来の組織に戻る。
