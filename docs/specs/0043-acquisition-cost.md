# 仕様: 獲得のコストと、届け方の賭け

> 状態: 完了(実装済み。未確定事項は設計書で答え済み。@attumkwg が 2026-10-27 に完了とした)
> 設計: [docs/designs/0043-acquisition-cost.md](../designs/0043-acquisition-cost.md)・ADR: [0054](../adr/0054-acquisition-cost-from-manual-inputs.md)
> 穴 G-36(場面 8-7)。費用のページ(仕様 0019・0020)と賭け(`docs/guides/bets-and-assets.md`)の上に積む。

## なぜ作るか

- 展示会・記事・紹介のどれから来たお客さんが払っているか、1社を取るのにいくらかかったかが分からない。費用のページにはインフラ・SaaS・人の時間(開発)はあるが、広告費と営業の時間が無い。
- 賭けは機能ごとで、「この届け方は効くか」を同じ形(線・期限・小石)で確かめる型が無い。届け方は「良さそうだから続ける」になりやすい。
- 1社を取る額を1年以内に回収できるか、が事業として成り立つかの目安とされる。

## 受け入れ条件

> 「誰が・何をすると・どうなる」。どのテストかは設計書の「7. 要求との対応」。

届け方の賭け(人と `/bet`):

- [ ] PdM が届け方の賭けを開くと、ひな形 `docs/product/bets/_template-channel.md`(「種類: 届け方」・届け方での段階の意味・線の例)で書ける。段階・線・期限・小石・意思で進む・会計区分は機能の賭けと同じで、`pnpm bets` がそのまま確かめる
- [ ] 会計区分の案は、届け方の賭けではどの段階でも `費用`

獲得のコスト(費用のページ):

- [ ] 人が月に1回、届け方ごとに「広告費など・営業の時間・獲得した組織の数」を非公開の置き場の `acquisition.csv` に書くと、費用のページに「獲得のコスト」の表が出る
- [ ] 表は直近3か月(今月を含む)を届け方ごとに足し、広告費など・営業の時間・営業の費用(時給の既定)・合計・獲得した組織の数・**1社を取るのにいくら**を出す。全体の行も出す
- [ ] 時給が無いときは、営業の時間を円にしない(広告費だけで1社あたりを出し、そう書く)。獲得が0の届け方は1社あたりを出さない
- [ ] 獲得が5組織未満の届け方には、少ないことの印が付く(継続率・1社あたりの原価と同じ考え方)
- [ ] 入力が無いときは表を出さず、「読めなかった物・足りない物」に書く(0円として隠さない)。形の合わない行は数えない
- [ ] 個社の名前・人ごとの時間は、入力にもページにも無い(届け方ごとの合計だけ)

## 権限の表に足す行

API は足さない(権限の表に足す行は無い)。入力は今までの非公開の置き場(`cost/inputs/`)。

## 要配慮個人情報

- 当たらない。入力は届け方ごとの金額・時間・組織の数だけで、個人・個社のデータを持たない。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし(新しい入口が無い) | — |
| 改ざん | 入力を書き換えて、ある届け方を安く見せる | 置き場に書けるのは人の役割だけ(ADR 0032)。手入力であることと、足した月の範囲をページに出す |
| 否認 | 「その額はどう出したか」と言われる | 数え方(直近3か月・時給の既定)をページと手引きに書く |
| 情報漏えい | 広告費・営業の時間・獲得の数が広まる | ページと入力は非公開の S3 だけ。個社の名前・人ごとの時間は持たない |
| 妨害 | 該当なし(手入力の小さな表) | — |
| 権限昇格 | 該当なし | — |

## やらないこと

- 届け方とお客さんの組織の結びつけ(どの組織がどこから来たか。組織の ID を費用のページに持ち込まない)。
- 広告の画面(Google 広告など)からの自動の取り込み(外の会社の鍵が要る)。
- 顧客の生涯の売上(LTV)の自動の計算(手引きに回収の目安の見方だけ書く)。
- 営業の時間を人ごとに書くこと・人の評価。

## 決めたこと

- G-36 の中身(費用のページに広告費と営業の時間を手入力・非公開の S3・賭けに届け方の賭けを線・期限・小石で)は、親のセッションの依頼(2026-10-25)のとおり。`scripts/bets*` は触らない(依頼: 触るなら最小に)。
