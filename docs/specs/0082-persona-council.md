## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM・代表)
- 動かす KPI: (キットの「使える」の条件 1 通しで作れる)

仕様 0081 のペルソナは見本が2人で、立場の偏りを見る仕組みも、ペルソナどうしで議論する仕組みも無かった。持ち主の言葉: 「ペルソナ全然想定足りない。なんで二人なんでしょうか」「AI でペルソナのシミュレーションの価値は、合議制を超高速に回せること。その合議のレベル感はかなり高めないといけない」「その合議で出てきた KPI が、本当に価値のある KPI」「ペルソナは作れるようにすべき。今は会社に固定しているが、業界での差はあるはず」。

### 業務の要求

- 作るプロダクトの業界・客層に合わせて、業界の前提とペルソナを作れる(別の業界・2つ目の客層にも広げられる)
- ペルソナは、使う人だけでなく、買う人・決める人・止める人・周りの人・失う人・運営の立場をそろえる
- ペルソナの合議を AI で回し、KPI の木と、出す前の合否の一覧と、本物の人に確かめる問いを出す
- KPI は合議から来たものにする

### 業務ルール

- 業界の前提を先に書き、そこからペルソナを起こす — 業界が違えば、使う人も止める人も断る理由も違う。作り手の思い込みをそのまま人にしない
- 7つの立場をそれぞれ1人以上(客層ごと) — 使う人だけの合議は、止める人に断られる案を通してしまう
- 合議は1人ずつ別の AI がほかを見ずに答える — つられて同じ意見にならないように
- 主張に根拠の強さを付け、推測だけの賛成は数えない — 作り手の推測どうしの一致を合意と取り違えない
- 拒否権の反対は多数決で消さず、反論役を必ず置き、満場一致は疑う — 1人の拒否で導入が止まる現実に合わせる
- 割れた所・推測の所は、本物の人に確かめる問いにする。決めるのは人 — 合議は判断の材料
- 「確か」の KPI は合議から来た物だけ — 合議で出てきた KPI に価値がある

### 受け入れ条件(業務の言葉で)

- [ ] `/persona` で、業界の前提(`industry.md`)を根拠つきで書き、7つの立場を埋めるペルソナを足せる。2つ目の客層は `- 客層:` で分けられる
- [ ] 立場が欠けた地図・書き方の違うペルソナは、`pnpm kpi` が CI で落とす(客層ごとに見る)
- [ ] `/council` で、1人ずつ別の AI → 反論役 → 議論の回 → 議長のまとめ、の記録(`councils/`)ができる
- [ ] 合議の記録の形(見出し・賛否・根拠・立場のそろい・拒否した人の扱い・問い・人の判断)が違うと、`pnpm kpi` が落とす
- [ ] `kpi.yaml` の指標に、どの合議から来たかを書ける。「確か」の指標で書いていないと落ち、「仮説」は知らせる
- [ ] キットの見本に、10人(7つの立場)のペルソナ・業界の前提・実際に回した合議の記録・合議から作った KPI の木がある
- [ ] `/kickoff` は `/persona` → `/council` で KPI の木を作り、`/bet` は psf の前に合議を回す

### 要配慮個人情報

- 当たらない(架空の像と業界の一般の前提。個人や会社が分かることは書かない決まり)。

### やらないこと

- キットに業界ごとの出来合いのペルソナを持たせる(業界の前提は、使う人が `/persona` で根拠つきで作る)
- 合議の結論で、KPI・賭け・仕様を自動で確定する(決めるのは人)
- 背景の AI・Slack から頼まれたときの Web の調べ物(人が見ているときだけ)

### 決めたこと

- 立場の地図を必ず埋める(7つの立場)・合議の水準(1人ずつ別に・根拠の強さ・拒否権と反論役・次に確かめる問い)・#150 を土台として先に入れる(@attumkwg 2026-10-28。会話で回答。どれもおすすめの案)。
- KPI は合議から・ペルソナは業界ごとに作れるように(@attumkwg 2026-10-28。会話での指摘)。

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 状態 \ 操作 | `pnpm kpi` |
|---|---|
| personas.md に足りない立場がある(客層ごと) | 落ちる |
| 立場・決める力・根拠の書き方が違う | 落ちる |
| 合議の記録の見出しが欠けている・賛否や根拠の言葉が違う・立場がそろわない | 落ちる |
| 拒否した人の扱いが 4 に無い・6 に問いが無い・7 が未定でも @名前でもない | 落ちる |
| 「確か」の指標に council が無い・記録が無い | 落ちる |
| 「仮説」の指標に council が無い | 知らせる |

### 境界値

- やめたペルソナ(「- 状態: やめた」)は立場のそろいに数えない
- 客層を書かない人は、同じ1つの客層として数える
- 合議の表は「| P-」で始まる行だけを読む

### 権限の組み合わせ

- 該当なし(アプリの API は変えない)

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 合議の記録を書き換え、拒否が無かったことにする | 記録は足すだけ(やり直しは新しいファイル)・拒否した人は 4 に名前が要る(`kpi.test.mjs`) |
| 改ざん | 都合のよいペルソナだけで合議する | 7つの立場がそろわないと落ちる |
| 情報漏えい | 実在の人・会社をペルソナにする | 型とスキルで禁止(機械では見ない) |
| 否認・妨害・権限昇格 | 該当なし | — |
