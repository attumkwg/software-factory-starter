# 仕様: 操作する部品の枠を 3:1 以上にする(`--color-border-control`)

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。会話で回答)
> 設計: [docs/designs/0037-control-border-contrast.md](../designs/0037-control-border-contrast.md)
> 仕様 0024(`pnpm contrast`)の上に積む。

## なぜ作るか

- `pnpm contrast` で、いまの枠の線(`--color-border` と背景)が明るいテーマ 1.45:1・暗いテーマ 1.92:1 と出た。入力欄・選択・チェックボックスは、枠が見えないと「どこを押す・どこに書くか」が分かりにくい(WCAG 2.2 の 1.4.11: 操作する部品を見分けるのに要る見た目は 3:1 以上)。特に空のチェックボックスは、枠だけで見分ける。
- 持ち主の答え(2026-10-25・会話で):「入力欄の枠だけ濃くする」。区切りの線・カードなど飾りの線は今のまま。

## 受け入れ条件

- [ ] トークン `--color-border-control` が、明るいテーマと暗いテーマの両方にあり、背景(`--color-bg`)と面(`--color-surface`)の両方に 3:1 以上
- [ ] 入力欄(`ui-input`)・選択(`ui-select__button`)・チェックボックス(`ui-checkbox__box`)・副のボタン(`ui-button--secondary`)の枠が `--color-border-control` を使う
- [ ] 区切りの線・カード・表・一覧・ポップオーバーの枠は `--color-border` のまま
- [ ] `pnpm contrast` が `--color-border-control` の組を「文字でない物(3:1)」として確かめ、届かなければ 1 で終わる(`pnpm test:scripts` のテストも)
- [ ] VRT の基準を撮り直し、どの画面をなぜ変えたかを PR に1行書く
- [ ] `docs/design-system.md` に、2つの枠のトークンの使い分けが書いてある
