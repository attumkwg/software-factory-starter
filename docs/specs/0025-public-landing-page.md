# 仕様: 公開してよい LP の型(検索に載る・どこから来たかを測る・事前登録を本物の組織につなぐ)

> 状態: 下書き(置き場所 U-1 などの答え待ち。設計書の「未確定事項」)
> 設計: [docs/designs/0025-public-landing-page.md](../designs/0025-public-landing-page.md)・設計判断: [ADR 0038](../adr/0038-public-landing-page.md)
> 手引き(置き場所に関わらず要る物): [guides/landing-page.md](../guides/landing-page.md)

## なぜ作るか

約束と売り文句が決まったあと(言葉 → LP → 色の順)、業界の記事・会のメール・広告から人を呼び、事前登録を集めたい。どこから来た人が登録したかも知りたい。
いまある試作(`/prototype`)の申し込みのページは、本物と混ぜない守りのため **検索に載らない(noindex)・計測を入れられない・外へ送らない**。人を呼ぶ LP には使えない。
一方で LP は、キットの中で初めて **ログインしていない人の個人情報(メールアドレス・会社名)を集める所**で、計測の Cookie を外へ送ると同意と公表の決まりがかかることがある。型が無いと、毎回この判断をやり直し、事前登録の記録が外の道具に散らばり、本物の組織にするときに手で写すことになる。

## 受け入れ条件

> 置き場所(設計書の U-1)に関わらず要る物と、U-1 が「キットの中に型を持つ」(案 a・c)のときだけ要る物に分ける。

### どの置き場所でも要る(この PR で入れる手引き)

- [ ] LP を作る人が、手引きを読めば **LP に要る物の一覧**(見出し・困りごと・解決・値段・申し込み・プライバシーポリシーへのリンク・運営者の表示)を確かめられる
- [ ] 事前登録の **同意の文の型**(何に使うか・いつ消すか・どこで消せるか・プライバシーポリシーへのリンク・同意のチェック)と、同意の文の版を記録に残す決まりがある
- [ ] 計測の **同意の考え方**(外へ送らずに自前で数える / 外の解析を入れる / 広告のタグを入れる の比べ・それぞれに要る同意と公表・委託先の台帳)が手引きにあり、法令の当てはめは専門家に確かめる、と書いてある
- [ ] 事前登録の記録の **利用目的・保存期間・消し方・委託先** の決まりと、本物の組織を作るコマンド(G-01 の `create-tenant`)の入力にする形が、設計書にある
- [ ] プライバシーポリシーに足すこと(事前登録・計測)が、規約の手引きから辿れる
- [ ] 試作の手引きから「公開して人を呼ぶなら LP の手引き」へ辿れる

### U-1 で「キットの中に型を持つ」と決まったら(実装の PR)

- [ ] 公開のページ(`apps/site`)は、本番では検索に載る(noindex を付けない・`robots.txt` で許す・サイトマップ)。本番以外(プレビュー・stg)では全部 noindex
- [ ] 公開のページは、画面(`apps/web`)と同じトークンと部品(`@app/ui`)で作られ、ログインの画面と色がそろう
- [ ] 来た人が事前登録の形に会社名・メールアドレスを入れ、同意のチェックを付けて送ると、確認のメールが届く。メールのリンクを開くと「確認済み」になる。チェックが無いと送れない(400)
- [ ] 確認のリンクを開かない登録は、7日で消える
- [ ] 登録した人は、メールのリンクから自分の登録を消せる。運営は、問い合わせを受けてコマンドで消せる
- [ ] URL の UTM(`utm_source`・`utm_medium`・`utm_campaign`)が、登録の記録と日ごとの集計に残る。Cookie を使わず、外へ何も送らない
- [ ] 運営がコマンドで、日ごと・来た所ごとの **見た数・登録の数・確認の数・率** を見られる(個人の行は出ない)
- [ ] 確認済みの登録の ID を渡すと、組織を作るコマンドの入力(組織の名前・最初の管理者のメールアドレス)にできる。作ったら登録は「開通済み」になり、組織の ID が残る
- [ ] 同じメールアドレスへの確認のメールは、24時間に1通まで(他人のアドレスを入れて、確認のメールで攻撃させない)

## 権限の表に足す行

U-1 が案 a・c のときの実装の PR で足す。ログインに関わらず同じ(ログイン済みの人も、公開のページからは未ログインと同じに扱う)。

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `POST /api/public/pre-registrations` | 303 | 303 | 303 | 303 | 303 |
| `GET /api/public/pre-registrations/confirm?token=…` | 303 | 303 | 303 | 303 | 303 |
| `POST /api/public/pre-registrations/withdraw` | 303 | 303 | 303 | 303 | 303 |
| `POST /api/public/lp-views` | 204 | 204 | 204 | 204 | 204 |

組織の中の人が使う API は足さない(事前登録は運営のコマンドだけで扱う)。

## 要配慮個人情報

- 当たらない見込み: 集めるのは会社名・メールアドレス・会社の規模の幅・来た所(UTM)だけ。自由に書ける欄(「困っていること」など)を足すと病歴などが入りうるので、**自由記述の欄は置かない**(設計書の 6)。**人が答える**(実装の PR の前に確かめる)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 他人のメールアドレスで登録し、その人に確認のメールを送りつける・その人の会社として組織を作らせる | 確認のメールのリンクを開くまで「確認待ち」(組織を作る入力にできない)・同じアドレスへは24時間に1通・確認しなければ7日で消す(結合テスト) |
| 改ざん | 確認・取り消しのリンクの token を作り替えて、他人の登録を確認・取り消す | token は推測できない乱数(32バイト)を DB にはハッシュで持つ・使い切り・期限つき(結合テスト) |
| 否認 | 「同意していない」と言われる | 同意の文の版・プライバシーポリシーの版・同意の日時・確認の日時を記録に残す(書き換えない) |
| 情報漏えい(他社のデータ) | 登録の一覧が外から読める・ログやエラーにメールアドレスが出る・AI に一覧を渡す | 一覧を返す API を作らない(運営のコマンドだけ)・ログは許可リスト(メールアドレスを出さない)・AI に渡すのは件数と率だけ(AI-6)・列の分類は `personal` |
| 妨害(重い処理・大量の要求) | 登録や見た数の API を大量に叩いて、表を太らせる・数を狂わせる | WAF の数の上限・入力の長さの上限・罠の欄(人には見えない欄に値があれば黙って捨てる)・見た数は日ごとの集計の行を足すだけ(行は増えない) |
| 権限昇格 | 公開の API からテナントの文脈を作り、他の組織の表を読む | 公開の API は運営の組織の文脈に固定し、事前登録の表しか触らない(Semgrep で表の読み書きを領域の中に閉じる・結合テスト) |

## やらないこと

- ブログ・記事・お知らせの仕組み(CMS)。記事が要るなら外の CMS を使い、LP の言葉と色だけそろえる(手引き)
- A/B テストの仕組み・広告の配信・CRM。届け方ごとの賭け(G-36)と営業の道具(G-35)は別
- 事前登録の人へのお知らせのメールを、画面や API から一斉に送ること(運営のコマンドだけ。実装の PR で決める)
- 外の解析(Cookie で外へ送る物)を既定で入れること(U-2)
- 組織を作るコマンドそのもの(G-01)。ここでは入力の形だけ決める
