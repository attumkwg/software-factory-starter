# 仕様: 営業の道具(毎晩戻るデモの組織・見積から申込・稟議の資料の束)

> 状態: 下書き
> 設計: [docs/designs/0053-sales-kit.md](../designs/0053-sales-kit.md)・ADR: [0064](../adr/0064-sales-kit-demo-on-stg.md)
> 穴 G-35(場面 8-5)。開通(仕様 0026)・プラン(仕様 0047)・申込書と SLA の型(仕様 0028)・質問票の下書き(`/security-questionnaire`)の上に積む。

## なぜ作るか

- 商談のたびに、デモの組織を手で掃除する・見積と申込書を一から作る・稟議の資料(SLA・取り扱い・委託先・セキュリティの答え)をばらばらに集めている。
- デモに本番を使うと本物のお客さんのデータが見えうる。手元の種データは商談で開けない。
- 見積・申込書・開通でプランの名前や価格表の版がずれると、値上げのときに誰が据え置きかが分からなくなる。

## 受け入れ条件

> 「誰が・何をすると・どうなる」。どのテストかは設計書の「7. 要求との対応」。

デモの組織(運営・営業):

- [ ] 運営が `demo-reset` を流すと、デモ用の組織(`DEMO_TENANT_ID`)の計画・タスク・招待・利用の記録など(組織の行のある表のうち、残す物のほか全部)を消し、決まったデモのデータを入れ直す。試し(数えるだけ)→ `--execute`
- [ ] 組織・人(ログインのまま)・契約のプラン・入れた機能・同意・監査ログは残る。要配慮の表には触らない。戻したことがその組織の監査ログに「仕組みが」「デモのデータを戻した」として残る
- [ ] `APP_ENV` がはっきり stg・手元・テスト・プレビューで、`DEMO_TENANT_ID` があるときだけ動く。本番・`APP_ENV` の無い所・運営の組織を指したときは、何もせずに止まる。デモの組織が無い・管理者がいなければ止まる
- [ ] ほかの組織には触れない。出す行に組織と人の ID は無い
- [ ] 毎晩(日本時間 3:00)、キットから作ったリポジトリ(`KIT_ROLE == 'product'`)で、変数 `DEMO_TENANT_ID` と stg のデプロイの役割があるとき、stg で自動で戻る。手でも流せる

見積から申込(営業):

- [ ] 見積書の型(項目・キットの既定・根拠・使う人が決めること)があり、プランと価格表の版を申込書・申し込みの JSON とそろえる流れが手引きにある

稟議の資料の束(営業):

- [ ] 営業が `pnpm sales:pack --out <ファイル>` を流すと、仕組みの事実・SLA の型・個人データの取り扱いの型・委託先の一覧を順に1つにまとめた Markdown ができる。頭に「出す前に埋める所」(`<…>`・`YYYY`・`◯`・「仮の既定」。コードの中は除く)の一覧、キットの版と作った日、専門家に確かめる・質問票の下書きを後ろに付ける、の注が付く
- [ ] キットの中へのリンクは文だけになる(束の外では開けない)。外の URL は残す。無いファイルは「無い」と書く

## 権限の表に足す行

API は足さない(権限の表に足す行は無い)。デモを戻すのは運営のコマンドと、stg のデプロイの役割だけを引くワークフロー。

## 要配慮個人情報

- 当たらない。デモのデータは偽の題名だけで、要配慮の表には触らない。見込み客の個人データを stg に入れない(未確定事項 U-1)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 本番のお客さんの組織の ID を `DEMO_TENANT_ID` に入れて、その組織を消す | コマンドは `APP_ENV` がはっきり stg・手元・プレビューのときだけ。ワークフローが引くのは stg のデプロイの役割だけ(本番に届かない)。運営の組織は指せない |
| 改ざん | ワークフローを書き換えて別のコマンドを流す | ワークフローは main からだけ・Environment stg(GitHub の側で止める)。ワークフローの変更は危険度「高」 |
| 否認 | 「誰がデモを戻したか」 | デモの組織の監査ログに `demo.reset`(仕組み)・Actions の実行の記録 |
| 情報漏えい | デモに本物のお客さんのデータが入る・束にお客さんの名前が入る | デモのデータはコードの偽の題名だけ。stg に置き、本番を使わない。束は型だけで、書き出し先はリポジトリの外をすすめる |
| 妨害 | 戻す処理が重い・商談の最中に戻る | 1組織の1トランザクション。夜中の 3:00 に流す |
| 権限昇格 | 該当なし(API が無い) | — |

## やらないこと

- 本番のデモの組織・見込み客ごとの試しの組織(試用の開通は G-01 の `create-tenant` で)。
- 見積書・申込書の自動の作成(PDF・電子契約)・金額の計算。
- CRM との連携(道具の扱いは `docs/guides/sales-tools.md`)。
- 質問票の答えを束に自動で入れること(会社ごとの答えはリポジトリの外)。

## 決めたこと

- G-35 の中身(毎晩きれいに戻るデモ用の組織・種データ・戻す運営のコマンドか定期の仕事・本番の個人データは使わない・stg に置く・見積から申込の流れを申込書の型とプランの価格表とつなぐ・稟議の資料の束を SLA・取り扱い・質問票の下書きから1つにまとめる手順・定期は `KIT_ROLE == 'product'` のときだけ)は、親のセッションの依頼(2026-10-25)のとおり。
