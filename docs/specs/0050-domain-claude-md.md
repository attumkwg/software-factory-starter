# 仕様: 領域ごとの CLAUDE.md の型と、領域を足す手順

> 状態: 下書き(想定の場面の穴 G-16 から AI が書いた。2026-10-25。承認は PR で)
> 設計: [docs/designs/0050-domain-claude-md.md](../designs/0050-domain-claude-md.md)

## なぜ作るか

- 人が増えて領域ごとのチームに分かれると(想定の場面の 7-3)、AI には「この領域だけ」の文脈を渡したい。フォルダとスキーマの分け方・ほかの領域を `index.ts` 経由でしか使わない決まりはあるが、**領域ごとの CLAUDE.md の型が無い**。AI は領域の作業のたびに、どこを触ってよいか・何を先に読むか・どのテストを流すかを探し直す。
- 新しい領域を足す手順もまとまっていない(向き・フォルダ・スキーマと RLS・分類・解約で消す一覧・資料)。

## 受け入れ条件

- [ ] 型 `docs/domain/_template-CLAUDE.md` があり、見出しは「触ってよい所・触らない所・先に読む・外との出入り・流すテスト」。守るルールは書き写さず `docs/domain/<領域>/README.md` を指す、と型の中に書いてある
- [ ] 今ある4つの領域(organizations・projects・tasks・legal)に、型から作った `apps/api/src/domains/<領域>/CLAUDE.md` がある。中身(出している関数・出来事・監査ログの名前・使ってよい領域・テスト)が今のコードと合っている
- [ ] スキル `.claude/skills/add-domain` に、新しい領域を足す手順(名前・向き・4つのファイル・スキーマと RLS の移行・列の分類・解約で消す一覧・API・領域の資料・CLAUDE.md・表の説明書・持ち主)と確かめるテストがある
- [ ] `apps/api/CLAUDE.md`・ルートの `CLAUDE.md`・`/update-domain-docs` から、領域ごとの CLAUDE.md と `add-domain` を指す

## 権限の表に足す行

該当なし(API を足さない)。

## 要配慮個人情報

- 当たらない(文書とスキルだけ)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし | — |
| 改ざん | 領域の CLAUDE.md に「この領域ではほかの表も直接読んでよい」と書いて、境界の決まりを緩める | 境界は `domain-boundaries` のテストが守る(CLAUDE.md では変わらない)。CLAUDE.md は README とテストを指すだけ |
| 否認 | 該当なし | — |
| 情報漏えい(他社のデータ) | 該当なし(テナント分離の決まりは変えない) | — |
| 妨害(重い処理・大量の要求) | 該当なし | — |
| 権限昇格 | 領域の作業として、危険度「高」の共通の部品(auth・authz・db)まで直す | 領域の CLAUDE.md の「触らない所」に共通の部品と危険度「高」を書く |

## やらないこと

- 既存の領域の分け方を変える
- CODEOWNERS を領域ごとに分ける(人数が増えたら人が直す。危険度「高」)
- 画面(`apps/web`)の領域ごとの CLAUDE.md
- 想定の場面(`docs/scenarios/`)の判定と穴の一覧の書き換え(場面の持ち主が直す)

## 決めたこと

- 人に聞く4つに当たる判断は無かった(設計書 0050 の「決めたこと」)。
