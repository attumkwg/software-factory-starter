# 仕様: プロジェクトとタスク

> 状態: 完了(この雛形の最初の機能。書き方の例)

## なぜ作るか

組織の中で、やることをプロジェクトごとにまとめて、誰が見ても進み具合が分かるようにする。

## 受け入れ条件

- [x] admin / member はプロジェクトを作れる
- [x] viewer はプロジェクトとタスクを見られるが、作る・直す・消すはできない(403)。画面にもボタンを出さない
- [x] プロジェクトを消せるのは admin だけ。消すと中のタスクも消える
- [x] admin / member はタスクを足す・完了にする・消すができる
- [x] 他社(別の組織)のプロジェクトやタスクは、一覧に出ず、ID を直接指定しても 404
- [x] 名前・題名は前後の空白を落とし、空なら 400
- [x] 一覧(プロジェクト・タスク)は1回に最大 100 件(既定 50 件)。続きは `nextCursor` で読める。抜けも重なりも無い(2026-10-20 に追加。速さの点検)

## 権限の表に足した行

`docs/authz/matrix.yaml` の `/api/projects*` と `/api/tasks*` の8行。

## 悪用のされ方(STRIDE)

| 観点 | どう悪用されうるか | どう防ぐか |
|---|---|---|
| なりすまし | Cookie を書き換えて別人・別の組織を名乗る | 署名つき Cookie。結合テスト「Cookie を書き換えると 401」 |
| 改ざん | 他社のタスクの ID を指定して書き換える | RLS+リポジトリで tenant_id を絞る。結合テスト「他社のタスクを書き換えられない」 |
| 否認 | 消したのに「消していない」と言う | (今後)監査ログ。今は access log に requestId と tenantId |
| 情報漏えい | 他社のプロジェクトの ID を推測して読む | 404 で存在も漏らさない。権限の表の other_tenant 行 |
| 妨害 | 1社が大量に作って全体を遅くする | 一覧は1回に最大 100 件・並びと同じ索引・statement_timeout。今後テナントごとの流量の上限 |
| 権限昇格 | viewer が API を直接叩いて書き込む | 認可の関所(既定は拒否)。E2E「閲覧者は API でも 403」 |

## やらないこと

- タスクの担当者・期限・並べ替え
- 複数の組織に入る人(ADR 0001 の今後)
