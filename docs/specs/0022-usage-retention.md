# 仕様: 継続率(同じ組織が使い続けたか)

> 状態: 完了(実装済み。未確定事項は設計書で答え済み。@attumkwg が 2026-10-27 に完了とした)
> 設計: [docs/designs/0022-usage-retention.md](../designs/0022-usage-retention.md)
> 仕様 0012 の「利用の記録」(`platform.feature_usage`・運営のコマンド `usage-report`)の上に積む。表は変えない。

## なぜ作るか

- いまの `usage-report` は、週ごとに「その機能を使った組織の数・人の数」しか出さない。毎週5組織が使っていても、同じ5組織が使い続けているのか、毎週入れ替わっているのかが分からない。
- 賭けの `psf`・`rollout` の線(「入れた組織の 70% 以上が4週続けて使う」)と、プロダクトの PMF の兆し(継続の曲線が下がり切らずに横ばいになる)は、**同じ組織が N 週後もまだ使っているか**で測る([bets-and-assets.md](../guides/bets-and-assets.md)・[before-pmf.md](../guides/before-pmf.md))。
- 運営が手で組織ごとの記録を突き合わせると、組織の ID を扱うことになる。数と割合だけを出す仕組みで測れるようにしたい。

## 受け入れ条件

> 「誰が・何をすると・どうなる」。どのテストかは設計書の「7. 要求との対応」。

見る(運営):

- [ ] 運営が `usage-report <機能>` を流すと、今までの週ごとの数(1行目)に続けて、**継続率**の行(2行目)が出る。1行目の形は変えない
- [ ] 組織を「その機能を**初めて使った週**」でまとめ(組)、組ごとに **N 週後にその機能を使った組織の数と割合**(`active`)と、**1週後から N 週後まで毎週使った組織の数と割合**(`continued`。「N 週続けて」)が出る
- [ ] 組を足し合わせた行(N 週後ごとに、N 週後まで届いた組だけを足す)も出る。賭けの線はふつうこれで読む
- [ ] **人**の単位でも同じ物が出る(人を、その人が初めて使った週でまとめる。組織の組とは別)
- [ ] N 週後に数えるのは、**数え終わった週**(先週まで)だけ。今週は途中なので入れない
- [ ] 数える週より前(と、保存期間の端より前)に始めた組織・人は、どの組にも入れない(始めた週が分からない)
- [ ] いまその機能が入っているのに一度も使っていない組織の数も出る(「入れた組織のうち」を数えるため。どの組にも入らない)
- [ ] 大きさが小さい組(と足し合わせ)には、小さいことの印(`small`)が付く。数と割合は出す(小さい組の扱いは設計書の 6)
- [ ] **組織の ID・名前・人の ID は出さない**(数と割合と週の日付だけ)。運営の組織と、代理ログインの社員の操作は今までどおり入らない

他社:

- [ ] 集計は組織ごとに組織の文脈を付けて読み(表は RLS)、足した後の数だけを出す。ある組織の数が、組織の ID と結びついて出ることはない

## 権限の表に足す行

新しい API は足さない(権限の表 `docs/authz/matrix.yaml` に足す行は無い)。集計は運営のコマンド(`node dist/cli.js usage-report …`)だけ。

## 要配慮個人情報

- 新しく取る項目は無い。読むのは仕様 0012 の利用の記録(組織・人の ID・機能・日)だけで、出すのは数と割合。要配慮の表(スキーマ `sensitive`)には触らない。新しい項目を取らないので、要配慮に当たるかの人の答えは仕様 0012 のときのまま。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | お客さんが集計を流す | 集計は運営のコマンドだけ(API が無い)。流すのは表の持ち主の接続で、ECS の運営の手順でだけ |
| 改ざん | 記録を水増しして継続率を上げる | 記録は1日1人1機能1行で、アプリは読む・足すだけ(仕様 0012)。継続率は「その週に1回でも使ったか」だけを見るので、回数を増やしても変わらない |
| 否認 | 「その数字はどう出したか」と言われる | 数え方(組・N 週後・`active` と `continued`・数え終わった週)を設計書と手順書に書き、出力に数えた範囲(`cohortsFrom`・`lastFullWeek`)を入れる |
| 情報漏えい(他社のデータ) | 出力や小石から、どの組織が使い続けたかが分かる | 出すのは数と割合と週の日付だけ(結合テストが ID の無いことを確かめる)。人の ID は DB から読み出さない(週の一覧だけを読む)。小さい組には `small` を付け、小石には足し合わせの割合で書く(手順書) |
| 妨害(重い処理・大量の要求) | 組織や記録が増えて集計が重くなる | 組織ごとに1回だけ読み(索引 `feature_usage_feature_day_idx`)、計算は組織と人の数に比例する。記録は保存期間(400日)で消える。流すのは人で、読むだけ |
| 権限昇格 | 該当なし(新しい入口が無い) | — |

## やらないこと

- 機能を**入れた週**でまとめる組(入れた日の記録が無い・`on` の機能には入れた日が無い)。入れた組織のうちの割合は、使っていない組織の数と組み合わせて読む(手順書)。
- 組ごとの差の検定(A/B)・くじの組分け(ADR 0025 の見直す合図のまま)。
- 日ごと・月ごとの組(賭けの線は週で書く)。
- 集計の画面(ダッシュボード)・費用のページへの載せ替え。
- 組織の大きさ・プランなどで組を分けること(組織の属性を持ち出すことになる)。

## 決めたこと

- 始めた週は「その機能を初めて使った週」で決める(依頼: 親のセッションからの依頼 2026-10-25「始めた週ごと(その機能を初めて使った週)の組織のまとまりについて、N 週後もまだ使っている割合を出す」)。
- 出力は数と割合だけで、組織と人の ID は出さない(`docs/security.md` の AI-6・仕様 0012 と同じ)。
