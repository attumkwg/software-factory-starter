# 仕様: 「今日」「今週」を1つの時計で決める(日付の数え方をそろえる)

> 状態: 完了(実装済み)
> 穴 G-122(`docs/scenarios/gaps.md`)。時刻の持ち方の決まりは [ADR 0005](../adr/0005-money-and-time.md)。北極星の分子「使われた数」(`docs/product/kpi.yaml`・[../kit/roadmap.md](../kit/roadmap.md) の 4)を数える `usage-report` の週の切れ目を直す。

## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM)と、運営のコマンドで数を見る人
- 動かす KPI: (キットの物差し: 北極星の分子「使われた数」の正しさ)
- 利用の記録は組織の時間帯の日付で持つのに、運営のコマンドは「今日」を UTC の日付で決めていた。日本の月曜 0〜9時に `usage-report` を流すと、今週の月曜の利用が入らず、「数え終わった週」が1つ前にずれる。契約の期限・PMF の回・事前登録の消す日も、日本の朝は前の日になる。

### 業務の要求

- 運営のコマンドが出す「今日」「今週」「数え終わった週」が、日本の朝に流しても昼に流しても同じになる
- キットの道具(期限の判定・判断待ちの一覧・進み具合)の「今日」が、1つの関数から来る

### 業務ルール

- 組織ごとの記録の日付は、組織の時間帯のまま — 「1日」を組織の時間帯で区切るのは ADR 0005 の決まり(変えない)
- 足し合わせる側(運営のコマンド)の「今日」は、運営の時間帯 `OPERATOR_TIME_ZONE`(日本時間)で決める — 組織ごとに「今日」が違うと、全部の組織を足した数の終わりの日が1つに決まらない
- 日付から日付を数える(n 日前・その週の月曜)ときは、ある瞬間に直さずに日付のまま数える(`addDays`・`mondayOf`) — 瞬間に直すと、直した時間帯でまたずれる
- キットの道具の「今日」は `todayInTokyo`(`scripts/checkup/phase.mjs`)1つ — 毎週の知らせ・期限は日本時間の朝に流れる
- 組織ごとの費用の按分(`tenant-shares`)の月は UTC のまま — AWS の請求の月が UTC で区切られるので、按分の元もそれに合わせる

### 受け入れ条件(業務の言葉で)

- [ ] 運営が日本時間の月曜 8時に `usage-report` を流すと、今週は「その月曜から」、数え終わった週は「先週の月曜」になる
- [ ] 運営が日本時間の昼に流すと、これまでと同じ期間になる
- [ ] `pre-registrations-report` の既定の期間は、日本時間の今日までの28日(月をまたいでも日付で数える)
- [ ] 事前登録の日ごとの数を消す境目と、登録を消す日が、日ごとの数と同じ日本時間の日付で決まる
- [ ] `pnpm kpi`・`pnpm decisions`・`pnpm bets`・`pnpm vulns`・`pnpm queue`・`pnpm progress`・`pnpm sales-pack` の「今日」が日本時間の日付

### 要配慮個人情報

- 当たらない(日付の数え方だけ。新しく持つ項目は無い)

### やらないこと

- 組織ごとの記録の持ち方(組織の時間帯の日付)は変えない
- 運営の時間帯を設定で変えられるようにはしない(使う会社が日本以外の運営になったら `OPERATOR_TIME_ZONE` を1か所直す)
- `tenant-shares` の月の区切り(UTC。上の業務ルール)
- 「UTC の今日」を書かせない検査(Semgrep の決まり)は、守る場所(`.semgrep/`)なのでこの仕様では足さない。G-122 の行に次の一手として残す

### 決めたこと

- 運営の時間帯は定数1つ(`packages/shared/src/time.ts` の `OPERATOR_TIME_ZONE = DEFAULT_TIME_ZONE`)。運営の組織の `time_zone` を読む形にはしない — コマンドの期間の計算を DB を読まない関数のままにでき、テストで境目を確かめられる(2026-10-29。人に聞く4つに当たらないので AI が決めた)

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

該当なし(状態を持たない。日付の計算だけ)

### 境界値

- 日本時間 0:00〜8:59(UTC では前の日): 運営の「今日」は日本時間の日付。`reportWindow` のテスト(`apps/api/test/unit/usage-report-window.test.ts`)
- 月曜の朝(UTC ではまだ日曜): 今週の月曜はその日・数え終わった週は先週の月曜
- 月末・年末・うるう年をまたぐ n 日前 / 後: `addDays`(`packages/shared/src/time-dates.test.ts`)
- 日曜: その週の月曜は6日前(週は月曜始まり)
- 日付でない文字列(`2026-10-32`・`2026/10/26`): `addDays`・`mondayOf` は受け付けない(`DateOnlySchema`)
- 保存期間の端(400日): `cohortsFrom` は端の週の月曜より前にならない

### 直した所

| 場所 | これまで | これから |
|---|---|---|
| `apps/api/src/usage/command.ts`(`usage-report`・`usage-purge`) | UTC の日付で今日・週の月曜 | `reportWindow`: 運営の今日から日付で数える |
| `apps/api/src/plans/command.ts`(`plan-report`) | UTC の日付 | 運営の今日・`addDays` |
| `apps/api/src/pmf-survey/command.ts`(`pmf-survey-report`) | UTC の日付で回を決める | 運営の今日で回を決める |
| `apps/api/src/domains/growth/*`(事前登録の消す日・日ごとの数の境目) | 日ごとの数は日本時間・消す境目は UTC | どちらも日本時間(`tokyoDay` を `toLocalDate(…, OPERATOR_TIME_ZONE)` に) |
| `apps/api/src/pre-registrations/command.ts` | 始まりを瞬間に直して27日前 | `addDays(to, -27)` |
| `scripts/` の7つの道具 | UTC の日付・+9時間・`Intl` が混ざる | `todayInTokyo` |
