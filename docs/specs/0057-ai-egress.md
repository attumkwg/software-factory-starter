# 仕様: AI の環境から外への通信を絞る(結合テストを回せる形で)

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。会話で回答)
> 設計: [docs/designs/0057-ai-egress.md](../designs/0057-ai-egress.md)・ADR: [0068](../adr/0068-ai-egress-by-where-it-runs.md)
> 穴 G-22(`docs/scenarios/gaps.md`)。場面は `06-security-audit.md` の 6-11(背景の AI を夜も回す)。決まりは [docs/security.md](../security.md) の AI-2。
> **この PR は設計だけ**。作るのは段ごとの PR(設計書の 7)。

## なぜ作るか

- AI-2「AI の環境から外に出られる先を絞る」が「未」のまま。前に devcontainer で絞ったら、中から Docker が使えず、AI が結合テストと E2E を回せなくなって見送った。
- 人が見ていない所(夜・背景の AI)で長く回すなら、AI が書いたコード(テスト・スクリプト)が外へ何かを送っても、だれも気づかない。想定の場面 6-11 では、禁じていなかった「フォームの送信」で外の機関に作り話を送り、見つかったのは2か月後だった。
- **書いて禁じるより、手段を持たせない**。「何を送ってはいけないか」を全部書くことはできない。送る手段(道具・通信・鍵)の側を、要る物だけにする。

## 受け入れ条件

### 外へ送る手段を持たせない(全部の AI)

- [ ] 外へ送る手段の棚卸し(設計書の 2)があり、手段ごとに「対話の AI」と「背景の AI」でどう止めるかが決まっている
- [ ] 背景の AI(`claude.yml`)は、Web を読む・調べる道具(WebFetch・WebSearch)と MCP の道具を持たない。Bash で使えるのは今の許可の一覧だけ(`curl` などは無い)
- [ ] AI の環境に、外へ送れる鍵(メール・チャット・本番・AWS)を置かない(AI-1 のまま)。GitHub のトークンは、このリポジトリだけに届く物

### 通信を絞る(AI が書いたコードを動かす所)

- [ ] 人が見ていない作業(長い作業・背景の AI)は、外への通信が絞られた所でだけ回す: ① 絞った devcontainer か ② GitHub Actions の背景の AI
- [ ] ① 絞った devcontainer の中で、AI が `pnpm test:integration` と `pnpm test:e2e` を回せる(Docker が使える)
- [ ] ① の中から外へ出られるのは、許可リストの宛先だけ(パッケージの取得先・GitHub・モデルの API・コンテナの置き場)。ほかは止まり、止まった宛先が記録に残る
- [ ] ② の背景の AI は、結合テストと E2E を自分の中で回さず、push して CI の結果を読む

### 頼まれていない外向きの行動を報告する

- [ ] AI が外へ向けてした操作(push・PR やコメント・Web を読んだ・止められた通信)が記録に残り、PR の本文に「外へ出した物」として並ぶ。**頼まれていない物には印を付ける**
- [ ] 記録には宛先と手段だけを書く(中身・個人データは書かない。AI-6)

## 権限の表に足す行

該当なし(アプリの API を足さない)。

## 要配慮個人情報

- 当たらない(AI の環境と CI の設定。アプリのデータを扱わない)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | AI が会社の名前で外のフォーム・メールに送る | 送る道具(MCP・メールの鍵)を AI の環境に置かない。Web を読む道具も背景では持たない |
| 改ざん | AI が許可リストや絞りの設定を書き換えて外へ出る | 絞りの設定は危険度「高」の一覧(AI-5)。devcontainer の中では、絞りの設定を root でしか変えられない |
| 否認 | AI が外へ送ったことが後から分からない | 外向きの操作と止められた通信の記録・PR の「外へ出した物」 |
| 情報漏えい | AI が書いたテストのコードが、ソース・鍵・データを外へ送る | ①②の通信の絞り。鍵を置かない(AI-1)。URL の問い合わせに載せて送る形も、宛先の許可リストで止まる |
| 妨害 | 絞りすぎて、AI がテストを回せず仕事が止まる | 結合テストと E2E が回ることを、絞った devcontainer の受け入れ条件にする |
| 権限昇格 | Docker の操作から、絞りの外(ホスト)へ出る | devcontainer は Docker の中の Docker(ホストの Docker の口を渡さない)。Claude Code の sandbox に Docker の口を渡さない |

## やらないこと

- 人が見ている対話の AI の通信を、OS の仕組みで絞ること(今の確認で止める形のまま。手元の OS ごとに方法が違い、Windows のそのままの手元では効かない)
- 社員の端末全体への配り(管理者の設定。`docs/guides/local-guards.md` の「手元の設定を全社に配る」)
- 中身を見て止めること(TLS を開く・送る文を調べる)

## 決めたこと

- 穴 G-22・想定の場面 6-11・AI-2 を、この仕様の要求にした。親のセッションから伝わった持ち主の依頼(「AI が結合テストを回せる形で通信を絞る案を比べる」「禁じていない『フォームの送信』で外へ送る形を、手段の側で止める」)による。人に聞くこと(仮決め)は設計書の「未確定事項」に書く。
