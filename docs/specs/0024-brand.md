# 仕様: ブランド(名前・トーン・色)を決める段取り(`/brand`・`pnpm contrast`)

> 状態: 完了(実装済み。未確定事項は設計書で答え済み。@attumkwg が 2026-10-27 に完了とした)
> 設計: [docs/designs/0024-brand.md](../designs/0024-brand.md)・ADR: [0037](../adr/0037-promise-before-lp-and-brand.md)
> 穴 G-32(`docs/scenarios/gaps.md`)。仕様 0023(約束と売り文句 `/positioning`)の上に積む。

## なぜ作るか

- 色を、約束と相手から決める段取りが無い(想定の場面の 8-2)。トークン・生の色コードを止める Semgrep・axe・VRT・部品の一覧ページはあるが、「何色にするか」を決める手前が無い。
- 約束の前に色を決めると、LP もプロダクトも合わない物になる(ADR 0037)。決める順番は 言葉 → LP → 色。
- 色の案は、出す時点でコントラストの比が分かっているべき(後で axe に落とされて作り直すのは高い)。いまは比を計算する道具が無く、目で決めるか外のサイトに頼ることになる。
- 持ち主の言葉(2026-10-25):「何を決めるかが無いと、LP もプロダクトと合わない物になり、プロダクトのカラーも決まらない」。

## 受け入れ条件

### `/brand`

- [ ] 担当者が Claude Code で `/brand` と打つと、`docs/product/positioning.md` が無ければ「先に約束(仮でよい)」と伝えて `/positioning` へ案内し、何も書かない
- [ ] 約束があれば、約束と相手(業種・使う場所)から、**話し方のトーン・名前(仮)・色の案を2〜3つずつ**、理由(約束のどの言葉・相手のどの条件か)つきで出し、1問ずつ選んでもらう(選択肢で出す)
- [ ] 色の案は `tokens.css` の主な色(`--color-primary`・`--color-primary-hover`・`--color-on-primary`・`--color-focus`・`--color-info`)を、**明るいテーマと暗いテーマの両方**で置き換える形で出し、案ごとに `pnpm contrast` の比の表を添える。届かない組がある案は出さない
- [ ] 危険・成功・注意・文字・背景の色は、理由なしに変えない
- [ ] 名前の案には、商標(J-PlatPat・区分)・ドメイン・同じ名前のサービスを確かめるまで「仮」と書き、当てはめは弁理士と確かめる、と添える
- [ ] 聞き終わったら1画面にまとめて見せ、**OK をもらう前にはファイルを書かない・PR を作らない**
- [ ] OK の後、`docs/product/_template-brand.md` を写して `docs/product/brand.md` を書き、`tokens.css` の選んだ値だけを書き換え、`pnpm contrast` を通し、VRT の基準を撮り直して(画像を見てから)PR にする。PR の本文に比の表を貼り、VRT のスクショが PR のコメントに貼られることを書く。危険度は「中」
- [ ] 2つの案を画面で見比べたいときは、案ごとに下書きの PR を作れる
- [ ] 「選ばなかった案」と「これまでの判断」は足すだけ

### `pnpm contrast`

- [ ] `pnpm contrast` が `packages/ui/src/tokens.css` の明るいテーマと暗いテーマを読み、画面で重なる文字と背景の組ごとに比を出す(PR に貼れる表)
- [ ] 文字 4.5:1・文字でない物(フォーカスの枠・選んだ印)3:1(WCAG 2.2 AA)に届かない組があれば 1 で終わる。参考の組(枠の線)は落とさない
- [ ] 比は切り捨てで出す(4.499 を 4.5 と見せない)
- [ ] ファイルを並べて渡すと、案ごとに比べられる
- [ ] `pnpm test:scripts` の中で、いまの `tokens.css` が全部の組で届くことを確かめる(色を変えた PR はここで落ちる)

### 資料

- [ ] `docs/design-system.md` の分担と確かめる仕組みに `/brand`・`pnpm contrast` が書いてある

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | ほかの会社のブランド(名前・色)に似せて、利用者を取り違えさせる | 名前は商標とドメインを確かめるまで「仮」。代わりの物と紛れないかを案ごとに1行(スキル) |
| 改ざん | 比の届かない色に、こっそり変える | `pnpm test:scripts` がいまの `tokens.css` の比を確かめる(CI)。E2E の axe。VRT で画面の差が PR に出る |
| 否認 | 誰が色を決めたか分からない | brand.md の「これまでの判断」に決めた人。PR の承認 |
| 情報漏えい | Web フォントを外の配信から読み、利用者の情報が外の会社に送られる | 既定は端末の文字。Web フォントは `packages/ui` に置いて自分で配る(スキルの「してはいけない」)。外へ送るなら委託先の台帳(`pnpm vendors`) |
| 妨害 | 重い Web フォントで最初の表示が遅くなる | 既定は端末の文字。使うなら使う字だけに絞る(スキル) |
| 権限昇格 | 読んだ Web ページの指示に従って、ほかのファイルを書く | データとして扱う。OK の前に何も書かない |

## やらないこと

- ロゴ・絵を作ること(人かデザイナーが作る)
- 商標の当てはめ(確かめることと、弁理士と確かめる一言まで)
- LP そのもの(G-33)
- 押す所の大きさ・文字の大きさを変えること(部品の `size`。必要なら別の Issue)
- 暗いテーマの VRT(いまは明るいテーマだけを撮る。暗いテーマは比の計算と手元で1回見る)
