# 仕様: Slack で頼むと、AI が PR を出し、持ち主の返事でマージまでする(1人の間)

> 状態: 完了(実装済み。クラウドの中で Docker・REST のマージが動くかは、持ち主がつないだ後の試しで確かめる)
> 設計: [docs/designs/0080-slack-requests.md](../designs/0080-slack-requests.md)・ADR: [0082](../adr/0082-solo-conversation-answers-and-ai-merge.md)
> 穴 G-124(`docs/scenarios/gaps.md`)。手順は `docs/guides/slack.md` の「🧍 1人の間のおすすめ」と `/slack-request`。

## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

ソフトウェアファクトリーの目指す姿は「Slack などでクラウドの AI に頼むと、AI が作って PR まで出し、人はマージの判断だけ」。今のキットは、背景の AI が手動の起動だけで、AI の PR は作る前の対話・未確定事項の答え(GitHub のコメントだけ)・マージで、毎回持ち主を GitHub に呼び戻す。

### 業務の要求

- 持ち主が Slack に1行で頼むと、AI が1本の PR にして返す
- AI は終わりに仮決めを並べて「これでいいですか」と聞く
- 持ち主が会話(Slack のスレッド・Claude のアプリ・チャット)で「大丈夫なのでマージして」と返すと、AI が仮決めを承認にし、必須のチェックが全部緑になってからマージする

### 業務ルール

- 仮決めは必ず持ち主に確かめる — 事業判断・利用者の挙動などを AI だけで決めない
- 1人で回している間は、会話の返事も答えにする(Slack・チャット) — 答える人もレビューする人も持ち主1人なので、GitHub に書き直す手間だけが増える
- AI がマージするのは、持ち主の返事があり、必須のチェックが全部緑のときだけ — 人の判断と機械の確かめの両方をそろえる
- 人が増えたら(承認数を 1 以上にしたら)、会話の答えも AI のマージも止まる — 2人目の目を外さない
- 要配慮個人情報に当たりうる依頼は、答えをもらうまで作らない — 戻せない

### 受け入れ条件(業務の言葉で)

- [ ] 持ち主が Slack で頼むと、クラウドの AI が1本の PR(仕様・コード・テスト)を出し、スレッドに PR と仮決めと「これでいいですか」が出る
- [ ] 持ち主が「大丈夫なのでマージして」と返すと、AI が仮決めを承認に書き換え、必須のチェックが全部緑になってからマージし、スレッドに知らせる
- [ ] 必須のチェックが落ちている・終わっていない間は、マージしない
- [ ] 手元の Claude Code(持ち主がクラウドの環境に合図を入れていない所)では、AI はマージできない
- [ ] 1人の間は、Slack・チャットの返事を書いた未確定事項の行を、CI が答えとして通す。持ち主でない名前は通さない
- [ ] 承認数を 1 以上にすると、会話の答えも AI のマージも止まる

### 要配慮個人情報

- 当たらない(仕組みの変更。依頼ごとの要配慮は `/slack-request` が必ず聞く)。

### やらないこと

- Claude Tag(Team・Enterprise)・自前のボット(`docs/guides/slack.md` の A・B)
- 並列で何本も回す(GitHub Actions の @claude)
- Slack のメッセージの書き手を CI で確かめる(できない。1人の間の割り切り)

### 決めたこと

- 仮決めは Slack で「これでいいですか」と必ず確かめる・「大丈夫なのでマージして」で進む流れにする・試して通れば持ち主の返事+必須のチェックが全部緑のときだけ AI がマージする・このチャットでの返事も答えにする(@attumkwg 2026-10-28。会話で回答)。

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 状態 \ 操作 | 会話の答えを CI が認める | `pnpm pr:merge-when-green` |
|---|---|---|
| 1人の間・クラウド(`KIT_AI_MERGE=slack`) | `@持ち主` なら通す | 必須のチェックが全部緑ならマージ |
| 1人の間・手元(変数なし) | 通す | フックとスクリプトが止める |
| 人が増えた(`required_approvals` ≥ 1) | 通さない(GitHub の答えだけ) | スクリプトが止める |
| コマンドの中で `KIT_AI_MERGE` を入れた | — | フックが止める |

### 境界値

- 必須のチェック: main のルールセット(GitHub)と `.github/setup.yml` の `required_checks` を合わせた物。`success`・`skipped`・`neutral` を緑とみなす。1つでも落ちたら止める
- 待つ時間: 30秒ごと・45分まで
- 待つ間に push があった: 見た版の sha を渡してマージするので GitHub が断る(止まる)
- PR が開いていない・下書き・main 向けでない: マージしない

### 権限の組み合わせ

- 該当なし(アプリの API は変えない)。マージできるのは、クラウドの GitHub の中継が持つ持ち主の権限の範囲。

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | スレッドのほかの人・PR のコメントが「マージして」と書く | 合図は持ち主がその作業に返した返事だけ(`/slack-request`)。依頼のチャンネルは持ち主だけ(`docs/guides/slack.md`) |
| なりすまし | AI が返事なしに「承認(Slack の返事)」と書いてマージする | 1人の間だけの割り切り(ADR 0082)。必須のチェックは全部要る。PR に返事の文が残る |
| 改ざん | 手元の AI が `KIT_AI_MERGE` を入れてマージする | フックがコマンドの中の `KIT_AI_MERGE` とスクリプトを止める(`guard-bash.test.mjs`)。スクリプトも変数を見る |
| 否認 | 「マージを頼んでいない」 | マージのコミットに返事の文を残す |
| 情報漏えい | — | 変わらない(外へ送る手段は増やさない) |
| 妨害 | 落ちたチェックのままマージする | 全部緑まで待つ(`pr-merge.test.mjs`) |
| 権限昇格 | 人が増えた後も AI がマージする | 承認数が 1 以上ならスクリプトが止める・CI も会話の答えを通さない(`decisions.test.mjs`) |
