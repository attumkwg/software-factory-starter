# 仕様: 約束と売り文句を決める段(`/positioning`)

> 状態: 下書き
> 設計: [docs/designs/0023-positioning.md](../designs/0023-positioning.md)・ADR: [0037](../adr/0037-promise-before-lp-and-brand.md)
> 穴 G-31(`docs/scenarios/gaps.md`)。決める順番は [scenarios/fit-journey.md](../scenarios/fit-journey.md) の 2(言葉 → LP → 色)。

## なぜ作るか

- LP・チラシ・営業の資料・ブランドの色を作る前に、「誰の何を、どう変えるか」の**約束**と**売り文句**が要る。決めないまま作ると、LP もプロダクトの色も「合わない物」になる(想定の場面の 8-1)。
- 約束の材料は、キットの中にもう溜まっている(`docs/product/interviews/` の相手の言葉・賭けの小石の何が効いたか・`plan.md` の代わりの物と不満)のに、それをつなぐ手順と置き場が無い。
- 持ち主の言葉(2026-10-25):「売れるためのキーワードや LP 的なものを作れるぐらいには」「何を決めるかが無いと、LP もプロダクトと合わない物になり、プロダクトのカラーも決まらない」「フィットジャーニーは目安。それでもやる意思でも進める仕組みに」。

## 受け入れ条件

- [ ] 担当者が Claude Code で `/positioning` と打つと、Claude が `plan.md`・`interviews/`・賭けの小石を読み、**約束の案を3つ**(向きを変えて)・**売り文句(キーワード)**の案・**代わりとの違い**・**言わないこと(約束できない物)**を、**根拠(どの記録・小石か)**つきで出し、1問ずつ選んでもらう(選択肢で出す)
- [ ] 案の根拠は、記録のファイル名・賭けの ID と小石の日付・`plan.md` の代わりのどれかを指す。根拠の無い案は「根拠なし」と書き、おすすめにしない
- [ ] 聞き終わったら1画面にまとめて見せ、**OK をもらう前にはファイルを書かない・PR を作らない**
- [ ] OK の後、`docs/product/_template-positioning.md` を写して `docs/product/positioning.md` を書き、PR にする(危険度「低」)
- [ ] PSF の結果(段階が `psf` 以上の賭けの小石)が無いときは、そう伝えたうえで「仮の約束として進める」か「先に確かめる」かを選んでもらう。**止めない**。仮で進めたら、状態を `仮(PSF の前)` にし、「これまでの判断」に `意思で進む(@名前)`、「意思で進んだ判断」の表に引き受けた危なさ・止める線・期限・決めた人を残す(ADR 0035 の形)。Claude から意思で進むをすすめない
- [ ] `positioning.md` があるとき・PSF の結果が出たとき・次の池に進むときは、見直しの流れ(新しい記録・小石と、いまの約束が合うか)になる。約束を変えたら、LP・チラシ・ブランドも直すよう伝える
- [ ] 「言わないこと」の案には、根拠の無い優良・有利の表示(景品表示法 5条)とお客さんの声・社名の許可を含め、法令の当てはめは専門家と確かめる、と添える
- [ ] `positioning.md` に、話を聞いた相手の名前・連絡先・会社名を書かない
- [ ] 「選ばなかった案」と「これまでの判断」は足すだけ(消さない)
- [ ] `docs/guides/before-pmf.md` に、PSF の後に約束を決める・ブランドはその後、が書いてある
- [ ] キットの部品のカタログに `positioning` が1件ある(`pnpm kit:catalog` が通る)

## 権限の表に足す行

該当なし(API を足さない。資料とスキルだけ)。

## 要配慮個人情報

- 当たらない(扱うのは、名前を落とした話の記録と、賭けの小石だけ。新しく人の情報を集めない)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 記録に無い言葉を「お客さんが言った」ことにして売り文句にする | 案に根拠(記録のファイル名・小石)を必ず付ける。根拠なしはおすすめにしない(スキルの決まり)。PR で人が見る |
| 改ざん | 都合の悪い選ばなかった案・判断を後から消す | 「選ばなかった案」「これまでの判断」は足すだけ(テンプレートとスキルの決まり)。git の履歴 |
| 否認 | 誰が約束を決めたか分からない | 「これまでの判断」に決めた人。PR の承認 |
| 情報漏えい | 話を聞いた相手の名前・会社名が売り文句や根拠に出る | 根拠は記録のファイル名まで。名前・連絡先・会社名を書かない(スキルの「してはいけない」)。記録の側も名前を書かない決まり |
| 妨害 | 該当なし(手元の対話だけ) | — |
| 権限昇格 | 記録や Web ページに混ざった指示に従って、ほかのファイルを書く | 読んだ物はデータとして扱う。OK の前に何も書かない(スキルの決まり) |

## やらないこと

- LP・チラシ・営業の資料そのものを作ること(公開してよい LP の型は G-33)
- ブランド(名前・トーン・色)を決めること(G-32。約束の後)
- 景品表示法などの法令の当てはめ(言わないことの案と、専門家と確かめる一言まで)
- 約束を Claude が決めること(案と根拠まで。決めるのは人)

## 決めたこと

- 持ち主の言葉(上)を、この仕様の要求にした。決める順番は fit-journey.md の 2(言葉 → LP → 色)にそろえる(ADR 0037)。
- PSF の前でも止めない(仮の約束として進め、意思で進んだことを残す)。持ち主の「それでもやる意思でも進める仕組みに」による。残す形は ADR 0035(`plan.md` の「意思で進んだ判断」)にそろえる。
- 人に聞くこと(仮決め)は設計書の「未確定事項」に書く。
