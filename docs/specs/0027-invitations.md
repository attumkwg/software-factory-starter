# 仕様: 招待(管理者が画面から人を招く)

> 状態: 完了(実装済み。未確定事項は設計書で答え済み。@attumkwg が 2026-10-27 に完了とした)
> 設計: [docs/designs/0027-invitations.md](../designs/0027-invitations.md)・ADR: [0040](../adr/0040-invitations-signed-link.md)
> 穴 G-02(`docs/scenarios/gaps.md`)。開通(仕様 0026)の上に積む。決まり `docs/security.md` の T-8。

## なぜ作るか

お客さんの管理者が人を足す道が無く、運営が本番の DB に SQL で `organizations.users` に行を足していた(`docs/runbooks/cognito-login.md`)。お客さんが10社を超えると CS の手が回らず、監査ログにも残らない。T-8 は「招待はリンクの期限と1回きり」を決まりにしている。開通(仕様 0026)で作った最初の管理者にも、登録の仕方を仕組みで知らせたい。

## 受け入れ条件

管理者が招く:

- [ ] 管理者は画面「設定」→「招待」で、メールアドレスとロール(管理者・メンバー・閲覧者)を選んで人を招ける。招待のメールが届く(アウトボックス経由)
- [ ] 招待のリンクは**7日**で切れ、**1回だけ**使える。管理者は受けていない招待を取り消せる(リンクはすぐ使えなくなる)
- [ ] 一覧に、自社の招待と状態(受けていない・参加した・期限切れ・取り消し済み)が新しい順に出る
- [ ] もうこの組織にいる人・受けていない招待がある人は招けない(409)。取り消せば招き直せる
- [ ] 受けていない招待は、1つの組織で50件まで(招待のメールを大量に送らせない)
- [ ] 招いた・取り消したことが監査ログに残る(メールアドレス・ロールは記録に入れない)
- [ ] メンバー・閲覧者・代理の社員は招けない・一覧も見られない(403)
- [ ] 他社の招待は見えない・取り消せない(404)

招かれた人が受ける:

- [ ] 招かれた人は、メールのリンクを開き、名前を入れて「参加する」を押すと、その組織に招いたロールで入る(ログインは要らない)
- [ ] そのあと、**招待のメールアドレス**で Cognito に登録(確認コード)→ ログインすると、その組織を使える。規約の同意は、ふつうの初めての人と同じ
- [ ] リンクが正しくない・期限切れ・使用済み・取り消し済みは、どれも同じ文で断る(どれかは言わない)
- [ ] 組織はリンクが指す招待で決まる(リクエストの値・ログイン中のセッションの組織では決まらない)
- [ ] **他社の人を招けない**: そのメールアドレスがもうどこかの組織で使われていれば、受けるときに断る(1人 = 1組織)。招く時点では、他社にいるかを管理者に教えない
- [ ] メールのドメインは確かめない(会社のドメインの確認は SSO を足すときに。T-8)
- [ ] 受けたことが、その組織の監査ログに本人として残る

開通の案内:

- [ ] 運営のコマンド `create-tenant` で組織を作ると、最初の管理者に「準備ができました」のメール(登録の URL と手順)が届く(試しでは届かない)

## 権限の表に足す行

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `GET /api/invitations` | 200 | 403 | 403 | — | 401 |
| `POST /api/invitations` | 201 | 403 | 403 | — | 401 |
| `DELETE /api/invitations/{invitationId}` | 204 | 403 | 403 | 404 | 401 |
| `POST /api/invitations/accept` | 公開(札が正しくなければ 400) | | | | |

## 要配慮個人情報

- 当たらない(招く人のメールアドレス・名前・ロール)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 招待のリンクを手に入れた他人が受けて、その組織に入る | 受けても、ログインできるのは招待のメールアドレスを Cognito で確かめた本人だけ(初めてのログインで、確認済みのメールが一致したときだけ結びつく)。リンクは1回きり・7日 |
| なりすまし | 札を作る・当てる | 札は招待の ID とサーバーの秘密の署名(HMAC-SHA256)。署名が違えば DB に聞く前に断る。結合テスト「署名が違う・ほかの秘密・形が違う」 |
| 改ざん | 他社の招待の ID に、自分の招待の署名を付け替える | 署名は ID ごと。結合テスト「付け替えられない」 |
| 改ざん | 受けるときに組織やロールを選ぶ | 本文は札と名前だけ。組織・ロール・メールは招待の行から DB の関数が写す |
| 否認 | 「招いていない」「入った覚えがない」 | 招いた・取り消した(管理者)・受けた(本人)が監査ログに残る |
| 情報漏えい(他社のデータ) | 招く画面で、他社にいる人かが分かる | 招く時点では確かめない(他社にいても 201)。受けるときにだけ断り、それは招待のメールを受け取った本人にだけ見える |
| 情報漏えい | 札がサーバーのログ・Referer・画面の写しに残る | 札は URL の `#` の後ろ(サーバーに届かない)。受けたら URL から消す。メールの本文には札があるので、メールは本人の受信箱にだけ |
| 妨害 | 管理者が招待のメールを大量に送る(送信元の評判を落とす) | 受けていない招待は1組織50件まで。招いたことは監査ログに残る |
| 権限昇格 | アプリの接続から users に好きな行を足す | アプリの接続は users に行を足せない。足せるのは「生きている招待を受ける」DB の関数だけで、その行は招待とメール・ロール・組織がそろう物だけ(ポリシーで確かめる)。結合テスト |
| 権限昇格 | メンバーが自分より強いロールで人を招く | 招けるのは管理者だけ(権限の表) |

## やらないこと

- 招待の送り直し(取り消して招き直す)・期限の延長
- 人を外す・無効にする・ロールを変える画面(別の仕様)
- 会社のドメインの確認・SSO(T-8 の後半。SSO を足すときに)
- 1人が複数の組織に入る形(G-21)。他社にいる人は参加できない
- 人数の上限(プランと一緒に。G-03)
- 開通の最初の管理者を招待のリンクにすること(設計書の U-1)

## 決めたこと

- リンクの札は DB に持たず、招待の ID とサーバーの秘密の署名にする(ADR 0040)。
- 招待を受けるのはログインの前の公開の API。受けても自動ではログインさせない(本人の確認は Cognito の登録とログイン)。
