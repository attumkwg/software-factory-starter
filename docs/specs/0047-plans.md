# 仕様: 契約のプランの表(人数の上限・機能とのつなぎ・価格表と据え置き)

> 状態: 下書き
> 設計: [docs/designs/0047-plans.md](../designs/0047-plans.md)・ADR: [0058](../adr/0058-plans-table.md)
> 手順書: [docs/runbooks/plans.md](../runbooks/plans.md)。穴 G-03(`docs/scenarios/gaps.md`)。

## なぜ作るか

組織ごとの契約(どのプランか・何人までか)を持つ所が無く、「上のプランの会社だけに機能を出す」は運営が組織ごとに機能フラグを手で入れていた。値上げのとき、今のお客さんを旧価格に残す(据え置き)には「どの版の価格表で契約しているか」「据え置きはいつまでか」を持つ必要があるが、その形も無い。申込書の型(`docs/legal/order-form.md`)のプラン・人数の欄にも、キットの中で受ける先が無い。請求そのもの(金額の計算・請求書・決済)は外の会計ソフトで手で行う前提で、キットは持たない。

## 受け入れ条件

プランと価格表の定義:

- [ ] プラン(名前・画面に出す名前・入る機能・人数の上限を超えたときの扱い)と価格表(版の名前・いつからか)は `packages/shared` に定義する。足す・変えるのは PR で(書き方の誤りは単体テストが落とす)
- [ ] 価格表は金額を持たない(金額は申込書と会計ソフト)。値上げは新しい版を**足す**(古い版は消さない)

組織の契約(運営):

- [ ] 運営はコマンド `plan <組織の ID>` でいまのプランとこれまでの契約を見られ、`--plan <プラン>`(と `--seats`・`--price-list`・`--locked-until`・`--effective-on`)で**試し**、`--execute` で1行足せる
- [ ] 契約は足すだけ(変えるたびに1行)。いまのプランは「効き始めの日が今日まで」で一番新しい行。先の日付の契約はその日まで効かない
- [ ] 同じプランで人数だけ変えると、価格表と据え置きはそのまま。**プランを変えると、その日の価格表に移り、据え置きは消える**。価格表を渡せば旧版のまま据え置きを付けられる
- [ ] 変えたことが、その組織の監査ログに「仕組みが・プランを変えた(プランと価格表の名前)」として残る。同じ中身なら足さない
- [ ] 運営は `plan-report` で、プランと価格表ごとの組織の数・旧価格表の組織(据え置きの期限が近い・過ぎた・無い)・人数を超えた組織を、組織の ID で見られる(読むだけ)
- [ ] 開通のコマンド `create-tenant` の申し込みにプラン・人数・価格表・据え置きの期限があれば、最初の契約も同じトランザクションで足す(定義に無いプランなら試しでも止まる)

人数の上限:

- [ ] プランの扱いが block のとき、いる人+受けていない招待が上限に届いていれば、管理者は人を招けない(409 `seat_limit_reached`)。count のとき・上限なし・プランが無いときは止めない

機能とのつなぎ:

- [ ] 機能フラグに状態 `plan` を足す。いまのプランの機能に入っている組織にだけ出る(API の守り・`GET /api/me` の features の両方)。運営が組織ごとに入れた行も効く(プランの外の組織に試しに出す)

管理者が見る:

- [ ] 管理者は画面「招待」で、プランの名前・人数の上限・いまの人数(受けていない招待を含む)を見られる(`GET /api/organization/plan`)。メンバー・閲覧者・代理の社員は見られない(403)。他社のプランは見えない

## 権限の表に足す行

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `GET /api/organization/plan` | 200 | 403 | 403 | — | 401 |

変えるのはコマンドだけ(API は作らない。契約の正は申込書と会計ソフトで、画面の鍵1本で変えられないようにする)。

## 要配慮個人情報

- 当たらない(プランの名前・価格表の版・人数・日付)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 管理者になりすまして、上のプランにする | 変える API は無い。運営のコマンドだけ(表の持ち主の接続) |
| 改ざん | アプリの接続からプランの行を書き換えて、機能や人数を増やす | アプリ(app_rw)は読むだけ(移行 0015)。行は足すだけ |
| 否認 | 「プランを変えた覚えがない」 | その組織の監査ログに、いつ・どのプランと価格表にしたかが残る。行は消せない(解約の削除だけ) |
| 情報漏えい(他社のデータ) | 他社のプラン・人数が見える | RLS と組織の ID で絞る。結合テスト「自社だけ」。plan-report は組織の ID と数だけ |
| 妨害 | 上限の確かめで招待が重くなる | 索引つきの1行と、2つの数え上げだけ |
| 権限昇格 | メンバーが契約の中身を見る | 管理者だけ(権限の表) |

## やらないこと

- 金額の計算・請求書・決済(会計ソフトで手で。部品のカタログの `billing` は「未」のまま)
- ARR・NRR などの売上の指標(金額を持たないので、会計ソフトの数字で手で出す)
- お客さんが画面からプランを変える(申し込み・解約と同じく、書面を受けて運営が変える)
- 招待を受けるときの人数の確かめ(招く時点で、受けていない招待も数えるので足りる)
- 人数の上限を超えた人のログインを止める(止めるのは招待だけ)

## 決めたこと

- プランと価格表の定義はコード(`packages/shared`)、組織ごとの契約は DB(足すだけの表)。変えるのは運営のコマンド(ADR 0058)。
- 人に聞く判断(価格表に金額を持たない・プランを変えたら据え置きが消える・上限の既定は招待を止める・キットの既定のプラン)は、設計書の「未確定事項」に仮決めで置く。
