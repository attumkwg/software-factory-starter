# 仕様: 上場の監査に耐える工数の実績(週の記録と開発の段階)

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。会話で: 設計書の U-1 を「既定として承認」。記録の形は使う人が自分の監査法人と導入時に決める)
> 設計: [docs/designs/0044-actual-hours.md](../designs/0044-actual-hours.md)・ADR: [0055](../adr/0055-actual-hours-weekly-record.md)
> 穴 G-26(場面 4-4)。費用のページの人の時間と PL・`/ledger`(仕様 0020)の上に積む。

## なぜ作るか

- 上場を目指すと「ソフトウェアの原価計算」が要る。監査では**見積もりの幅ではなく工数の実績**を求められ、よくある間違いは工数の管理・開発の段階(研究開発か、自社利用のソフトウェアの制作か)の確認。
- いまの人の時間は、PR からの自動の目安と週ごとの割合の手入力の**幅**(推定)で、`/ledger` の案も推定から作る。実際に何時間使ったか・どの段階の仕事だったか・誰が確かめたかの記録が無い。

## 受け入れ条件

> 「誰が・何をすると・どうなる」。どのテストかは設計書の「7. 要求との対応」。

記録する(人):

- [ ] 人が週に1回、人ごとに「記録の始まりの日・賭け(か土台)・開発の段階(研究開発・制作・運用)・実際の時間・確かめた人」を、非公開の置き場の `actuals.csv` に書ける。月をまたぐ週は月ごとに2行に分ける
- [ ] 形の合わない行(段階が3つのどれでもない・時間が負か数でない・人か賭けが空)は数えず、その数がページの「読めなかった物」に出る
- [ ] 確かめた人の無い行は「未確認」として数え、その数がページに出る

見る(費用のページと `/ledger`):

- [ ] 実績があると、PL の人の時間は「実績 N時間」になり、人の費用は推定の幅ではなく実績(時給 × 実績の時間)になる。無ければ今までどおり推定の幅
- [ ] `ledger.csv` に、賭け × 開発の段階ごとの実績の行が足される(研究開発 → 費用・制作 → 資産の候補・運用 → 費用)。根拠の欄に、記録の行の数・未確認の行の数・記録した段階が賭けの段階からの案と違うこと
- [ ] 実績が無いときは、ページの「足りない物」に「推定の幅で出した(上場の準備には週の記録が要る)」と出る
- [ ] ページと `/ledger` は、会計・税の当てはめは専門家が確かめる、と毎回添える
- [ ] 人ごとの時間・金額はページに出さない(賭けごとの合計だけ。今までどおり)

## 権限の表に足す行

API は足さない(権限の表に足す行は無い)。入力は今までの非公開の置き場(`cost/inputs/`)。

## 要配慮個人情報

- 当たらない。記録は人の名前(ハンドル)・賭け・段階・時間だけ。働いた時間は人事の情報なので、リポジトリには置かず、非公開の置き場だけに置く(時給と同じ)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 別の人の名前で時間を書く | 確かめた人の欄で別の人が確かめる。空なら未確認として数える |
| 改ざん | 後から段階を「制作」に書き換えて資産を大きくする | 置き場は版を残す(前の版に戻れる)。締めた月の `ledger.csv` は月ごとの写しが残る。段階が賭けの段階からの案と違えば根拠に出る |
| 否認 | 「その時間は誰が確かめたか」と言われる | 確かめた人の欄。`/ledger` で人が確かめた記録を賭けのファイルに残す |
| 情報漏えい | 人ごとの働いた時間が広まる | 入力は非公開の置き場だけ。ページは賭けごとの合計だけ。リポジトリに置かない |
| 妨害 | 該当なし(手入力の小さな表) | — |
| 権限昇格 | 該当なし | — |

## やらないこと

- 勤怠の仕組み・タイムシートの画面(記録は CSV。勤怠の道具があれば、その書き出しを形に合わせる)。
- 時間を日ごと・作業ごとに細かく持つこと(週 × 賭け × 段階まで)。
- 区分の確定(案まで。確定は人と専門家)。
- 推定(自動の目安・割合の手入力)をやめること(実績が無い月・比べるために残す)。
