# 仕様: 週の数字に「引き渡し」(実装の完了 → 受け入れ・設計が原因の作り直し)を足す

> 1つの仕様 = 1つ以上の Issue。大きければ親 Issue → 子 Issue に割ってから AI に渡す。
> 状態: 下書き
> **書く人を「説明の責任」で分ける**([concepts/people-and-ai.md の 1.1](../concepts/people-and-ai.md#11-段を決める問い説明の責任))。第1部は PdM が書く。第2部は AI が網羅して書き、エンジニアが見る。
> **印**: 何も付けない行 = 確定。`(仮説)` = まだ確かめていない思い込み。`(未確定 U-n)` = 決まっていない(中身は設計書の「未確定事項」の U-n)。

## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

AI で実装が速くなると、速い工程の出力が遅い工程(受け入れ・確かめ)の前に積み上がる。どの継ぎ目で待っているか・設計のせいの手戻りがどれだけあるかが見えないと、どこを先に直すかを感覚で決めることになる。

### 業務の要求

- 毎週の振り返りで、実装が終わってから受け入れを始めるまで何日待ったかが見える。
- 受け入れの点数と、外れた理由の内訳(要求・設計・AI の仮決め・実装)が週ごとに見える。
- 作り直しのうち、設計が原因の物の割合が週ごとに見える。

### 業務ルール

- 数は改善のための物で、人の評価に使わない。人ごとの数は出さない — 人の評価に使うと、数を良く見せる動きが先に起きる(`docs/guides/metrics.md` の 2)。
- 待ちは第1回の受け入れだけで数える — 2回目からは直した後の確かめで、引き渡しの待ちではない。
- 継ぎ目は1か所ずつ直す。数が悪い継ぎ目を1つ選び、入力・出力・人が判断する所を決めて1回回し、振り返りを次の判定の決まりにする — 一度に全部を直すと、何が効いたか分からない。

### 受け入れ条件(業務の言葉で)

- [ ] `pnpm metrics` に「引き渡し」の節が出て、週ごとに 受け入れの回・実装の完了から受け入れまでの日数(中央値)・受け入れの点数・外れた理由の内訳・作り直しの数・うち設計が原因の割合 が並ぶ
- [ ] 先週の受け入れが1回ずつ(記録・回・待ち・PdM と全体の点数・外れた理由)並ぶ
- [ ] 実装の PR が読めないときは、その回の待ちを数えず、「読めなかった物」に出る
- [ ] 毎週の Actions の要約(`metrics.yml`)にも同じ節が出る

### 要配慮個人情報

- 当たらない(PR の番号・日付・数だけ。受け入れの見た人は数えない)

### やらないこと

- QA の人の作業の開始(別の道具の記録)を読むこと。受け入れの記録(`docs/acceptance/`)の第1回の日付を「確かめの開始」とする
- 引き渡しの判定(渡してよいか)を自動にすること(数を見て人が継ぎ目を選ぶ)
- 決裁用の表に列を足すこと(改善の数として別の節にする)

### 決めたこと

- 本人の依頼(学びをキットに入れる5本の5本目)で作る。受け入れの点数を週の数字に出すのは仕様 0075 の「やらないこと」からここへ移した

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 記録の状態 \ 数 | 待ち(日) | 点数 | 作り直し |
|---|---|---|---|
| 第1回・実装の PR が全部マージ済みで読める | 第1回の日付 − 最後にマージした日(日本時間) | 合 ÷(合+否) | — |
| 第1回・実装の PR が無い・読めない・まだマージしていない | 数えない(読めない番号は「読めなかった物」へ) | 数える | — |
| 第2回から | 数えない | 数える | — |
| 設計書の作り直しの記録の行(日付が YYYY-MM-DD) | — | — | 週に1つ。入った工程が「設計」なら設計が原因 |

### 境界値

- 週に受け入れの回が0: 待ち・点数は「—」(0 にしない)
- 判定した項目(合+否)が0: 点数は「—」
- 作り直しが0: 割合は「—」
- 実装の PR が受け入れより後にマージ: 待ちは負の日数のまま出す(記録の誤りに気づけるように)
- 期間より前の回: 読まない(第1回の実装の PR も聞かない)

### 権限の組み合わせ

該当なし(アプリの API は変えない。GitHub は読むだけ)。

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし | — |
| 改ざん | 受け入れの日付を早めて待ちを短く見せる | 記録は足すだけ・git の履歴で見える(仕様 0075) |
| 否認 | 該当なし | — |
| 情報漏えい(他社のデータ) | 要約に機能の中身が出る | 出すのは記録のパス・回・数だけ(項目の文は出さない) |
| 妨害(重い処理・大量の要求) | 実装の PR の番号を大量に書いて GitHub を何度も読ませる | 期間の中の第1回の番号だけ・重ねない |
| 権限昇格 | 該当なし | 読むだけ(既存の `metrics.yml` の権限のまま) |

> 設計(どう作るか)は [docs/designs/0077-handoff-metrics.md](../designs/0077-handoff-metrics.md) に書く(AI 用。網羅的に)。
