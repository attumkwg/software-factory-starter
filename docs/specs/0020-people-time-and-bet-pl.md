# 仕様: 人の時間の見積もり・賭けごとの損益(PL)・`/ledger`

> 状態: 完了(実装済み。未確定事項は設計書で答え済み。@attumkwg が 2026-10-27 に完了とした)
> 設計: [docs/designs/0020-people-time-and-bet-pl.md](../designs/0020-people-time-and-bet-pl.md)・ADR: [0033](../adr/0033-people-time-and-bet-pl.md)
> 仕様 0019 の費用のページ(`cost.yml`)の上に積む。

## なぜ作るか

- 費用のページ(仕様 0019)は AWS・Actions・SaaS の「何にいくら」を出すが、いちばん大きい原価である**人の時間**が入っていない。PMF の前は、インフラより人と AI のほうが高いことが多い([段階と費用](../concepts/stages.md) の 4.)。
- 賭け(`docs/product/bets/`)ごとに、売上と原価を並べて「採算が合っているか」を見たい。作り終えてから PL を出して赤字に気づくのを防ぎたい。
- 月1回、人の時間とインフラを「作っている途中の資産(開発)」か「費用(運用・失敗した賭け)」かに分ける案を、根拠(PR・賭けの段階)つきで会計の側に渡したい。キットには案の表([bets-and-assets.md](../guides/bets-and-assets.md))があるが、集計が無い。
- 持ち主の言葉(2026-10-25):「人の時間の見積もりも入れてください。bet ごとの損益まで見たいです」「PL を出したときに採算が合わないとなるのが一番嫌」。

## 受け入れ条件

### 人の時間

- [ ] 費用のページが、今月作った PR を本文の「取り組み」(`bet:B-NNNN` か土台)ごとに数え、1件あたりの分数(AI の PR の確認・人が書いた PR・レビュー・コメント。`docs/cost/people.yaml` で変えられる)を掛けて、**自動の目安**の時間を出す
- [ ] 人が週1回、賭けごとの時間の割合を手で書くと(非公開の置き場の `time.csv`)、**手入力**の時間も出る。ページは自動の目安と手入力を並べ、**幅**で見せる。どちらも「推定」と明記する
- [ ] 時間は、人ごと(か役割ごと)の時給を掛けて円にする。時給の実額は**リポジトリに置かず**、使う側の非公開の置き場(S3 の `cost/inputs/rates.json`)から読む。時給の考え方(給与 × 1.3〜1.5 の会社の負担 ÷ 年の働く時間)は手引きに書く
- [ ] ページにもログにも、人ごとの金額は出さない(賭けごとに足した後だけ)

### 賭けごとの損益

- [ ] 賭けごとに、売上・インフラ(AWS のタグ `Bet`)・SaaS(`saas.yaml` の `bet`)・人の時間・共通の費用の配り分を並べ、原価と粗利を**下と上の幅**で出す。幅の全部が赤字なら「赤字」、全部が黒字なら「黒字」、またがれば「分からない」
- [ ] 共通の費用(土台 `core`・タグなし・共通の SaaS)は、決めた配り方(`people.yaml` の `allocation`)で賭けに配る。配る前の直接の原価も並べる
- [ ] 売上は手で書く(非公開の置き場の `revenue.csv`。賭けごとか全体)。売上の無い賭けは「売上なし」と出す
- [ ] 全体の PL(売上の合計 − 原価の合計)も出す

### `/ledger`

- [ ] 担当者が Claude Code で `/ledger` と打つと、前の月(か指定の月)の賭けごとの人の時間とインフラ・SaaS を、PR の作業の種類と賭けの段階から「資産の候補」「費用」「除却の候補」に分けた**案の CSV** を作り、1つずつ確かめる。会計・税の当てはめは専門家が確かめる、と毎回添える
- [ ] CSV は非公開の置き場(費用のページと同じ S3 の `cost/<年-月>/ledger.csv`)か手元にだけ置く。リポジトリにコミットしない

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | PR の本文の取り組みを書き換えて、ほかの賭けに時間を付け替える | 取り組みは CI(`pr-work.yml`)が形を確かめる。数えるのは main の `cost.yml` だけ。目安は手入力と並べて見る |
| 改ざん | 時給・売上の入力を書き換える | 入力は非公開の S3(prod の役割で読むだけ。書くのは人)。版が残る |
| 否認 | 時間の手入力を誰が書いたか分からない | `time.csv` の行に人の名前。S3 の版が残る |
| 情報漏えい | 給与・時給・売上が公開のリポジトリやログに出る | 実額はリポジトリに置かない(見本は偽の数字)。ログに金額を出さない・ページには人ごとの金額を出さない(テスト) |
| 妨害 | PR の数が多い月に GitHub の API を使い切る | 1か月の PR は 300件まで数え、超えたら注記 |
| 権限昇格 | 該当なし(読むだけ) | — |

## やらないこと

- 会計の仕訳・償却の計算・税の判断(案と根拠まで。確定は専門家)
- 勤怠や作業時間の自動の記録(PR からの目安と手入力だけ)
- 売上を決済の会社から自動で取ること(手入力か CSV)
- 人の評価に使うこと(時間は賭けの原価の目安。手引きに書く)

## 決めたこと

- 持ち主の言葉(上)と、持ち主が依頼で伝えた `/ledger` の案(月1回・人の時間とインフラを資産の候補か費用かに分ける案と CSV。会計・税は専門家に確かめる)を、この仕様の要求にした。キットの `/bet` と案の表([bets-and-assets.md](../guides/bets-and-assets.md))にそろえる。
- 人に聞くこと(仮決め)は設計書の「未確定事項」に書く。
