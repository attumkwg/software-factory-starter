# 仕様: 1人が複数の組織に入る(組織を選び直す)

> 状態: 下書き
> 設計: [docs/designs/0055-multi-org-membership.md](../designs/0055-multi-org-membership.md)・ADR: [0066](../adr/0066-multi-org-membership.md)(ADR 0001 の「1人 = 1組織」を置き換える)
> 穴 G-21(`docs/scenarios/gaps.md`)。**この PR は仕様と設計まで**(実装は答えが出てから)。

## なぜ作るか

いまは「1人 = 1組織」(ADR 0001)。メールアドレスと Cognito の利用者(sub)が全部の組織で1つの行にしか結びつかないので、午前は A クリニック・午後は B 病院で働く医師は、アカウントを2つ(メールを2つ)持つしかない。招待も「ほかの組織にいる人は参加できない」(仕様 0027)。100人規模のお客さん・複数の拠点や取引先を持つ会社では詰まる。一方で、**テナントはセッションからだけ決める**(ADR 0001 の 2)は崩さない。

## 受け入れ条件

所属:

- [ ] 1人(同じメール・同じ Cognito の利用者)が、複数の組織に、組織ごとのロールと名前で所属できる
- [ ] 招待を受けると、ほかの組織にもういる人でも、その組織への所属が増える(仕様 0027 の「ほかの組織にいる人は 409」をやめる)
- [ ] 運営の開通のコマンドも、ほかの組織にいる人を最初の管理者にできる

ログインと選び直し:

- [ ] ログインすると、**前回使った組織**に入る(初めてなら、所属の中で一番古い組織)。所属が1つなら今と同じ
- [ ] 画面の上に、所属している組織の一覧と切り替えがある。切り替えると、その組織のセッションに出し直す(Cookie は1つの組織分だけ有効)
- [ ] 切り替えられるのは、本人が所属している組織だけ(ほかは 404。所属しているかは DB の関数で確かめる)
- [ ] 切り替えはパスワードを入れ直さない。ログインの時刻(最長12時間)は引き継ぐ。切り替え先が二段階認証を必須にしていて本人が未設定なら、今と同じく設定の画面へ回す。規約の同意は組織ごと(今と同じ)
- [ ] 切り替えたことが、**元の組織と先の組織の両方の監査ログ**に残る

本人のアカウント:

- [ ] パスワード・二段階認証・メールアドレスは本人に1つ(Cognito)。変えると全部の所属に効く(ほかの端末を切るのも全部の組織で)
- [ ] 組織の名前・ロールは組織ごと

運営と代理ログイン:

- [ ] 代理ログインの最中は切り替えられない(代理を終えてから)
- [ ] 解約の削除(`delete-tenant`)は、ほかの組織にも所属している人を Cognito から消さない(その組織の所属だけを消す)
- [ ] 1人分の開示・削除の試し(`person-data`)は組織ごとのまま。Cognito から消すのは、最後の所属が消えるときだけ

他社のデータ:

- [ ] 所属が複数あっても、1つのリクエストで見えるのはセッションの組織の物だけ(RLS と関所は今のまま)

## 権限の表に足す行

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `GET /api/me/organizations` | 200 | 200 | 200 | — | 401 |
| `POST /api/session/organization` | 200(所属していれば)/ 404 | 200 / 404 | 200 / 404 | 404 | 401 |

(実装の PR で `docs/authz/matrix.yaml` に足す。代理の最中は `POST` が 403)

## 要配慮個人情報

- 当たらない(組織の名前・ロール・所属)。ただし「この医師がどの病院に勤めているか」が所属の一覧で本人に見える。他人には見せない(下の STRIDE)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 切り替えの本文に他社の組織の ID を入れて入る | 所属しているかを DB の関数で確かめる(Cognito の sub・確認済みのメールで結びついた行だけ)。無ければ 404。結合テスト |
| 改ざん | セッションの Cookie の組織だけを書き換える | Cookie は署名つき(今のまま)。関所は毎回、その組織にその人の行があるかを確かめる(今のまま) |
| 否認 | 「その組織に入っていない」 | 切り替えを両方の組織の監査ログに残す |
| 情報漏えい(他社のデータ) | A の画面を開いたまま B に切り替えて、A のデータが B の画面に混ざる | 切り替えたら画面のデータを全部読み直す(画面の状態を捨てる)。Cookie は1組織分だけ |
| 情報漏えい | A の管理者に、その人が B にも所属していることが分かる | 所属の一覧は本人にだけ返す。管理者の画面・書き出し・監査ログにほかの組織の名前・ID を出さない |
| 妨害 | 何千の組織に所属して一覧が重い | 1人の所属の数に上限(設計書 U-4) |
| 権限昇格 | A で管理者の人が、B でも管理者として動く | ロールは組織ごとに毎回 DB から引く(今のまま)。セッションは1組織分だけ |

## やらないこと

- 1つの画面で複数の組織のデータを並べて見る(横断の検索・通知の一覧)
- 組織をまたぐ物の移動・コピー
- 組織ごとに別のメールアドレス・別のパスワードでログインする(本人は1つ)
- SSO の組織と、そうでない組織の両方に所属する人の扱い(仕様 0056 で決める)
- 所属の数での課金(プランの人数は組織ごとのまま)

## 決めたこと

- テナントはセッションからだけ、は崩さない。選び直すと Cookie を出し直す(ADR 0066)。
- 人に聞く判断(前回の組織に入る・切り替えでパスワードを入れ直さない・所属の上限・既存の一意の外し方)は、設計書の「未確定事項」に仮決めで置く。
