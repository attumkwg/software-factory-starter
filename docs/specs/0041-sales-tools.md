# 仕様: CRM・MA・広告の道具の扱い

> 状態: 下書き(想定の場面の穴 G-37 から AI が書いた。2026-10-25。承認は PR で)
> 設計: [docs/designs/0041-sales-tools.md](../designs/0041-sales-tools.md)

## なぜ作るか

- 営業が商談の記録を外の道具(CRM)に置き始めるが、商談の記録には相手の名前と連絡先が入る(個人データ)。どこに置き、委託先の台帳にどう書き、AI に何を渡してよいかが決まっていない(想定の場面の 8-5)。
- MA・広告を入れると、アプリの利用者のデータを宣伝に回す・アプリの画面に外のタグを入れる、が起きやすい。

## 受け入れ条件

- [ ] `docs/guides/sales-tools.md` に、道具ごと(CRM・MA・広告・名刺の管理)に何が入り、どの区分かの表がある
- [ ] 入れるときにそろえる物(委託先の台帳に1件・人ごとのアカウントと二段階認証・入社と退職の道具の一覧・道具の AI の機能を切る・越境)がある。台帳の1件の例は手引きの中にあり、台帳(`vendors.yaml`)には使っている物だけを書くと書いてある
- [ ] 守ること(アプリの中にタグを入れない・アプリの利用者のデータを宣伝に回さない・CRM とアプリは組織の ID で結ぶ・利用の記録を CRM に送らない・リポジトリに商談の中身を書かない)がある
- [ ] AI に渡してよい物・渡さない物の表があり、`compliance/ai-data.md` に行がある
- [ ] 解約したお客さんの担当者の記録を消す時期と、道具をやめたときがある
- [ ] LP のタグの決まりは `landing-page.md` を正として指し、繰り返さない

## 権限の表に足す行

該当なし(API を足さない)。

## 要配慮個人情報

- 当たらない(文書だけ)。商談の記録に要配慮(病歴など)を書かない、は既存の決まり(ai-data.md・分類表)のとおり。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 共有のアカウントで CRM を使い、誰が書いたか分からない | 人ごとのアカウント・二段階認証・入社と退職の手順 |
| 改ざん | 該当なし(文書だけ) | — |
| 否認 | 「宣伝のメールに同意していない」 | 宣伝は同意した人だけ・アプリの利用者のデータを回さない(U-1) |
| 情報漏えい(他社のデータ) | 商談の記録を AI や Issue に貼る / 道具の AI の機能に読ませる / アプリの画面のタグから利用者の情報が外の会社に送られる | AI には ID と集計まで・道具の AI の機能は切る・アプリの中にタグを入れない |
| 妨害(重い処理・大量の要求) | 該当なし | — |
| 権限昇格 | 該当なし | — |

## やらないこと

- 道具を選ぶ・委託先の台帳に実際の1件を足す(使い始めたとき)
- アプリから CRM への自動の連携
- 獲得のコスト・届け方の賭け(穴 G-36)
- 想定の場面(`docs/scenarios/`)の判定と穴の一覧の書き換え(場面の持ち主が直す)
