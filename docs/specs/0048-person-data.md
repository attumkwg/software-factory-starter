# 仕様: 利用者1人分の開示・削除(手順書と運営のコマンドの試し)

> 状態: 完了(実装済み。未確定事項は設計書で答え済み。@attumkwg が 2026-10-27 に完了とした)
> 設計: [docs/designs/0048-person-data.md](../designs/0048-person-data.md)・ADR: [0059](../adr/0059-person-data-dry-run-first.md)
> 手順書: [docs/runbooks/person-data.md](../runbooks/person-data.md)。穴 G-06(`docs/scenarios/gaps.md`)。

## なぜ作るか

利用者1人から「私のデータを見せて・消して」と求められたとき(個人情報保護法 33条・35条)、答える手順も道具も無い。組織を丸ごと消す仕組み(`delete-tenant`)はあるが、1人分は無く、どの表にその人のデータがあるかを毎回 SQL で探すことになる。誰が答えるか(お客さんの会社か、運営か)も決まっていない。まずは手順書と、運営のコマンドの「試し」(どこに何件あるかを数えるだけ)までを作る。

## 受け入れ条件

- [ ] 運営はコマンド `person-data <組織の ID> <利用者の ID>` で、その人のデータがどの表のどの列に何件あるかと、消すときの扱い(匿名化・削除・残す)の案を見られる。**何も変えない**
- [ ] 引数は ID だけ(名前・メールを ECS の引数 = CloudTrail に残さない)。形が UUID でなければ止める
- [ ] 出力は表と列の名前・件数・扱いだけ(名前・メールなどの値は出さない)。Cognito と結びついていれば、その利用者の ID(sub)を出す(消すときに Cognito からも消すため)
- [ ] 数えるのはその組織の行だけ。その組織にいない人(他社の人・無い ID)は「いない」とだけ言う(他社にいるかは言わない)
- [ ] 利用者を指す列(利用者の ID を持つ …_by・…user_id・actor_id)が DB に増えたのに、コマンドの一覧に無ければ CI が落ちる
- [ ] 手順書に、求めを受けてから答えるまで(誰が受けるか・本人の確かめ・利用者の ID の見つけ方・開示の中身の作り方・消すときに残る所と期間)を書く
- [ ] 誰が答えるかの既定は、取り扱いの取り決めの型(`docs/legal/data-processing.md`)に合わせる: **お客さん(委託元)が本人に答え、運営(委託先)はお客さんの指示で手伝う**
- [ ] 部品のカタログの `person-deletion` を「あり」にする(いまある範囲: 試しと手順書)

## 権限の表に足す行

なし(API は作らない。運営のコマンドは表の持ち主の接続で、ECS の1回きりのタスクとして人が流す)。

## 要配慮個人情報

- 当たらない(数えるだけで値を読まない)。要配慮の表(スキーマ `sensitive`)には、いまは利用者を指す列が無い。足したときは一覧と手順書に足す。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 本人を名乗る他人が、ほかの人のデータの開示・削除を求める | 求めはお客さん(委託元)が受け、本人を確かめる(手順書の 1)。運営はお客さんの管理者の指示(書面)でだけ動く |
| 改ざん | 違う人のデータを消す | 試しは何も変えない。消す手順は次の一歩(それまでは手順書で2人で) |
| 否認 | 「頼んだ・頼んでいない」 | 指示は書面で受け、作業の記録に ID だけを残す |
| 情報漏えい(他社のデータ) | 他社の人の有無が分かる | その組織の文脈で数え、いなければ「いない」だけ。結合テスト |
| 情報漏えい | 出力・ログに名前やメールが出る | 出すのは表と列の名前・件数・扱い・ID だけ。結合テスト「値が入らない」 |
| 妨害 | 重い数え上げ | 1人分の数える SQL を十数本。運営が手で流す |
| 権限昇格 | 社員が試しを口実に中身を見る | コマンドは件数だけを出す。中身を見る道は今まで通り代理ログイン(閲覧者・記録が残る)だけ |

## やらないこと

- 本当に消す・匿名化する(次の一歩。試しの扱いの案を人が承認してから)
- 開示の中身(値)を運営が作って渡す(お客さんが自分の書き出しから作る)
- 利用停止(ログインだけ止める)・訂正(本人が画面で直せる物は画面で)
- 本人が画面から直接求める窓口
- バックアップの中から1人分を消す(できない。保存期間で消える)

## 決めたこと

- まずは試し(数えるだけ)と手順書(ADR 0059)。引数は ID だけ。
- 誰が答えるか・消すときの扱い・開示の中身の作り方は、キットの既定として @attumkwg が承認(2026-10-25)。使い始めた人が自分の契約の形に合わせて決める(設計書 0048 の U-1〜U-3。`pnpm decisions --adopt`)。
