# 仕様: 資産の累計と ROI・北極星の分母と分子を毎週出す

> 状態: 完了(実装済み)
> 穴 G-136(`docs/scenarios/gaps.md`。ロードマップ 6 の6・G-127 の残り)。ROI の式は [仕様 0083](0083-close-the-loop.md) の `roiRange`、日付の数え方は [仕様 0087](0087-one-clock-for-today.md)。数の出どころ(【実測】と【推定】)は [../kit/roi.md](../kit/roi.md)。

## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

ROI の式(`roiRange`)はあるが、賭けと PR をまたいで足していないので、賭けのファイルの「ROI」の表は人が手で計算していた。PR の「動かす KPI」が賭けの KPI と合っているかも人が見るしかない。北極星(意義があると判断した物が、使う人に届いて使われた数 ÷ 人の工数)は、分母も分子も毎週出せない。

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM)と、費用と投資を見る人
- 動かす KPI: (キットの物差し: 北極星の分母と分子を毎週出せるか)

### 業務の要求

- 持ち主が、賭けごとの原価の累計(人日)・資産の候補の PR の数・ROI の幅と回収の月数を、1つのコマンドで見られる
- 持ち主が、「動かす KPI」が空か、賭けの KPI と合わない PR を一覧で見られる
- 持ち主が、北極星の分子(届いて使われた賭けの数)と分母(人の時間)を、週ごとに見られる。毎週月曜に Actions の要約にも出る

### 業務ルール

- 金額は出さない。原価は人日・時間、ROI は倍率、回収は月数 — リポジトリと Actions の要約は公開されうる(費用のページと同じ)
- 【実測】と【推定】を表の見出しで分ける。PR の数・マージした週・KPI の記録は実測、人の時間と得る物は推定 — 推定を実測のように見せない([../kit/roi.md](../kit/roi.md))
- 人の時間は費用のページと同じ式(PR × `docs/cost/people.yaml` の分)。幅の上の端は、人が答えた問い1つに5分を足す — roi.md の 2 の幅と同じ置き方
- 得る物は賭けの「- 得る物の見込み(月):」(人日相当の幅)から。rollout に入った日から数える — 届く前の得は数えない
- 「届いて使われた」は、rollout に入った後に、賭けの動かす KPI に最初の記録(`kpi.yaml` の `records`)が付いた日 — 出しただけでは使われたと言えない。記録は毎週の手順で付く
- 週は日本時間の月曜始まりで、数え終わった週だけ(今週は入れない) — 仕様 0087 の1つの時計(`todayInTokyo`・`addDays`・`mondayOf`)
- 人の名前・PR の題名・本文は出さない。出すのは PR の番号・賭けの ID・KPI の番号・数だけ — 週の数字(`metrics.yml`)と同じ

### 受け入れ条件(業務の言葉で)

- [ ] 持ち主が `pnpm kpi --roi` を流すと、賭けごとに PR の数・資産の候補の数・原価の累計(人日【推定】)・ROI の幅と回収の月数(rollout 以降で得る物の見込みがある賭け)と、ROI を出せない理由(rollout の前・得る物の見込みが無い・PR が無い)が出る
- [ ] ROI を出せた賭けを足した合計の ROI の幅と、賭けの外(土台)の PR の原価が出る
- [ ] 数え終わった週ごとに、分子(その週に届いて使われた賭けの数)・PR の数・分母(人の時間の幅)と、窓の合計・10時間あたりが出る
- [ ] 窓の中の PR で「動かす KPI」が空の物の数と番号、賭けの KPI と合わない PR が出る(ボットの PR と、KPI をまだ持たない賭けの PR は出さない)
- [ ] 毎週月曜の `metrics.yml` の要約に、同じ表が出る
- [ ] ふつうの `pnpm kpi`(CI)は、これまでどおり GitHub を読まない

### 要配慮個人情報

- 当たらない(PR の番号・賭けの ID・数だけ。利用者のデータを読まない)

### やらないこと

- 金額の ROI(時給・売上は非公開の置き場。費用のページ `pnpm cost` と `/ledger` の領分)
- PR を出すときに「動かす KPI」が合わない PR を落とすこと(一覧に出すだけ。落とすかは使ってみてから)
- キット自身の北極星の分子(外のチームに届いた数)を数えること。公開の後に、届けた外のチームの報告で数える([../kit/roadmap.md](../kit/roadmap.md) の 4)。このコマンドは、使う人のリポジトリの賭けを数える
- 賭けのファイルの「ROI」の表に自動で書くこと(表は足すだけの記録。値は人がこのコマンドから写す)

### 決めたこと

- 入口は `pnpm kpi --roi`(別のコマンドにしない) — ROI の式と KPI の記録が `pnpm kpi` の物で、package.json を触らずに済む(2026-10-29。人に聞く4つに当たらないので AI が決めた)
- 1人日 = 8時間・1か月 = 30日 — 意義の判断役の「人日の幅」と同じ単位にそろえるため。どちらも幅の見方で、細かい違いは結論を変えない(2026-10-29。AI が決めた)
- 合計の ROI は「得た物の累計(得る物(月)× 経った月数)の和」と「原価の累計の和」から `roiRange` で出す(月数 1 で渡す) — 賭けごとに経った月数が違うので、月あたりの和にはしない(2026-10-29。AI が決めた)
- 「意義があると判断した物」は賭け(`docs/product/bets/`)— 賭けは `/bet` で開くときに意義の判断役を通るため。判断の記録(verdicts)とは賭けの ID で結ばれていないので、別に数えない(2026-10-29。AI が決めた)

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 賭けの段階 \ 出す物 | 原価の累計 | ROI | 北極星の分子 |
|---|---|---|---|
| idea・cpf・psf | 出す | 出さない(rollout の前) | 数えない |
| rollout・adopted(得る物の見込みと PR がある) | 出す | 出す | rollout の後の最初の記録の週に1 |
| rollout・adopted(得る物の見込みが無い / PR が無い) | 出す | 出さない(理由を出す) | 同上 |
| dropped・retired | 出す | 出さない | 数えない |

### 境界値

- 週の境目: 日本の月曜 0〜9時(UTC では日曜)にマージした PR は、その月曜の週(`todayInTokyo(mergedAt)` → `mondayOf`)
- 今週: 数え終わっていないので出さない。窓は `mondayOf(addDays(今日, -7))` から n 週前まで
- `--weeks`: 1〜26。外れたら 1 で終わる
- 原価の累計が 0(賭けの PR が無い): ROI を出さず、理由を出す(0 で割らない)
- 人の時間が 0 の窓: 10時間あたりは「—」
- KPI の記録が rollout より前: 届いて使われたとは数えない
- PR が 1000 件を超えた: 古い PR は数えず、そう知らせる
- 「- 動かす KPI:」が注だけ: 空と数える

### 権限の組み合わせ

該当なし(API を足さない。手元か Actions で、マージした PR を読むだけ。Actions は `pull-requests: read`)

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし | — |
| 改ざん | PR の本文の「動かす KPI」を書き換えて一覧から外す | 一覧は知らせるだけで判定に使わない。本文の履歴は GitHub に残る |
| 否認 | 該当なし | — |
| 情報漏えい | 要約に PR の本文や人の名前が出る | 出すのは番号・ID・数だけ(`roi.mjs` の出力。PR の事実 `prFactOf` は名前・題名・本文を持たない) |
| 妨害 | PR が多すぎて重くなる | 1000 件で止める |
| 権限昇格 | 該当なし | — |
