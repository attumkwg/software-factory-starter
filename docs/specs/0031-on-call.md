## なぜ作るか

- 夜中に `#alerts-prod` へアラームが流れても、誰が・何分以内に見るのか、朝まで待ってよいのはどれか、が決まっていない(想定の場面の 5-5)。
- SLA の型([legal/sla.md](../legal/sla.md))は連絡の時間を「営業時間の中で数える」にしている。夜中も約束する契約を結ぶなら、当番の決まりが先に要る。

## 受け入れ条件

- [ ] `docs/guides/on-call.md` に、当番の表の役(一次・予備・上げる先)と人数の目安(3人から・週ごとの交代なら4〜5人)・交代の単位がある。表そのもの(名前・電話)はリポジトリに置かない、と書いてある
- [ ] 連絡の段(一次 → 予備 → 上げる先)と、それぞれの待ち時間がある
- [ ] 夜と休日に起こすアラームと、朝まで待つアラームが、`guides/monitoring.md` の全部のアラームについて理由つきで分かれている。起こす線は「お客さんに影響がある・約束の水準を割りそう・漏えいのおそれ」
- [ ] 当番の間は改善の作業だけ(しきい値・手順書・再発防止・点検)と書いてある
- [ ] アラームに手順書の見出しが結んであることと、アラームを足すときに手順書と夜の扱いを一緒に足す決まりがある
- [ ] 呼び出しの道具を入れる手順(委託先の台帳・知らせの道の2本をつなぐ・試す)がある
- [ ] SLA の型の項目(連絡の時間の数え方・最初の知らせ・事実の確定・例外)と、当番を置く前・後の対応の表がある
- [ ] 点検の台帳 `docs/checkup/todo.yaml` に、当番の体制を半年ごとに聞く項目が1つあり、`docs/checkup/README.md` と適用宣言書が作り直してある
- [ ] `alarms.md`・`monitoring.md`・`incident.md`・`legal/sla.md` から、この決まりを指す

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 呼び出しの道具に、当番になりすまして「受けた」を押す | 道具のアカウントは個人ごと(共有しない)。応答は Slack のスレッドにも書く |
| 改ざん | 「起こす」アラームを「朝」に書き換えて、夜の障害を見逃す | 決まりの表を変えるのは PR。アラームを足すときは表を一緒に直す |
| 否認 | 「呼ばれていない」 | 道具とSlack に呼んだ・応答した時刻が残る |
| 情報漏えい(他社のデータ) | 当番の表(名前・電話)や、道具に送るアラームの中身から個人情報が漏れる | 表はリポジトリに置かない。道具に渡すのはアラームの名前と時刻だけ(委託先の台帳に書く) |
| 妨害(重い処理・大量の要求) | アラームを大量に鳴らして当番を疲れさせ、本物を見逃させる | 鳴りすぎは当番の間の改善でしきい値を直す。起こすのは3 の表の物だけ |
| 権限昇格 | 該当なし(文書だけ) | — |
