# 仕様: 背景の AI に読ませる文章の書き手を確かめ、秘密を見せない・書かせない

> 1つの仕様 = 1つ以上の Issue。大きければ親 Issue → 子 Issue に割ってから AI に渡す。
> 状態: 下書き

## なぜ作るか

背景の AI(`.github/workflows/claude.yml`)は、起動した人が持ち主かは確かめているが、**AI が読む Issue・PR の本文やコメントの書き手は確かめていない**。外の人が Issue に指示を仕込み、持ち主が「#42 を直して」と頼むと、AI はその指示を読む。AI は Edit とテストを許されているので好きなコードを動かせ、`gh issue comment` で公開の場所に書ける。ジョブの中の Claude の API キーと GitHub のトークンが Bash から見えるかも確かめていなかった(台本 [10-ai-incidents.md](../scenarios/10-ai-incidents.md) の 10-1・穴 G-58)。

## 受け入れ条件

- [ ] 背景の AI は、頼まれた Issue・PR(手動の起動の頼む文に出てくる番号・`@claude` が付いた Issue や PR)の本文・コメント・レビュー・行のコメントの書き手が、全員書き込める人(OWNER・MEMBER・COLLABORATOR)か決めたボット(このリポジトリのワークフローが書く物)のときだけ動く。1人でも違えば、AI のジョブは動かず、誰のどの文章かと直し方を出す
- [ ] 書き手を確かめる段は、Claude の API キーと Environment を持たないジョブで流れる
- [ ] 頼む文に番号が無いときは確かめずに通す(読ませる文章は起動した人の物だけ)。番号が多すぎる(11 個以上)と動かない
- [ ] Bash・フック・MCP のサブプロセスから Claude の API キーなどの秘密が消える(Claude Code の `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB`)。Claude Code の本体の環境も、Bash から `/proc` で読めない(bubblewrap)。入らなければ AI は動かない
- [ ] AI が外へ書く文章(`gh` のコメント・PR や Issue の本文・`gh api`・MCP の書き込み)に秘密の形をした値(Anthropic・GitHub・AWS の鍵・秘密鍵・JWT・Slack)か、いまの環境の GitHub のトークン(そのままか base64)があれば、フックが止める。止めた理由に値を出さない
- [ ] AI が動いた後、その間に書かれた Issue・PR の本文とコメントを gitleaks で見て、見つかればジョブを落として鍵の差し替えを知らせる
- [ ] フックは `pnpm guards` で、書き手の確かめは `pnpm test:scripts` でテストされる

## 権限の表に足す行

該当なし(アプリの API は変えない)。

## 要配慮個人情報

- 当たらない(GitHub の Issue・PR の書き手の区分と、外へ書く文章の形だけを見る。アプリのデータに触れない)

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 外の人がボットの名前に似たアカウントで書く | ボットは `user.type === "Bot"` で、名前が決めた物だけ。人のアカウントは書き込める人かで決める(`ai-input-authors.test.mjs`) |
| 改ざん | 外の人が書いた Issue の本文に AI への指示を仕込む | 書き込めない人が書いた文章があれば AI を動かさない。持ち主が自分の言葉で書き直した Issue で頼む |
| 否認 | 誰の文章で止まったか分からない | 止まった理由に番号・種類・書き手を出す |
| 情報漏えい(他社のデータ) | 仕込まれた指示で、ジョブの中の鍵を公開のコメントに貼る | サブプロセスから API キーを消す・外へ書く文章の秘密の形をフックで止める・動いた後に gitleaks で見る・GitHub のトークンはジョブの間だけ |
| 妨害(重い処理・大量の要求) | 頼む文に番号を大量に並べて API を連打させる | 1回 10 個まで・前の段は5分で打ち切り |
| 権限昇格 | 前の段から秘密や書く権限を得る | 前の段は読むだけ(`contents`・`issues`・`pull-requests` の read)で Environment を持たない |

## やらないこと

- AI が動いている間に、頼まれていない番号の Issue・PR を読むのを機械で止める(`gh issue view` は番号で絞れない。頼む文で「読まない」と伝えるだけ。わざと残る穴)
- GitHub のトークンを Bash から消す(`gh` とブランチへの送り出しに要る。権限は `permissions` とジョブの長さで絞る)
- 書き手を確かめた後に付いたコメントを読ませない(確かめから AI が読むまでの短い間。わざと残る穴)
- 外の人の Issue を AI が要約して書き直す(要約する AI が指示を読む。書き直すのは人)
