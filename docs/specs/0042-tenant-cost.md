# 仕様: 1社あたりの原価(組織の大きさの帯ごとの按分)

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。会話で: 設計書の U-1 を「既定として承認」。帯の区切りは使う人が導入時に決める)
> 設計: [docs/designs/0042-tenant-cost.md](../designs/0042-tenant-cost.md)・ADR: [0053](../adr/0053-tenant-cost-by-size-bands.md)
> 穴 G-10(場面 4-5・7-5)。費用のページ(仕様 0019・0020)と利用の記録(仕様 0012・0022)の上に積む。

## なぜ作るか

- 「小さいお客さんは月 4,980円で赤字にならないか」「大きいお客さん1社のために DB を分けるか」を決める根拠が無い。費用のページは賭けごと・動いている物ごとで、組織ごとの数が無い([concepts/stages.md](../concepts/stages.md) の 4 は「1社あたりの原価も出す」と書いているが、出す仕組みが無い)。
- 組織ごとの費用をそのまま出すと、どの組織がいくらかが分かる(組織の ID と金額が結びつく)。値決めに要るのは「どの大きさの組織が、1社あたりいくらか」と「いちばん大きい組織がどれだけ占めるか」まで。

## 受け入れ条件

> 「誰が・何をすると・どうなる」。どのテストかは設計書の「7. 要求との対応」。

数える(運営):

- [ ] 運営が `tenant-shares --month YYYY-MM` を流すと、組織ごとに「人数・データの行の数・その月の人の書き込みの数」を数え、**組織の大きさ(人数)の帯ごとの合計**と、**いちばん大きい組織が全体の何 %**(元ごと)だけを JSON で出す。月を省くと前の月
- [ ] 出力に組織の ID・名前・人の ID は無い。運営の組織は数えない。要配慮の表(スキーマ `sensitive`)は数えない
- [ ] 書き込みは、その月の監査ログのうち人(と代理ログインの社員)の許された操作だけ(仕組みの記録・断られた操作は数えない)
- [ ] 組織の数が少ない帯には、少ないことの印(`small`)が付く(継続率と同じ。5組織未満)

見る(費用のページ):

- [ ] 人が出力の1行目を非公開の置き場(`cost/inputs/tenants.json`)に置くと、費用のページに「1社あたりの原価」の表が出る: 帯ごとの組織の数と1社あたり(月)・全体の平均・いちばん大きい組織
- [ ] 按分するのは、元の月の本番の AWS(過ぎた月は Cost Explorer の実績・今月なら月末の見込み)。1社あたりは、3つの元(人数・行の数・書き込み)の割合で按分した値の**下と上**の幅
- [ ] 置き場に元が無い・元の月の本番の AWS が読めないときは、表を出さず「読めなかった物・足りない物」に書く(0円として隠さない)
- [ ] ページに組織の名前・ID は出ない

## 権限の表に足す行

API は足さない(権限の表に足す行は無い)。数えるのは運営のコマンド(`node dist/cli.js tenant-shares`)だけ。費用のページは今までどおり非公開の S3 だけ。

## 要配慮個人情報

- 新しく取る項目は無い。読むのは今ある表の行の数・人の数・監査ログの件数だけで、出すのは帯ごとの合計。要配慮の表は数えない(件数も渡さない決まり。`docs/security.md` の AI-6)。

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | お客さんが数を流す | 運営のコマンドだけ(API が無い)。表の持ち主の接続で、ECS の運営の手順でだけ |
| 改ざん | 置き場の `tenants.json` を書き換えて、1社あたりを小さく見せる | 置き場に書けるのは人の役割だけ(費用のページの入力と同じ。ADR 0032)。ページに元の月と組織の数を出す |
| 否認 | 「その原価はどう出したか」と言われる | 元の月・3つの元・按分した金額と実績か見込みかを、ページに出す |
| 情報漏えい | 出力やページから、どの組織がいくらかが分かる | 出すのは帯ごとの合計といちばん大きい組織の割合だけ(結合テストが ID の無いことを確かめる)。小さい帯に印。ページは非公開の S3 だけ |
| 妨害(重い処理) | 組織や行が増えて、数えるのが重くなる | 組織ごとに表ごとの `count(*)`(`tenant_id` の索引)。月1回・人が流す。時間がかかるようになったら見直す(設計書の 8) |
| 権限昇格 | 該当なし(新しい入口が無い) | — |

## やらないこと

- 組織ごとの金額の一覧(組織の ID と金額を結びつけない)。
- 人の時間(サポート・導入の手伝い)・SaaS・stg を1社あたりに入れること(未確定事項 U-1)。
- 料金のプランと1社あたりの原価の自動の比べ(値段は人が決める)。
- リクエストの数(ALB・ログ)からの按分(読むのに AWS の別の権限が要る。書き込みの数で代える)。
- 1社を足したときに増える分(限界の原価)の計算。

## 決めたこと

- G-10 の中身(費用のページに組織ごとの按分・利用の記録・データ量・リクエストの数の割合など・組織の ID は出さない・小さい組の扱いは G-28 と同じ考え方)は、親のセッションの依頼(2026-10-25)のとおり。
