> 状態: 完了(実装済み。未確定事項 U-1・U-2 は @attumkwg が 2026-10-28 に会話で選んだ。設計書の状態は PR のコメントで出どころを残してから)
> 設計: [docs/designs/0079-member-admin.md](../designs/0079-member-admin.md)
> 穴 G-103(`docs/scenarios/gaps.md`)。招待(仕様 0027)・強制ログアウトと SCIM(仕様 0056)・プラン(仕様 0047)の上に積む。

## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

お客さんの管理者が、辞めた職人を外す・ロールを変える道が無い。止められるのは情シスの道具(SCIM。大きなお客さんだけ)からだけで、A 社のような小さな会社は CS に頼むしかなく、CS は本番の DB を触るしかない(台本 18-2)。外せない人は契約の人数に数え続けられ、ログインもでき続ける。

### 業務の要求

- 組織の管理者が、辞めた人を「止める」(外す)。止めた人はログインできず、契約の人数にも数えない
- 組織の管理者が、止めた人を「戻す」(出戻り・間違えて止めた)
- 組織の管理者が、人のロール(管理者・メンバー・閲覧者)を変える

### 業務ルール

- 外す = 止める。人の行・作ったプロジェクト・タスク・写真・監査ログは残し、あとで戻せる(未確定 U-1) — 作った物の持ち主と「誰が何をしたか」が分からなくならないように。1人分のデータを本当に消すのは本人からの求めに応じる別の手順(運営の person-data・G-06)
- 情シスの道具が扱う人も、画面から止める・戻す・ロールを変えられる(未確定 U-2) — 退職の当日に、道具の同期を待たずに止められるように
- 自分のロール・有効かは自分では変えられない — 自分を締め出して、組織に管理者がいなくなるのを防ぐ
- 止めた人を戻すとき、契約の人数の上限は見ない — 人数の上限で止めない決まり(仕様 0047)とそろえる

### 受け入れ条件(業務の言葉で)

- [ ] 管理者は「設定」→「組織の人」で、人を止められる。止めた人は、開いている端末でも次の操作から入れず、もうログインもできない
- [ ] 止めた人は契約の人数(「招待」の画面の人数)に数えない。戻すと、また数える
- [ ] 止めた人の作ったプロジェクト・タスク・写真はそのまま残り、ほかの人が使い続けられる
- [ ] 止めた人には、タスクの完了・規約の変更などのメールを送らない
- [ ] 管理者は止めた人を戻せる。戻した人は前のロールで入れる
- [ ] 管理者は人のロールを変えられる。変えたロールは、その人の次の操作から効く
- [ ] 一覧に、止めた人と情シスの道具で管理している人が分かる印が出る
- [ ] 止める・戻す・ロールを変えたことが監査ログに残る
- [ ] 管理者は自分を止められない・自分のロールを変えられない(ほかの管理者に頼む)

### 要配慮個人情報

- 当たらない(人の名前・メール・ロール・止めた時刻)。

### やらないこと

- 1人分のデータを消す(G-06 の残り。運営の person-data)
- 止めた人の作った物を、ほかの人に付け替える(作った人の名前はそのまま出る)
- 人数の上限で、戻す・招くを止める(仕様 0047 のとおり止めない)
- 止めた人が持っていた招待(その人が出した、受けていない招待)を取り消す(管理者が「招待」で取り消せる)

### 決めたこと

- 外す = 止める(U-1)・情シスの道具の人も画面で変えられる(U-2)は、@attumkwg が 2026-10-28 に会話で選んだ(どちらもおすすめの案)。

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 状態 \ 操作 | 止める | 戻す | ロールを変える | 強制ログアウト |
|---|---|---|---|---|
| 使える(自分以外) | できる(セッションも切る) | 何もしない(200) | できる | できる |
| 止めた(自分以外) | 何もしない(200) | できる | できる(戻すとそのロール) | 画面に出さない(API は 204) |
| 自分 | 409 cannot_change_yourself | 409 | 409 | 画面に出さない |
| 最後の緊急用の管理者(SSO を必須にしている間) | 409 last_sso_exempt | — | 管理者から外すと 409 | できる |

### 境界値

- 有効な管理者: 操作する管理者は対象と別の有効な管理者なので、変えた後も1人は残る。2人の管理者が同時にお互いを外すと、後の方は 403(有効な管理者の行をロックしてから、自分がまだ有効な管理者かを見直す)
- 止めた管理者は「有効な管理者」に数えない
- 同じロールへの変更・止めた人を止める・使える人を戻すは、何も変えずに 200(監査ログには残る)
- 緊急用の管理者: 管理者から外す・止めると、緊急用からも外れる。SSO を必須にしていて、ほかに有効な緊急用の管理者がいなければ 409
- 戻した人は緊急用には戻らない(管理者が「SSO」の設定で選び直す)

### 権限の組み合わせ

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `PUT /api/organization/members/{memberId}/role` | 200 | 403 | 403 | 404 | 401 |
| `POST /api/organization/members/{memberId}/disable` | 200 | 403 | 403 | 404 | 401 |
| `POST /api/organization/members/{memberId}/enable` | 200 | 403 | 403 | 404 | 401 |

- [ ] メンバー・閲覧者・代理の社員(閲覧者)は、止める・戻す・ロールを変えるができない(403)
- [ ] 他社の人は止められない・戻せない・ロールを変えられない(404)。一覧にも出ない

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 止めた人が、止める前のセッション・ほかの端末で使い続ける | 止めると sessions_valid_after も今にし、関所が毎回 disabled_at を見る(401)。ログインの所属にも出ない。結合テスト |
| 改ざん | 他社の人の ID を指定して止める・ロールを変える | 行は組織の中だけ(RLS と tenant_id の条件)。404。権限の表 |
| 否認 | 「止めていない」「管理者にしていない」 | member.disable・member.enable・member.role_change が監査ログに残る(変えた先のロールは details に入れない) |
| 情報漏えい(他社のデータ) | 一覧で他社の人が見える | 一覧は組織の中だけ。結合テスト |
| 妨害 | 管理者同士で外し合い、管理者が0人になる | 自分は変えられない・有効な管理者の行をロックして見直す(後の方は 403)。結合テスト |
| 妨害 | SSO を必須にした組織で、最後の緊急用の管理者を外し、IdP が止まると誰も入れない | 409 last_sso_exempt。結合テスト |
| 権限昇格 | メンバーが自分を管理者にする | ロールを変えられるのは管理者だけ(権限の表)・自分は変えられない。DB はアプリの接続にロールの書き換えを許すが、行は組織の中だけ |
