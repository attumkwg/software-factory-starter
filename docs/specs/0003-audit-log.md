# 仕様: 監査ログ(誰が・いつ・何をしたか)

> 状態: 承認済み(承認した人: @attumkwg。2026-10-18 の選択「DB の表・お客さんの管理者が画面で見られる」)

## なぜ作るか

お客さんの管理者が「誰がこのプロジェクトを消したか」「いつ誰が入ったか」を自分で確かめられるようにする。運営にとっても、障害・事故・問い合わせのときに「何が起きたか」の正になる。後から入れる**代理ログイン(社員がお客さんの画面を見る)**と**解約**の記録の置き場でもある(docs/security.md の AZ-6「大事な操作は監査ログ」・T-7「お客さんからも見える監査ログ」)。

## 受け入れ条件

- [ ] 自社の人が**書き込み**(プロジェクトを作る・消す/タスクを作る・直す・消す)をすると、監査ログに1行残る: 時刻・誰が・何を・どれに・許可された
- [ ] 書き込みが失敗した(入力の誤り・同時の変更・こちらのバグ)ときは残らない(起きていないことは記録しない)
- [ ] 権限が無くて断られた書き込み(403)も「拒否された」として残る
- [ ] ログインとログアウトが残る(ログインに失敗した記録は会社に結びつけられないので、監査ログには残さずアプリのログだけ)
- [ ] タスクを直したときは、どの項目を直したか(項目の名前だけ。値は残さない)
- [ ] 管理者は画面「監査ログ」で、自社の記録を新しい順に見られる(50件ずつ、続きを読める)
- [ ] メンバーと閲覧者は見られない(403)。画面のリンクも出ない
- [ ] 他社の記録は見えない(RLS。API は自社の分しか返さない)
- [ ] 記録は**足すだけ**: アプリの接続ユーザーは直す・消すができない。表の持ち主でも、決まった手順(解約・保存期間の削除)の外では直す・消すができない
- [ ] 新しい書き込みの API を足したのに、監査ログの名前を決めていなければ CI が落ちる

## 権限の表に足す行

| API | admin | member | viewer | 他社 | 未ログイン |
|---|---|---|---|---|---|
| `GET /api/audit-events` | 200 | 403 | 403 | 200(自社の分だけ) | 401 |

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 誰がやったかを書き換えて残す | 誰が(actor)はセッションから決める。リクエストの値は使わない |
| 改ざん | 都合の悪い記録を消す・直す | アプリの接続ユーザーは INSERT と SELECT だけ。UPDATE は常に・DELETE は決まった手順の外では、トリガーが止める(結合テスト) |
| 否認 | 「消していない」と言い張る | 書き込みと同じトランザクションで記録する(書き込みだけ成功して記録が無い、が起きない) |
| 情報漏えい(他社のデータ) | 他社の記録を読む | RLS(tenant_isolation)と、API の自社の絞り込み。結合テスト「他社の記録は見えない」 |
| 情報漏えい(中身) | 記録から、お客さんの入力(題名・本文)が漏れる | 記録するのは ID と項目の名前だけ。値は入れない |
| 妨害(重い処理・大量の要求) | 監査ログの一覧を何度も読んで DB を重くする | 1回 最大100件・(tenant_id, 時刻) の索引 |
| 権限昇格 | メンバーが監査ログを見る | 権限 `audit:read` は admin だけ(権限の表のテスト) |

## やらないこと

- 読んだことの記録(一覧や1件を見た)。量が多く、PMF の前は書き込みだけで足りる。**ただし代理ログインの社員は、読んだことも残す**(次の PR)
- 消せない S3 への写し(PMF 後。docs/concepts/running.md の「ログの種類と置き場所」の「別アカウントの S3」)
- 保存期間を過ぎた記録の削除(解約の PR で、削除の手順と一緒に)
- 絞り込み・検索・書き出し(CSV)
- 接続元の IP アドレス(個人の情報になる。要るようになったら、保存期間と一緒に決める)

## 決めたこと・人に判断してほしいこと

- 記録は API の「認可の関所」(`src/authz/middleware.ts`)で自動に取る。書き込みの API ごとに名前(`project.create` など)を `src/audit/actions.ts` に決め、無ければ CI が落ちる(書き忘れを仕組みで防ぐ)。
- 表は共通の仕組みとしてスキーマ `platform` に置く(アウトボックスと同じ)。ADR 0013。
