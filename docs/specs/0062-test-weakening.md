# 仕様: テストと検査を弱めた変更を人の目に出す

> 1つの仕様 = 1つ以上の Issue。大きければ親 Issue → 子 Issue に割ってから AI に渡す。
> 状態: 完了待ち(作り終えて main に入っている・穴 G-60 は済み。「完了」にするのは持ち主。2026-10-28 の整合の直しで「下書き」のままと分かった)

## なぜ作るか

CI を緑にしようとした AI が、落ちたテストに `skip` を付け、カバレッジの下限を少し下げて通すことがある。カバレッジの下限(`vitest.config.ts`)・lint の設定(`biome.json`)・移行の検査の設定(`.squawk.toml`)・E2E の設定(`playwright.config.ts`)は守る一覧に無く危険度「中」で、1人の間は人の承認なしに入りうる。テストを消した・`skip` を足した・確かめが減った、を PR に出す仕組みも無い(台本 [10-ai-incidents.md](../scenarios/10-ai-incidents.md) の 10-3・穴 G-60)。

## 受け入れ条件

- [ ] `apps/api/vitest.config.ts`・`packages/*/vitest.config.ts`(カバレッジの下限)・`biome.json`・`apps/api/.squawk.toml`・`apps/web/playwright.config.ts`・`apps/web/playwright.vrt.config.ts` は危険度「高」(守る一覧・labeler・CODEOWNERS がそろう。`pnpm guards`)
- [ ] PR で、テストのファイルを消した(かテストでない名前にした)・`skip`/`only`/`todo` などを足した・`expect`/`assert` が減った・カバレッジの下限を下げたか外した・検査を黙らせる注釈(`biome-ignore`・`@ts-ignore`・`nosemgrep` など)を足した、のどれかがあれば、ラベル `tests:weakened` が付き、どこを何で見つけたかがジョブの要約に出る
- [ ] 見つからなくなったら(直して push した)ラベルが外れる
- [ ] `tests:weakened` の付いた PR は危険度「高」とみなし、人の承認の人数(`ruleset.high_risk_approvals`)を数える
- [ ] 見つける中身は土台のブランチの物で流す(PR の中で緩めても効かない)。スクリプトは危険度「高」
- [ ] 差分が大きくて読めないテスト・設定は「読めない差分」として印を付ける

該当なし(アプリの API は変えない)。

## 要配慮個人情報

- 当たらない(PR の差分の形だけを見る)

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし | — |
| 改ざん | PR の中で見つけるスクリプトを緩める・設定を「中」のまま書き換える | 土台のブランチの物で流す・スクリプトと設定は「高」 |
| 否認 | 何を弱めたか後から分からない | ラベルとジョブの要約にファイルと理由を出す |
| 情報漏えい(他社のデータ) | 該当なし | 読むのは PR の差分だけ |
| 妨害(重い処理・大量の要求) | 巨大な差分で重くする | GitHub の差分の上限で切れる(読めない差分は印を付けて人へ)・5分で打ち切り |
| 権限昇格 | ラベルを付ける権限で PR のコードを動かす | 書く権限のジョブは checkout しない・フォークの PR では付けない |

## やらないこと

- 弱めた変更を止める(落とす)。理由のある変更(古いテストを消す・不安定な E2E を一時的に飛ばす)もあるので、印を付けて人が見る
- 期待値の書き換え(`toBe(1)` → `toBe(2)`)・例外を握りつぶす `try/catch` を見つける(形では見分けにくい。人のレビューと `/review-pr`)
- AI が書いた PR だけに絞る(人の PR も同じに見る)
