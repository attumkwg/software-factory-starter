## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM・代表)
- 動かす KPI: (キットの物差し: 1件の依頼で人が呼ばれる回数・1件の依頼の時間)

合議(仕様 0082)は、7つの立場をそろえ、1人ずつ別の AI → 反論役 → 議論の回 → 議長、を回すまで先へ進めなかった。持ち主: 「重くなりすぎ。この遅さだと判断の参考ぐらいにしかならない」。2026-10-29 の合議で本当に効いた指摘は、反論役1人から出た。一方で、「これは意義があるからやる / やらない」を言い切る役がいない。熱意だけで何にでも意義を見つけると、意義の無い物を速く作ることになる。工場の使命は「**意義のあることを、意味の分からない速さで実現する**」。

### 業務の要求

- 合議は判断の参考にし、必須の関所にしない。既定は反論役1人の軽い形
- アイデア・大きな依頼を PR に分ける前・受け入れの3つの場面で、「意義があるから、やる / やらない / 条件つき」を短く言い切る役がいる
- その判断が賛成係にならず、ROI の根拠を持ち、後で当たったかを確かめられる
- 1件の依頼で人に聞く問いは、多くて2つ

### 業務ルール

- やる・条件つきは、誰の・どんな困りごとが・どれだけ減るかを数で言う。言えなければ「やらない」 — 熱意で何にでも意義を見つける賛成係にしない
- やる・条件つきには ROI の見込み(費用と得る物の幅・倍率と回収の月数)と止める線を付け、ROI は式で出す(手で上げない)。金額は書かない — ソフトウェアは ROI でしか測れない。リポジトリは公開されうる
- 判断は記録に残し、期限の後に実測と比べる。判断役もセンサーなので、正しかったかは人が判定する — 人が見るのはセンサーが正しいかと、人が決める所だけ(持ち主の原則)
- 判断役は PR 1本ずつには呼ばない — 重くなる
- 守り(脆弱性・分離・個人データ・CI)を削る案を、意義で正当化しない — 熱意があるから守りもちゃんとしたい

### 受け入れ条件(業務の言葉で)

- [x] `pnpm kpi` が、7つの立場のそろい・合議の出席の立場を知らせるだけにし、落とさない
- [x] 合議の記録に「軽い形」(`- 形: 軽い`)があり、反論役・結論の案・問い・人の判断だけで通る。`/council` の既定が軽い形になっている
- [x] 意義の判断役(`.claude/agents/purpose-judge.md`)があり、`/bet`(開くとき)・`/new-feature`(分解の前)・`/accept`・`/slack-request`(大きな依頼)から呼ばれる。キット自身の判断(`docs/kit/verdicts/`)にも使える
- [x] 判断の記録(`docs/product/verdicts/`)で、やる・条件つきなのに意義に数が無い・ROI の根拠が無い・ROI を手で上げた・止める線が無い・問いが2つ以上、のどれかなら `pnpm kpi` が落ちる
- [x] 期限の後、`pnpm kpi` が判断ごとの当たり・外れ・測っていないと判断役の当たり率を出し、人の判定を待つ記録を知らせる。外れが半分を超えたら物差しの見直しをすすめる
- [x] 「確か」の KPI は、合議か意義の判断の記録から来ていればよい
- [x] `/new-feature`・`/slack-request` に「1件の依頼で人に聞く問いは多くて2つ」がある

### 要配慮個人情報

- 当たらない。

### やらないこと

- 判断役を PR 1本ずつに付ける・CI で毎回呼ぶ(重くなる)
- 全員の形の合議を消す(KPI を最初に決めるときと、人が頼んだときに使う)
- 人が呼ばれた回数を自動で数える(足りない物 2 の判断待ちの積み場と、`pnpm metrics` で)

### 決めたこと

- 意義の判断役を、工場の 3(重さを削る)に入れる。歯止めの3つ(やらない線・ROI の根拠・当たり外れの記録)も入れる(@attumkwg 2026-10-29。会話で回答)
- 合議は判断の参考。残すのは任意の反論役1人(@attumkwg 2026-10-29。会話で回答)
- 人に端的に聞く問いは、1件の依頼で多くても2問(@attumkwg 2026-10-29。会話で回答)
- (AI が決めた)判断役の「当たり」は、見込みの幅の中か良い向きの外(やると言った物が見込みより良く動いたら、判断は正しかった)。KPI の向き(`target.direction`)に合わせる
- (AI が決めた)費用と得る物は人日の幅で書く(金額を書かずに ROI の倍率と回収の月数を出すため)
- (AI が決めた)判断役の定義は `.claude/` の下なので、変える PR は AI がマージしない(`scripts/pr-merge-lib.mjs` の守りの場所)→ 2026-10-29 の仕様 0085 で、1人の間は持ち主の会話の答えを PR に残してマージする形に変わった

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 状態 \ 操作 | `pnpm kpi` |
|---|---|
| 客層ごとに7つの立場がそろわない・全員の合議に足りない立場がある | 知らせる |
| 軽い形の合議に反論役・結論の案・問い・人の判断の見出しが無い・反論役が空 | 落ちる |
| 判断の記録: 日付・場面・判断・意義・人の判定の書き方の誤り・問いが2つ以上 | 落ちる |
| やる・条件つきで、意義に数が無い・KPI が無い(K- なのに木に無い)・見込みの幅と期限が無い・ROI の根拠が無い・ROI が式と違う・止める線が無い | 落ちる |
| やらない(数・ROI が無い) | 通す |
| 期限の前 / 期限の後で実測あり / 実測なし | まだ / 当たり・外れ / 測っていない |
| 期限を過ぎて人の判定が「未定」 | 知らせる |
| kpi.yaml が無い | キット自身の判断の記録だけを見る |

### 境界値

- 当たり: 多いほど良い指標は実測 ≧ 幅の下の端、少ないほど良い指標は実測 ≦ 幅の上の端
- 実測: 記録の「- 実測:」を先に。無ければ期限の日までの最後の `records`
- 当たり率: 確かめられた判断が2つ以上で、半分未満なら見直し
- ROI: 小数1桁。得る物が 0 なら回収は「回収しない」

### 権限の組み合わせ

- 該当なし(アプリの API は変えない)

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |

| 改ざん | ROI の見込みを手で上げて、意義があるように見せる | 式で出した値と違うと落ちる(`verdict.test.mjs`) |
| 改ざん | 判断役の定義の歯止めを弱める | `.claude/**` に触る PR は AI がマージしない(`pr-merge-lib.mjs`。→ 仕様 0085 で、1人の間は会話の答えを PR に残してから) |

| 情報漏えい | ROI のために金額を書く | 型と手引きで人日の幅だけ |
| なりすまし・妨害・権限昇格 | 該当なし | — |
