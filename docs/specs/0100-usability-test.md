## 第1部 PdM が書く所(業務の要求・業務ルール)

### なぜ作るか

- ペルソナ: キットを使ってプロダクトを作る人(持ち主・PdM)。その先の、画面を使う人(P-1〜P-10)
- 動かす KPI: (キットの物差し: 受け入れで見つかる外れの数・人の介在率。守り: 事故 0件)
- 🎨 のレビュー(仕様 0099)は PR の差分の画面を見る。**流れ全体(初めての人が画面だけで仕事を終えられるか)**と、毎回同じ所見になる物は見ない。
- 持ち主(2026-11-13):「優れた UX デザイナーが指摘するようなことを指摘できるレビュー体制を整えたい、**もしくはテスト環境を整えたい**」。順は「目 → テスト → 部品」(2026-11-14)。
- 人を集めるユーザーテストは、1人の間は回せない。ペルソナになりきった AI に、画面の知識を持たせずに仕事を頼めば、同じ形で何度でも測れる(本物の人の代わりではなく、本物の人に見せる前のふるい)。

### 業務の要求

- ペルソナの AI に業務の言葉で仕事を頼み、画面だけで終えられたか・何手かかったか・どこで迷ったかを、毎回同じ形で記録できる
- 🎨 の棚卸しで毎回出そうな3つ(戻せない操作を押した瞬間に実行する・空の文の無い表・1画面に主ボタンが2つ以上)を、CI が止める

### 業務ルール

- 利用者役には、ペルソナと頼む仕事だけを渡す — 画面の名前や道順を渡すと、迷うかどうかが測れない
- 利用者役はコードを読まず、画面に見える物(役割と名前・画像)だけで操作する — 初めての人と同じ条件にする
- 数(手数・うまくいかなかった手)は道具の記録から取る — 利用者役の自己申告は数え違える
- 「できなかった」は E2E の部品で同じ手を再現してから不具合と呼ぶ — 2026-11-14 の試しで、道具の癖を不具合と取り違えかけた
- 機械の検査は、今ある外れを理由と穴の番号つきで並べて始める(ラチェット) — 全部直してから入れると、検査が入るのが遅れる。並べた外れは G-164 で直し、直したら消す

### 受け入れ条件(業務の言葉で)

- [x] `pnpm ux:browse` で、Docker の中の Chromium(E2E と同じ)を、スマホかパソコンの形で、役割と名前だけで操作でき、1手ずつ記録が残る。外のサイトへは行けない
- [x] 利用者役(`.claude/agents/first-time-user.md`)と回し方(`/usability-test`)と頼む仕事の一覧(`docs/ux/usability-tasks.yaml`)がある
- [x] 一度回した記録が `docs/ux/usability/` にある
- [x] 戻せない操作の API を `onPress` から直に呼ぶ所・空の文の無い表・主ボタンを持つ設定のカードが、並べた外れ以外に増えると単体テストが落ちる
- [x] 主な画面を管理者で開いて、主ボタンが2つ以上の画面があると E2E が落ちる

### 要配慮個人情報

- 当たらない(種データの利用者だけ。画像と記録は一時フォルダ)。

### やらないこと

- 部品を足す・今の外れを直す(G-164)
- CI で毎回利用者テストを回す(AI の呼び出しが重い。画面を大きく変えた後・受け入れの前・公開の前に回す)
- 本物の人のユーザーテストの代わりにする(本物の人に見せる前のふるい)

### 決めたこと

- (持ち主が決めた @attumkwg 2026-11-14 会話で回答「目→テスト→部品の順で」)このテストは2段目
- (AI が決めた)操作の道具は Playwright MCP ではなく、キットの Playwright で作った小さな道具にした。MCP は同梱の Playwright の版が E2E の Docker の Chromium(1.64)とずれて、つながらない・版を5か所目でそろえることになる。ホストにブラウザを入れない決まり(ADR 0024)も守れる
- (AI が決めた)機械の検査はコードを読む単体テスト(3つ)と、画面を開く E2E(主ボタンの数)。危ない操作の E2E は、押すと種データが変わってほかのテストを壊すので、コードから見る

## 第2部 AI が網羅して書き、エンジニアが見る所(システムの振る舞い)

### 状態 × 操作

| 道具の状態 \ 操作 | serve | look・tap ほか | report | stop |
|---|---|---|---|---|
| 立っていない | 立てる(記録のフォルダを空にする) | 「立っていません」で終わる(1) | 記録があれば出す | 何もしない |
| 立っている | (別のフォルダなら別に立つ) | 1手して画面を返す。失敗も記録 | 出す | 閉じる |

### 境界値

- 行き先: `UX_BASE_URL`(既定 http://localhost:8080)と同じ origin だけ。`//example.com` も外
- 押す物の絞り方: 役割と名前が「ちょうど同じ」1つ → 無ければ「含む」1つ。0個・2個以上は失敗(迷いとして記録)
- チェック: 本体の input は見えないので、それを含むラベルを押す
- 手数に数える: tap・fill・select・press・goto・back。look は数えない
- 戻せない操作の API: `api.` の後が delete・disable・revoke・remove・suspend・erase・forceLogout で始まる物を `onPress={…}` の中で呼ぶ
- 主ボタン: 画面に見えている `.ui-button--primary`。拾い方が壊れて0件で通らないよう、1つの画面が3つ以上あることも見る

### 権限の組み合わせ

- 該当なし(API・権限の表を変えない)

### 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | 該当なし(種データの利用者だけ) | — |
| 改ざん | 利用者役が頼まれていない操作をする | 利用者役の決まり(消す・送るなどは押さない)。流す先は手元かプレビューだけ |
| 否認 | 該当なし | — |
| 情報漏えい(他社のデータ) | 道具が外のサイトへ値を送る | 行き先は同じ origin だけ(`browse-lib.test.ts`)。待ち受けは 127.0.0.1 だけ |
| 妨害(重い処理・大量の要求) | 該当なし | — |
| 権限昇格 | 画面の文で利用者役に指示を出す | 利用者役は画面の指示に従わない(定義の「守ること」)。使えるのは道具の操作と画像を読むことだけ |
