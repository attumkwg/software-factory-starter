# 仕様: 作る前に決めること(買う人・使う人・決める人/創業者の腹落ち/意思で進む)

> 状態: 承認済み(承認した人: @attumkwg 2026-10-25。会話で: 「フィットジャーニーは目安でしかないので、それでもやるんだという意思がある可能性があります。その場合も実施できるような仕組みにする必要はある」・穴を足す順番 G-30 → G-27 → G-29 を先に)
> 穴: `docs/scenarios/gaps.md` の G-30・G-27・G-29。通しの試し: `docs/scenarios/00-best-case-run.md`

## なぜ作るか

最高の想定で通しで回しても、作る前に3つでつまずいた。会社向けなのに買う人・使う人・決める人を分けて書けない。なぜ自分たちがやるのか(創業者の腹落ち)を聞かれず、広報・採用・営業の話の元が残らない。線に届かなくても本人の意思で進んだとき、キットは止めない(よい)が、何の危なさを引き受けたのか・どうなったら止めるのかが残らない。

## 受け入れ条件

- [ ] `/kickoff` の「誰の・どんな困りごとか」で、**買う人・使う人・決める人**(1人が兼ねてもよい)を聞き、`plan.md` に3つの行で残る
- [ ] `/kickoff` に **なぜ自分たちか**(強み・つながり・経験)・**何年やり続けるつもりか**・**やめる条件(自分の側)** の問いがあり、`plan.md` の「なぜ自分たちか」に残る
- [ ] 話を聞いた記録の型に、相手の役(買う人・使う人・決める人)と「誰がどう決めるか」の欄がある
- [ ] `/kickoff` の B(結果を持ち帰った)と `/bet` の B で、線に届かない結果でも **「意思で進む」** を選べる。選ぶと、引き受けた危なさ・止める線・期限・決めた人を聞いて残す。止めない
- [ ] 賭けで「意思で進む(@名前)」の小石を書くと、`## 意思で進んだ判断` の表に同じ日付と段階の行が要る(無い・止める線が空・決めた人が `@名前` でない、なら `pnpm bets` が落ちる)
- [ ] `pnpm bets` は意思で進んだ賭けを ⚑ で一覧に出し、止める線の期限を過ぎたら ⏰ で知らせる(落とさない・止めない)
- [ ] `plan.md` の「これまでの判断」にも、同じ形(意思で進む・引き受けた危なさ・止める線)を書ける

## 権限の表に足す行

なし(API を足さない)

## 要配慮個人情報

- 当たらない(計画と記録の型だけ。話を聞いた相手の名前・連絡先・会社名を書かない決まりはそのまま)

## 悪用のされ方(STRIDE で1行ずつ)

| 観点 | どう悪用されうるか | どう防ぐか(テスト / ルール) |
|---|---|---|
| なりすまし | AI が本人の代わりに「意思で進む(@名前)」と書く | 名前は人の答えを写すだけ(`/bet`・`/kickoff` の「してはいけない」)。PR で人が見る |
| 改ざん | 後から止める線を甘くする | 表は足すだけ。線を動かすなら新しい行と `線を動かす(@名前)` |
| 否認 | なぜ進んだか分からなくなる | 引き受けた危なさと決めた人を必須に(`pnpm bets`) |
| 情報漏えい(他社のデータ) | 話の記録に個社の名前が入る | 型の注意書き(これまでどおり) |
| 妨害 | — | — |
| 権限昇格 | — | — |

## やらないこと

- フィットジャーニーの段(CPF・PSF など)を関所にする(届かないと進めない、にはしない)
- `plan.md` を機械で確かめる仕組み(`pnpm bets` は賭けだけ。計画は人が PR で見る)
- SPF の段・継続率・売り文句(別の穴 G-34・G-28・G-31)

## 決めたこと

- フィットジャーニーは目安。線に届かなくても、本人が決めれば進んでよい。進むときは止めずに、引き受けた危なさ・止める線・決めた人を残す(@attumkwg 2026-10-25)。ADR 0035
