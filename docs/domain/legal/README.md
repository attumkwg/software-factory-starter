# 領域: 規約と同意(legal)

> 利用規約・プライバシーポリシーの版と、誰が・どの版に同意したかを持つ領域(docs/specs/0009-legal-consent.md・ADR 0022)。

## エンティティ

| もの | 置き場所 | 持っていること |
|---|---|---|
| 文書の版 | `@app/shared` の `LEGAL_VERSIONS`(本文は `apps/web/src/legal/<文書>/v<版>.md`) | 種類(利用規約・プライバシーポリシー)・版・公開と効力の日時・変更の要約・同意し直しが要るか・本文の sha256 |
| 同意 | `legal.consents` | 誰が・どの文書の・どの版に・いつ・どの画面から(登録 / 同意の画面)・組織としてか本人としてか |
| お知らせ | `legal.notices` | 誰に・どの版の変更のメールを送ると決めたか(周知の証拠・2回送らない) |

## 状態

- 文書の版: 公開前 → 予告中(公開 〜 効力。帯が出る・前もって同意できる・お知らせを送れる)→ 効いている → 古い版(次の版が効いた)。版は PR で足すだけ。公開した版の本文は変えない。
- 利用者と版: 同意していない → 同意した(戻せない。撤回の操作は無い)。効いている「同意し直し」の版に同意していない間は**同意待ち**。

## 守るルール

1. **同意待ちの人は、同意の画面に要る API(自分・同意する)とログアウトしか使えない**(関所が 403 `terms_acceptance_required`)。二段階認証の設定待ちとの両方にかかる人は、同意 → 設定の順に回す。
2. 後の版への同意は、前の版の同意を含む(文書ごとに「同意した最大の版」で見る)。
3. 同意してよいのは、公開済みで、いまの版かそれより後の版だけ。
4. 利用規約を管理者が同意すると**組織(契約者)として**、ほかは本人として(ロールで決まる。本文で選べない)。
5. 記録は足すだけ(アプリは読む・足すだけ。消すのは解約のコマンドだけ)。同意は監査ログ `legal.consent` にも残る。
6. 対象にしない人: サポートの代理ログイン中の社員(代わりに同意もできない)・運営の組織の人。
7. 登録の画面での同意は、確認コードが通った後(メールの持ち主だと分かってから)に記録する。
8. お知らせのメールは運営のコマンド(`legal-notify`)だけが積む。同じ人に同じ版は1回だけ。
