# 領域: 組織と利用者(organizations)

> 「誰が・どの組織として」使っているかを持つ領域。他の領域はすべて、この領域が決めた組織の中で動く。

## エンティティ

| もの | 表 | 持っていること |
|---|---|---|
| 組織 | `tenants` | 名前。`tenant_id` が全テーブルの分け目。二段階認証を全員に必須にするか(`mfa_required`) |
| 利用者 | `users` | メール・名前・ロール・認証の製品側の ID(`external_id`)・二段階認証の写し(`mfa_enabled`)・ほかの端末を切った時刻(`sessions_valid_after`)・SSO の緊急用か(`sso_exempt`) |
| サポートへの許可 | `support_grants` | 管理者が出した「サポートに見せてよい」。期限・取り消し。サポート番号は持たない(ハッシュだけ) |
| メールの変更の申し込み | `email_changes` | 本人が申し込んだ新しいアドレスと古いアドレス・確認した時刻。古いアドレスは「変わりました」のお知らせの宛先 |
| 招待 | `invitations` | 管理者が招いたメールアドレスとロール・期限(7日)・受けた時刻とできた人・取り消し。リンクの札は持たない(招待の ID とサーバーの秘密の署名) |
| 契約のプラン | `platform.tenant_plans`(共通の仕組み `src/plans`) | いつから・どのプラン・どの版の価格表・何人まで・据え置きはいつまで。足すだけ。定義は `@app/shared` の `PLANS`・`PRICE_LISTS`(docs/specs/0047-plans.md) |
| 会社のドメイン | `domains` | 組織が登録した会社のメールのドメインと、DNS の TXT に置く確かめの文字・確かめた時刻。確かめたドメインは全体で1つの組織だけ(docs/specs/0056-sso-scim-ip-audit-export.md) |
| つないだ IdP | `sso_connections` | 組織につないだ SAML の IdP(Cognito の IdP の名前)と、SSO を必須にしているか。1組織に1つ。つなぐ・外すのは運営のコマンド `sso-connect`(docs/runbooks/sso.md) |
| 入れる IP の範囲 | `ip_allowlist` | 組織に入れる IP の範囲(CIDR。20 まで)。空なら制限しない |
| サポートの入室 | `support_sessions` | 社員が番号で入っている間の記録。社員の名前とメールの写し・期限・終わった時刻 |

## 状態

- 組織: 無い → ある(開通。運営がコマンド `create-tenant` で。`docs/runbooks/tenant-provisioning.md`)→ 消した(解約。運営がコマンドで。`docs/runbooks/offboarding.md`)。止めるの流れは未実装。
- 利用者: 無い → ある(開通の最初の管理者・招待を受けた人)。無効化は未実装。
- 招待: 受けていない(7日)→ 参加した(1回きり)/ 期限切れ / 取り消し済み(どれも戻らない)。
- 契約のプラン: (無い)→ 行を足す → 行を足す …(いまの行は効き始めの日で決まる。先の日付は予約)。プランを変えると据え置きが消える。人数の上限(block)に届くと招けない。
- 利用者の二段階認証: 未設定 ⇄ 有効(本人がパスワードを入れ直して。組織が必須なら外せない)。運営が手順書で外すこともある(`docs/runbooks/mfa-reset.md`)。
- 組織の二段階認証: 任意 ⇄ 全員に必須(管理者。自分が設定済みのときだけ入れられる。運営の組織は最初から必須で切れない)。
- メールの変更の申し込み: 申し込み中(24時間)→ 変わった / 期限切れ / 新しい申し込みで上書き。
- サポートへの許可: 有効 → 期限切れ / 取り消し済み(戻らない)。
- 会社のドメイン: 未確認 → 確かめた(DNS の TXT が見えたとき。ほかの組織が確かめ済みなら 409)。消せる。
- SSO: IdP なし → つないだ(運営)→ 必須(管理者。緊急用の管理者が1人以上要る)⇄ 任意 → 外した(運営)。プランの機能 `sso` が外れると、SSO で入れず、必須も効かない。
- 入れる IP の範囲: 無い(制限しない)⇄ ある(一覧ごと入れ替える。いまの IP を外す一覧は保存できない)。プランの機能 `ip-allowlist` が外れると、残った範囲は効かない。
- サポートの入室: 入っている → 終わった(自分で終えた・ログアウト・許可の取り消し)/ 期限切れ(最長1時間・許可の期限まで)。

## 守るルール

1. **組織はログインのセッションからだけ決まる**。URL・本文・ヘッダーの値で決めない(ADR 0001)。
2. 全テーブルに `tenant_id`。DB の RLS が他の組織の行を返さない(`apps/api/drizzle/0001_rls.sql`)。
3. **1人が複数の組織に所属できる**(users の行が所属。docs/specs/0055-multi-org-membership.md・ADR 0066)。セッションは1つの組織分だけで、選び直すと Cookie を出し直す。所属の一覧を引くのは DB の関数(`auth_find_memberships`)だけで、本人にだけ返す。人に1つの物(メール・二段階認証・ほかの端末を切る)は全部の所属の写しにそろえる(`auth_sync_person`)。メールと sub の一意は組織ごと(全体の一意は移行 0019 で外した)。
4. ロールは毎回 DB から引く(Cookie に入れない)。変えたらすぐ効く。
5. ログインのときだけ、組織が決まる前に「このメールは誰か」を引く特別な関数を通る(`auth_find_user_by_email`)。
6. **社員がお客さんの組織に入れるのは、サポートの代理ログインだけ**(docs/specs/0004-support-access.md)。お客さんの管理者の許可があり・運営の組織(`SUPPORT_TENANT_ID`)の人で・**閲覧者に固定**・最長1時間。入った・見た・出たはお客さんの監査ログに残る。全社を一覧する画面は作らない。
7. 社員が番号から許可を探すのも、組織が決まる前なので特別な関数を通る(`support_find_grant`)。
8. **本人のアカウント(二段階認証・メール・パスワード)は、本人だけが変える**(パスに人の ID を取らない)。変える前にパスワード(とコード)を入れ直し、変えたらほかの端末を切り、本人に知らせる(docs/specs/0006-account-security.md)。代理の社員は変えられない。
9. **組織が二段階認証を必須にしていれば、未設定の人は設定の API しか使えない**(関所が 403 `mfa_setup_required`)。必須の組織に代理で入れるのは、二段階認証を設定済みの社員だけ。
10. メールアドレスが使われているかは組織をまたぐので、真偽だけを返す関数(`auth_email_in_use`)を通る。言うのは確認コードを受け取った人(そのアドレスの持ち主)にだけ。
11. **人が増えるのは、開通のコマンドと、生きている招待を受ける関数(`auth_accept_invitation`)だけ**。アプリの接続は users に行を足せない。招待を受けるときの組織は、リンクの札が指す招待で決まる(リクエストの値で選ばせない)。ほかの組織にいる人も招けて、受けると所属が増える(ADR 0066)。ドメインは確かめない(SSO を足すときに)。
12. **利用者1人分の開示・削除は、お客さん(委託元)が本人に答え、運営は書面の指示(組織の ID・利用者の ID)で手伝う**。運営のコマンド `person-data` はどこに何件あるかを数えるだけ。利用者を指す列を足したら `src/person-data` の一覧にも足す(docs/specs/0048-person-data.md)。
13. **組織が IP の範囲を決めていれば、外からはログインも操作もできない**(関所とログインが 403 `ip_not_allowed`)。いまの人の IP は、設定のヘッダー(`CLIENT_IP_HEADER`。既定 `X-Forwarded-For`・CloudFront なら `CloudFront-Viewer-Address`)を、前にいる中継の数(`TRUSTED_PROXY_HOPS`)だけ右から数えた値(左は信じない)。代理の社員は対象外。締め出されたときは運営が手順書で外す(`docs/runbooks/sso.md`)。
14. **管理者は組織の人を強制ログアウトできる**(その人の `sessions_valid_after` を今に。サーバー側のセッションの保存は作らない。ADR 0067)。会社のドメインは DNS で確かめた物だけを、SSO で「この組織の人」を決めるのに使う(T-8)。
15. **SSO で入れるのは、その IdP をつないだ組織の、確かめたドメインのメールの人だけ**(人は作らない)。組織を決めるのは IdP で、メールの文字列で組織を選ばない(L-8)。必須の組織では、そのドメインの人は SSO で入ったセッションだけが通り(ほかは 403 `sso_required`)、緊急用の管理者(2人まで)だけがパスワード+二段階認証で入れる。

## 他の領域との境目

| 相手 | 渡すもの | 受け取らないもの |
|---|---|---|
| projects・tasks | 組織(`tenant_id`)と、利用者(`user_id`・ロール) | 他の組織の情報 |
| legal(規約と同意) | 利用者(同意した人・お知らせの宛先)・組織の時間帯 | 他の組織の情報 |
| 認証の製品(Cognito) | — | 「この人の sub はこれ」だけを受け取る。パスワードは持たない |

## 関係するファイル

- `apps/api/src/auth/`(セッション・ログイン)・`apps/api/src/authz/`(権限)
- `apps/api/src/domains/organizations/`(Postgres のスキーマ `organizations`)の `tenants`・`users`。組織の時間帯 `time_zone`(ADR 0005)
- `docs/db/organizations.tenants.md`・`docs/db/organizations.users.md`(表の説明書)
