# 解決済みの論点

> 受け入れ(`/accept`)で「要求のせい」で外れた所を、次の仕様で同じ穴を作らないために残す一覧。**`/new-feature` と `/design` が仕様と設計の前に読む**。
> 番号は `R-1` から。消さない・使い回さない(答えが変わったら新しい行を足し、古い行の「答え」に「R-n で変わった」と書く)。
> 受け入れの記録が指す `R-n` がここに無いと CI が落ちる(`pnpm acceptance`)。書き方は [guides/acceptance.md](../guides/acceptance.md) の 4。
> 用語や領域の決まりそのものが足りなかったなら、ここに書くのに加えて用語集・領域の説明・ADR も直す(`/update-domain-docs`)。
