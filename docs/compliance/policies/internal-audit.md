# 内部監査の規程

> ひな形。ISMS(箇条 9.2)・P マーク(JIS Q 15001 の内部監査)とも、年1回以上、決めたとおりに回っているかを、作った人と別の人が確かめる。「要記入」の所を埋め、責任者が承認する。

## 1. いつ・誰が

- 年1回(【要記入: 月】)と、大きな事故・大きな変更の後。点検の `internal-audit` が知らせる。
- 監査する人は、監査される所を自分で作っていない人(少人数なら、外の人に頼むか、互いの担当を入れ替える)。

## 2. 見る物

| 見る所 | 何で確かめるか |
|---|---|
| 規程が今も合っているか・見直しの日を過ぎていないか | [規程の一覧](README.md)・`pnpm compliance` |
| 適用宣言書の適用・除外が今も合っているか | [適用宣言書](../soa.md)・[管理策の一覧](../controls.yaml) |
| 点検が回っているか(答え残し・相談先に回ったまま・落ちたまま) | [点検の台帳](../../checkup/README.md)・`pnpm checkup` |
| 毎月の証跡が欠けていないか・設定が外れた月が無いか | 消せない置き場の `evidence/<年>/` と目録(`manifest.json`) |
| 教育を全員が受けたか | 教育の記録 |
| 権限の棚卸しをしたか・辞めた人の権限が残っていないか | 証跡の `github-collaborators`・`aws-iam-users` |
| 事故の振り返りと再発防止が閉じたか | [振り返り](../../incidents/README.md) |
| 委託先の見直しをしたか | 委託先の一覧 |
| 前回の監査の指摘が直ったか | 前回の報告 |

## 3. 進め方

1. 監査する人が、2. の表から今回見る所を決め、計画(いつ・誰に聞くか)を責任者に知らせる。
2. 資料と証跡を見て、担当者に聞く。
3. 見つけた物を「不適合(決まりを守れていない)」「気づき(良くできる)」に分け、報告に書く。
4. 不適合には、担当者が直す計画(何を・いつまでに)を書き、責任者が確かめる。直したら報告に書き足す。
5. 報告は、マネジメントレビューに出す。
6. `/compliance-check` で点検の `internal-audit` に「やった」を記録する。

## 4. 報告の型

```markdown
# 内部監査の報告 YYYY

- 監査した人: @ ・ 期間: YYYY-MM-DD 〜 YYYY-MM-DD
- 見た所: (2. の表の行)
- 聞いた人: @

## 見つけた物

| 番号 | 種類 | 見つけた事(事実) | 根拠(資料・証跡) | 直す計画(何を・いつまでに・誰) | 直した日 |
|---|---|---|---|---|---|
| 1 | 不適合 / 気づき | | | | |

## 前回の指摘

| 番号 | 中身 | 直ったか |
|---|---|---|

- 責任者の確認: @ (日付)
```
