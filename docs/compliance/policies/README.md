# 規程と様式のひな形

> どれも**ひな形**。「要記入」の所(`【要記入: …】`)を自社の言葉で埋め、責任者(基本方針は経営者)が承認した日を頭の `established` に、1年以内の日を `next_review` に書く。
> 頭の YAML(`controls`)は、その規程が当たる管理策の番号。[適用宣言書](../soa.md)の「規程・根拠」の欄はここから作られる。
> 使い始めの流れと、見直し・教育・内部監査の回し方は [../README.md](../README.md)。

| 規程・様式 | 何を決めるか | 主な管理策 | P マーク(JIS Q 15001)で言うと |
|---|---|---|---|
| [basic-policy.md](basic-policy.md) | 情報セキュリティと個人情報保護の基本方針・役割・使い方の決まり・端末・人の出入り | A.5.1・A.5.2・A.6.x・A.7.x・A.8.1 | 個人情報保護方針(外に公表する版は 1.〜3.) |
| [personal-information.md](personal-information.md) | 個人情報の台帳・目的・頼む・渡す・消す・本人からの求め・事故 | A.5.34・A.5.12・A.8.10 | 内部規程 |
| [vendors.md](vendors.md) | 委託先(クラウド・SaaS・業務委託)の選び方・契約・年1回の見直し・やめ方 | A.5.19〜A.5.23 | 委託先の監督 |
| [training.md](training.md) | 教育(入るとき・年1回)と記録の型 | A.6.3 | 教育 |
| [internal-audit.md](internal-audit.md) | 内部監査(年1回・作った人と別の人)と報告の型 | A.5.35・A.5.36 | 内部監査 |
| [management-review.md](management-review.md) | マネジメントレビュー(年1回・経営者)の議事録の型 | A.5.1・A.5.4 | 代表者による見直し |

- 規程の頭の日付と `controls` の書き方が違う・指している管理策が無い・リンクが切れている、で CI の `pnpm compliance` が落ちる。
- 「要記入」が残っている・制定日が無い間は、点検の `policies-adopt` が「まだ」を出す。`next_review` を過ぎると `policy-review` が知らせる。
- ひな形の中身は、法令と規格の**分かる範囲での**下書き。審査の前に、コンサルタントか審査機関の資料で確かめる。
