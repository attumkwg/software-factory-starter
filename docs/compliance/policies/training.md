# 教育の規程

> ひな形。P マーク・ISMS とも、全員が年1回以上教育を受け、その記録を残すことが求められる。「要記入」の所を埋め、責任者が承認する。

## 1. 誰が・いつ

| いつ | 誰 | 中身 |
|---|---|---|
| 入るとき(権限を渡す前) | 新しく入る全員(社員・業務委託・派遣) | 2. の全部 |
| 年1回(【要記入: 月】) | 全員 | 2. の全部+この1年の事故とヒヤリとした事 |
| 規程を大きく変えたとき | 全員 | 変えた所 |
| 役割が変わったとき | その人 | 新しい役割の手順書 |

## 2. 中身(30分〜1時間)

1. [基本方針](basic-policy.md)と、使い方の決まり・端末・離れた場所での仕事。
2. [個人情報保護規程](personal-information.md)(何が個人データか・目的の外で使わない・本人からの求め)。
3. 事故に気づいたら(誰に・どこで知らせるか。[障害の入口](../../runbooks/incident.md))。
4. よくある手口(なりすましのメール・鍵の漏れ・AI の道具に秘密を貼る)。
5. 開発をする人は追加で: [セキュリティの決まり](../../security.md)・危険度「高」の場所と人の確認([local-guards](../../guides/local-guards.md))・秘密を書かない。

## 3. 確かめと記録

- 受けた後に、短い確かめ(5問ほど。【要記入: 確かめの置き場】)をする。8割に届かなければ、受け直す。
- 記録は1回ごとに1枚([記録の型](#4-記録の型))。置き場は [records/](../records/README.md)(個人の名前が入るので、リポジトリが公開なら別の非公開の場所に置き、ここには置き場だけを書く)。
- 年1回の教育が済んだら、`/compliance-check` で点検の `training` に「やった」を記録する。

## 4. 記録の型

```markdown
# 教育の記録 YYYY-MM-DD

- 種類: 入るとき / 年1回 / 規程の変更 / 役割の変更
- 中身: (2. のどれ。資料の版)
- 講師: @
- 受けた人と確かめの点:
  | 名前 | 受けた日 | 確かめ(点) | 受け直し |
  |---|---|---|---|
  |  |  |  |  |
- 受けていない人と、いつ受けるか:
- 責任者の確認: @ (日付)
```
