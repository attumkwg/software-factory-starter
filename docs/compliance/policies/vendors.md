# 委託先の管理規程

> ひな形。クラウド(AWS・GitHub)・SaaS(Sentry・Slack・メールなど)・業務委託の人と会社に、情報を預ける・扱わせるときの決まり。「要記入」の所を埋め、責任者が承認する。

## 1. 範囲

当社の情報(特に個人データ)を、預ける・見られる・扱わせる相手の全部。使っている物の一覧は【要記入: 委託先の一覧の場所】に置く(名前・何を預けるか・データの場所(国)・契約の形・第三者の報告書・最後に見直した日・責任者)。

## 2. 選ぶとき

次を確かめ、結果を一覧に残してから使い始める。

1. 守りの水準: 第三者の報告書(SOC 2 Type II・ISO/IEC 27001 の認証・ISMAP など)があるか。無ければ、質問票で確かめる。
2. データの場所(国)と、その国の制度。外国なら、プライバシーポリシーに書く。
3. 再委託(さらに別の会社に頼むか)と、その一覧が見られるか。
4. 事故のときの連絡(何時間以内に・誰に)。
5. 解約したときに、データを返す・消すこと。
6. 二段階認証と、権限を分けられるか(管理者を絞れるか)。

## 3. 契約で確かめること

- 秘密を守る義務(業務委託の人とは秘密を守る約束を交わす)。
- 個人データを、頼んだ目的の外で使わない。
- 事故の連絡・監査に応じる(または第三者の報告書を出す)。
- 終わったら返す・消す。

クラウドや SaaS の定型の契約(利用規約)で、これらが書いてあるかを確かめ、足りない所は一覧に「足りない所」として残す(相手に直してもらえないことが多い。その上で使うかは責任者が決める)。

## 4. 使っている間

- 年1回、一覧の全部を見直す(第三者の報告書の新しい版・事故の公表・値上げと規約の変更)。点検の `vendor-review` が知らせる。
- 委託先の大きな変更(規約・データの場所・事故)は、月1回の世の中の変化の取り込み(`/checkup-refresh`)でも拾う。
- 権限は要る分だけ。使わなくなった連携・鍵は外す(四半期の棚卸し `access-review`)。

## 5. やめるとき

データを書き出してから、消すことを確かめ(消した証明が出せるなら受け取る)、権限と連携と鍵を外す。一覧に、やめた日を残す(行は消さない)。
