# マネジメントレビューの議事録の型

> ひな形。ISMS(箇条 9.3)・P マーク(JIS Q 15001 の代表者による見直し)とも、年1回以上、経営者が仕組み全体を見直し、その記録を残す。
> 1回ごとに、下の「議事録」を写して埋める(置き場は [records/](../records/README.md))。点検の `management-review` が知らせ、`/compliance-check` で「やった」を記録する。

## 進め方

- 年1回(【要記入: 月】。内部監査の後)。1時間ほど。経営者・情報セキュリティの責任者・内部監査の責任者が出る。
- 責任者が、下の「出す物」を前もってそろえる。経営者が「決めたこと」を決める。

## 議事録

```markdown
# マネジメントレビュー YYYY-MM-DD

- 出た人: @経営者 @責任者 @内部監査の責任者
- 前回: YYYY-MM-DD(前回の決めたことの進み具合は 1.)

## 出す物(責任者がそろえる)

1. 前回の決めたことの進み具合
2. 外と中の変化(事業・法令・委託先・使っている技術。/checkup-refresh の取り込み)
3. 点検の結果(落ちたまま・答え残し・相談先に回ったまま。docs/checkup/README.md)
4. 内部監査の結果(不適合と直した物)
5. 事故とヒヤリとした事・振り返りと再発防止
6. 目標の達成(【要記入: 目標。例: 重い脆弱性を期限内に直した割合・戻す訓練の成功・教育を受けた割合】)
7. 毎月の証跡の欠け・Security Hub の点数の動き
8. 委託先の見直しの結果
9. 費用(守りにかかった費用と、足りない所)
10. 利害関係者(お客さま・委託先)からの求めと苦情

## 決めたこと(経営者)

| 番号 | 決めたこと(良くする所・変える所・資源) | 誰が | いつまでに |
|---|---|---|---|
| 1 | | | |

- 基本方針と目標を変えるか: 変えない / 変える(どこを)
- 適用宣言書の範囲を変えるか: 変えない / 変える(どこを)
- 次回: YYYY-MM

- 承認: @経営者(日付)
```
