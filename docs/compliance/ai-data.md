# AI に渡すデータの決まり

> **本番の個人データは AI に渡さない。渡してよいのは ID と集計まで。要配慮(sensitive)は一切渡さない。**([docs/security.md の AI-6](../security.md))
> AI は本番に入れない(AI-1)ので、本番の物を AI が読むのは「人が出して、貼った」ときだけ。だから **貼る前に人が見る** のが守りの本体。
> AI の会社(Anthropic)は委託先の台帳に「委託・internal まで」で載っている([vendors.yaml](vendors.yaml)。personal を書くと CI が落ちる)。

## 1. 渡してよい物・渡さない物

区分は `apps/api/src/db/classification.ts` と同じ。**internal(ID・時刻・回数)と public(選択肢・真偽)まで**が渡してよい物。

| 出どころ | 渡してよい(ID と集計) | 渡さない |
|---|---|---|
| アプリのログ(CloudWatch Logs) | 許可リストの項目(`requestId`・`tenantId`・`userId`・`route`・`status`・`durationMs`・`err.type`・`code`)と、その件数・割合 | `[REDACTED]` を外した値・`err.message` の中の値(貼る前に読む。値が入っていたら消す) |
| Sentry | タイトル(値は `[…]` に伏せてある)・タグ・スタック・件数・人数 | 画面に出る「User」の詳しい欄を開いて写した物 |
| DB | 件数・合計・分布(「この組織のタスクは 1,204件・完了 62%」)・行の ID | 行の中身(名前・メールアドレス・題名・本文)・ダンプ・CSV の書き出し |
| 監査ログ(`platform.audit_events`) | 誰が(ID)・何を(出来事の名前)・いつ・件数 | 書き出しの中身 |
| 管理操作の記録(CloudTrail) | 出来事の名前と件数 | 社員の名前(IAM の名前)・IP |
| 問い合わせ・不具合の報告 | 組織の ID・人の ID・requestId・再現の手順 | お客さんの名前・メールアドレス・電話・本文の写し(ID に置き換えてから Issue に) |
| 画面 | stg か手元で再現して撮ったスクショ | 本番の画面のスクショ(名前・題名が映る) |
| 要配慮(病歴・障害・信条など) | **なし**(件数も、少ないと人が分かるので渡さない) | すべて。stg・手元にも本物は置かない |

- **ID は単体では人が分からない**が、こちらの DB と突き合わせれば人に結びつく。だから AI の会社は「渡さない」ではなく **委託** として台帳に載せている(越境の扱いは 3)。
- **集計は小さすぎると人が分かる**(「この組織の admin は1人」)。人数が数人の集計は、ID と同じ扱いにする。
- **コード・設計書・stg と手元の種データ**(偽物)は渡してよい。種データに本物の個人データを入れない。

## 2. どう渡すか(本番から出すのは人)

1. 本番の物を出すのは人(AI-1)。AI に頼むのは「何を出せばよいか」まで(例: 「この requestId の行を、許可リストの項目だけで」)。
2. ログは項目を決めたクエリで出す。`fields` に書いた項目しか出ない:

```
fields @timestamp, service, level, message, method, route, status, durationMs, err.type, code, tenantId, userId
| filter requestId = "<requestId>"
| sort @timestamp asc
```

3. **貼る前に読む**: 名前・メールアドレス・題名・本文・電話・住所らしい物があれば消すか ID に置き換える。迷ったら貼らない。
4. AI の答え(原因の候補・直し方)は、ふつうどおり Issue と PR に。PR・Issue にも個人データを書かない(GitHub も委託先。台帳の区分は internal まで)。

障害のとき([runbooks/incident.md](../runbooks/incident.md))も同じ。急いでいても、貼るのは ID と集計まで。

## 3. 越境(日本の外の委託先)

AI(Anthropic)・Sentry・GitHub・Slack は米国にある。ID(internal)だけでも、こちらでは人に結びつくので、個人情報保護法の「外国にある第三者への提供」(28条)に当たるかどうか・当たるなら本人への情報提供や同意が要るかは、**専門家に確かめる**(設計書 0017 の未確定事項 U-1)。

- 確かめる前にできること: 置き場所を選べる物は日本か近くに(Sentry は EU の置き場もある)・渡す物を ID と集計に絞る(この決まり)・委託先の台帳に国と契約を書く(プライバシーポリシーに書く元になる)。
- 確かめた答えは、プライバシーポリシー(`docs/guides/legal-documents.md`)と台帳の `country` の書き方に戻す。

## 4. 渡してしまったら

1. その会話・メッセージを消す(Claude Code なら、その会話を消す。@claude なら Issue・PR のコメントを消し、編集の履歴も消す)。
2. いつ・どの AI に・何を(ID か、名前か)を記録する。
3. 名前・メールアドレス・要配慮だったら、[runbooks/personal-data-breach.md](../runbooks/personal-data-breach.md) で「漏えいに当たるか」を判断する(委託の範囲の中か、どこに残ったか)。要配慮なら件数に関係なく当たりうる。
4. なぜ貼ったかを振り返り、クエリの型・この表・スキルのどれかを直す(気をつける、で終わらせない)。
