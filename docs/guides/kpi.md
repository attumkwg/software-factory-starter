# ペルソナ → KPI → 計測 → 資産(機能を作る理由を、数で言う)

> 仕様 [0081](../specs/0081-persona-kpi.md)。型は `docs/product/_template-personas.md`・`_template-kpi.yaml`、見本は `docs/product/personas.md`・`kpi.yaml`(TODO アプリ・架空)。確かめは `pnpm kpi`・`pnpm bets`。

## なぜ

このキットでやりたいのは、**安全に、KPI を達成したかを見て、資産価値を高める**こと。そのためには、作る機能が「誰の・何を・どれだけ良くしたか」を数で言えないといけない。言えないと、計測も KPI も決まらず、資産に載せる根拠(「将来の収益か費用の削減が確実」)も出せない。守り(CI・関所)は、この線で価値を生む物を安全に出し続けるためにある。

```
ペルソナ(personas.md の P-n)
  → 欲しい成果(数で言える形)
    → KPI の木(kpi.yaml): 北極星 K-0 ← 入力 K-1〜K-4 / 守り K-G1…
      → 賭け(bets/)が入力の指標を動かす。psf から必須
        → 計測(usage-report・「無くなったら困るか」・手で数える)→ records に値
          → 線に届いたか → 会計区分の判定の根拠(資産の候補か)
```

## 1. ペルソナ(`docs/product/personas.md`)

- 1人ずつ `## P-n <一言>`。使う人・買う人・決める人を分ける(使う人と買う人が違うと、欲しい物も違う)。
- **欲しい成果は数で言える形**にする(「整理が 30分 → 0分」「催促の電話が週5回 → 1回」)。北極星と入力の指標はここから作る。
- 確かめていない物は `(仮説)`。話を聞いたら記録(`interviews/`)へのリンクを足す。
- 番号は変えない。やめたペルソナも消さない(賭けが指しているため)。

## 2. KPI の木(`docs/product/kpi.yaml`)

| 種類 | 数 | 中身 | 例(見本) |
|---|---|---|---|
| 北極星 `K-0` | 1つ | ペルソナが価値を得た瞬間を数える。売上ではなく、その手前の「価値が届いた」数 | 期限の前に完了したタスクがあった組織の数(週) |
| 入力 `K-1`〜 | 2〜4 | 北極星を動かす物。**賭けはこれを動かす** | 期限が近いタスクに、期限の前に気づけた割合 |
| 守り `K-G1`〜 | 1つ以上 | 「安全に」の部分。北極星が伸びても、これが悪くなったら止める | 知らせがうるさいと答えた人の割合・1組織あたりの費用 |

- 目標は `target: { value, by }`(少ないほど良い指標は `direction: below`)。PMF の前で決まらなければ書かない(`pnpm kpi` が「目標が無い」と出すだけ)。
- 守りは `limit: { value, direction }`(below = 下回っていること)。
- `status` は 仮説 / 確か / やめた。やめた指標も消さない。

## 3. 計測(どこで数えるか)

| `measure.how` | 何で数えるか | 書く物 |
|---|---|---|
| `usage` | 機能の利用の記録(`platform.feature_usage`)。運営のコマンド `usage-report <機能>` の、使った組織・人の数と継続率(仕様 0012・0022) | `feature`(機能フラグの名前)・`metric` |
| `survey` | 「無くなったら困るか」の問い(仕様 0046) | `source` |
| `manual` | 運営の集計・費用のページ・手で数える | `source`(何で数えるか) |

- 値は `records` に足す(古い行は消さない): `{ date, kpi, value, source }`。
- **割合と件数はリポジトリに書いてよい**(組織名・個人は書かない)。**金額の指標(`money: true`)は、目標・線・値の金額をリポジトリに書かない**。金額は費用のページと同じ非公開の置き場に置き、リポジトリには `reached: true / false`(線に届いたか)だけ。
- 毎週の点検か、賭けの小石を足すときに測って1行足す。`pnpm kpi` が最新の値と線を並べる(届いた・まだ・期限を過ぎた・守れている・超えた)。

## 4. 賭け・仕様・PR とのつなぎ

- 賭けの「いまの状態」に `- ペルソナ: P-n` と `- 動かす KPI: K-n`(守りの K-Gn も)。**psf から必須**(無い・木に無い番号なら `pnpm bets` が落ちる)。idea・cpf は任意。
- 仕様の「なぜ作るか」と、PR の「🎯 取り組み」の「動かす KPI」に、賭けから写す。
- 賭けの線(合格・撤退)は、なるべく動かす KPI の言葉で書く(「入れた組織の K-1 が 70% 以上」)。

## 5. 資産の根拠

- 会計区分の判定(`bets-and-assets.md`)の「理由」に、合格の線と並べて **動かす KPI が線に届いたか** を書く(`K-1: 届いた(2026-11-30 の記録)`)。
- 届いていなくても、自動で費用にはしない。案と根拠をそろえるだけで、確定は人(会計)。

## 6. 既存のリポジトリに入れるとき

キットを丸ごと入れなくても、**`personas.md` と `kpi.yaml` の2つと `pnpm kpi` だけ**入れれば、この線は引ける。次に賭けのファイル(`bets/`)を足すと、機能ごとに「どの KPI を動かしたか」が残り始める。CI・関所はその後でよい(穴 G-51 の入口)。
