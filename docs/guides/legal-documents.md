# 利用規約・プライバシーポリシーの版を足す

> ⚠️ **このキットは仕組みだけを持つ。規約の文面・何を「同意し直し」にするか・予告の日数は、法務の確認を経て決める。**
> 下の「法令の要点」は一次資料の要旨だけで、条文そのものはまだ確かめていない(設計書 `docs/designs/0009-legal-consent.md` の U-7)。
>
> 決めた理由は [ADR 0022](../adr/0022-legal-documents-and-consent.md)、仕様は [specs/0009](../specs/0009-legal-consent.md)。お知らせのメールの送り方は [runbooks/legal-notice.md](../runbooks/legal-notice.md)。

## 仕組み

| 物 | 置き場所 |
|---|---|
| 本文(1つの版 = 1つのファイル) | `apps/web/src/legal/<terms\|privacy>/v<版>.md`(見出し `##`・段落・`- ` の箇条だけ読む。`<!-- -->` は画面に出ない) |
| 版の一覧(公開・効力の日時・要約・同意し直しが要るか・本文の sha256) | `packages/shared/src/legal.ts` の `LEGAL_VERSIONS` |
| 同意の記録(足すだけ) | DB の `legal.consents`(誰が・どの版に・いつ・どの画面から・組織としてか本人としてか)。監査ログの `legal.consent` |
| お知らせを送った記録 | DB の `legal.notices` |
| 本文の画面(ログイン無しで読める) | `/legal/terms`・`/legal/privacy`(いまの版)・`/legal/<文書>/<版>` |
| 同意の画面 | `/legal/accept`(同意し直しが要る版に同意していない人は、どの画面を開いてもここへ。API は 403 `terms_acceptance_required`) |

- **公開の日時(`publishedAt`)より前は、どこにも出ない**。マージしておけば、決まった時刻から本文・帯が出る(デプロイの日を合わせなくてよい)。
- **効力の日時(`effectiveAt`)から効く**。`reconsent: true` なら、その版(か後の版)に同意していない人を関所が止め始める。
- 予告中(公開 〜 効力)は、ログインした人の画面の上に帯が出る。同意し直しの版なら、帯から前もって同意できる。
- 対象にしない人: サポートの代理ログイン中の社員(見るだけ)・運営の組織の人(運営そのもの)。

## 版を足す手順

1. 本文を書く: いまの版のファイルを写して `v<次の版>.md` を作り、直す。**公開した版のファイルは書き換えない**(書き換えると単体テストが落ちる)。
2. 版の一覧に1行足す(`packages/shared/src/legal.ts`):
   ```ts
   {
     document: "terms",
     version: 2,
     publishedAt: "2026-12-01T00:00:00+09:00", // この時刻から出る・お知らせを送れる
     effectiveAt: "2027-01-01T00:00:00+09:00", // この時刻から効く(公開から 30 日以上あける)
     summary: "料金の支払いの期限を変えます", // 帯・同意の画面・メール・履歴に出る(1〜2行)
     reconsent: true, // 同意し直しが要るか(下の「何を同意し直しにするか」)
     sha256: "…", // 分からなければ空で流すと、apps/web の documents.test.ts が正しい値を教える
   },
   ```
3. `pnpm test` が通ること(`packages/shared` の `legal.test.ts` = 版の並び・日付・30日、`apps/web` の `documents.test.ts` = 本文のファイルとハッシュ)。
4. PR を出す。**法務(か責任者)が、本文の差分・要約・`reconsent`・日付を見て承認する**。
5. 公開の日時を過ぎたら、運営がお知らせのメールを送る([runbooks/legal-notice.md](../runbooks/legal-notice.md))。
6. 効力の日時を過ぎたら、`reconsent` の版なら同意の画面が出始める。同意の数は `legal.consents` で数える。

## 何を「同意し直し」にするか(既定の案。U-1)

| 同意し直し(`reconsent: true`) | 知らせるだけ(`reconsent: false`) |
|---|---|
| 料金・支払いの条件を、利用者に不利に変える | 誤字・言い回し・条の番号の整理(意味が変わらない) |
| 責任の範囲・免責を広げる・解約の条件を厳しくする | 会社の名前・住所・連絡先 |
| 禁止事項を足す(いまの使い方が違反になりうる) | 利用者に有利な変更(料金を下げる・期限を延ばす) |
| プライバシーポリシーの**利用目的を広げる**・**第三者への提供を足す** | 委託先の追加など、利用目的の範囲の中の変更(公表で足りるかは法務に確かめる) |

迷ったら同意し直しにする(合理性の争いを避けられる)。ただし同意し直しは、全員の仕事を一度止める(効力の日に同意の画面が出る)。

## 法令の要点(条文と一次資料で確かめた。U-7)

- **定型約款が契約の中身になる**: 「約款を契約の内容とする」合意をするか、取引のときにその旨を個別に表示しておく(民法 548条の2)。内容を見せてと言われて正当な理由なく断ると、契約の中身にならない(548条の3)。→ 登録の画面のチェックとリンク、本文はログイン無しで読める。
- **定型約款の変更**: 個別の合意なしに変えられるのは、①相手方の一般の利益に合う変更、②契約の目的に反せず、変更の必要性・変更後の内容の相当性・「変更することがある」旨の定めの有無と内容などに照らして合理的な変更、だけ(548条の4第1項)。「当社都合で変更することがあります」と書いても一方的に変えられるわけではない。**どちらの変更も、効力の日を決めて、変えること・中身・効力の日をインターネットなどで周知する**(同第2項。有利な変更でも要る)。②の変更は、効力の日までに周知しないと効かない(同第3項)。→ 予告の帯・メール・公開の日時。規約の中に「変更することがある旨」の条を置く(ひな形の第10条)。
- **利用目的の変更(個人情報保護法)**: 変更前と関連性があると合理的に認められる範囲まで(17条2項)。変えたら本人に通知か公表(21条3項)。範囲を超えるなら、あらかじめ本人の同意(18条1項)。第三者への提供は、例外を除きあらかじめ本人の同意(27条1項)。同意は、確認欄へのチェック・ボタンを押す、などの方法で得てよい。
- 出典: 法務省「売買、消費貸借、定型約款などの契約に関する民法のルールが変わります」https://www.moj.go.jp/content/001289629.pdf ・ 法務省民事局「民法(債権関係)の改正に関する説明資料 －主な改正事項－」https://www.moj.go.jp/content/001259612.pdf ・ 個人情報保護委員会「個人情報の保護に関する法律についてのガイドライン(通則編)」2-14・2-15・2-16・3-1-2 https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/
- 条文: e-Gov 法令 API で 2026-10-22 に、民法 548条の2〜4・個人情報保護法 17・18・21・27条の現行の版を確かめた(版の ID は [specs/0009](../specs/0009-legal-consent.md) の「法令」)。法令が変わったら読み直す。ほかの法令(特定商取引法・消費者契約法など)は、サービスの中身に合わせて法務と確かめる。

## プライバシーポリシーに書くこと(キットの作りから決まる物)

ひな形は見出しだけ。文面は法務と書くが、キットの作りから次は必ず入る([designs/0008](../designs/0008-personal-data.md) の U-1・U-3)。

- 「2. 取得する情報」: 組織・プロジェクトの名前・タスクの題名など、利用者が自由に入れる文(人の名前などが入りうる。キットは個人情報として扱う)
- 「2. 取得する情報」「3. 利用目的」: 障害の調査のため、**利用者の ID(アプリの ID・Cognito の ID)をログに残す**(90日)。IP アドレス・User-Agent はアプリのログに出さない(ALB・WAF のログを有効にするなら、そちらに書く)
- 要配慮個人情報(病歴など)を扱う機能を足すときは、取る前に本人の同意が要る(個人情報保護法 20条2項)。置き場所は [ADR 0018](../adr/0018-sensitive-data-isolation.md)

## してはいけない

- 公開した版の本文・`publishedAt`・`effectiveAt` を後から変える(直すなら新しい版)
- 本文に、HTML やスクリプトを入れる(文字のまま出るだけだが、決まりとして)
- 効力の日の直前に `reconsent: true` の版を足す(30日の決まりは CI が止める)
- お知らせのメールを API や画面から送れるようにする(運営のコマンドだけ)
