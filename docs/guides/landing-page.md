# 公開してよい LP を出す(事前登録・どこから来たかを測る)

> 記事・会のメール・広告から人を呼び、事前登録を集めるページ(LP)の決まり。**どこに作っても(キットの中でも、外の CMS でも)守ること**をここに書く。
> キットの既定は **キットの中の静的な公開のページ `apps/site`・事前登録は自前の API と DB・計測は外へ送らずに自前で数える**(@attumkwg 2026-10-25 に承認。[設計書 0025](../designs/0025-public-landing-page.md)・[ADR 0038](../adr/0038-public-landing-page.md))。仕様は [specs/0025](../specs/0025-public-landing-page.md)。どの法令が当たりそうかの洗い出しは `docs/product/legal.md`(`/kickoff` が書く)。
> ⚠️ **法令の当てはめ(外部送信の決まり・個人関連情報・広告のメール)は、事業とページの中身で変わる。下の要点は入口で、決めるのは専門家(弁護士など)に確かめてから。**

## いつ作るか(言葉 → LP → 色)

LP は、**約束(誰の何を、どう変えるか)と売り文句が決まった後**に作る。色や名前から決めない(約束が決まる前の LP は、後で全部書き直しになる)。

| 段 | 出す物 | 使う物 |
|---|---|---|
| 解決策を確かめる(賭けの `psf`) | 押せる画面だけ・偽のデータ | 試作([prototypes.md](prototypes.md))。**検索に載らない・測らない・外へ送らない** |
| お金を確かめる(話を聞いた相手に) | 説明・値段・事前登録の形(どこにも送らない) | 試作の申し込みのページ |
| **人を呼ぶ**(知らない人に) | 検索に載る LP・事前登録の記録・どこから来たかの数 | **この手引き** |

- 試作の申し込みのページを、そのまま公開の LP にしない。試作の守り(偽のデータだけ・noindex・本物の API を読まない)を緩めることになる。
- 約束と売り文句の置き場所は、言葉を決める段(G-31)。LP の文はそこから写す。色は `packages/ui/src/tokens.css`(デザインシステムの決まり)。

## LP に要る物

置き場所に関わらず、出す前にそろえる。

- [ ] **見出し**: 約束の1行(相手の言葉で)
- [ ] **困りごと**: 相手がいまどうしていて、何が不満か(話を聞いた相手の言葉から。作らない)
- [ ] **解決**: 何がどう変わるか(画面の絵は、偽のデータの物だけ)
- [ ] **値段**(決まっていれば。決まっていなければ「提供開始の前にお知らせします」)
- [ ] **事前登録の形**(下の「同意の文の型」)
- [ ] **運営者の表示**: 会社の名前・問い合わせ先
- [ ] **プライバシーポリシーへのリンク**(事前登録と計測のことが書いてある版。下の「プライバシーポリシーに足すこと」)
- [ ] **言わないこと**を言っていないか: 約束できない物(「必ず」「No.1」「業界初」など根拠の無い言い方)。広告の表示の決まり(景品表示法など)に当たりうるので、比べる言い方・数字は根拠を残すか、専門家に確かめる
- [ ] 本番以外(下書き・確かめの URL)は検索に載らない(noindex)。本番だけ載せる
- [ ] スマホの幅で読める・押せる(画面と同じ決まり。`docs/design-system.md`)

## 言葉と色を写す段取り

| 写す物 | 正 | キットの中に作るとき(案 a) | 外の CMS に作るとき(案 b) |
|---|---|---|---|
| 約束・売り文句・言わないこと | 言葉を決める段の置き場所 | AI が LP の案を PR で出し、人が OK する | 同じ文をそのまま貼る。**変えたら正の方を先に直す**(CMS で直さない) |
| 色・文字 | `packages/ui/src/tokens.css` | 部品とトークンをそのまま使う(axe と VRT が見る) | 主な色(`--color-primary` など)の値を写し、CMS の色の設定にする。コントラストの比は正の方で確かめた物を使う |
| 事前登録 | キットの事前登録の記録(設計書 0025 の 2) | キットの公開の入口へ送る | CMS のフォームに集めたままにしない。キットの入口へ送るか、運営がコマンドで取り込む(委託先の台帳に CMS を1件) |

- どちらでも、LP を出した・直したら、賭けの小石か全体の計画の「これまでの判断」に **どの文を・いつ出したか** を1行残す(後で「どの言葉が効いたか」を比べるため)。

## 同意の文の型(事前登録)

メールアドレスと会社名は個人情報(個人事業なら会社名が人の名前になる)。**集めるなら必ず、送るボタンの近くに**:

```text
ご入力いただいた会社名とメールアドレスは、<サービス名>の提供開始のご案内と、
試しの利用のご招待にだけ使います。登録から1年で消します(提供開始のご案内のメールから、いつでも消せます)。
詳しくは<プライバシーポリシー(リンク)>をご覧ください。

[ ] 上の使い方に同意して登録する        [登録する]
```

- **チェックが無いと送れない**(画面でも、受ける側でも)。最初からチェックを付けておかない。
- 文の中身(何に使うか・いつ消すか・どこで消せるか)を変えたら、**文の版を1つ上げ**、登録の記録に「どの版の文に同意したか」と「そのときのプライバシーポリシーの版」を残す(設計書 0025 の 2)。
- 送ったら、**確認のメール**(リンクを開いて確かめる)を送り、開くまでは案内を送らない(設計書 0025 の U-4)。他人のアドレスの登録・打ち間違いを防ぎ、前もっての同意が本人のものだと示せる。
- 集める項目は **会社名・メールアドレス・会社の規模の幅** まで。名前・電話・自由記述(「困っていること」など)は置かない(要配慮個人情報が入りうる・組織を作るのに要らない)。
- 期間(「1年」)はキットの既定(設計書 0025 の U-3)。自分のプロダクトでは、プライバシーポリシーの書き方と合わせて法務(か責任者)が確かめる。

## 事前登録の記録の決まり

| 項目 | 決まり |
|---|---|
| 利用目的 | 提供開始の案内・試しの利用の招待・組織を作るときの最初の管理者。**ほかに使わない**(広げるなら同意を取り直す) |
| 置き場所 | キットの事前登録の記録(運営の組織の持ち物。設計書 0025 の 2)。**リポジトリ・スプレッドシート・チャットに一覧を置かない** |
| 保存期間 | 確認待ち7日・確認済みは登録から1年・組織にしてから30日(U-3) |
| 消し方 | 本人がメールのリンクから / 問い合わせを受けて運営がコマンドで / 期限で自動 |
| 委託先 | 確認のメールはいまのメールの中継(AWS の SES。台帳に載っている)。**外のメールの配信の道具・CMS・フォームの道具を使うなら、委託先の台帳(`docs/compliance/vendors.yaml`)に1件**(預け方は委託・データは personal)。台帳は人の確認が要る |
| 本物の組織へ | 確認済みの登録の ID 1つを、組織を作るコマンド(G-01)に渡す。利用規約への同意は、招待された管理者が登録の画面で取る(事前登録の同意は案内と招待まで) |
| AI に渡してよい物 | 件数と率まで。**メールアドレス・会社名の一覧は渡さない**(`docs/security.md` の AI-6) |

## 計測(どこから来たか・事前登録の率)

### 測る物

- **どこから来たか**: 呼ぶリンクに UTM を付ける(`?utm_source=koumuten-kai&utm_medium=email&utm_campaign=launch-2026-11`)。英数と `-_.` だけ。**UTM に人のメールアドレスや名前を入れない**(残るのはリンクを配った人の側の失敗になる)。
- **率**: 見た数 → 登録 → 確認、を来た所ごとに。届け方を比べるのに要るのは、まずここまで。

### 3つの案と、要る物

| 案 | 何をするか | 同意の帯 | 公表 | 委託先の台帳 | できること |
|---|---|---|---|---|---|
| **自前で数える(キットの既定。U-2)** | 自分のサーバーに、ページ・UTM ごとの「見た数」を送り、日ごとに足すだけ。Cookie・端末の ID・IP は残さない | 要らない見込み | プライバシーポリシーに「数え方」を1行 | 足さない | 来た所ごとの率。誰が見たかは分からない |
| 外の解析(Cookie などで解析の会社へ送る) | 解析の会社のタグを置く | 要ることが多い(下の法令の要点) | 送る先・送る情報・目的 | 1件(預け方を確かめる) | 見た人の流れ・滞在など |
| 広告のタグ(コンバージョンを広告の会社へ送る) | 広告の会社のタグを置き、登録を知らせる | 要ることが多い | 同上 | 1件 | 広告の最適化 |

- **外へ送る物を入れるのは人の判断**(事業判断。キットの型には入れていない。U-2)。入れるなら、同意の帯(同意するまでタグを読み込まない・拒否と同じ手間で断れる)・プライバシーポリシーの公表・委託先の台帳を、タグと同じ PR でそろえる。
- 外へ送らない案でも、ALB・WAF のログには IP が残る(30日。[data-retention.md](data-retention.md))。これはいまの決まりのまま。

### 法令の要点(入口。当てはめは専門家に確かめる)

- **外部送信の決まり**(電気通信事業法 27条の12): 利用者の端末から外の会社へ情報を送らせる(解析・広告のタグなど)とき、送る情報・送り先・目的を公表か通知などする決まり。**かかるかどうかは、事業とサービスの種類で変わる**。外へ送らない案なら、送る先がそもそも無い。
- **個人関連情報**(個人情報保護法 31条): Cookie の ID・見た履歴などを、受け取る側で個人データになると想定される相手に渡すとき、受け取る側が本人の同意を得ていることを確かめる決まり。広告のタグで当たりうる。
- **広告・宣伝のメール**(特定電子メール法): 前もって同意した人にだけ送る・送る人の名前と、止める道を書く。提供開始の案内は宣伝に当たりうるので、確認のメールで同意を確かめ、どのメールにも止める(消す)リンクを入れる。
- **日本の外の人を呼ぶなら**、その国の決まり(EU の Cookie の同意など)もかかりうる。
- 法令が変わったら読み直す。点検の台帳(`docs/checkup/todo.yaml`)の見直しに乗せる。

## プライバシーポリシーに足すこと

LP を出す前に、プライバシーポリシーの版を足す(足し方は [legal-documents.md](legal-documents.md))。利用目的を広げる変更なので、すでに公開した版があるなら新しい版にし、同意し直しにするかは法務と確かめる。

- 「取得する情報」: 事前登録の会社名・メールアドレス・会社の規模の幅・どこから来たか(UTM)
- 「利用目的」: 提供開始の案内・試しの利用の招待・組織を作るときの最初の管理者の連絡先・届け方ごとの数を比べること
- 「保存期間」: 上の表の期間
- 「計測」: 自前で数える案なら「Cookie を使わず、ページと来た所ごとの数だけを数える。外へ送らない」。外の解析・広告のタグを入れたら、送る先・送る情報・目的
- 「委託」: メールの送信(AWS)。外の配信の道具・CMS を使うならその会社

## してはいけない

- 事前登録のメールアドレス・会社名を、リポジトリ・Issue・PR・チャット・スプレッドシートに貼る(AI にも渡さない。渡してよいのは件数と率)
- 同意のチェックを最初から付けておく・チェックなしで送れるようにする
- 同意の文の中身を変えて、版を上げない
- 外の解析・広告のタグを、同意の帯・公表・台帳より先に入れる
- 試作のフォルダ(`prototypes/`)に、本物の送り先を作る(試作は偽のデータだけ)
- 本番以外の URL(下書き・確かめ)を検索に載せる
