# お知らせ・プレスリリースの下書きと、お客さんの名前を出す許可

> 正式に出す日・大きな機能を出す日に、業界紙・地域の新聞・業界の会・自社のサイトに知らせる文の型と、**お客さんの会社の名前・ロゴ・導入事例を出す許可**の取り方と記録の置き場。
> 下書きは Claude(`/release-notes` の続き)、出すのは人。景品表示法などの当てはめ(「No.1」「最も」などの言い方)は専門家に確かめる。
> 既定の値の未確定事項は設計書 [0040](../designs/0040-announcements.md) の U-1・U-2。

## 1. 何を出すか

| 種類 | 相手 | 元 | 出す人 |
|---|---|---|---|
| リリースノート | 使っている人 | `/release-notes` の利用者向け | 開発の人(GitHub のリリースを公開) |
| お知らせ(自社のサイト・メール) | 使っている人・検討中の人 | リリースノート+約束と売り文句 | 広報(か責任者) |
| プレスリリース | 記者・業界紙・業界の会 | 下の 3 の型 | 広報(か責任者)。配信の道具を使うなら委託先の台帳に1件 |
| 導入事例 | 検討中の人 | お客さんへの聞き取り(許可を取ってから) | 広報。公開の前に原稿をお客さんに見せる |

## 2. 下書きの材料と決まり

- **元**: `/release-notes` の利用者向け(何ができるようになったか)・約束と売り文句 `docs/product/positioning.md`(約束・売り文句・代わりとの違い)・ブランド `docs/product/brand.md`(話し方のトーン)。
- **書かない**:
  - positioning.md の「**言わないこと**」に書いた物(まだ確かめていない・まだ無い・守れない・根拠が無い)。
  - 根拠の無い数字(「作業が半分に」)。書くなら、根拠(賭けの小石・計測の結果)をその場で示せる物だけ。
  - 「No.1」「最も」「業界初」などの比べる言い方(根拠と専門家の確認が要る)。
  - **許可の記録が無いお客さんの名前・ロゴ・声**(下の 4)。
  - まだ出していない機能・時期の約束(ロードマップの社外の版も「約束しない」。`pnpm bets --roadmap --public`)。
  - 中の言葉(テーブル名・AWS のサービス名)。
- 料金を書くなら、その時点の料金表と同じ値(書き間違えると、その値で求められる)。

## 3. プレスリリースの型

文面は使う人が書く。Claude はこの欄を埋めた下書きを作る。

```markdown
# <見出し: 誰の・何が・どう変わるか(30字前後)>

<日付> <会社の名前>

<リード(3行): いつから・誰に向けて・何を出すか・いちばんの変化>

## 背景
<相手の困りごと(positioning.md の「誰への約束か」)。根拠のある事実だけ>

## <プロダクトの名前>でできること
- <できること1(リリースノートの利用者向けから)>
- <できること2>

## お客さまの声(許可の記録がある場合だけ)
> <声>(<会社の名前> <役職>。名前を出すなら本人の同意も)

## 提供の開始日と料金
- 開始日: <日付>
- 料金: <料金表と同じ値>(載せないなら「お問い合わせください」)

## 会社の情報
<会社の名前・所在地・代表・設立・事業の内容>

## このお知らせの問い合わせ先
<部署・メールアドレス(個人のアドレスにしない)>
```

- 下書きを見せるとき、「言わないこと」「許可の記録」「数字の根拠」を確かめたかを1行ずつ添える。
- 配信(記者への送付・配信の道具)は人がやる。

## 4. お客さんの名前・ロゴ・事例を出す許可

**既定は「出さない」**。出すのは、お客さんが選んで許可した範囲だけ(U-1)。

| 段 | 何を出すか | 誰の許可 |
|---|---|---|
| 出さない(既定) | 何も | — |
| 名前 | 「導入している会社」の一覧に会社の名前 | 会社(申込書の欄か、書面・メール) |
| 名前とロゴ | 上に加えてロゴ | 会社(ロゴの使い方の決まりがあれば従う) |
| 事例の記事・声 | 記事・引用・写真 | 会社と、**名前や顔を出す本人**(本人の同意は会社の許可とは別。個人データ) |

- **取り方**: 申込書の欄で選んでもらう([legal/order-form.md](../legal/order-form.md) の「導入事例・名前とロゴ」)か、後から書面・メールで。口頭だけで出さない。
- **記録の置き場**: **リポジトリの外**(契約の管理の置き場。申込書と同じ所)。会社の名前と許可の組み合わせをリポジトリに書かない。記録の欄:

  | 欄 | 中身 |
  |---|---|
  | 会社 | 組織の ID と会社の名前 |
  | 範囲 | 名前 / 名前とロゴ / 事例の記事・声 |
  | 許可した人 | 役職(と名前) |
  | 日付・取り方 | 申込書・書面・メール(写しの場所) |
  | 期限 | 無し / いつまで |
  | 取り消し | 取り消した日・外した日 |

- **出す前に**: 記録があるか・範囲に入っているかを確かめる。事例の記事は、公開の前に原稿をお客さんに見せて OK をもらう。
- **取り消されたら**: 自社のサイト・資料から **30日以内**に外す(U-2)。印刷した物・相手の媒体に載った記事は外せないので、許可を取るときにそう伝えておく。
- 解約したお客さん: 許可は解約で自動では消えない扱いにせず、**解約したら外す**(使っていない会社を「導入している」と見せない)。

## 5. 専門家に確かめること

- 比べる言い方・数字の言い方が、景品表示法などに当たらないか。
- 事例の記事でお客さんの社員の名前・写真を出すときの同意の取り方。
