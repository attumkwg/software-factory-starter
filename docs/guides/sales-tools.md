# CRM・MA・広告の道具を入れるとき(商談の記録は個人データ)

> 営業とマーケティングの道具(商談を記録する CRM・メールを送る MA・広告)は**キットの外**。この手引きは、入れるときに守ること: 委託先の台帳に1件・商談の記録は個人データ・AI に渡すのは ID と集計まで([security.md](../security.md) の AI-6)・アプリの利用者のデータを宣伝に回さない。
> 広告・解析の**タグを LP に置く**ときの決まり(同意の帯・外部送信・個人関連情報)は [landing-page.md](landing-page.md) の「計測」が正。ここでは繰り返さない。
> 法令の当てはめ(外部送信の決まり・個人関連情報・広告のメール)は専門家に確かめる。既定の値の未確定事項は設計書 [0041](../designs/0041-sales-tools.md) の U-1・U-2。

## 1. 道具ごとに、何が入るか

| 道具 | 例 | 入る物 | 区分 |
|---|---|---|---|
| **CRM**(商談・顧客の記録) | 表計算・HubSpot・Salesforce など | 相手の会社・**担当者の名前・役職・メールアドレス・電話**・商談のメモ・見積 | **personal** |
| **MA**(メールの配信・フォーム) | 配信の道具・フォームの道具 | 受け取る人のメールアドレス・開いた・押した の記録 | **personal** |
| 広告 | 検索・SNS の広告 | 広告の文・(タグを置けば)見た人の端末の情報 | LP に置くなら [landing-page.md](landing-page.md) |
| 名刺の管理 | 名刺の読み取りの道具 | 名前・連絡先・顔写真のこともある | **personal** |

- 道具の例は変わるので、選ぶときに公式で確かめる。料金と置き場所(国)も。
- **表計算で始めても同じ**: 商談の一覧は個人データ。共有の範囲・置き場所(どのサービスか)を決める。

## 2. 入れるときにそろえる物(同じ日に)

1. **委託先の台帳** `docs/compliance/vendors.yaml` に1件(危険度「高」。人の確認)。`pnpm vendors --write`。台帳は**使っている物だけ**を書く(候補は書かない)。CRM の例:

   ```yaml
   - id: crm
     name: <サービスの名前>
     status: active
     relation: 委託
     what: 商談と顧客の記録(営業・CS。docs/guides/sales-tools.md)
     country: <国>
     data: [personal]
     contract:
       dpa: <結んだ(日付)/ 約款に含む / 未確認>
       link: <DPA の URL>
     certifications: [<ISO/IEC 27001 など>]
     certifications_link: <URL>
     checked_on: <確かめた日>
     deletion:
       when_we_leave: <アカウントを閉じると、いつ消えるか>
       when_tenant_leaves: 解約したお客さんの担当者の記録を、いつ消すか(U-2)
     match: {}
   ```

   - コードやワークフローから呼ぶ(SDK・Actions)なら `match` に書く(書かないと `pnpm vendors` が落ちる)。手で使うだけなら空でよい。
2. **アカウント**は人ごと・二段階認証。入社・退職の手順の道具の一覧に足す([runbooks/joiner-leaver.md](../runbooks/joiner-leaver.md) の 0)。
3. **道具の AI の機能**(商談の要約・メールの自動の下書き・相手の情報の補完)は**切る**。商談の記録を AI の会社に預けることになる(台帳の決まりで、AI の会社に personal は預けない。AI-6)。
4. 外国の会社なら、越境の扱いを専門家に確かめる(委託先の台帳の `country`)。

## 3. 守ること

- **アプリの中(ログインの後の画面)に、広告・MA・解析のタグを入れない**。利用者の業務の画面を外の会社に送ることになる。タグを置くのは LP と公開のサイトだけ([landing-page.md](landing-page.md))。
- **アプリの利用者のデータを、宣伝に回さない**(U-1): アプリの DB の利用者のメールアドレスを MA に入れて宣伝のメールを送らない。宣伝を送るのは、LP の事前登録や展示会で**宣伝のメールに同意した人**だけ(特定電子メール法。止める道を必ず入れる)。お知らせ(障害・規約の変更・請求)は今のまま運営から。
- **CRM とアプリは ID で結ぶ**: CRM の会社の記録に、アプリの**組織の ID** を書く。アプリから CRM へ、利用者の名前・メールアドレスを自動で写さない。
- 使い方の数(誰がどの機能を使ったか)を CRM に送らない。商談に使うなら、組織ごとの集計(機能ごとの利用の数。[guides/feature-flags.md](feature-flags.md) の利用の記録)を人が見て書く。
- **リポジトリに商談の中身を書かない**: お客さんの名前・担当者・金額。賭けの小石や費用のページに書くのは、件数と率(何社に話した・何社が申し込んだ)まで。

## 4. AI に渡してよい範囲(AI-6 の当てはめ)

| 渡してよい | 渡さない |
|---|---|
| 組織の ID・商談の段階ごとの件数・受注の率・来た所ごとの数(UTM) | 担当者の名前・メールアドレス・電話・名刺の画像 |
| 人が分類した「失注の理由」ごとの数 | 商談のメモ・メールの本文の写し |
| 会社の業種・人数の帯ごとの集計(数社以上の束) | 1社だけの集計(会社が分かる) |

- 商談の傾向を AI に見てほしいときは、**人が CRM から件数と分類の表に落としてから**渡す。CRM の書き出しをそのまま貼らない。
- 話を聞いた記録(`docs/product/interviews/`)と同じく、名前・連絡先を書かない形でなら材料にできる。

## 5. 解約・やめたとき

- お客さんが解約したら、その会社の担当者の記録を **1年後**に CRM から消す(U-2)。また商談になるかもしれないので、すぐには消さない。消すまでの間、宣伝のメールは送らない(同意が無ければ)。
- 道具をやめたら: 書き出してから閉じ、委託先の台帳を `status: ended` と `ended_on` にする(消さない)。

## 6. 専門家に確かめること

- CRM・MA の会社が外国にあるときの扱い(外国にある第三者への提供か・委託か)。
- 展示会・名刺で受け取った連絡先に、宣伝のメールを送ってよいか(同意の取り方)。
- 解約したお客さんの担当者の記録を残す期間と、プライバシーポリシーの書き方。
