# 公開 API の変え方(版の決まり)

> API は、**何ヶ月も前の版の画面・スマホのアプリからも呼ばれる**(利用者は更新しない。SSR の画面も、デプロイの途中は古い版と新しい版が同時に動く)。
> だから **項目は足すだけ・消さない・意味を変えない**。壊す変更は CI(`ci.yml` の「API の互換」)が止める。

## いまの版

- `/api/...` が版1。**版の番号を URL に出していない**のは、壊さない限り版を上げないため。
- どうしても壊すときだけ `/api/v2/...` を足し、古い方はしばらく両方動かす(下の手順)。

## してよい変更・いけない変更

| してよい(足すだけ) | いけない(古い画面・アプリが壊れる) |
|---|---|
| 新しい API(パス)を足す | API を消す・パスを変える |
| 応答に項目を足す | 応答の項目を消す・名前を変える・型を変える |
| 入力に「無くてもよい」項目を足す | 入力に「必須」の項目を足す |
| 失敗の code(`ERROR_CODES`)を足す | 失敗の code を消す・意味を変える |
| 入力の制限を緩める(長さの上限を上げる) | 入力の制限を厳しくする |

- 判定は [oasdiff](https://github.com/oasdiff/oasdiff) が、PR の元と比べて行う(`breaking --fail-on ERR`)。
- 画面とアプリは、**知らない項目・知らない code が来ても動く**ように書く(例: `apps/web/src/errors.ts` は知らない code でも文を出す)。

## どうしても壊すとき

1. 新しい形を `/api/v2/...` として足す(古い `/api/...` はそのまま)。
2. 画面を新しい方に移す。スマホのアプリは、新しい方を使う版を出し、**古い版を強制的に更新させる**(スマホの手順書)。
3. 古い方が呼ばれていないのをログで確かめてから(少なくとも数ヶ月)、消す PR を別に出す。
4. CI の「API の互換」は、壊す PR では落ちる。人が中身を確かめ、**理由を PR に書いたうえで**、その PR だけ必須のチェックを外してマージする。

## 手元で確かめる

```bash
pnpm openapi
```

`apps/api/openapi.json` ができる(生成物なので git に入れない)。main の物と比べるときは、CI と同じ `docker run tufin/oasdiff breaking base.json head.json`。
