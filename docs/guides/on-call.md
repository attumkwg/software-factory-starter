# 当番の決まり(夜中にアラームが鳴ったら、誰が見るか)

> **当番を置くまでは**、アラームは Slack の `#alerts-prod` に流れ、営業時間に気づいた人が [runbooks/alarms.md](../runbooks/alarms.md) を見て動く([guides/monitoring.md](monitoring.md))。SLA の連絡の時間も「営業時間の中で数える」が既定([legal/sla.md](../legal/sla.md) の 6)。
> **当番を置くのは**、夜中や休日も連絡や復旧を約束する契約を結ぶ前(設計書 [0031](../designs/0031-on-call.md) の U-1)。置く日を決めたら、この決まりで回す。
> 決めた理由は [ADR 0042](../adr/0042-on-call-wake-only-for-customer-impact.md)。点検の台帳の `oncall-rota` が、半年ごとに体制を聞く。

## 1. 当番の表(3人から)

| 役 | やること | 何人 |
|---|---|---|
| **一次** | 鳴ったら応答する。[runbooks/alarms.md](../runbooks/alarms.md) の見出しで止血する。障害なら宣言して指揮をとる([runbooks/incident.md](../runbooks/incident.md) の 1・2) | 1人 |
| **予備** | 一次が応答しないとき・1人で手に負えないときに入る | 1人 |
| **上げる先** | お客さんへの知らせ・メンテナンスで止める・個人データの事故の判断。当番ではなく責任者(基本方針の最高責任者か、その人が決めた人) | 1人 |

- **3人から**。一次と予備を交代で回すなら、週ごとの交代で **4〜5人**いると、同じ人に深夜が続かない。
- 交代は**週ごと**(月曜 10:00)が既定。深夜の呼び出しが続く週が出たら、**日ごと**の交代に変える。
- **表はリポジトリに置かない**(人の名前・電話番号が入る)。呼び出しの道具(下の 6)か、チームのカレンダーに置く。リポジトリにあるのは、この決まりだけ。
- 人が足りないうちは、夜中を約束しない(SLA を営業時間で約束する)。1人で夜中も持つのは、続かない。

## 2. 連絡の段

| 何分 | 誰に | どうやって |
|---|---|---|
| 0分 | 一次 | 呼び出しの道具(電話かアプリの通知)。同時に Slack の `#alerts-prod` |
| 15分応答が無い | 予備 | 同じ |
| さらに15分応答が無い | 上げる先 | 同じ |

- **応答**とは、Slack のスレッドに「見ています」と書く(か道具で「受けた」を押す)こと。直すことではない。
- 営業時間は、Slack を見ている人が15分以内に応答する(道具で起こさない)。
- 応答の時間(15分)は設計書 0031 の U-2。

## 3. 夜と休日は、お客さんに影響があるときだけ起こす

**起こすのは「お客さんが使えない・使えなくなりそう」か「約束の水準(SLA)を割りそう」か「データが漏れたかもしれない」とき**。それ以外は朝(次の営業時間)にまとめて見る。

| アラーム([guides/monitoring.md](monitoring.md) の 2) | 夜と休日 | なぜ |
|---|---|---|
| `uptime-web` / `uptime-api` | **起こす** | 外から開けない = 全員が使えない。SLA の停止の分に入る |
| `api-target-5xx` / `web-target-5xx` / `elb-5xx` | **起こす** | 利用者の操作が失敗している |
| `{api,web}-unhealthy-hosts` / `{api,web}-running-tasks` | **起こす** | 台数が減り、続けば止まる |
| `sensitive-key-*`(要配慮の鍵)・管理操作の記録の root の利用と、記録を止める操作 | **起こす** | 漏えいのおそれ。知った時点から期限が始まる([runbooks/personal-data-breach.md](../runbooks/personal-data-breach.md)) |
| Security Hub の CRITICAL | **起こす** | 乗っ取りのおそれ([runbooks/secret-leak.md](../runbooks/secret-leak.md)) |
| `task-stops` | 朝 | 5xx・台数が一緒に鳴っていなければ、利用者は困っていない |
| `slow` / `db-cpu` / `db-capacity` / `db-connections` | 朝 | 遅いが使える。5xx が一緒に鳴ったら、そちらで起きる |
| `mail-running-tasks` / `ses-bounce-rate` / `ses-complaint-rate` | 朝 | メールは手前で待っていて消えない([runbooks/mail-not-delivered.md](../runbooks/mail-not-delivered.md)) |
| `waf-hits` | 朝 | 止めている間は守れている。5xx が一緒なら、そちらで起きる([runbooks/attack.md](../runbooks/attack.md)) |
| RDS のイベント・AWS Backup の失敗 | 朝 | 1回なら次の日を見る([runbooks/db-restore.md](../runbooks/db-restore.md) の 6) |
| Security Hub の HIGH・`cert-expiry`・Budgets | 朝 | 期限まで日がある |

- **どのアラームにも手順書の見出しが結んである**(アラームの説明に `docs/runbooks/alarms.md#<名前>` か、その手順書の節)。アラームを足すときは、手順書の見出しと、この表の「夜と休日」を一緒に足す。
- 迷ったら起こす側に倒し、翌日にこの表を直す(起こしすぎは、しきい値を上げて直す)。

## 4. 当番の間は、改善だけ

- 当番の週は、ふだんの機能の開発を受け持たない。やるのは:
  - 鳴りすぎ・鳴らなすぎのしきい値を直す([guides/monitoring.md](monitoring.md) の 2 の表も)
  - 手順書の通りに動けなかった所を直す
  - 振り返りの再発防止の Issue([runbooks/incident.md](../runbooks/incident.md) の 6)
  - 点検(`/checkup`)
- 夜中に起こされたら、次の日の朝は休む(設計書 0031 の U-2)。

## 5. 交代のときの引き継ぎ(5分)

Slack の当番のスレッドに、次の人へ1回書く:

- 鳴った物と、それぞれどうしたか(アラームの名前・時刻・止血・Issue)
- まだ続いている物・様子を見ている物
- 直したしきい値・手順書

## 6. 呼び出しの道具

- **Slack だけでは夜中に起こせない**(通知を切っている人が多い)。当番を置くなら、電話かアプリで鳴らす道具(PagerDuty など)を入れる。
- 入れるとき:
  1. 委託先の台帳 `docs/compliance/vendors.yaml` に1件足す(渡すのはアラームの名前と時刻だけ。個人データは渡さない)。`pnpm vendors --write`。
  2. 知らせの道(SNS)から道具へつなぐ。2本ある: 東京の `<名前>-alerts` と、外形監視のバージニアの `<名前>-uptime-alerts`。**両方**つなぐ(外形監視を落とすと、いちばん大事な「開けない」が鳴らない)。Terraform の `modules/alerts`・`modules/uptime` の変更(危険度「高」)。
  3. 道具の側で、上の 3 の表のとおり「起こす / 朝」を分ける(アラームの名前で分ける)。
  4. 試しに stg のアラームを1つ鳴らし、一次 → 予備 → 上げる先まで届くことを確かめる。
- 24時間365日を自前の数人だけで回すのは無理がある。人が増えるまでは、SLA を営業時間で約束する方が続く。

## 7. SLA との対応

| SLA の項目([legal/sla.md](../legal/sla.md)) | 当番を置く前 | 当番を置いた後 |
|---|---|---|
| 連絡の時間の数え方(6) | 営業時間の中で数える。外は努力 | 夜と休日も数えられる(3 の「起こす」に当たる物だけ) |
| 最初の知らせ(S1 30分・S2 1時間) | 営業時間の中 | 起こしてから。2 の段で最長30分かかるので、夜中の S1 は「応答から30分」にするかを契約で決める |
| 停止の事実の確定(7) | 指揮(営業時間に気づいた人) | 指揮(一次の当番) |
| 例外を認める人(7) | 責任者 | 責任者(= 2 の上げる先) |

## 8. 専門家に確かめること

- 夜中の待機(呼ばれたら動ける状態でいること)を、働いた時間として扱うか・手当をどうするか(社会保険労務士など)。
