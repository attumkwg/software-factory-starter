# お客さんのデータはどこに・いつまで残るか

> 解約の手順([runbooks/offboarding.md](../runbooks/offboarding.md))と、**契約書・利用規約・プライバシーポリシーの「データの保存と削除」**の元になる表。仕組みや期間を変えたら、この表と契約の文面を一緒に直す。
> 期間は Terraform の既定の値。環境ごとに変えていたら、その値に読み替える。

## 1. 置き場所と、消した後に残る期間

| 置き場所 | 中身 | 解約で消す(削除のコマンド) | 消した後も残る期間 | なぜ |
|---|---|---|---|---|
| DB(Aurora) | 組織・利用者・プロジェクト・タスク・監査ログ・サポートの許可と入室・送信待ち | **すぐ消える** | — | |
| Aurora の自動バックアップ | DB の写し(時点復元) | 消せない | **14日**(prod の `backup_retention_days`) | 期限で自動で消える |
| AWS Backup の保管庫(毎日) | DB の写し | 消せない | **35日** | 保管庫のロック(誰にも消せない) |
| AWS Backup の保管庫(毎月) | DB の写し | 消せない | **365日** | 同上。「先月末に戻したい」に答えるため |
| Cognito | ログインのメール・パスワード(のハッシュ)・二段階認証 | 手順書の 3 で消す | — | |
| CloudWatch Logs(アプリのログ) | ID(組織・利用者・リクエスト)・失敗の種類。**題名・本文・メールアドレスは出さない決まり** | 消さない | **90日**(prod の `log_retention_days`) | 期限で自動で消える |
| Sentry | 失敗の種類・スタック・ID(値は伏せる) | 消さない | Sentry のプランの保存期間(既定 90日) | 同上 |
| 送ったメール | 相手の受信箱にある物 | 消せない | — | こちらの手を離れている |
| 書き出したファイル | お客さんの手元 | 消せない | — | お客さんの物 |

- **バックアップの中から1社だけを消すことはできない**(写しは全社まとめて)。上の期間が過ぎれば、自動で消える。期間の内にバックアップから戻すことがあっても、**消した組織は戻さない**(戻したら、その組織だけ削除のコマンドをもう一度流す)。
- いちばん長く残るのは、**毎月のバックアップの最長 365日**。契約には「解約から最長1年(と数日)で、バックアップからも消える」と書く。

## 2. 契約・規約に書くこと(下書き)

> 解約日から○日以内に、お客様のデータを当社のシステムから削除します。削除の前に、管理者の画面からデータを書き出せます。バックアップに含まれるデータは、バックアップの保存期間(最長1年)が過ぎると自動で削除されます。その間、バックアップからお客様のデータを戻すことはありません。

- ○日は、運営が手順書を回せる日数で決める(例: 30日)。
- 個人情報の扱い(利用者の削除の依頼)も同じ表で答えられる。1人だけを消すのは、いまはコマンドが無い(利用者の削除・匿名化は次の一歩)。

## 3. 次の一歩

- テナントごとの KMS の鍵(大きなお客さん向け): 鍵を消せば、バックアップの中のその組織のデータも読めなくなる(暗号による消去。my-life の security.md 4.3 の 5)
- 利用者を1人だけ消す・匿名化する(監査ログの「誰が」は ID のまま残る)
- 監査ログの保存期間を決めて、過ぎた分を消す(`app.audit_purge` の仕組みは入っている)
