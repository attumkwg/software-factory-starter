# ラベルの手引き(何のラベルか・誰が付けるか・付いたらどうするか)

> この1枚は [.github/labels.yml](../../.github/labels.yml)(ラベルの一覧。ここが正)から `pnpm setup:labels` で作る。手で直さない。
> ラベルは `pnpm setup:github --apply` が GitHub に作る([github-setup.md](github-setup.md))。GitHub の画面のラベルの説明は、下の表の短い版。

## まず覚えること

- **ほとんどのラベルは自動で付く。** PR の危険度と場所は変えたファイルで(labeler)、Issue の種類はテンプレートで、依存の更新は Renovate が、点検の知らせは checkup.yml が付ける。
- **人が手で付けるのは `restore-drill`・`vrt:update` だけ。** ほかに、仕分けた Issue から `needs-triage` を外す。
- いちばん大事なのは **`risk:high`**(危険度「高」)。付いた PR は、マージの前に人が中身を読む。
- 一覧に無いラベル(GitHub の既定の `bug` など)は使わなくてよい(消してもかまわないが、セットアップは消さない)。

## 危険度(PR)

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `risk:high` | 間違えると戻せない・守りが外れる場所(認証・認可・DB と移行・権限の表・infra・CI・AI のハーネス)を変えた PR | 自動(labeler。.github/labeler.yml のパス) | PR を開いた・push したとき。複数付いたら一番高いものがその PR の危険度 | 人が中身を読む(👥 人が増えたら2人。CODEOWNERS)。PR の「人に判断してほしい所」から読む |
| `risk:medium` | API・画面・部品の中身を変えた PR(高の場所は含まない) | 自動(labeler) | PR を開いた・push したとき | 人は全体像と「人に判断してほしい所」を見る(細かい所は CI と AI のレビュー) |
| `risk:low` | 変えたファイルが全部、文書かテストの PR | 自動(labeler)。不具合の Issue には /report-bug が見込みで付ける | PR を開いた・push したとき | CI が緑ならマージしてよい(最初の1〜2か月は人も見て、AI の見逃しを数える) |
| `tests:weakened` | テストのファイルを消した・skip や only を足した・expect や assert が減った・カバレッジの下限を下げた・biome-ignore などの注釈を足した PR(G-60) | 自動(test-weakening.yml。差分の形から)。見つからなくなれば外れる | PR を開いた・push したとき | PR の本文に、なぜ弱めたか(古いテストを消した・不安定な E2E を一時的に飛ばす など)が書いてあるかを人が見る。無ければ /rework。危険度「高」とみなし、人の承認の人数を数える |

## 変えた場所(PR)

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `area:api` | API(apps/api)を変えた PR | 自動(labeler) | PR を開いた・push したとき | 何もしなくてよい(PR を探す・数えるための印) |
| `area:web` | 画面(apps/web)を変えた PR | 自動(labeler) | PR を開いた・push したとき | 何もしなくてよい。見た目が変われば VRT の結果が PR のコメントに出る |
| `area:infra` | インフラ(infra/terraform)を変えた PR | 自動(labeler) | PR を開いた・push したとき | 何もしなくてよい。apply はマージの後に人が CI で |

## 数えるための印(PR)

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `ai:assisted` | AI(Claude Code など)が書いた・手伝った PR。週の数字(pnpm metrics)の「AI が手伝った PR の割合」「人の介在率」と、費用のページの人の時間が数える | 自動(ai-label.yml。本文に docs/cost/people.yaml の ai_markers がある・AI のボットが作った PR)。印の無い AI の PR は人が手で付ける | PR を開いた・本文を直したとき(付けるだけで外さない) | 何もしなくてよい。間違って付いたら外し、本文の印も消す(残っていると本文を直したときにまた付く) |

## Issue の種類・仕分け

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `kind:bug` | 不具合の報告の Issue | 自動(Issue のテンプレート「不具合」)・AI(/report-bug) | 不具合の Issue を作ったとき | 再現の手順と危険度を見て、直すなら /rework か /new-feature で PR に |
| `kind:feature` | 機能の要望・機能の親 Issue | 自動(Issue のテンプレート「機能」)・AI(/new-feature) | 機能の Issue を作ったとき | 賭け(/bet)が無ければ先に開く。仕様と子 Issue は /new-feature |
| `needs-triage` | まだ誰も中身を見て仕分けていない Issue | 自動(Issue のテンプレート)・人(Slack のフォームから来た Issue) | Issue を作ったとき | 週に1回まとめて見て、やる・やらない・後で を決めたら外す |

## 依存の更新

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `dependencies` | 部品(ライブラリ・Action・イメージ)の版を上げる PR | 自動(Renovate。renovate.json) | 更新の PR が出たとき(毎週月曜の朝・最大5本) | CI が緑で危険度「低」ならまとめてマージ。大きい版は Dependency Dashboard の Issue で承認してから |
| `security` | 既知の脆弱性を直すための依存の更新の PR | 自動(Renovate の脆弱性の直し) | 直った版が出たとき(いつでも。待たない) | 先にマージする。届くか・ほかに要る直しがあるかは /cve で |

## 点検の知らせ

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `checkup` | 点検(docs/checkup/todo.yaml)の知らせの Issue | 自動(checkup.yml。毎週月曜 8:00) | 毎週の「点検 YYYY-Www」と、急ぎの Issue を作ったとき | Claude Code で /checkup と打って1問ずつ答える(Issue のチェックは「やった」の印だけ) |
| `checkup-urgent` | 守りが外れた・重い穴が開いている・秘密が漏れた など、すぐ直す物 | 自動(checkup.yml。毎日 8:00) | 急ぎの確かめが落ちたとき(1件ずつ) | その日のうちに直す。直れば次の朝に自動で閉じる |

## 記録

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `restore-drill` | DB を戻す訓練の結果を残した Issue | 人 | prod の戻す訓練(四半期に1回・手で)の結果を Issue に書いたとき | 何もしなくてよい(点検と監査のときに、訓練をした証拠として探す) |

## 見た目の回帰テスト(PR)

| ラベル | 何のラベルか | 誰が付けるか | いつ付く | 付いたら何をするか |
|---|---|---|---|---|
| `vrt:update` | 見た目の比べ(VRT)の基準の画像を、GitHub の上で撮り直してほしい印 | 人(手元に Docker が無いとき) | 画面をわざと変えた PR で、VRT が赤のとき | CI が撮り直し、取り込む1行が PR のコメントに出る。取り込んでコミットしたらラベルを外す |

## ラベルを足す・変えるとき

1. `.github/labels.yml` に1件足す(名前・色・短い説明・何のラベルか・誰が・いつ・付いたらどうするか・使っている所)。
2. `pnpm setup:labels` でこの1枚を作り直す。`pnpm setup:check` が、コードが使うラベルが一覧にあるか・この1枚が古くないかを見る(CI でも)。
3. PR をマージしたら、`pnpm setup:github --apply` で GitHub にも作る。
