# 8. 売る(言葉・ブランド・LP・広報・営業)

> 入口は [README.md](README.md)。人は [companies.md](companies.md)。判定の印: ✅ 回る / 🟡 人の手か外の道具で回る / ❌ 穴([gaps.md](gaps.md))。
> 「📚 世の中では」は、公開の事故報告・登壇・記事から一般化した学び(2026-10 時点。出どころは書かない)。決める順番は [fit-journey.md](fit-journey.md) の 2(言葉 → LP → 色)。
> キットは開発の雛形なので、広告・CRM・会計などの道具そのものは持たない。持つのは **決める段取り・記録の置き場・プロダクトとつながる所**(申込から開通・デモ・計測と同意・委託先の台帳)。

## 8-1 売り文句を決める(A 社・2人 → 5人)

- 👩‍💼 佐藤: 話を聞いた8人の言葉と、試作で効いた所から、「誰の何を、どう変えるか」を1行にしたい。展示会のチラシにも LP にも同じ言葉を使いたい。
- 🤖 Claude にできること: `docs/product/interviews/` の相手の言葉・賭けの小石(何が効いたか)・`plan.md` の代わりの物と不満を並べ、約束の案を3つ・売り文句(キーワード)の案・代わりとの違い・言わないこと(約束できない物)を出す。
- 判定: ✅ 回る(G-31 済み。仕様 0023・ADR 0037)。`/positioning` が話の記録・小石・代わりの物から、約束・売り文句・代わりとの違い・言わないことの案を `docs/product/positioning.md` に出す。決めるのは人。
- 足す前の判定: ❌ **約束と売り文句を決める段と置き場が無い**(穴 G-31)。材料はキットに溜まるのに、つなぐ手順が無い。

## 8-2 ブランド(名前・トーン・色)を決めて、デザインシステムに入れる(A 社・5人)

- 🎨 デザイナー(山本): 約束が「現場の写真が勝手にそろう」なら、相手は現場の職人と事務。屋外のスマホで見やすい・手袋でも押せる・頼れる感じの色にしたい。
- 🤖 Claude にできること: 約束と相手から色の案を2〜3つ出し、`packages/ui/src/tokens.css` の主な色(`--color-primary` など)に置き換えた案を PR に。コントラストの比を計算して添える。画面とデザインシステムの一覧のスクショは VRT が PR に貼る。
- ✅ ある物: トークン・生の色コードを止める Semgrep・axe のコントラストの検査・VRT・部品の一覧ページ。
- 判定: ✅ 回る(G-32 済み。仕様 0024)。`/brand` が約束と相手から名前(仮)・トーン・色の案を出し、`tokens.css` の PR(コントラストの比・VRT のスクショつき)にする。決めるのは人。
- 足す前の判定: 🟡 入れる仕組みはある。**約束と相手から名前・トーン・色を決める段取りが無い**(穴 G-32)。決めるのは人(デザインシステムの決まり)。

## 8-3 LP を出して、事前登録を集める(A 社・5人)

- 👩‍💼 佐藤: 業界の記事と、工務店の会のメールから人を呼び、事前登録を集めたい。どこから来た人が申し込んだかも知りたい。
- ✅ ある物: 試作(`/prototype`)の申し込みのページ。利用目的と同意を付ける決まり。
- 判定: ✅ 回る(G-33 済み。仕様 0025・ADR 0038)。公開の LP は `apps/site`(本番だけ検索に載る・どこから来たかの計測は同意と公表つき・事前登録の記録・プライバシーポリシー)。決まりは [../guides/landing-page.md](../guides/landing-page.md)。CMS で作るなら、言葉と色を写す段取りと、事前登録を組織につなぐ所だけ使う。
- 足す前の判定: ❌ **公開してよい LP の型が無い**(穴 G-33)。試作は本物と混ぜない守りのため、**検索に載らない(noindex)・計測を入れられない**。LP には、検索に載る・どこから来たかを測る(Cookie などで外へ送るなら同意と公表。外部送信の決まりがかかることがある)・事前登録の記録(利用目的と同意)・プライバシーポリシーへのリンク、が要る。
- 📚 世の中では: 宣伝のサイトは CMS で作ることが多い。キットの外で作るなら、**同じ約束と言葉・同じ色**をそこに写す段取りと、事前登録を本物の組織につなぐ形(8-6)だけキットで持てばよい。

## 8-4 広報(A 社・10人)

- 👩‍💼 佐藤: 正式に出す日に、業界紙・地域の新聞・工務店の会に知らせたい。展示会にも出る。
- ✅ ある物: `/release-notes`(利用者向けと社内向けのリリースノート)・規約の変更のお知らせ。
- 判定: ✅ 回る(G-38 済み。仕様 0040)。`/release-notes` から広報の文を下書きし、導入事例の公開の許可は記録の置き場に残す([../guides/announcements.md](../guides/announcements.md))。出すのは人。
- 足す前の判定: 🟡 **お知らせ・プレスリリースの型と、導入事例の公開の許可の記録が無い**(穴 G-38)。お客さんの会社の名前やロゴを出すには許可が要る(契約・申込書で取るか、個別に取る)。

## 8-5 営業する(A 社・10人/B 社)

- 🤝 営業(中村): 商談でデモを見せたい。見積を出し、申込書を受け、稟議の資料(セキュリティの答え・SLA)も渡したい。
- ✅ ある物: 種データの2社(手元とプレビュー)・規約の版と同意・セキュリティの決まりと管理策の一覧(質問票の材料)。
- 判定: ✅ 回る(G-35 済み。仕様 0053・ADR 0064)。デモ用の組織(stg で `demo-reset` で戻す)・見積から申込の流れ・稟議の資料の束(`pnpm sales:pack`。申込書・SLA・取り扱い・委託先を1つに)。[../guides/sales.md](../guides/sales.md)。
- 足す前の判定: ❌ **営業の道具が無い**(穴 G-35): 毎晩きれいに戻るデモ用の組織・見積から申込までの流れ・稟議の資料の束(申込書・SLA の型 G-04 と質問票の下書き G-20 から作る)。
- 📚 世の中では: 営業・CS の分業は受け渡しで揉める。商談の記録には相手の名前と連絡先が入るので、外の道具(CRM)は委託先の台帳に1件・AI に渡すのは ID と集計まで(穴 G-37)。

## 8-6 申込から開通へつなぐ(A 社・10人)

- 🤝 営業 → 🎧 CS: 事前登録・申込書の会社を、本物の組織にして最初の管理者を招く。
- 判定: ✅ 回る(G-01・G-02 済み)。事前登録の記録から `create-tenant --from-pre-registration` で組織を作り、最初の管理者に招待が届く。その人が画面から同僚を招く。
- 足す前の判定: ❌ 組織を作るコマンドと招待の画面が無い(穴 G-01・G-02)。事前登録の記録(LP)と申込書の項目を、そのまま `create-tenant` の入力にできる形にしたい。

## 8-7 どの届け方が効いたかを測る(A 社・10人 → B 社)

- 👩‍💼 佐藤: 展示会・記事・紹介のどれから来たお客さんが、続けて使って払っているか。1社を取るのにいくらかかったか。
- ✅ ある物: 費用のページ(インフラ・SaaS・人の時間・賭けごとの損益)。
- 判定: ✅ 回る(G-36 済み。仕様 0043)。費用のページが広告費と営業の時間から1社を取るのにいくらかを出し、届け方ごとの賭け(線・期限・小石)は [../guides/bets-and-assets.md](../guides/bets-and-assets.md) の「届け方の賭け」。
- 足す前の判定: ❌ **獲得のコスト(広告費・営業の時間)と、届け方ごとの賭けが無い**(穴 G-36)。賭けは機能ごとで、「この届け方は効くか」を同じ形(線・期限・小石)で確かめる型が無い。
- 📚 世の中では: 獲得のコストを1年以内に回収できるか・顧客の生涯の売上が獲得のコストの3倍以上か、が事業として成り立つかの目安とされる(多くは米国の数字)。

## 8-8 線に届かないが、それでも出す(A 社・5人)

- 👩‍💼 佐藤: 試作の結果は撤退の線に当たった。それでも「職人に撮らせられるなら欲しい」が2人いたので、5社に出したい。
- ✅ いまのキット: 「進む」と書けば止めない(2026-10-25 の通しの試しで確かめた)。
- 判定: ✅ 回る(G-29 済み)。`/bet` の「意思で進む」で、引き受けた危なさ・止める線・期限・決めた人を残す。キットは止めず、`pnpm bets` が ⚑ で出し、止める線の期限を過ぎたら知らせる。
