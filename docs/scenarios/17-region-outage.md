# 17. 東京リージョンが半日止まる(気づく・知らせる・待つか移すか・SLA・バックアップの置き場所)

> 入口は [README.md](README.md)。人は [companies.md](companies.md)。判定の印: ✅ 回る / 🟡 人の手か外の道具で回る / ❌ 穴([gaps.md](gaps.md))。
> 05 の障害(5-5・5-6)は「自分たちの変更や負荷で落ちた」。この台本は、**クラウドの東京リージョンそのものが広く止まり、半日戻らない**場面を通す。手順書の入口は [../runbooks/incident.md](../runbooks/incident.md)。
> 2026-10-27 に、キットの main の Terraform(`envs/prod`・`modules/backup`・`modules/uptime`)・手順書・SLA の型・設計判断を読んで判定した(止まったときの切り替えは試していない)。「📚 世の中では」は、公開の障害の報告・登壇・記事から一般化した学び(出どころは書かない)。

## 📌 いまの結論(2026-10-27)

- **気づく・宣言する・知らせるは回る**。外形監視は東京・シンガポール・オレゴンの3か所から見て、アラームは米国東部(us-east-1)に置いてあるので、東京が止まっても Slack に鳴る。稼働状況のページは自分の AWS の外に置く決まり(ADR 0043)。知らせの型(S1 は30分以内)がある。SLA の型は「東京のリージョン全体にまたがる障害」を数えない区分にしてある。
- **1つの AZ が止まるのは、本番は耐える**(DB は2台・NAT は AZ ごと・API と画面は2台から)。
- **東京が丸ごと止まると「待つ」しか選べない**(穴 G-93)。DB の写し(自動バックアップ・消せない保管庫)は同じアカウントの同じ東京にあり、鍵(KMS)も東京。Terraform の状態のバケット・イメージ(ECR)・ログイン(Cognito)・秘密も東京。別のリージョンに戻す材料が無い。これは今の段階では正しい選択でもある(ADR 0012 の「見直す合図」は、契約で災害時の復旧を約束したら)。
- **ただ「待つ」と決めた形が書いていない**(G-94)。何時間で何を決めるか・誰が決めるか・復旧の目標(どのくらいで戻し、どこまで失ってよいか)を、お客さんにも社内にも言えない。
- いちばん先は **G-94(待つ判断と目標の時間を書く)**。小さく安い。G-93(別のリージョンの写し)は、目標の時間を約束するお客さんが来てから。

## 17-1 気づく(A 社・10人・平日の朝)

- 🔔 9:10 に `#alerts-prod` へ「外形監視: 画面と API が開けない」。同時に、AWS のコンソールも東京だけ重い。
- 🏭 テックリード 兼 EM(鈴木): 自分たちの変更か、クラウドの障害か。
- 判定: ✅ 回る。
  - ✅ 外形監視は3か所(`infra/terraform/modules/uptime` の `regions` に `ap-northeast-1`・`ap-southeast-1`・`us-west-2`)。ほとんどの地点から2分続けて開けないと鳴る([../legal/README.md](../legal/README.md) の 2)。アラームと知らせの topic は us-east-1(`infra/terraform/envs/prod/main.tf` の WAF と uptime の注記)なので、東京が止まっても届く。
  - ✅ 直前のデプロイ・Terraform・設定の変更が無いかを先に見る(incident.md の 3 の 1)。AWS の Health Dashboard を見る(alarms.md の `rds-events`)。
  - 🟡 東京の中に置いているアラーム(DB・ECS・メール)は、東京と一緒に止まりうる。「鳴らない」こと自体が合図になる、を手順書に書いていない(G-94 に含める)。

## 17-2 宣言して、お客さんに知らせる(A 社・10人)

- 🏭 鈴木: S1 で宣言し、指揮を自分にする。
- 🎧 CS(小林): 第1報を30分以内に。問い合わせが一度に来る。
- 判定: ✅ 回る(稼働状況のページを入れていれば)。
  - ✅ 重さ・役割・知らせの型(第1報・続報・復旧)は [../runbooks/incident.md](../runbooks/incident.md) の 1・2・4。事実だけ・内部の仕組みの名前(AWS のサービス名)は書かない決まり。
  - ✅ 稼働状況のページは自分の AWS の外([../guides/status-page.md](../guides/status-page.md)・ADR 0043)。本番と DNS が止まっても見える。
  - 🟡 稼働状況のページは「要るようになったら」入れる物。入れる前なら、知らせは管理者へのメール。**メールの中継と送信(SES)も東京にある**ので、障害の間はアプリからは送れない。手元のメールで送る宛先の一覧を、障害の前に持っておく決まりが無い(G-94 に含める)。
- 📚 世の中では: クラウドの広い障害では、自分たちに何もできない時間が長い。信頼を分けたのは「次の知らせの時刻を書いて、その時刻に必ず出した」か。直す手が無くても、知らせの約束は守れる。

## 17-3 待つか、別のリージョンへ移すか(A 社・10人・3時間たっても戻らない)

- 👩‍💼 代表(佐藤): 大口のお客さんから「午後の現場が回らない。別の場所で動かせないのか」。何時まで待つと決めればよいか。
- 判定: ❌ **選べるのは「待つ」だけで、その決め方が書いていない**(穴 G-94・G-93)。
  - ✅ 契約の側は備えがある: SLA の型で「東京のリージョン全体にまたがる障害」は数えない区分(不可抗力の範囲。専門家と決める。[../legal/sla.md](../legal/sla.md) の 3)。別のリージョンへの備えは「仕組みを変えれば変えられる」の段で、入れるまで契約に書かない([../legal/README.md](../legal/README.md) の 3)。
  - ❌ 復旧の目標(何時間で戻すか・どこまでのデータを失ってよいか)がどこにも無い。だから「待つ」と言い切る根拠も、「移す」と決める線も無い。
  - ❌ 手順書に「クラウドの広い障害」の節が無い(何時間ごとに何を決めるか・誰が決めるか・東京が戻ったときの確かめ)。(`alarms.md` の `rds-events` の failure から [../runbooks/db-restore.md](../runbooks/db-restore.md) へは 2026-10-28 に結んだ。)
- 📚 世の中では: 多くの会社は、半日の広い障害では「待つ」を選ぶ。移す作業そのものが新しい事故を起こすから(戻ってきた東京と、移した先の両方に書き込みが入る)。大事なのは、待つと**先に決めて書いておく**ことで、その場で迷わないこと。

## 17-4 別のリージョンで立ち上げられるか(A 社・10人・調べてみた)

- 🧑‍💻 エンジニア(伊藤): 大阪(か別の国)で動かすには何が要るか、障害の後に調べた。
- 判定: ❌ **戻す材料が東京にしか無い**(穴 G-93)。
  - ✅ Terraform のリージョンは変数(`infra/terraform/envs/prod/variables.tf` の `region`)。コードとイメージは GitHub から作り直せる(`deploy.yml`)。
  - ❌ DB の写しが東京だけ: Aurora の自動バックアップ(14日)も、AWS Backup の保管庫(`infra/terraform/modules/backup`。毎日35日・毎月1年)も、同じアカウントの東京。保管庫の鍵(KMS)も東京。別のリージョンへの写し(コピー)の設定が無い。
  - ❌ ほかにも東京にある物: Terraform の状態のバケット([../guides/manual-setup.md](../guides/manual-setup.md) の `-backend-config="region=ap-northeast-1"`)・イメージの置き場(ECR)・秘密(Secrets Manager)・ログイン(Cognito の利用者プール)・メールの送り元の確認(SES のドメイン)。**Cognito の利用者は別のリージョンへそのまま写せない見込み**(パスワードは持ち出せない。AWS の今の仕様で確かめる)ので、移すと全員がパスワードを決め直すことになる。
  - ❔ 写しを取る(保管庫のコピーを別のリージョンへ)のは月の費用が小さい。立ち上げまで用意する(状態・イメージ・秘密・ログインの写し・DNS の切り替え)と運用が大きくなる。どこまで持つかは事業判断。
- 📚 世の中では: 災害の備えには段がある。① 写しだけ別の場所に置く(戻すのに1日以上)② 立ち上げの手順と材料を置いて年に1回練習する(数時間)③ 別の場所でも常に動かす(数分・費用は倍)。最初は ① で十分なことが多く、「別の場所に写しがある」は情シスの質問票でもよく聞かれる。

## 17-5 病院から「災害のときも止まらないと言ったよね」(B 社・100人)

- 🏥 大きな病院の情シス: 契約の前の質問票に「バックアップを遠い場所に置いているか」「災害のときの復旧の目標は」とある。営業は「AWS だから大丈夫」と答えかけた。
- 判定: 🟡 **断る・上位の段にする形はある**。
  - ✅ 取り決めと SLA の型は、置き場所を東京とし、別のリージョンへのバックアップは「仕組みを変えれば変えられる」(上位のプラン・個別の見積もり)。守れない約束を書かない決まり([../legal/README.md](../legal/README.md) の 3)。`/security-questionnaire` は根拠のある「はい」だけを書く。
  - ✅ 消せない保管庫(compliance のロック)と、戻す訓練(`restore-drill.yml`。有効にすれば stg で毎月・prod は四半期に1回人が手順書どおりに)は、同じ東京の中の備えとして答えられる。
  - ❌ 「遠い場所」「復旧の目標」の答えの元が無い(G-93・G-94)。医療の業界のガイドラインが、遠隔地のバックアップや復旧の目標を求めるかは確かめていない。専門家に確かめる先の候補: 医療情報の安全管理のガイドライン(事業の継続・バックアップの置き場所)。
- 📚 世の中では: 「クラウドだから大丈夫」は質問票で通らない。聞かれるのは、どこに写しがあり、何時間で戻し、いつ練習したか。数字を書けないなら「同じ地域の中で、消せない写しと毎月の訓練まで」と正直に書いた方が通る。

## 17-6 東京が戻った後(A 社・10人)

- 🏭 鈴木: 15:30 に東京が戻った。データは失われていないか。SLA はどう数えるか。
- 判定: ✅ 回る(🟡 確かめ方は人)。
  - ✅ 戻った後の確かめ: 外形監視が緑・DB のイベント([../runbooks/alarms.md](../runbooks/alarms.md) の `rds-events`)・送り待ちのメール(EFS。渡せなければ最長5日でやり直す。[../guides/data-retention.md](../guides/data-retention.md))。
  - ✅ 振り返り(S1 は5営業日以内)に停止の時間と原因の区分を書き、それが SLA の事実の正([../runbooks/incident.md](../runbooks/incident.md) の 6・[../legal/sla.md](../legal/sla.md) の 7)。広い障害の区分は数えない。
  - 🟡 障害の間に「保存できなかった変更」を利用者が入れ直す案内は、知らせの型の復旧の文にある。外へ出す仕組み(outbox)の詰まりは、自動でやり直すかを確かめていない。

## 17-7 AZ が1つ止まる(A 社・10人・よくある方)

- 🔔 東京の中の1つの AZ が1時間止まった。
- 判定: ✅ 回る。本番は DB が2台(`instance_count = 2`。もう1台に切り替わるまで30秒〜1分 API が 503)・NAT は AZ ごと(`single_nat_gateway = false`)・API と画面は2台から(`min_count = 2`)。`rds-events` の failover は「戻っていれば何もしなくてよい」([../runbooks/alarms.md](../runbooks/alarms.md))。
