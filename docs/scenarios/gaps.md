> 2026-10-29 に、意義の判断役で棚卸しした([../kit/verdicts/2026-10-29-gap-triage.md](../kit/verdicts/2026-10-29-gap-triage.md))。決まりは「誰の・どんな困りごとが・どれだけ減るかを数で言えなければ、やらない」。まだいない人(2人目・デザイナー・営業・入社した人)の困りごとは「使えた後で」へ、専門家や会計ソフトの領分は「⛔ やらない」へ。「使えた後で」の行には、**再開の合図**(どの場面が来たら)を書く。

### 「使える」の条件

1. **通しで作れる**: 捨てるリポジトリで、手引きだけで clone → `/kickoff` → `/tailor`(軽い型)→ 題材を1機能差し替え → PR → CI 緑 → マージまで通る
2. **SaaS の一周が手元で動く**: docker compose の上の1本の E2E が緑(事前登録 → 開通 → 招待 → 機能と写真 → プラン → 書き出し → 人を外す → 1人分の削除 → 解約)
3. **守りが文書どおりに強制される**(承認の人数・テストを弱める変更・承認の書き換え・AI が読む文章の書き手)
4. **少人数で本番を回せる**(2人目の承認・戻すワークフロー・AI を止める手順・引き継ぎの置き場)
5. **お金をもらえる**(申込書・SLA・取り決めの数字が1つ・プラン・請求の手順・AI の費用の上限)
6. **書いてあることが今の姿**(`pnpm gaps` が緑)
7. **外の人に渡せる**(取り込みの道・番号の範囲・本物の AWS で確かめる物の一覧)
8. **頼めば作る**(持ち主の目指す姿。2026-10-28): Slack でクラウドの AI に1行で頼む → AI が PR → 「これでいいですか」に返事 → 必須のチェックが緑でマージ、が、**キットを使う側のリポジトリで**本物の依頼で1回通る(キット自身は Slack とつながない)
