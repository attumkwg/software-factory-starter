# 1. 企画 → 困りごとの確認(CPF)→ PMF

> 入口は [README.md](README.md)。人は [companies.md](companies.md)。判定の印: ✅ 回る / 🟡 人の手か外の道具で回る / ❌ 穴([gaps.md](gaps.md))。
> 考え方の本体は [../guides/before-pmf.md](../guides/before-pmf.md) と [../guides/bets-and-assets.md](../guides/bets-and-assets.md)。

## 1-1 キットを自分のリポジトリにする(A 社・2人・初日)

- 🧑‍💻 鈴木: キットから自分のリポジトリを作り、`pnpm install` → `pnpm test` → `docker compose up --build` で手元で動かす。`admin@globex.test` で Acme のデータが見えないことを確かめる。
- 🧑‍💻 鈴木: `pnpm setup:github`(試し)で差分を見て、`pnpm setup:github --apply`。最後に出る「人がやること」(Renovate の App・秘密の値)を片づける。
- 🧑‍💻 鈴木: `pnpm checkup:adopt --by @suzuki` で点検の台帳を自分の物にする。毎週月曜に点検の Issue が来るようになる。
- 判定: ✅ 回る。半日で終わる。⚠️ 非公開のリポジトリを GitHub Free で使うと、ブランチ保護と Environments が使えない(公開か Pro / Team に。[../guides/local-guards.md](../guides/local-guards.md))。

## 1-2 何を作るかを決める(A 社・2人・1週目)

- 👩‍💼 佐藤: Claude Code で `/kickoff`。「工務店の現場の写真が、職人の LINE に散らばっていて探せない」と一言。
- 🤖 Claude: 1問ずつ聞く(誰の困りごとか・どこまで確かめたか・いちばん危ない思い込み・確かめ方・合格と撤退の線)。競合と値段は Claude が下調べする。答えを `docs/product/plan.md` に書いて PR にする。
- 👩‍💼 佐藤: 「いちばん危ない思い込み」は「事務所の人が、写真を探すのに週に数時間使っている」。確かめ方は「工務店の事務の人 8人に、最後に写真を探したときの話を聞く」。合格の線は「8人中5人が週1時間以上」、撤退の線は「2人以下」。
- 判定: ✅ 回る。

## 1-3 話を聞く(A 社・2人・2〜3週目)

- 👩‍💼 佐藤: 知り合いの工務店から紹介をたどって8人に30分ずつ聞く。聞くのは過去の行動だけ(「使いますか」は聞かない)。
- 👩‍💼 佐藤: 1人1ファイルで `docs/product/interviews/` に、その日のうちに書く。**名前・会社名は書かない**(「B 工務店の事務の人」)。
- 👩‍💼 佐藤: 結果を持って、もう一度 `/kickoff`。基準と比べて「進む・変える・やめる」を決め、plan.md を直す。
- 判定: ✅ 回る。🟡 録音や文字起こしを外の道具でするなら、委託先の台帳(`docs/compliance/vendors.yaml`)に1件と、相手の同意が要る。

## 1-4 解決策を画面だけで確かめる(A 社・2人・4〜5週目)

- 👩‍💼 佐藤: `/bet` で最初の賭けを開く(`B-0001 現場ごとに写真を自動で並べる`)。親は plan.md の仮説。合格と撤退の線を先に書く。
- 🧑‍💻 鈴木: `/prototype` で押せる画面だけの試作(3〜5枚・偽のデータ・相手に頼むことの台本)。合言葉つきの URL で見せる。本物の API・DB・秘密を読むと CI が落ちる(`pnpm prototypes`)。
- 👩‍💼 佐藤: 話を聞いた8人のうち5人に見せ、「この画面で、先週の写真を探してください」と頼んで、迷った所を数える。
- 判定: ✅ 回る。費用は数十円。

## 1-5 お金を払うかを確かめる(A 社・2人・6〜8週目)

- 👩‍💼 佐藤: 試作に申し込みのページを足す(`/prototype`)。「月 9,800円・最初の3か月は半額」で事前の申し込みを取る。メールを集めるので、利用目的と同意をページに書く。
- 🤖 Claude: 特定商取引法などの表示が要るかは「お客さんが会社か個人か」で変わる、と添える(B2B なら多くは要らないが、法務に確かめる)。
- 判定: 🟡 申し込みのページまでは回る。**申し込んだ会社を「本物の組織」にする手順が無い**(穴 G-01)。お金の受け取りも無い(穴 G-03)。PMF の前は手で請求書を出せばよい。

## 1-6 少人数に使ってもらう → PMF の兆し(A 社・2人 → 5人・3〜6か月目)

- 🧑‍💻 鈴木: 題材の TODO を写真と日報に差し替える([../getting-started.md](../getting-started.md) の ②)。`/new-feature` で仕様 → `/design` → PR。stg を本番の代わりにして、5社に使ってもらう。
- 👩‍💼 佐藤: 毎週 `pnpm bets` で期限を過ぎた賭けを見る。「無くなったらとても困る」が40%を超え、使い続ける会社の割合が横ばいになったら PMF の兆し。
- 🧑‍💻 鈴木: 本番の前に `pnpm decisions --launch`。キットが既定で決めた所(導入時に決める 16件)を `/tailor` で1問ずつ決める。
- 判定: ✅ 開発のラインは回る。🟡 **お客さんの管理者が人を招く画面が無い**(穴 G-02)ので、5社に使ってもらう段で、毎回テックリードが SQL で人を足すことになる。

## 1-7 新しい客層を狙う(ムーンショット)(B 社・100人)

- 👔 CEO: 「診療所の次は、介護施設の問診」を、本業と別の賭けとして始めたい。
- 📝 PdM: プロダクト全体を「新しい版」として `/kickoff` からもう一度回す(PMF は繰り返せる。[../guides/bets-and-assets.md](../guides/bets-and-assets.md) の「2段の入れ子」)。
- 判定: 🟡 考え方はあるが、**`docs/product/plan.md` が1つだけ**で、本業の計画と並べて「2つ目の客層の計画」を持つ置き場が無い(穴 G-19)。予算と止める線は、費用のページの賭けごとの損益で見られる(→ [04-money.md](04-money.md))。
