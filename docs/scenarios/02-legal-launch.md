# 2. 法令の確認 → リリースの前の規約・申込書の整備

> 入口は [README.md](README.md)。人は [companies.md](companies.md)。判定の印: ✅ 回る / 🟡 人の手か外の道具で回る / ❌ 穴([gaps.md](gaps.md))。
> 「📚 世の中では」は、公開の事故報告・登壇・記事から一般化した学び(2026-10 時点。出どころは書かない)。
> ⚠️ キットは**仕組みだけ**を持つ。法令に当たるか・文面・契約の中身は、弁護士などの専門家と決める。ここに書く法令の名前は「確かめる先の候補」で、当たると言い切る物ではない。

## 2-1 この事業が法令の上でやれるかを洗い出す(A 社・2人/B 社)

- 👩‍💼 佐藤(A): `/kickoff` の下調べで、Claude が「関係しそうな法律・規制(個人情報・業界の規制・決済)」を一言伝える。
- 📝 B 社の PdM: 問診は病歴を扱うので、要配慮個人情報(取る前に本人の同意。個人情報保護法 20条2項)と、医療の情報を扱う事業者向けの国のガイドラインを確かめたい。病院からは「ガイドラインのどの項目に、どう対応しているか」の表を求められる。
- 🤖 Claude が出せる物: 個人情報の利用目的・委託・外国にある第三者への提供(個人情報保護法 28条)の論点、要配慮の分け方(ADR 0018・0029)、ログに残す物と残さない物。
- 判定: ✅ 回る(G-05 済み)。`/kickoff` が `docs/product/legal.md` に、作り・データ・相手から当てはまりそうな候補と専門家に聞くことを書き、`/bet` が機能を足すたびに見直す。判断は専門家。
- 足す前の判定: ❌ **法令・業界の決まりを洗い出して「専門家に聞くことの一覧」にする段が無い**(穴 G-05)。`/kickoff` の一言で終わり、確かめた結果の置き場も無い。例えば A 社が「事務所と職人のチャット」を足すと、他人の通信を媒介する形になり、電気通信事業の届出が要るかを確かめる必要が出る。こうした「機能を足したら確かめ直す法令」も、どこにも残らない。
- 📚 世の中では: 国の参入の手引きは「サービスの一部として**利用者どうしのメッセージを媒介する**なら届出が要る」と整理している(自社あての問い合わせは当たらない。外のチャットの部品を使っていても関係ないとは限らない)。届出をすると、Cookie などで利用者の情報を外へ送るときの公表・通知の決まりもかかる。医療機関と契約する SaaS は、提案するとまず国のガイドラインへの対応を聞かれ、委託先を選ぶときに ISMS か P マークを求められる。

## 2-2 利用規約とプライバシーポリシー(A 社・5人・本番の前)

- 🗂 管理(または代表): 規約とプライバシーポリシーのひな形(`apps/web/src/legal/`)を弁護士に見てもらい、版を足す([../guides/legal-documents.md](../guides/legal-documents.md) の「版を足す手順」)。
- 🧑‍💻 鈴木: プライバシーポリシーに、キットの作りから必ず入る物(ログに利用者の ID を90日・機能の利用の記録を400日)を入れる。登録の画面に同意のチェックがあり、同意の記録は DB と監査ログに残る。
- ✅ 点検の台帳の「利用規約・プライバシーポリシーを専門家に見てもらう」が、公開の前に知らせる。
- 判定: ✅ 回る(文面は専門家)。

## 2-3 申込書と契約の形(A 社・10人・営業が回り始めたとき)

- 🤝 営業(中村): 工務店から「申込書をください。会社の印鑑で出します」と言われる。プラン・人数・始まりの日・支払いの方法・契約の期間・解約の申し出の期限を書く紙が要る。
- 🤝 営業: 大きめのお客さんから「稼働率の約束(SLA)と、障害のときの連絡の時間は?」と聞かれる。
- 判定: ✅ 回る(G-04 済み。仕様 0028・ADR 0041)。キットの作りから決まる項目を埋めた型が [../legal/order-form.md](../legal/order-form.md)・[../legal/sla.md](../legal/sla.md)(測り方・原因の区分・補償の段・例外を決める人)・[../legal/quote.md](../legal/quote.md)。文面は専門家。
- 足す前の判定: ❌ **申込書(注文書)・SLA の型が無い**(穴 G-04)。キットの作りから決まる項目(バックアップの保存の期間・戻せる時点・解約後にデータが消えるまでの日数・障害の連絡の型・稼働の見張り)は、もう決まっているのに、営業が使える1枚になっていない。
- 📚 世の中では: 会社向けでは「社員が権限なく申し込む」のを防ぐため、申込書(電子でも)を求める流れにする。SLA は稼働率の数字だけ書いて違反したときの救済を書かないひな形が多く、法的な義務か努力義務かも曖昧になりがち。大企業は個別の契約書を求めることが多いので、変えてよい条件と変えない条件を先に分けておくと交渉が速い。

## 2-4 個人データの取り扱いの取り決め(A 社・10人/B 社)

- 🗂 管理(加藤): お客さんの工務店から見ると、A 社は施主の個人データを預かる**委託先**になる。「安全管理措置と、再委託先(AWS・Sentry など)を書いた書面をください」と言われる。
- 🤖 Claude: 再委託先の一覧は、委託先の台帳から作れる(`pnpm vendors --write` → `docs/compliance/vendors.md`。国・預け方・消え方つき)。安全管理措置の中身は `docs/security.md`・`docs/compliance/soa.md` にある。
- 判定: ✅ 回る(G-04 済み)。取り扱いの取り決めの型は [../legal/data-processing.md](../legal/data-processing.md)(再委託先・消えるまでの日数・連絡の型)。🟡 病院ごとの個別の覚書は、型を元に人と専門家で。
- 足す前の判定: 🟡 材料はそろっているが、**お客さんに渡す取り決めの型が無い**(穴 G-04)。B 社では、さらに病院ごとに個別の覚書になる。

## 2-5 セキュリティの質問票に答える(B 社・100人)

- 🤝 B 社の営業: 大きな病院の情シスから、200問のセキュリティの質問票(暗号化・権限・ログ・バックアップ・脆弱性の対応・委託先・事故の連絡)が届く。期限は2週間。
- 🤖 Claude が引ける所: `docs/security.md`(番号つきの決まり)・`docs/compliance/controls.yaml` と `soa.md`(管理策と適用)・委託先の台帳・手順書(漏えい・攻撃・戻す)・点検の台帳の答え。
- 判定: ✅ 回る(G-20 済み。仕様 0039)。`/security-questionnaire` が `docs/security.md`・SoA・委託先の台帳・手順書から、根拠のリンクつきの下書きを作る(下書きはリポジトリの外)。最後に確かめて出すのは人。
- 足す前の判定: 🟡 答えの材料は全部キットの中にあるが、**質問票に答えを下書きする手順(スキル)が無い**(穴 G-20)。毎回、営業とセキュリティの担当が手で探すことになる。
- 📚 世の中では: 質問票は50〜150問がふつう(100問で半日)。形式は会社ごとにばらばらで、同じ「バックアップは?」でも毎回書き直しになる。窓口は営業でも答えを持つのは情シス、根拠の書類は事務、で止まる。過去の回答と社内の資料から AI に一次の回答を下書きさせ、営業が15分で返せるようにした会社もある。「はい」と書いたら本当にそうでなければならないので、**根拠のリンクつきの下書き**にする。国の共通の物差し(サプライチェーンのセキュリティの評価制度。★3・★4 は 2026年度末ごろの開始の見込み)が始まると、質問票の一部はそれで置き換わりうる(穴 G-25)。

## 2-6 リリースの前の最後の確認(A 社・5人)

- 🧑‍💻 鈴木: `pnpm decisions --launch` が通る(導入時に決める物が0件)。`pnpm checkup` で「公開の前」の項目(外部の診断・規約を専門家に・二段階認証・管理者を2人)を確かめる。
- 🧑‍💻 鈴木: prod に apply したら3日のうちに、バックアップの保管庫の設定を確かめる(その後は誰も変えられない)。
- 👩‍💼 佐藤: 公開のサイト(料金・問い合わせ・会社の情報)を用意する。**キットの外**(作るなら CMS か、静かなページのサービス)で十分。
- 判定: ✅ 回る(G-11 済み。仕様 0033)。問い合わせの受け口の決め方と、受けた物の仕分け(`/report-bug` や Issue へのつなぎ方)は [../guides/support-intake.md](../guides/support-intake.md)。受け口の道具そのものはキットの外。
- 足す前の判定: ✅ キットの中は回る。🟡 問い合わせの受け口(フォーム・メール・ヘルプの記事)はキットの外で、そこから `/report-bug` にどうつなぐかが決まっていない(穴 G-11)。

## 2-7 規約を変える(A 社・10人・運用中)

- 🗂 管理: 料金の改定で規約を変える。利用者に不利な変更なので「同意し直し」(`reconsent: true`)。効力の日の30日前までに公開(CI が止める)。
- 🧑‍💻 鈴木: 運営のコマンド `legal-notify` でお知らせのメールを送る([../runbooks/legal-notice.md](../runbooks/legal-notice.md))。効力の日から、同意していない人は同意の画面へ。
- 判定: ✅ 回る。
