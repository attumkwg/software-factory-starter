# 想定の場面(このキットで本当に回せるか)

> 架空の2つの会社の人が、企画から運用までこのキットを使う台本。**どの場面で回り、どの場面で詰まるか**を確かめるために書いた。
> 使い始める人は「自分の会社だとどの場面か」を探して読む。キットを育てる人は、詰まった所([gaps.md](gaps.md))から足す。

## 📌 いまの結論(2026-10-25)

- **10人(A 社)までの開発・セキュリティ・お金の見える化は、キットのままで回る**。企画(`/kickoff`・`/bet`)→ 仕様と設計 → 危険度で分けたレビュー → 本番、ライブラリの更新と CVE、攻撃と漏えいの手順書、費用と賭けごとの損益まで、台本の上で詰まらない。
- **詰まるのは「お客さんを迎える所」**: 申し込みから組織を作る・お客さんが人を招く・プラン(契約)・申込書や SLA の型・法令の洗い出し・1人分の開示と削除。最初のお客さんからお金をもらう前に6つ要る(🔴)。
- **100人(B 社)では、さらに大きなお客さんの情シスの条件**(SSO・IP の制限・質問票)と、**人の出入り**(入社・退職のアカウント)と、**数字**(DORA・人の介在率・1社あたりの原価)が足りない。
- 後回しにしていたスマホのアプリ・SEO のサイト型・軽めのアプリは、両社の場面でも**まだ要らない**(要るようになる線は [gaps.md](gaps.md) の「後回しにしていた物の見直し」)。

## 判定の印

| 印 | 意味 |
|---|---|
| ✅ 回る | キットの仕組みと手順だけで回る |
| 🟡 人の手で回る | 手順か型はあるが、人の作業か外の道具が要る(それで良い所も含む) |
| ❌ 穴 | キットに無く、その場面で詰まる。[gaps.md](gaps.md) に番号(G-01 など)で並べた |

## 会社と人

[companies.md](companies.md): **A 社**(工務店向けの現場の写真と日報・2人 → 10人)と **B 社**(診療所・病院向けの Web 問診と予約・100人・要配慮個人情報)。営業・CS・エンジニア・EM・PdM・管理部門・セキュリティの担当まで。1,000人はキットの外。

## 使い方

- 📖 **使い始める人**: 自分の会社に近い方(A か B)と、いまの段階の場面を読む。❌ の場面に当たるなら、その穴を先に埋めるか、手作業で回す段取りを決めてから始める。
- 🎭 **演習する**: Claude Code で「`docs/scenarios/05-run.md` の 5-1 を、うちの会社に置き換えて一緒に演じて。私は CS の役」のように頼む。台本どおりに1歩ずつコマンドとスキルを回し、詰まった所を書き出す。
- 🔁 **キットを育てる人**: [gaps.md](gaps.md) の上から足す。足したら、穴の行を「済み」にして、場面の判定も同じ PR で直す。新しい部品を足したときは、どの場面の判定が変わるかを見る。

## 直すとき

- 場面は「いまの正」(キットの今の姿に合わせて直す)。部品が増えたら判定を直す。
- 法令の名前は「専門家に確かめる先の候補」として書く。当たると言い切らない。
- 実在の会社・人の名前を書かない(架空の2社のまま)。
