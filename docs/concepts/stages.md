# 段階と費用(PMF の前 → PMF の後 → 規模拡大)

> 入口は [README.md](README.md)。何をどこまで作り込むかは段階で変える。ただし**後から直すと高くつく所**は最初から固くする。
> 金額は **2026-10 時点の目安**(東京リージョン・定価・1ドル = 150円)。実際は使い方で2〜3倍ぶれる。このキットそのものの費用(stg・本番・プレビュー)は [../getting-started.md](../getting-started.md) の「月の費用の目安」。

## 1. 3つの段階

| | ① PMF の前(確かめる) | ② PMF の後(伸ばす) | ③ 規模拡大 |
|---|---|---|---|
| 目安 | 1〜3人・数十テーブル・数十社 | 5〜15人・〜数百テーブル・数百〜数千社 | 数十〜100人・数千テーブル・大企業も |
| 目的 | 速く作って捨てられる | 壊さずに速く伸ばす | 領域ごとに独立して回す |
| AI の PR(目安) | 週20〜50件 | 週50〜300件 | 週1,000件〜 |
| 月の費用 | **約7万〜11万円** | **約27万〜160万円** | **約1,500万〜2,000万円** |

何を作るかを確かめる段取り(PMF の前の進め方)は [../guides/before-pmf.md](../guides/before-pmf.md)。

### PMF の前: 雑でいい所と、雑にしてはいけない所

| 雑でいい(後から足せる) | 雑にしてはいけない(後から直すと高い・事故になる) |
|---|---|
| PR ごとの環境(stg を1つで回す) | 全テーブルにテナント ID+RLS |
| E2E は大事な流れ5本ほど | 認証は製品に任せる(自作しない) |
| キャッシュ・検索・分析の別建て | 秘密情報は Secrets Manager・GitHub からは OIDC |
| 監視は Sentry と基本のアラームだけ・当番なし | 本番とそれ以外の AWS アカウントを分ける |
| 外部の脆弱性診断(自前の検査と AI の診断で代える) | バックアップと、戻せることの確認 |
| 機能フラグ・段階的な公開 | 領域の境界(フォルダとスキーマを分けるだけでよい) |
| 指標(DORA など)の計測 | ログは標準出力の JSON+request ID |

- 💡 **PMF の前に「速さ」を一番くれるのは、雑さではなく AI**。インフラ定義やテストを省くより、AI に書かせて残すほうが、後で捨てるときも伸ばすときも楽。
- このキットが「土台(消さない)」としている部品は、右の列に当たる物([../kit/catalog.yaml](../kit/catalog.yaml) の `removable: false`)。

### PMF の後: ラインを全部そろえる

- PR ごとの環境・E2E 20本前後・危険度で分けたレビュー・背景エージェント・権限の表・監視と当番([line.md](line.md))。
- 大きな顧客に売る前に、**外部の脆弱性診断**を1回(テナントの分離を重点に。[../security.md](../security.md) の「外部の診断を頼むときの渡し物」)。

### 規模拡大: 領域ごとに分ける

- 下の 3 の段階表(M → L → XL)。DB を領域ごとに・キャッシュと検索を外へ・ログの階層化・基盤チーム。

## 2. 最初の日に決めておく8つ

数千テーブルのサービスは最初から数千あるのではなく、育ってそうなる。大事なのは「**育っても作り直さずに済む決め方を、最初の日にしておく**」こと。キャッシュや分割そのものは、数字が要ると言ってから足せばよい。

| 決めること | 中身 | 後から変えると | このキットのどこ |
|---|---|---|---|
| 領域の境界 | モジュラーモノリス。領域ごとにフォルダと Postgres のスキーマを分け、他の領域の表を直接読まない | 全部が全部を読み、分けられなくなる | `apps/api/src/domains/`・[ADR 0004](../adr/0004-domain-boundaries.md) |
| テナント ID | 全テーブルに組織の ID。RLS と分割のキーになる | 全テーブルの作り直し | [ADR 0001](../adr/0001-shared-tables-with-rls.md)・[../security.md の T-1〜T-9](../security.md#層を重ねて守るt-1t-9) |
| ID の形 | UUIDv7(時刻順に並ぶ)。連番を外に出さない | 分割・統合のたびに衝突 | `apps/api/src/db/columns.ts` |
| 移行の作法 | 「足す → 両方書く → 移す → 消す」の段階移行。消すのは別の PR | 本番がロックで止まる | `.claude/skills/db-migration`・squawk |
| イベントの出し方 | 変更を同じトランザクションで「送信待ち」の表に書く(アウトボックス) | キャッシュ消しや連携が取りこぼす | [ADR 0006](../adr/0006-outbox.md) |
| ログとトレースの ID | 全部のログに request ID・tenant ID | 障害の調査ができない | `packages/logging` |
| 時刻とお金 | 時刻は UTC で保存、お金は整数(円・セント) | 集計のずれ・丸めの事故 | [ADR 0005](../adr/0005-money-and-time.md)・`packages/shared` の `money.ts`・`time.ts` |
| 公開 API の版 | 項目は足すだけ。壊すときは版を分ける | 古いクライアントが壊れる | CI の「API の互換」(oasdiff) |

- 🤖 これらを **CLAUDE.md と lint・テストで強制**しておくと、AI が何千回 PR を出しても崩れない(例: 別の領域の表を import したら CI が落ちる)。

## 3. 規模に合わせて足すもの

| 段階 | 目安 | 足すもの |
|---|---|---|
| S | 〜100テーブル・〜数万人 | キットのまま(ECS+Aurora 1つ) |
| M | 〜500テーブル・〜数十万人 | 読み取り専用のレプリカ・アプリのキャッシュ(Valkey)・重い処理をキューへ・検索を OpenSearch へ |
| L | 〜数千テーブル・〜数百万人 | 領域ごとに DB を分ける・分析は DWH へ・ログの階層化・負荷試験を毎晩 |
| XL | 数千テーブル超・巨大なテナントあり | 大きいテナントだけ別の DB・テナント単位の分割・領域ごとにサービスを分ける |

- 📏 **「足す」のは数字が言ったときだけ**: DB の CPU が常に60%超・p95 が目標を超える・特定の表の行数が億を超える、など。先回りで入れると、運用する物だけ増える。
- 🔑 キャッシュを足すときの決まり: **キーに必ずテナント ID**(キーを作る関数を1つにする)・「何が変わったら消すか」を宣言する・権限の判断は長くキャッシュしない(数十秒まで)・ヒット率を見て、低いキャッシュは外す。
- 🏢 規模が大きくなったときの AI の使い方: 「この領域だけ」の文脈を渡す(領域ごとの CLAUDE.md・自動で作る表の説明 `docs/db/`)。1タスク1領域。テストは影響範囲だけ+全体は毎晩。

## 4. 段階ごとの月の費用(内訳)

| 項目 | ① PMF の前(2人) | ② PMF の後(5人) | ② PMF の後(15人) | ③ 規模拡大(100人) |
|---|---|---|---|---|
| 本番+stg | 約4万円 | 約10万円 | 約30万〜45万円 | 約750万円 |
| PR ごとの環境・CI | 約0〜1万円 | 約3万円 | 約8万〜15万円 | 約300万円 |
| AI(席+背景エージェント) | 約3万〜6万円 | 約14万〜22万円 | 約60万〜90万円 | 約500万〜900万円 |
| 有料の検査 | 0円(無料の道具で) | 0〜4万円 | 約11万円 | 約70万円 |
| **合計** | **約7万〜11万円** | **約27万〜40万円** | **約110万〜160万円** | **約1,500万〜2,000万円** |
| 外部の脆弱性診断(別枠) | なし | 年1回 数十万円〜 | 年1回 数十万〜数百万円 | 領域ごとに年1回以上 |

- 📐 **AI の費用は「人数に比例」、インフラは「利用者とデータに比例」**。1人あたりの AI はどの段階でも月3万〜6万円ほど。PMF の前はインフラより AI のほうが高いこともある。
- 💸 **PMF の前の節約の順番**: stg は夜止める → NAT を減らす → ログは短く消す。AI の席は削らない(一番の速さの源)。
- 🔎 有料のコードの検査は、非公開のリポジトリだと書く人1人あたり月数十ドル。PMF の前は gitleaks・Semgrep・Trivy など無料の道具で代える(このキットの既定)。
- 📐 100人の規模では、インフラ+AI は人件費の約2割。AI の費用はインフラの半分ほどに並ぶので、AI の利用額も予算と人ごとの上限で見る。
- 🧾 **1社あたりの原価**も出す(全体の費用 ÷ 有料の会社数)。料金の決め方と、巨大なテナントを別の DB に分ける判断の根拠になる。費用のページが、組織の大きさの帯ごとに本番の AWS を按分した幅を出す([../guides/cost-dashboard.md](../guides/cost-dashboard.md) の 7)。

### 費用の見積もりの型

前提(台数・データ量・PR の数)を自分の数字に置き換えて計算し直すための型。最初の3か月は Cost Explorer を毎週見て、どの行が一番大きいかを掴む。

| 単価(東京・目安) | |
|---|---|
| Fargate | vCPU 1時間 約$0.05・メモリ 1GB 1時間 約$0.0055 |
| Aurora Serverless v2 | 1 ACU 1時間 約$0.15〜0.2(推定) |
| CloudWatch Logs の取り込み | 1GB $0.76(低頻度アクセスは約半額) |
| GitHub Actions(Linux 2コア) | 1分 $0.006(公開のリポジトリは無料) |

| 規模 S の例(5人・100テーブル未満・数万人) | 前提 | 月の目安 |
|---|---|---|
| 本番の計算 | API 2台+ワーカー1台 | 約$110 |
| 本番の DB | Aurora Serverless v2 平均2 ACU・50GB | 約$250 |
| stg | API 1台+DB は夜止める | 約$90 |
| 周辺 | ALB・NAT・CloudFront・WAF・DNS・秘密情報 | 約$150 |
| ログ・監視 | 1日1GB+Sentry | 約$75 |
| プレビュー・CI | | 約$200 |
| **インフラの小計** | | **約$900(約13万円)** |
| AI | 5人 × $150〜200+背景エージェントの従量 | 約$900〜1,500 |

- ⚠️ **ログは何もしないと一番高くつく**: 1日500GB 出すと CloudWatch だけで月 約170万円。種類で分けて送り先を変えれば 約23万円([running.md の 2](running.md#2-ログが残らないを防ぐ))。
