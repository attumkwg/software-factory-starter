# 人が決めること(一覧と積み場)

> 入口は [README.md](README.md)。仕様 0085・ADR 0085。人の出番を極限まで絞る([../kit/roadmap.md](../kit/roadmap.md) の 6)。
> 人が見るのは**センサーが正しいかの判定**と、**人が決めなければならない所への端的な答え**の2つだけ。コードそのものはセンサー(テスト・型・検査・E2E・計測)が確かめる。

## 1. 人が決めることの一覧

「強制」は、人の答えが無いと仕組み(フック・CI・スクリプト)が止める物。「頼み」は、手順書やスキルに書いてあるだけで、AI が守る前提の物(止める仕組みはまだ無い)。

| 決めること | 種類 | 強制か頼みか | 止める物・書いてある所 | 1人の間に答える場所 |
|---|---|---|---|---|
| センサー(テスト・守る場所)を変えてよいか | センサーの判定 | 強制 | 守る場所(`.claude/hooks/protected-paths.json`)は Edit で確認が出る・印 risk:high・`pnpm guards` | 会話(PR に記録が残る) |
| テストを弱めてよいか | センサーの判定 | 強制 | 印 tests:weakened(`test-weakening.yml`) | 会話(PR に記録) |
| 危険度「高」の領域を変えてよいか(認証・課金・個人データ・顧客への連絡・移行・インフラ・CI) | 戻せないリスク | 強制 | 印 risk:high・領域ごとの問い([risk-areas.md](risk-areas.md)) | 会話(問いへの答えを PR に記録) |
| 設計書の未確定事項(事業判断・利用者の挙動・他チームとの契約・戻せないリスク) | 4つの問い | 強制 | `仮決め` が残る PR は `pnpm decisions --strict` が落とす・答えの出どころのチェック | 会話(`承認(@持ち主 日付 会話で回答)`) |
| レビューの所見を直すか・このままか(書いた人と別の AI が人格ごとに出した物) | センサーの判定 | 強制 | 記録(「## 🔍 レビューの記録」)が無い・❌ と ❓ に決めていない物がある・「直す」を直していない PR は `pnpm pr:merge-when-green` が止める(仕様 0096) | 会話(1問ずつ。Slack は番号つきで1返事。PR に記録) |
| PR をマージしてよいか | マージ | 強制 | フックが AI のマージを止める(例外は `pnpm pr:merge-when-green`。必須のチェックが全部緑のときだけ) | 会話(「マージして」)。`setup.yml` の `ai_merge.sensors_only: true` の所では、上の行に1つも当たらない PR は**聞かない**(`--sensors`。センサーが緑なら入れる。ADR 0094・[../guides/throughput.md](../guides/throughput.md)) |
| 本番に出してよいか | 戻せないリスク | 強制 | GitHub の環境 prod の承認(`deploy.yml`・Required reviewers) | GitHub の承認(会話では代えない) |
| 本番の DB・AWS に書き込む操作 | 戻せないリスク | 頼み | CLAUDE.md の「してはいけない」・手順書のコマンドを人が打つ | 人が打つ |
| 仕様を承認してよいか(ブロッカーがゼロか) | 事業判断 | 頼み | [../guides/human-review.md](../guides/human-review.md) の 6 | 会話 |
| 意義の判断が正しかったか | センサーの判定 | 頼み | `pnpm kpi` と積み場が待ちを知らせる(「- 人の判定:」) | 会話(記録に人が書く・AI が写す) |
| 賭けの段階を進める・やめる | 事業判断 | 頼み | `/bet` の手順(段階の線は `pnpm bets` が形だけ見る) | 会話 |
| 受け入れ(出してよいか) | 利用者の挙動 | 頼み | `/accept`([../guides/acceptance.md](../guides/acceptance.md)) | 会話 |
| 点検で人がやる項目 | 運用 | 頼み | 毎週の点検の Issue(`docs/checkup/todo.yaml` の who: human) | `/checkup`(1問ずつ) |

- 「頼み」の行を「強制」にするのは、守られなかったことが1度でもあったとき(原則 5: 同じ失敗は2回目でルールにする)。
- 1件の依頼で人に聞くのは多くて2問(仕様 0084)。**レビューの所見はこの外**(人が決める材料。仕様 0096。持ち主が 2026-10-29 に決めた)。PR の「🧑‍⚖️ 人に判断してほしい所」も多くて2問で、3問目から `pnpm bets --pr-body`(CI「取り組みと作業の種類(PR の本文)」)が落とす。

## 2. 答えは人がいる場所で。工場が記録して実行する

「GitHub を開いて押してください」はやめる。人はチャットか Slack で答え、工場(AI)がその言葉を記録して実行する。

| いつ | 人がすること | 工場がすること | 偽りへの守り |
|---|---|---|---|
| 1人の間(`.github/setup.yml` の `required_approvals: 0`) | チャット・Slack で端的な問いに答える(「マージして」まで) | 持ち主の言葉をそのまま PR にコメントで残す(「## 持ち主の承認(会話で・日時)」・当てた版・人の答えが要った理由・領域の問い)→ 必須のチェックが全部緑なら、危険度「高」もマージ(`pnpm pr:merge-when-green`) | 必須のチェック・PR に残る言葉と日時・持ち主が依頼の場所を自分だけにする(ADR 0082 の割り切り)。CI は会話の書き手を確かめない |
| 人が増えたら(承認数が 1 以上) | Slack のボタンを押す | 押した人(Slack が署名した利用者)を確かめてから、その人の答えとして記録する | Slack の署名・人の対応表(まだ作っていない。G-133) |

- 問いの形は1問1行・選択肢つき(「(a) 12-06 にずらす か (b) 11-29 に出す か」)。理由は「なぜそうしたか」の欄に書き、問いに混ぜない。
- 答えた日時は、持ち主が返した時刻(会話の時刻)。マージした時刻ではない。
- 人が増えると、AI のマージは自動で止まる(`scripts/pr-merge-when-green.mjs` が承認数を見る)。
- 人を呼ぶ範囲(G-135・仕様 0096): 1. の表の「強制」の行(守る場所・高の領域・印・問い・未確定事項・レビューの所見)に当たる PR だけが人を呼ぶ。レビューの所見が0件なら、その行には当たらない。当たらない PR は、使う人が `ai_merge.sensors_only: true` にした所では、センサーが緑なら返事なしで入る(既定はオフ = 全部の PR で返事を待つ)。背景の AI の上限(`AI_OPEN_PR_LIMIT`)も、人を待つ PR だけを数える。

## 3. 判断待ちの積み場(毎朝)

`pnpm queue` が、人の答えを待つ物を古い順に1枚に出す。`human-queue.yml` が毎朝 8:10(日本時間)に「🧑‍⚖️ 判断待ち」の Issue を1つだけ直し、`SLACK_WEBHOOK_URL` があれば Slack にも送る(キットから作ったリポジトリだけ)。

- 載る物: 下書きでない開いた PR のうち、印(needs-human・risk:high・tests:weakened)か「🧑‍⚖️」の表に問いがあり、会話の答えの記録がまだ無い物・印 needs-human の Issue・期限を過ぎて人の判定が未定の意義の判断。
- 見る物: 種類ごとの数・待ちの日数・いちばん古い待ち。
- 無くなったら Issue を閉じる。
