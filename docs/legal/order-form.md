# 型: 申込書(注文書)

> ⚠️ **文面は書かない。専門家に確かめる。** ここにあるのは「申込書に何の欄が要るか」と、キットの既定・根拠・使う人が決めること。申込書と利用規約のどちらが優先するか・印鑑か電子の署名か・特定商取引法などの表示が要るかは、専門家と決める。
> 共通の項目と「変えてよい / 変えない」の分けは [README.md](README.md)。既定の値の未確定事項は [designs/0028](../designs/0028-contract-templates.md) の U-6・U-7。

## 1. なぜ申込書が要るか

- 会社向けでは、**申し込んだ人に会社を代表する権限があるか**が後で争いになる(社員が勝手に申し込んだ・前任者が申し込んだ)。申込書で「誰が・会社の誰の承認で申し込んだか」を残す。
- 画面から誰でも組織を作れる作りにしていない(組織は運営のコマンド `create-tenant` が作る。[runbooks/tenant-provisioning.md](../runbooks/tenant-provisioning.md))ので、**申込書が組織を作るきっかけ**になる。申込書の欄が、組織を作るときに運営が見る物になる。

## 2. 欄の一覧

| 欄 | キットの既定 | 根拠(どのファイル) | 使う人が決めること |
|---|---|---|---|
| 申し込む会社 | 会社の正式な名前・住所。**組織の名前(画面に出る名前)とは別に持つ** | 組織の名前は解約の削除で `--confirm-name` に使う([runbooks/offboarding.md](../runbooks/offboarding.md) の 1・4)。契約の会社名と突き合わせる | 法人番号も書いてもらうか |
| プラン | プランの名前(`@app/shared` の `PLANS` の id)と、**どの版の価格表か**(`PRICE_LISTS` の id)・据え置きの期限があればその日。運営は開通のときにこの欄を申し込みの JSON の `plan`・`priceList`・`priceLockedUntil` に写す。金額はキットに無い(会計ソフト) | [specs/0047-plans.md](../specs/0047-plans.md)・[runbooks/plans.md](../runbooks/plans.md) | プランの名前と中身(どの機能が入るか)・価格表の金額 |
| 人数 | 契約の人数。申し込みの JSON の `seats`。キットは**超えても止めない**(いる人+受けていない招待で数え、超えた組織は運営が毎週の点検で知る) | 同上(設計書 0047 の U-3) | 超えたときの扱い(申込書の変更を頼むか・翌月から請求するか) |
| 始まりの日 | 組織を作って、最初の管理者がログインできた日を「使い始め」とする案 | 組織は運営が `create-tenant` で作る([runbooks/tenant-provisioning.md](../runbooks/tenant-provisioning.md)) | 契約の始まりを申込日にするか・使い始めにするか |
| 支払い | 欄だけ置く。**キットは請求も決済もしない**(外の会計ソフトで手で) | [kit/catalog.yaml](../kit/catalog.yaml) の `billing`(未) | 支払いの方法(振込・カード)・締めと期限・前払いか後払いか |
| 契約の期間 | **1年**(仮の既定) | 設計書 0028 の U-6 | 月ごとか・1年か |
| 自動更新 | **する**(同じ期間で) | 同上 | しないなら、満了の前に誰が知らせるか |
| 解約の申し出の期限 | **満了の1か月前まで・書面(電子でも)で**。口頭やチャットだけでは受けない | 解約の削除は「解約の申し込みの書面」を確かめてから([runbooks/offboarding.md](../runbooks/offboarding.md) の 1) | 期限の長さ・途中で解約したときの返金 |
| 解約したときのデータ | 契約の終わりまでに管理者が書き出す。終わりから **30日以内**に消す。バックアップからは最長 365日で消える | [guides/data-retention.md](../guides/data-retention.md)・設計書 0028 の U-5 | 消すまでの日数(**縮めるのは「変えない」側**。365日はロックで縮められない) |
| 最初の管理者 | 名前と、会社のドメインのメールアドレス。運営はこの人を管理者として組織を作る(ほかの人は管理者が足す) | [domain/organizations/README.md](../domain/organizations/README.md)・[runbooks/tenant-provisioning.md](../runbooks/tenant-provisioning.md)(最初の管理者に招待が届く)| 管理者を2人にしてもらうか(1人が辞めると誰も設定を変えられない) |
| 申し込む権限 | **申し込む人と、承認した人(決裁の権限がある人)を別の欄に**。承認した人の会社のメールアドレスに、運営から確かめのメールを1通送ってから組織を作る | 設計書 0028 の U-7 | 印鑑か・電子の署名か・確かめのメールで足りるか |
| 規約への同意 | 申込書に「利用規約(版)に同意する」欄。**画面の同意(1人ずつの記録)とは別**に、会社としての同意をここで取る | [guides/legal-documents.md](../guides/legal-documents.md)・[designs/0009](../designs/0009-legal-consent.md) の U-3 | どの版を指すか(版の番号を書く) |
| SLA・取り扱いの取り決め | 付けるかの欄(付けるなら [sla.md](sla.md)・[data-processing.md](data-processing.md) の型) | — | どのプランに付けるか |
| 導入事例・名前とロゴ | **任意の欄。既定は「出さない」**。選べる段: 出さない / 名前 / 名前とロゴ / 事例の記事・声(声と写真は本人の同意も別に) | [guides/announcements.md](../guides/announcements.md) の 4・設計書 0040 の U-1 | 欄を置くか(置かずに後から個別に頼むか) |

## 3. 申込書を受けてから組織を作るまで(キットの既定)

1. 申込書の欄が全部埋まっているかを見る。**申し込む権限**の欄(申し込む人・承認した人)が空なら受けない。
2. 承認した人の会社のメールアドレスに、確かめのメールを1通送る(返事で確かめる)。
3. 組織を作り、最初の管理者を足す(運営のコマンド `create-tenant`。[runbooks/tenant-provisioning.md](../runbooks/tenant-provisioning.md)。ほかの人は管理者が招待の画面で足す)。
4. 組織の ID と、申込書の会社名・申込日を、**契約の管理の置き場**(リポジトリの外)で結び付けておく。解約のとき、この結び付きで「消す組織」を確かめる。

## 4. 変えてよい欄・変えない欄

- 変えない: 解約の申し出を**書面で**受けること(削除の手順の前提)・バックアップから消えるまでの最長の日数・最初の管理者を名指しすること。
- 変えてよい: 期間・自動更新・申し出の期限・支払い・プランと人数・始まりの日の数え方。

## 5. 専門家に確かめること(出す前に)

- 申込書と利用規約(定型約款)のどちらが優先するか。申込書で規約の一部を変えたときの書き方。
- 自動更新と解約の申し出の期限を、会社向けの契約でどう書くか。
- 電子の申し込み(画面・メール)で、申し込む権限の確かめが足りるか。
