## 2. 反論役

- **全員が条件つき = 合意ではない**。各人の条件は自分の立場の物で、足したときの日数を誰も見積もっていない。
- 「3件中2件」は分母が小さく、作った本人が測る。持ち主以外の1人は必須に近い。
- 見落とされた立場: 後から保守を引き継ぐ人・Issue を受ける窓口(持ち主1人に集まる)・ライセンスの審査者・README が名指しする B2B 1〜15人のチーム・土台の提供元の規約。
- 案の弱点: 合議の記録へのリンクが切れていた・段の名前(公開の前 / 後)が `pnpm gaps` の段(今すぐ・使える前に・使えた後で)と違う・**2026-10-27 に承認した順番を黙って置き換えている**・「AI が高をマージした件数 0」は、3件が低と中なら必ず0で何も分からない・公開の後に毎週見る、が保守の約束が無いことと食い違う。

## 4. 拒否と、その扱い

- **P-5(情シス)**: ② は機械が強制する物を1つも削らないと明文化・AI のマージは既定オフ・README に「返事の書き手を CI は確かめない」・Slack は自分だけのチャンネル・外の人の Issue や共有チャンネルからマージまで進ませない。
  - 扱い: 既定オフは**今もそう**(`scripts/pr-merge-when-green.mjs` は `KIT_AI_MERGE=slack` のときだけ動く)。残りはロードマップの ② と README の頭(1 の「正直に書くこと」)に入れた。③ に「高」の依頼を1件。
- **P-7(お客さん側)**: G-65(戻す)と G-06 の残り(削除)を公開の前に。または ③ に「わざと壊して戻す」1件と、削除の手順書を1回通した記録。
  - 扱い: 後の案(記録で代える)を「今すぐ」に入れた。ワークフローとコマンドは「使える前に」。README に1人の間の戻し方と消し方を書く。**持ち主が決める**。

## 5. 結論の案

- 北極星は件数に(割合は分母3で運に左右される)。3件を「ふつう・高・わざと壊して戻す」にする。対の守りに「止まるべき所で止まった」。
- ② は「関所を軽く」から「関所の一覧」に名前を変え、強制は削らない。
- 日付は 11-23 → **11-29**(予備 12-06)。③ を2週間に。
- 公開の前から外す: G-114・G-116(大きく、使う人に遠い)。足す: 戻す・削除の通しの記録。
- できないこと(G-51 部品だけ・G-55 AWS 以外・G-54 導入前の基準・保守の約束)は、作らずに README の頭に書く。
- 公開の後の北極星は「持ち主以外の人が、手引きだけで最初のマージまで行けた件数」。
- 見込みの幅: 判定の日(11-22)に、3件中 1〜3件が通る。クラウドで Docker が動かなければ 0〜1件(推測)。
