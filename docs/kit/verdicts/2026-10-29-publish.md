- 判断: 条件つき
- 意義: 1〜3人で会社向け SaaS を始める人の「AI に任せても人が張り付く」困りごとが、1件の依頼で人が使う工数の割合で、基準(まだ。10-30 からの週で測る)から 30〜60% に減る(`pnpm metrics` の人の介在率と `docs/cost/people.yaml` の分数で、2026-10-30〜11-27 の週ごとに数える)
- 動かす KPI: 無人化率(1 − 人が使った工数の割合。毎週見る数)
- 見込み: 40〜70(2026-11-27 まで)
- 費用の見込み: 5〜12 人日
- 得る物の見込み(月): 1〜6 人日相当
- 測る月数: 3
- ROI の見込み: -0.8〜2.6 倍・回収 0.8〜12.0 か月
- 止める線: 11-27 の週に無人化率が 40% を下回る・事故(他社のデータ・鍵・本番)が1件でも出る・基準が測れていない、のどれかなら 11-29 には出さず 12-06 に見直す。12-06 でも 40% 未満なら、README の頭で「工場」と言い切らず、無人化率は確かめていないと limits.md に書く(11-27 と 12-06 に見る)
- 人に聞く問い: 11-27 に無人化率の基準が測れていなかったら、(a) 12-06 にずらして測ってから出すか、(b)「確かめていない」と limits.md に書いて 11-29 に出すか?
- 合議: なし

## 理由

- [記録] 10-19 の週にこのリポジトリで 97本をマージした(`pnpm metrics`)ので、1問目(週100〜200本)には近い。ただ「AI が手伝った 36%」「AI の PR で人の介入なし 31%」は AI で作っている実態と合わず、まずセンサー(AI の見分け)が正しいかを人が判定する要がある。
- [記録] 3問目(意義)に数で答える材料がまだ無い: 無人化率の基準は**まだ**(`pnpm metrics` の人の介在率と `docs/cost/people.yaml` で測る)。カタログ(G-128)・公開の形(G-108)は PR が開いたまま、6 の 2・4・5・6 は手つかず。
- [推測] people.yaml の分数(AI の PR を確かめる 15分・人が書く 120分)だと、人が確かめるだけになれば無人化率の上限は 9割近い。危険度「高」の PR で人が答えた問いは 2〜9 [記録] あるので、6 の 2・5 が入っても届くのは 40〜70%。
- [推測] 得る物の低い方は持ち主が問いに答える時間が減る分だけ(外の利用 0)、高い方は外の1〜2チームが土台を作らずに済む分。どちらも測っていないので「やる」ではなく条件つき。条件は、11-27 までに無人化率を4週測って 40% 以上・事故 0件・センサーの判定が回っていること。
