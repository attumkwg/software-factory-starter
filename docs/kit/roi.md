# 💴 カタログの数の出どころ(実測と目安)

> README の頭の「できることのカタログ」(G-128 で作った)で使う数の根拠。道のりは [roadmap.md](roadmap.md) の 1。
> **【実測】** = このキットの中で測った数。**【目安】** = 同じ物を自分で作ったら何人日かかるか(下の数え方による見込み)。根拠の無い得は書かない。

## 【実測】(2026-10-29)

手元(Windows 11・Docker Desktop)で、main の b8a30b2 を流した。

| 何を | 結果 | どう測ったか |
|---|---|---|
| 依存を入れる | 32秒 | `pnpm install --frozen-lockfile`(pnpm のストアはある状態) |
| 単体テスト | **462件が12秒で緑**(7つのパッケージ) | `pnpm test --force`(turbo のキャッシュを使わない) |
| 手元の起動 | 17〜37秒 | `bash .github/scripts/start-app.sh`(イメージを一度作った後。最初はイメージの取得が足される) |
| 1社の一周の E2E | **10段が18秒で緑**(17.6秒) | `pnpm test:e2e journey.spec.ts`。事前登録 → 開通 → 同意 → 招待 → 写真 → プラン → 書き出し → 人を外す → 1人分を数える → 解約 |
| E2E の全部 | **38件が緑・1分12秒**(ほかの4件はスマホの組だけの物で、パソコンの組では飛ばす) | 真っさらな DB(`docker compose down -v` の後)で `pnpm test:e2e`(パソコンの幅とスマホの幅) |
| キット自身を作った | **1人+AI で13日・258コミット**(2026-10-17〜10-29。コミットのあった日は12日。うち Renovate 4。マージした PR 151) | `git log` |

- 一周の E2E の「未」は2つ: 1人分の削除のコマンド(G-06 の残り。今は手順書で手で)・タスクの画面のファイルの欄(題材を差し替えるときに作る。E2E は API で上げる)。
- 結合テスト(2社の DB で叩く。`pnpm test:integration`)は 45ファイル・約340件。CI で流れる(この日は手元で流していない)。
- E2E は真っさらな DB で流す。この日、一周の E2E の後に同じ DB のまま全部を流すと、同意の画面の1件(`legal.spec.ts`。同意していない人が同意の画面へ回される)が落ちた。`docker compose down -v` の後では緑。流し直すときは `down -v` から。
- 自社の速さの約束ではない。キットを作った速さは、作った人とキットの中の話。

## 【目安】自分で作ると何人日か

**数え方**: カタログの行ごとに、その行の部品のコードとテストの行数(`.ts` `.tsx` `.mjs` `.sh` `.tf` `.sql` `.css`)を足し、**1日150行**で割る。1人月は20人日。

- 1日150行は、設計・レビュー・調べものの時間を入れない、**得を大きく見せない側**の置き方。1日100行なら1.5倍、200行なら0.75倍になる。
- **数えていない物**(得に入れない): 題材の TODO(プロジェクト・タスク)・DB の移行のファイル・キット自身を保守する道具(`pnpm gaps`・`pnpm self-contained`・`pnpm kit:catalog`)など 約9,400行。文書(約440ファイル。ADR 64・設計書 71・仕様 76)と、AI への手順(スキル 27)も数えていない。
- 1つのファイルは1つの行にだけ数える(二重に数えない)。

- README の頭の2行では、切り下げて **約20人月** と書く(1日100〜200行なら 17〜34人月)。
- お金にするときの計算の型: 450人日 × 1人日の単価。例: 時給5,000円 × 8時間なら 1人日4万円で 約1,800万円 **【仮定の例】**。自社の単価で置き換える。キットの費用(試すのは0円・本番は月 約8万円から)と並べると ROI(得 ÷ 費用)になる。
- AI の席(1人 月3万〜6万円)は、キットを使っても使わなくても払う。比べるのは「土台を自分で作る時間」と「キットを読んで差し替える時間」。後者は始め方の 1〜4 で半日〜1日 **【目安】**(30分・10分・半日・30分の積み上げ)。
