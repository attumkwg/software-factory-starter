- E2E は真っさらな DB で流す。この日、一周の E2E の後に同じ DB のまま全部を流すと、同意の画面の1件(`legal.spec.ts`。同意していない人が同意の画面へ回される)が落ちた。`docker compose down -v` の後では緑。

## 2. キット自身に、人がどれだけ関わったか(有人の工数と無人化率)

> 持ち主(2026-10-29)「実際の投入コストを出すべき。無人化率が出せるなら有人化率も出せる。有人化率は人が使った工数」。
> キット自身は、このキットの工場(1人+AI)で作った。その PR の履歴から数える。自社の速さの約束ではない。
> 置き方(持ち主 2026-10-29): 無人化率は**毎週いちばん目に入る数(入力の指標)**で、北極星ではない。北極星は「意義があると判断した物が、使う人に届いて使われた数 ÷ 人の工数」で、分母と分子は `pnpm kpi --roi` が毎週出す(4)。守りは事故0件と、センサーが正しいかの判定。

### 数えた事実【実測】

期間は 2026-10-17〜10-29 の13日(コミットのあった日は12日)。`git log` と `gh pr list --state merged`(本文・ラベル・コメント・レビュー)と、PR ごとのコミットを 2026-10-29 に読んだ。

| 何を | 数 |
|---|---|
| コミット | 258(うち Renovate 4) |
| マージした PR | 153(うちボット 4。残りの **149本**を数える) |
| AI が書いた PR | **149本のうち149本(100%)**。見分け方は費用のページと同じ(本文の「Generated with [Claude Code]」「Co-Authored-By: Claude」か、ラベル `ai:assisted`) |
| 人が答えた問い | **305**(102本の PR。PR の本文の「人に判断してほしい所」の表の行。`pnpm metrics` と同じ数え方) |
| 人が手で直した PR | **1本**(AI の印の無いコミットがある PR) |
| 人の介入が無かった AI の PR | **47本(32%)**(問い0・手直し0) |
| PR のコメント(人) | 99件。人のレビュー(作った人以外)は 0(1人で作ったため) |
| いちばん多い週 | **97本**(2026-10-19〜25。PR の番号で数えた。main の合わせ込みのコミットは113あるが、同じ PR を2回合わせた16を除く) |

### 人が使った工数【推定】

`docs/cost/people.yaml` の1件あたりの分数をかける(費用のページの「人の時間」と同じ式)。

| 何に | 式 | 分 |
|---|---|---|
| AI の PR を人が確かめる | 149本 × 15分 | 2,235 |
| ボットの PR を確かめる | 4本 × 5分 | 20 |
| PR のコメント | 99件 × 3分 | 297 |
| **人が使った工数** | | **2,552分 ≒ 43時間** |
| 比べる物: 全部を人が書いたら | 149本 × 120分 + ボット・コメントは同じ | 18,197分 ≒ 303時間 |

- **有人化率 = 43 ÷ 303 ≒ 14%、無人化率 ≒ 86%**。
- **幅**: 15分の中には「人に判断してほしい所を読んで答える」を入れてある(`people.yaml` の注)。問い1つに別に5分かかったとすると、305問 × 5分 = 約25時間が足されて **約68時間・有人化率 約22%(無人化率 約78%)**。README には「約43〜68時間・無人化率 約78〜86%」と幅で書く。
- **入っていない時間**: Claude Code への指示と会話・セッションを並べて見る時間。PR の履歴に残らないので数えられない(上の時間より大きい見込みもある)。
- 15分・120分・5分・3分は `people.yaml` の既定の目安で、測った値ではない。自分たちの実感で直せる。「全部を人が書いたら 120分」は、AI の PR の大きさを考えると小さめの置き方(無人化率は低めに出る側)。

### 使う人のリポジトリで見る

- `pnpm metrics`(毎週 Actions の要約にも出る): 週ごとの**無人化率【推定】**(上と同じ式・同じ幅。決裁用の表の1列と、その下の内訳: 人の工数・全部を人が書いたら・PR・問い・コメント・手直し)と、「AI が手伝った」割合・「AI の PR で人の介入なし」の割合・人が答えた問い・人の手直し。
- 費用のページ(`pnpm cost --out <フォルダ>` の「人の時間」): 今月の PR から、上と同じ式で人の時間の目安を出す。
- ⚠️ `pnpm metrics` の「AI が手伝った」は AI の PR をラベル `ai:assisted` だけで見分ける(無人化率は、費用のページと同じく本文の印でも見分ける)。このキットではラベルを途中から付けたので、2026-10-19 の週は「AI が手伝った 36%」と低く出る(本文の印でも見分ける費用のページでは 100%)。最初からラベルが付く使う側のリポジトリでは、2つはそろう。
- 2026-10-29 に `pnpm metrics` で流すと、2026-10-19 の週は **77〜86%**(AI の PR 97本・問い 219・コメント 67)。上の13日の数え(78〜86%)と、ほぼそろう(仕様 0098)。
- 北極星の分母(人の時間)と、賭けごとの原価の累計は `pnpm kpi --roi`(4)。

## 4. 資産の累計・ROI・北極星を毎週出す(`pnpm kpi --roi`)

> G-136(仕様 0094)。毎週月曜に `metrics.yml` が Actions の要約に出す(手で流すなら `pnpm kpi --roi --weeks 8`)。金額は出さない。

| 出す物 | 出どころ | 区分 |
|---|---|---|
| 賭けごとの PR の数・資産の候補の PR の数 | マージした PR の本文の「取り組み」「作業の種類」 | 【実測】 |
| 原価の累計(人日)・北極星の分母(人の時間) | PR × `docs/cost/people.yaml` の分(2 と同じ式)。幅の上は問い1つ × 5分を足す | 【推定】 |
| 得た物の累計 | 賭けの「- 得る物の見込み(月):」(人日相当の幅)× rollout から経った月数 | 【推定】 |
| ROI の幅・回収の月数 | 上の2つから `roiRange`(`docs/guides/kpi.md` の 10) | 【推定】 |
| 北極星の分子(届いて使われた賭けの数) | rollout に入った後、賭けの動かす KPI に最初の記録(`kpi.yaml` の `records`)が付いた週 | 【実測】 |
| 「動かす KPI」が空・賭けと合わない PR | PR の本文の「- 動かす KPI:」と賭けの「- 動かす KPI:」 | 【実測】 |

- **キット自身の北極星**: このコマンドは、使う人のリポジトリの賭けを数える。キット自身の分子(外のチームに届いて使われた数)は公開の後に、届けた外のチームの報告で数える([roadmap.md](roadmap.md) の 4)。公開の前のキットで流すと、分子は 0、分母は 2 と同じ人の時間(見本の賭けには PR が無いので、原価の累計も出ない)。
- **README の頭の数(43〜68時間・無人化率)は 2 の手で数えた値のまま**。このコマンドは同じ式で週ごとに出すので、数え直すときの突き合わせに使える(PR を読む範囲が違うので、合計はぴったりはそろわない)。週ごとの無人化率は `pnpm metrics`(2)が同じ式(`prMinuteRange`)で出す。

## 数え直すとき

公開の前と、大きく変えたときに数え直す。

- 1 は上の表の「どう測ったか」をそのまま流す。
- 2 は `gh pr list --state merged --json number,author,labels,body,comments,reviews` と、PR ごとのコミット(GraphQL の `pullRequests { commits }`)を読み、上の見分け方と `people.yaml` の分数で足す。問いと手直しの数え方は `scripts/metrics/lib.mjs` の `questionsOf`・`humanCommits` と同じ。
- 数が変わったら、README の頭(「🏭 何者か」の表)・カタログ・[one-pager.md](one-pager.md) を一緒に直す。
