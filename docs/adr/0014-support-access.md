# ADR 0014: 社員がお客さんの画面を見るのは「お客さんが許可した間だけ・見るだけ・全部記録」の代理ログインだけ

- 状態: 採用
- 日付: 2026-10-18
- 決めた人: @attumkwg

## 背景

問い合わせに答えるには、社員がお客さんの画面を見る必要がある。よくある作り(全社を一覧できる管理画面・社員が DB を直接見る・社員だけは RLS をすり抜ける)は、どれも「他社のデータが見える穴」になり、お客さんからは何をされたか見えない(docs/security.md の T-7・L-7)。仕様は `docs/specs/0004-support-access.md`。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 全社を一覧できる管理画面 | 社員が速く動ける | 穴そのもの。社員の鍵が漏れると全社が見える |
| B. 社内のもう1人が承認して入る | お客さんの手間が無い | お客さんは後から知る。「勝手に見られた」と感じうる |
| **C. お客さんの管理者が期限つきで許可し、番号で入る** | お客さんが決められる・いつでも止められる。番号が無いとどこにも入れない(一覧が要らない) | 急ぎのときにお客さんの操作が要る |

## 決めたこと

- **C**(作者 @attumkwg の選択)。社員は**閲覧者に固定**(作者 @attumkwg の選択「見るだけ」)。
- 社員は「運営の組織」(`SUPPORT_TENANT_ID`)の管理者・メンバー。ふつうのログインと同じ道で入り、番号で**代理**に切り替える。
- 代理の Cookie は「社員・本来の組織・見る組織・入室の ID」を持つ。**関所が毎回 DB で確かめる**: いまも運営の組織の人か・入室が終わっていないか・期限(最長1時間・許可の期限)・許可が取り消されていないか。外れたら Cookie を本来の組織に戻して 401。
- 番号は約59ビットのランダム(紛らわしい字を除く)。**ハッシュだけを保存**し、作ったときに1回だけ見せる。番号から許可を探すのは DB の関数だけ(`support_find_grant`。アプリは全社分の許可を読めない)。
- 入った・**見た**・出た・拒否は、お客さんの監査ログに「サポート(運営)」として残す(ADR 0013 の表)。運営の組織の記録にも「入った」を残す。

## 結果として起きること

- 良くなること: 社員がお客さんのデータを見る道が1本になり、全部お客さんから見える。取り消しはすぐ効く。社員が辞めても、次のリクエストで止まる。
- 我慢すること: 代理のリクエストは DB の確かめが2つ増える(入室と、社員であること)。代理では直せない(直すのはお客さんか、運営が記録つきで)。
- 見直す合図: 「直してもらう」の依頼が多くなったら、許可のときに「直してもよい」を選べる形(作者が最初に選ばなかった案)を検討する。社員が増えたら、運営の組織の作り方を SQL から画面か IdP(会社の SSO)へ。
