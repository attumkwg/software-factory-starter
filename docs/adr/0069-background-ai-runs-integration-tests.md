# ADR 0069: 背景の AI は GitHub の MCP を持ち、結合テストを PR の前に自分で回す(テストのコンテナは外へ出られない)

- 状態: 提案(ADR 0068 の「② 背景の AI」の所を置き換える)
- 日付: 2026-10-25
- 決めた人: @attumkwg(方針は 2026-10-25 に会話で回答。親のセッションから。この ADR の承認は PR で)

## 背景

- ADR 0068 は、背景の AI(Actions)を「Web と MCP の道具を持たず、Docker を置かず、テストは CI に任せる」形(設計書 0057 の案 D)にした。
- 持ち主の答え(2026-10-25):「GitHub MCP を取り上げるのは微妙な気もしますが、CI っていうか、結合テストを自分で回してからやってくれた方が、変な手戻りとかないですみませんかね」。
- Actions の中では Docker が使える。外の会社の部品を足さずに、Docker のコンテナから外への通信は止められる(設計書 0057 の U-2)。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| D. テストは CI に任せ、背景の AI に Docker を使わせない(ADR 0068) | 背景の AI の中で、AI が書いたテストが動かない | CI との往復で手戻りが増える。GitHub の MCP(CI の結果を読む・コメント)も無い |
| D'. 背景の AI が結合テストを自分で回し、その前にテストのコンテナから外への新しい通信を止める | PR の前に結合テストが通る。手戻りが減る。GitHub の MCP で CI の結果も読める | テストを動かす Node(Actions のホスト)は外へ出られる |

## 決めたこと

D'。背景の AI は、WebFetch・WebSearch と GitHub 以外の MCP を持たない。GitHub の MCP(このリポジトリだけに届く)は持つ。PR を出す前に `pnpm test:integration` を自分で回し、その前に `.github/scripts/block-container-egress.sh` で Docker のコンテナから外への新しい通信を止める。E2E は CI に任せる。ほかの所(① 絞った devcontainer・外へ送る手段の棚卸し・外へ出した物の記録)は ADR 0068 のまま。詳しくは設計書 0057(13 の作り直しの記録)。

## 結果として起きること

- 良くなること: 背景の AI の PR が、結合テストを通ってから出る。CI の結果を GitHub の MCP でも読める。
- 我慢すること: テストを動かす Node は Actions の中で外へ出られる(外の部品なしでは絞れない)。人が見ていない作業の中で、AI が書いたテストのコードが外へ通信できる余地が残る。
- 見直す合図: AI が書いたテストのコードが外へ通信していたことが、外へ出した物の記録や CI で見つかったとき。Actions の通信を外の部品なしで絞れる形が出たとき。
