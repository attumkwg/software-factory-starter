# ADR 0033: 人の時間は PR からの目安と手入力の幅で出し、時給と売上は非公開の置き場から読んで、賭けごとの PL を費用のページに足す

- 状態: 提案
- 日付: 2026-10-25
- 決めた人: @attumkwg(提案は AI。承認待ち)

## 背景

- 持ち主は「賭け(機能)ごとの損益まで見たい」「PL を出したときに採算が合わないとなるのが一番嫌」(仕様 0020)。費用のページ(ADR 0032)には、いちばん大きい原価の人の時間が入っていない。
- 人の時間を正確に測る道具(勤怠・作業時間の記録)はキットに無く、入れると人の手間が増える。一方、全部の PR の本文に「取り組み(どの賭けか)」と「作業の種類」があり(CI が形を保証)、AI が PR を出す前提なので、人の時間の多くは PR の確認とレビューに出る。
- 時給・給与・売上は、公開されうるリポジトリに置けない(bets-and-assets.md の「置かない物」)。

## 選択肢

### 人の時間の出し方

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. PR からの自動の目安(1件あたりの分数)と、週ごとの手入力の割合を並べて幅にする | 手間が少ない(手入力は週1回の割合だけ)。目安と実感のずれが見える | どちらも推定。幅が広いと判定が「分からない」になる |
| B. 手入力だけ | 実感に近い | 書き忘れると0になる。賭けに付け忘れる |
| C. PR の目安だけ | 手間が無い | 会議・調べ物・PR に出ない作業が抜ける |
| D. 勤怠・時間の記録の道具をつなぐ | 正確 | 道具と契約が増える。人の評価に見えやすい |

### 時給と売上の置き場

| 案 | 良い所 | 弱い所 |
|---|---|---|
| E. 費用のページと同じ非公開の S3 の `cost/inputs/`(人が置き、`cost.yml` が読む) | リポジトリにも Actions の変数にも金額が出ない。CSV を置き換えるだけ。版が残る | 置くのに AWS のコンソールか CLI が要る |
| F. Actions の秘密・変数 | 置き場が増えない | 売上を毎月秘密に入れ直すのが手間。秘密は中身が見えず確かめにくい |
| G. リポジトリ | 差分が読める | 公開のリポジトリなら誰でも見える(不可) |

## 決めたこと

- **人の時間は A**。自動の目安の分数は `docs/cost/people.yaml`(金額は無い)で変えられる。判定は幅で(全部が赤字なら赤字・全部が黒字なら黒字・またがれば分からない)。
- **置き場は E**。ページと `summary.json` には賭けごとの合計だけを出し、人ごとの時間と金額は出さない。
- 賭けごとの原価 = 直接(AWS のタグ `Bet`・`saas.yaml` の `bet`)+共通の配り分(既定は人の時間の割合。設計書 0020 の U-1)+人の時間。
- 月1回の `/ledger` は、同じ集計から案の CSV(資産の候補・費用・除却の候補)を作り、キットの案の表(bets-and-assets.md)にそろえる。確定は人と専門家(U-2)。

## 結果として起きること

- 良くなること: 賭けごとに「売上 − 原価(人を含む)」が毎日見え、作り込む前に採算の悪い賭けに気づける。会計の側に渡す案と根拠(PR の番号)がそろう。
- 我慢すること: 人の時間は推定。1人の賭けなら、合計から時給を割り戻せる(ページは非公開の置き場だけに置く)。入力の置き場に AWS の操作が要る。
- 見直す合図: 幅が広すぎて判定がいつも「分からない」(分数を見直すか、手入力を細かく)/ 人が増えて、人ごとの時間を誰が見てよいかを分けたくなった / 会計の側に時間の記録の道具が入った(D に寄せる)。
