# ADR 0083: 課金・個人データ・ログインの入口・顧客への連絡は、コードではなくセンサー(テスト)を守る

- 状態: 採用
- 日付: 2026-10-29
- 決めた人: @attumkwg(2026-10-29。会話で: 「人のレビューは極限まで絞る。人が判断するのは、センサーが正しいかの判定と、人が決めなきゃいけない所に端的に答えること」)

## 背景

- [line.md](../concepts/line.md) の 5 の表は「課金・個人データは危険度『高』」と書いているのに、守る場所の一覧(`.claude/hooks/protected-paths.json`)に `apps/api/src/` の `plans`・`person-data`・`export`・`sso`・`mail`・`usage`・`offboarding` が無かった(2026-10-29 の最終点検)。AI が人の確認なしに変え、`pnpm pr:merge-when-green` でマージまでできた。
- 文書の表と守る場所を突き合わせる検査が無く、新しい場所(`apps/api/src/<名前>/`)を足しても、危険度を決めないまま入った。
- 持ち主の方針は「人のレビューを極限まで絞る」。コードを全部守る場所に入れると、ふつうの機能の PR でも人が呼ばれる。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A コードの場所を守る場所に入れる | 分かりやすい。前の認証・認可と同じ | 機能を足すたびに人が呼ばれ、人がコードを読む。「極限まで絞る」と逆 |
| B その場所を確かめるテスト(センサー)を守る場所に入れ、文書の表と `pnpm guards` で突き合わせる | 扱いを変えるとテストも変わるので、そこでだけ人が呼ばれる。人はコードではなく問い1行に答える | テストが振る舞いを覆っていないと、扱いの変更がすり抜ける |
| C 今のまま(文書だけ) | 何も増えない | 文書と守りがずれたまま |

## 決めたこと

**B**。

- 領域ごとに「守る場所(センサー)」「センサーが確かめるコード(AI が変えてよい)」「変えたら聞く問い」を [risk-areas.md](../concepts/risk-areas.md) に1つの表で持つ。このファイルと検査のスクリプトも守る場所に入れる。
- `pnpm guards`(`scripts/check-guards.mjs`)が、line.md の「高」の言葉 ⇔ risk-areas.md の領域、risk-areas.md の守る場所 ⊆ `protected-paths.json`(⇔ labeler・CODEOWNERS は前からの検査)、`apps/api/src/` の下の場所が「高」か「中」のどちらかに決めてあること、を見る。ずれたら CI が落ちる。
- `pnpm pr:merge-when-green` は、守る場所に触る PR を断るときに、触った領域の問いを返す。AI はそれを「人に判断してほしい所」と Slack の返事に1行で写す。
- 持ち主が挙げた7か所に加えて、同じ考えで SCIM(`auth/` の中のコードは前から守っているが、テストは守っていなかった)・監査の取り漏れ・ファイルの組織の分離・全員へのお知らせのテストも入れた。「顧客への連絡」を line.md の「高」に足した。
- 認証・認可・DB の移行・インフラ・CI は、前どおりコードも守る(戻せない・自分のチェックを自分で緑にできる場所)。

## 結果として起きること

- 良くなること: 文書の「高」と守りが、検査でそろい続ける。過去2週間の main の 260 件のコミットで見ると、新しく人が呼ばれるのは3件(1%)だけ(もともと人が呼ばれるのは142件。その多くは CI・CLAUDE.md を触るキット自身の作業)。
- 我慢すること: テストが振る舞いを覆っていない所は、扱いの変更がすり抜ける。テストを弱める変更は `tests:weakened` の印(`scripts/test-weakening.mjs`)が先に止めるが、足りないテストは見つけない。
- 見直す合図: センサーに触る PR が週に数件を超えて人の待ちになったら、領域ごとに「問いが要る変更」と「要らない変更」を分ける(例: テストの追加だけは問いにしない)。
