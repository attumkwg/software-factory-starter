# ADR 0081: PR の動作確認の手順はコミットせずに PR へ貼り、「通った」を2層で疑う

- 状態: 採用
- 日付: 2026-10-27
- 決めた人: @attumkwg(2026-10-27。会話で回答「基本おすすめで良い」。設計書 0076 の U-1・U-2)

## 背景

- PR ごとの画面の動作確認を AI に回したい(仕様 0076)。AI は E2E の部品で手順を書いて流せる。
- AI の書いた確認は、確かめていないのに通ることがある。決まって出る形は、エラーの放置・API の直叩き・アサーション無し・操作の前から合格・うわべの確認・判定のすり替え(`docs/concepts/line.md` の 2)。
- ふだんの E2E は「大事な流れ5本程度まで」に絞っている(`apps/web/CLAUDE.md`)。PR ごとの確認を全部足すと、E2E が重くなり、手入れされなくなる。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 手順をふだんの E2E としてコミットする | CI で毎回流れる | E2E が PR の数だけ増え、遅く・手入れされなくなる。製品の知識の源(手入れされた E2E)が濁る |
| B. 手順はコミットせずに PR のコメントへ貼る。書き方を lint で止め、通った後も AI が記録を読む | E2E を絞ったまま、PR ごとに確かめられる。何を確かめたかは PR に残る | 同じ確認を何度も書く。lint はすり抜けがあり、2層目は AI の読みに頼る |
| C. 人が手で確かめる(今まで) | 確か | PR が増えると人が詰まり所になる |

## 決めたこと

B。手順は `apps/web/e2e/verify/`(`.gitignore`)に書き、`playwright.verify.config.ts` で流し、PR のコメントに貼る。`test` と `expect` は `e2e/verify-fixture.ts` から取り、画面のエラーと 5xx は通っても落とす。流す前に `pnpm verify:lint` で危ない書き方を止め(1層目)、通った後も AI が記録とトレースを読む(2層目)。何度も要る確認は、別の PR でふだんの E2E に足す。詳しくは設計書 0076。

## 結果として起きること

- 良くなること: PR ごとの画面の確認を AI に回せる。「通った」を信じすぎない形が、書き方と記録の両方に入る。
- 我慢すること: 1層目は文字の形で見るので、すり抜けも、止めすぎもある(止めすぎは書き方を直す。印で逃がさない)。2層目は AI の読みに頼る。
- 見直す合図: 2層目で同じ形が2回見つかったら、1層目(`scripts/verify-lint-lib.mjs`)に足す。同じ確認を3回書いたら、ふだんの E2E に足す。
