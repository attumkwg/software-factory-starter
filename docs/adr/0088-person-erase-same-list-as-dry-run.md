# ADR 0088: 1人分を消すのは、試しと同じコマンド・同じ一覧に --execute を足す

- 状態: 採用
- 日付: 2026-10-29
- 決めた人: @attumkwg(扱いの案 U-2 は 2026-10-25 に承認。G-06 の残りを作ることは 2026-10-29 の穴の棚卸しで承認)

## 背景

ADR 0059 で、1人分は「試し(数えるだけ)と手順書」から始め、消すのは手順書の SQL を2人で手で打つことにした。見直す合図に「扱いの案(U-2)が承認されたら `--execute` を足す仕様を別に出す」と書いた。U-2 は承認済みで、本物の個人データを持つ最初の組織が来る前に、手の SQL をやめたい(表が増えると SQL が古くなり、消し残しに気づけない)。仕様は `docs/specs/0089-person-erase.md`。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| **A. `person-data` に `--execute --confirm-rows <数>` を足す。消すのも試しの一覧(`PERSON_REFERENCES`)と同じ条件で** | 数えた物と消す物がずれない。解約(`delete-tenant`)・ほかの運営のコマンドと同じ「試し → 本番」の形 | 1つのコマンドが読むと書くの両方を持つ |
| B. 別のコマンド `person-erase` を作る | 読むだけのコマンドが書かない、と名前で分かる | 一覧と条件を2か所で持ちやすい。手順書が2つのコマンドを行き来する |
| C. 手順書の SQL を一覧から作って出す(人が流す) | 流すのは人 | 打ち間違い・貼り間違いが残る。監査ログを手で書くことになる |

## 決めたこと

- **A**。試しの数え方と消し方は、同じ一覧・同じ条件(`personMatch`)を使う。
- 確かめの引数は `--confirm-rows <試しの anonymize と delete の合計>`。1人分には名前を引数で渡せない(CloudTrail に残さない)ので、解約の `--confirm-name` の代わりに、2人で読み合わせた試しの数を渡す。違えば何も変えない。
- 1つのトランザクションで流し、終わる前に数え直して、消すはずの行・前のメールで指す行が残っていれば全部取り消す。
- その組織の監査ログに `person.erase`(行為者は仕組み・対象はその人・件数だけ)を残す。お客さんの管理者が自分の画面で見られる。
- 匿名化した人は止める(`disabled_at`)・セッションを切る・Cognito と情シスの道具との結びつきを切る。Cognito の利用者を消すのは、これまでどおり手順書で人が先に。

## 結果として起きること

- 良くなること: 手の SQL が無くなる。一覧の表に personal の列が増えたのに扱いが無ければ CI が落ちる。消したことがお客さんの監査ログに残る。
- 我慢すること: Cognito は手で。バックアップ・ログの中は消せない(保存期間で消える)。消した人の行(「削除した利用者」)は組織の人の一覧に止めたまま残る。
- 見直す合図: 求めが月に数件を超える(Cognito も含めて1回で流す形を考える)。要配慮の表に利用者を指す列ができる(暗号の鍵ごと消す形を考える)。
