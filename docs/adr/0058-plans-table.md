# ADR 0058: プランの定義はコード、組織の契約は足すだけの表、変えるのは運営のコマンド

- 状態: 提案
- 日付: 2026-10-25
- 決めた人: @attumkwg(承認待ち)

## 背景

組織ごとの契約(プラン・人数)を持つ所が無く、上のプランの会社だけに機能を出すのは機能フラグを手で入れていた。値上げで今のお客さんを旧価格に残す(据え置き)には「どの版の価格表か」「据え置きはいつまでか」が要る。請求は外の会計ソフトで手で行う。仕様は `docs/specs/0047-plans.md`。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| **A. 定義はコード(`PLANS`・`PRICE_LISTS`)・契約は足すだけの表・変えるのは運営のコマンド** | 機能フラグと同じ形で覚えることが少ない。定義の変更は PR で見られる。契約の履歴(いつから)がそのまま残る | プランを足すのにデプロイが要る |
| B. プランも価格表も DB(運営の画面で編集) | デプロイなしで変えられる | 運営の画面と権限が要る。定義の変更がレビューされない |
| C. 請求の会社(Stripe など)のプランをそのまま正にする | 請求と食い違わない | 決済の会社が先に要る(いまは会計ソフトで手で)。キットの外の状態に機能の入切が依存する |
| D. 組織の表に列を足す(プラン・人数) | 一番小さい | 履歴と先の日付の契約が持てない。据え置きの期限を足すと列が増え続ける |

## 決めたこと

- **A**。表 `platform.tenant_plans`(プラン・価格表の版・人数・据え置きの期限・効き始めの日)。アプリは読むだけ。運営のコマンド `plan`(見る → 試し → 本番)と `plan-report`(読むだけ)。開通の申し込みのプラン・人数も同じ表に足す。
- 価格表は金額を持たない(設計書 0047 の U-1)。
- 機能フラグに状態 `plan` を足し、プランの機能に入っている組織にだけ出す(組織ごとの行も効く)。
- 人数の上限はプランごとに block(招待を止める)か count(数えるだけ)。数えるのは、いる人+受けていない招待。

## 結果として起きること

- 良くなること: 申込書のプラン・人数がキットの中に入り、機能の入切と人数の上限がつながる。値上げのとき、据え置きの組織と期限が一覧で分かる。
- 我慢すること: プランを足す・機能を変えるのに PR とデプロイが要る。金額はキットに無いので、売上の指標は会計ソフトで出す。
- 見直す合図: 決済の会社を入れる(`billing`)→ C に寄せ、プランの正を請求の側に移すか決め直す。プランが毎月変わるほど多い → B。
