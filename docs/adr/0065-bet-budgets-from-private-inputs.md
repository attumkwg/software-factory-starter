# ADR 0065: 2つ目からの客層の計画は plans/ に置き、賭けの予算の枠は非公開の入力にして割合だけで知らせる

- 状態: 提案
- 日付: 2026-10-25
- 決めた人: @attumkwg(提案は AI。承認待ち)

## 背景

本業と並べて新しい客層を確かめ、ムーンショットに予算の枠を付けたい(仕様 0054・穴 G-19)。決めることは2つ: ① 2つ目の計画をどこに置くか ② 予算の枠をどこに持ち、どう知らせるか。

## 選択肢

① 計画の置き場

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. `docs/product/plan.md` の中に節を足す | ファイルが1つ | 本業と新しい客層の「いまの正」と「これまでの判断」が混ざる |
| B. 全部を `docs/product/plans/<名前>.md` に移す | 形がそろう | `plan.md` を読む所(スキル・セットアップの案内)を全部直す。今の使う人の計画が動く |
| C. 本業は `plan.md` のまま、2つ目からを `plans/<名前>.md` に | 今の所を変えない。場所で本業か新しい客層かが分かる | 本業だけ置き場が違う |

② 予算の枠

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 賭けのファイルに金額を書く | 1か所で見える | 金額をリポジトリに置かない決まりに反する(公開されうる) |
| B. AWS Budgets を賭けのタグごとに作る | AWS の知らせが使える | 人の時間・SaaS が入らない。Terraform の apply が要る |
| C. 非公開の入力 `budgets.csv` に置き、費用のページの賭けごとの PL と比べ、割合だけを Slack に知らせる | 人の時間を含められる。今の流れ(非公開の入力・PL・Slack の秘密)に乗る | 費用のページを流した時だけ知らせる(毎日にするかは `cost.yml` の定期による) |

## 決めたこと

① は **C**、② は **C**。使った額は PL の原価の上の端、見込みは月の中で増える分を日割りで伸ばす。注意の線の既定は 80%。知らせには賭けの ID と割合だけを出し、公開のリポジトリでは Actions の要約に出さない。

## 結果として起きること

- 良くなること: 新しい客層を本業と並べて確かめられる。枠を超える前に気づける。金額が外に出ない。
- 我慢すること: 知らせは費用のページを作った時だけ。期間の合計(半年で◯円)は人が月ごとの写しで見る。
- 見直す合図: 新しい客層の計画が3つ以上になり、本業との違いが分かりにくい(全部を `plans/` に移す)・期間の合計で止めたい賭けが増えた(前の月の写しを読む)。
