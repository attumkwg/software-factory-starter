# ADR 0057: 「無くなったら困るか」の答えは、答え終えた印(答えなし)と数(人なし)に分けて持ち、だれが何と答えたかを結びつけない

- 状態: 採用
- 日付: 2026-10-25
- 決めた人: @attumkwg(2026-10-25。会話で回答。親のセッションから)

## 背景

- PMF の兆し(「とても困る」の割合)を、キットの中で聞いて数えたい(穴 G-39・仕様 0046)。
- 1人1回にするには、だれが答えたかを覚える要る。一方で、だれが「困らない」と答えたかが運営や組織の管理者に分かると、正直に答えてもらえない・個人情報としても重くなる。
- 出す相手は、運営が選んだ組織だけにしたい(機能フラグがある。ただしフラグは賭けに結びつく決まり)。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 印(人・回・日。答えなし)と数(組織・回・答え・数。人と時刻なし)の2つの表 | 表の形だけで、だれが何と答えたかが分からない。1人1回も守れる | 表が2つ。後から「この人の答え」を直す・消すことはできない |
| B. 1つの表に人と答え | 作りが簡単。答えの直しができる | 運営・管理者が個人の答えを読める。消すまで個人の答えが残る |
| C. 外のアンケートの道具 | 作らない | 回答者の名前・連絡先が外に出る。使っている人に絞れない。委託先が増える |

## 決めたこと

A。数を足すのと印を足すのは同じトランザクション。数には時刻を持たせない(印の日と突き合わせられないように)。監査ログには「答えた」だけを残し、答えは入れない。集計は全部の組織を足した数だけを出す。

出す相手は機能フラグ `pmf-survey` で選ぶ。フラグの決まりに「キットの仕組み(賭けではない)は `bet: "kit"`」を足す。

## 結果として起きること

- 良くなること: PMF の兆しを、使っている人だけから・個人を出さずに・繰り返し測れる。
- 我慢すること: 個人の答えは直せない・消せない(数から1を引く道が無い)。自由記述の理由は取らない(話を聞く)。
- 見直す合図: 理由(自由記述)を集めたくなったとき(個人が分かる文が入るので、別の判断が要る)。組織ごとの割合を見たくなったとき(組織が少ないと個人に近づく)。
