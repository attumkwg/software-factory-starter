# ADR 0042: 当番は「お客さんに影響がある」ときだけ起こし、表はリポジトリの外に置く

- 状態: 採用
- 日付: 2026-10-25
- 決めた人: @attumkwg(2026-10-25。会話で回答)

## 背景

アラームは Slack に流れるだけで、夜中に誰が見るかが決まっていなかった。全部のアラームで人を起こすと、遅い・メールの評判・費用のような朝でよい物でも起こされ、続かない。逆に Slack だけでは夜中に誰も気づかない。SLA の型は連絡の時間を「営業時間の中で数える」にしているが、夜中も約束する契約を結ぶなら、決まりが先に要る。

## 選択肢

起こす線:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 全部のアラームで起こす | 見逃さない | 朝でよい物で起こされ、数週で当番が回らなくなる。本物を見逃す |
| B. **お客さんに影響がある・約束の水準を割りそう・漏えいのおそれのときだけ起こす**。ほかは朝 | 起きる回数が少なく、起きたら必ず意味がある | 朝に回した物が、実は影響の始まりだったことがある(5xx が一緒に鳴る作りで補う) |
| C. 起こさない(営業時間だけ) | 体制が要らない | 夜中の停止が朝まで続く。夜中を約束する契約が結べない |

表の置き場:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| リポジトリに表を置く | 1か所にそろう | 名前・電話が履歴に残る(公開のひな形から作ったリポジトリでは特に) |
| **呼び出しの道具かカレンダーに置き、リポジトリには決まりだけ** | 個人の情報を履歴に残さない。交代を道具が回す | 決まりと表が別の所になる |

## 決めたこと

- **B**。アラームごとに「夜と休日に起こすか」を理由つきで表にする(`docs/guides/on-call.md` の 3)。迷ったら起こす側に倒し、翌日に表を直す。
- 当番は一次・予備・上げる先の3人から。連絡の段は15分ずつ。当番の間は改善の作業だけ。
- 表はリポジトリの外。決まり・夜の扱いの表・SLA との対応だけをリポジトリに置く。
- 当番を置くのは、夜中も約束する契約を結ぶ前(それまでは C のまま、SLA を営業時間で約束する)。
- 呼び出しの道具は使う人が選ぶ。入れるときは委託先の台帳に1件、知らせの道は2本(東京とバージニア)ともつなぐ。

## 結果として起きること

- 良くなること: 夜中に鳴ったら「起こすべき物か」が表で決まっている。SLA で夜中を約束するかを、体制と一緒に決められる。
- 我慢すること: 朝に回したアラームで、影響の始まりに気づくのが遅れることがある。呼び出しの道具の費用。
- 見直す合図: 当番の間に夜中の呼び出しが週2回を超えたら、しきい値か作りを直す(交代を日ごとに)。朝に回した物が原因の障害が出たら、その行を「起こす」に変える。
