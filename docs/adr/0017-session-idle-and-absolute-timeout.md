# ADR 0017: ログインは「無操作1時間+ログインから最長12時間」。Cookie だけで数え、サーバー側のセッション保存は作らない

- 状態: 採用
- 日付: 2026-10-20
- 決めた人: @attumkwg(作者の決定 2026-10-20。設計は docs/designs/0006-account-security.md)

## 背景

セッションは署名つきの Cookie(ADR 0007)で、ログインから8時間で切れる(`SESSION_TTL_SECONDS`)。席を離れたまま開いておいても8時間は切れず、使い続けていても8時間で切れる。README と `session.ts` には「次の一歩: サーバー側のセッション保存(強制ログアウト)」と書いてあった。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. Cookie にログインした時刻を入れ、使うたびに出し直して期限を延ばす(無操作1時間・最長12時間) | 表も Valkey も要らない。いまの作りのまま | 端末を選んで切る・管理者が強制ログアウトさせる、はできない |
| B. サーバー側にセッションを持つ(DB か Valkey) | 端末の一覧・強制ログアウトができる | 表か Valkey・毎回の読み・掃除が増える |
| C. Cognito のリフレッシュトークンで延ばす | Cognito 側でも取り消せる | トークンをどこかに持つ必要がある(ADR 0007 に反する)。Cognito への呼び出しが増える |

## 決めたこと

**A**(作者 @attumkwg の決定。「サーバー側でのセッション時間などは特にやらなくてもいい」)。

- Cookie の中身: `人.組織.期限.ログインした時刻`(代理は後ろに `入室の ID.見ている組織`)。署名はいまと同じ。
- 期限 = min(最後に出し直した時刻 + 1時間, ログインした時刻 + 12時間)。設定は `SESSION_IDLE_SECONDS`(3600)・`SESSION_MAX_SECONDS`(43200)。`SESSION_TTL_SECONDS` は消す。
- 関所が認可を通したリクエストで、前に出してから60秒以上たっていれば出し直す。画面の読み込み(SSR)で API が返したセッションの Cookie も、画面の応答に写す。
- 代理ログインも同じ決まり(社員のログインした時刻を引き継ぐ)。代理の最長1時間などは今までどおり DB で確かめる。
- 古い形の Cookie は読まない。出したときに全員が1回ログインし直す(本番はまだ無い)。

## 結果として起きること

- 良くなること: 開いたままの画面・盗まれた Cookie が使える時間が短くなる。使っている人は8時間で切られなくなる。
- 我慢すること: 端末を選んでログアウトさせる・管理者が人を強制ログアウトさせる、はできない(パスワードなどを変えたときに全部の端末を切るのは、`users.sessions_valid_after` でできる。docs/designs/0006-account-security.md の U-2)。
- 見直す合図: 端末の一覧・端末ごとのログアウト・管理者による強制ログアウトが要るようになったら、B を検討する。
