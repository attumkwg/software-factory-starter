# ADR 0002: 部品の土台は React Aria Components にする

- 状態: 採用
- 日付: 2026-10-17

## 背景

画面を AI が多く書くので、**誰が書いても同じ見た目で、キーボードや読み上げでも使える**部品の置き場が要る。
アクセシビリティ(キーボード操作・読み上げ・フォーカスの管理)を部品ごとに自分で作るのは大変で、漏れやすい。
土台になる「見た目を持たない部品の集まり」を1つ選ぶ。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| React Aria Components(Adobe) | 1つのパッケージ。アクセシビリティが一番手厚い(国際化・日付・表のキーボード操作まで)。状態が `data-*` 属性で出るので CSS だけで見た目を決められる | 部品の名前や組み立て方に慣れが要る。通知(Toast)はまだ不安定版 |
| Radix UI+shadcn/ui の形 | 例と利用者が多く、AI も書き慣れている。部品をリポジトリに写して自由に直せる | 部品ごとにパッケージが分かれる。shadcn/ui は Tailwind が前提で、写した部品の更新を自分で追う |
| 自作 | 依存が無い | アクセシビリティを全部自分で。漏れる |

## 決めたこと

**React Aria Components** を土台にし、`packages/ui` で見た目(CSS 変数のトークン)を付けた部品として包む。

- 画面は `@app/ui` の部品だけを使う。React Aria を画面から直接使わない(見た目の決まりが散らばるため)。
- 見た目は `packages/ui/src/tokens.css` の変数だけ。生の色コード・直書きのスタイルは Semgrep で止める(`.semgrep/design/`)。
- 通知(Toast)だけは、React Aria の版が安定するまで、`aria-live` を使った小さな自前の部品にする。
- Tailwind は入れない(CSS 変数と小さな CSS で足りる規模。入れるなら ADR を書き直す)。

## 結果として起きること

- 良くなること: キーボード・読み上げ・フォーカスの扱いが部品に入っている。E2E の axe で、色のコントラストやラベルの漏れを毎回確かめられる。
- 我慢すること: 部品が足りないときは、画面ではなく `packages/ui` に足す手間がある(`docs/design-system.md` の手順)。
- 見直す合図: 部品が30個を超えて保守が重くなった/デザイナーが Figma のトークンと自動でつなぎたくなった/Toast が React Aria で安定した(自前をやめる)。
