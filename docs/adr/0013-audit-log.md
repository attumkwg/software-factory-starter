# ADR 0013: 監査ログは DB の「足すだけ」の表に、認可の関所で自動に記録する

- 状態: 採用
- 日付: 2026-10-18
- 決めた人: @attumkwg

## 背景

「誰が・いつ・何をしたか」の記録が無かった。お客さんの管理者は「誰が消したか」を確かめられず、運営も事故や問い合わせのときに頼れる記録が無い。このあと入れる**代理ログイン**(社員がお客さんの画面を見る。お客さんからも記録が見えること)と**解約**も、記録の置き場を必要とする。仕様は `docs/specs/0003-audit-log.md`。

## 選択肢

置き場所:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| **A. DB の表(足すだけ)** | 書き込みと同じトランザクションで残せる(書き込みだけ成功して記録が無い、が起きない)。お客さんの管理者に画面で見せられる。RLS で他社と混ざらない | DB の持ち主の権限があれば理屈の上では消せる(トリガーで決まった手順の外は止める) |
| B. A に加えて、消せない S3(Object Lock)に写す | 持ち主でも消せない | 送る仕組み(アウトボックス → S3)が増える。PMF 後 |
| C. ログ(CloudWatch)だけ | 安い・簡単 | お客さんに見せられない。保存期間が短い |

記録の取り方:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| 各 API の中で `recordAudit(...)` を呼ぶ | 何を残すかを自由に書ける | 書き忘れる(AI が API を足すたびに) |
| **認可の関所で自動に。名前だけ表に決める** | 書き忘れが起きない(名前が無ければ CI が落ちる)。全部の書き込みが同じ形 | 記録の中身は「対象の ID・ほかのパスの ID・直した項目の名前」まで。細かいことは残せない |

## 決めたこと

- **A** と**関所で自動**。本人の選択(2026-10-18)。
- 記録は**値を持たない**(題名・本文を入れない)。お客さんの入力を写すと、記録が二つ目のデータ置き場になる(漏れ・削除の範囲が広がる)。直した項目は**検証を通った本文**の項目の名前だけ(生の本文のキーは、好きな名前を送れるので使わない)。
- 拒否された書き込み(403)も残す。失敗した書き込み(入力の誤り・同時の変更・バグ)は残さない(起きていない)。
- 表の持ち主でも、UPDATE は常に・DELETE と TRUNCATE は `app.audit_purge = 'on'` の手順(解約・保存期間の削除)の外では、トリガーが止める。
- ページの続きは ID(UUIDv7 は時刻の順)で切る。時刻で切ると、JS の Date がマイクロ秒を落として行が抜けることがある。

## 結果として起きること

- 良くなること: 書き込みの API を足すと、名前を1行決めるだけで記録される。お客さんの管理者が自分で確かめられる。代理ログイン・解約の記録も同じ表に入る。
- 我慢すること: 「何を読んだか」は残さない(代理ログインの社員だけは次の PR で残す)。値が無いので「何から何に直したか」は分からない(要るならログと requestId で追う)。
- 見直す合図: 大きなお客さんから「消せない記録」「何年残す」を求められたら B(S3 の Object Lock)。表が大きくなったら(1社 数百万行)、月ごとに分ける(パーティション)か、古い分を S3 へ。
