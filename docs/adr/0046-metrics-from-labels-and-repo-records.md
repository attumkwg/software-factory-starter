# ADR 0046: 週の数字は、PR のラベルとリポジトリの記録から数える

- 状態: 提案
- 日付: 2026-10-25
- 決めた人: @attumkwg(提案は AI。承認待ち)

## 背景

AI に任せる範囲を広げる判断(危険度「低」の自動マージ・本番の承認の自動化)と、毎週の振り返りのために、DORA の4つ・AI が手伝った PR の割合・人の介在率・仕様の在庫を毎週数えたい(仕様 0035・穴 G-12)。何を元にして数えるかを決める必要があった。特に、① AI が手伝った PR をどう見分けるか、② 障害(変更の失敗率・復旧の時間)をどこから読むか。

## 選択肢

① AI が手伝った PR

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. コミットの署名(`Co-Authored-By: Claude`)から見分ける | 何も足さなくてよい | 人が手で足したコミット・署名の無い道具・squash で消えた署名で取りこぼす。人が直せない |
| B. PR の本文の印から、数えるたびに見分ける | 足す物が少ない(費用のページは今これ) | 間違いを人が直す道が無い(本文を書き換えるしかない) |
| C. 本文の印から Actions がラベルを付け、ラベルで数える | 画面で見える・人が付け外しして直せる・数える側は1つの見分け方 | ワークフローとラベルが1つずつ増える |

② 障害

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 障害の Issue にラベルを付けて、開いてから閉じるまで | 数えやすい | 今の手順(Slack で宣言 → 振り返りのファイル)に無い置き場が増え、閉じ忘れで数が狂う |
| B. 振り返り(`docs/incidents/`)に「戻るまで」「変更が原因」の2行を足して読む | 今ある記録(S1・S2 は必ず書く。指揮が書いた物が正)に乗る | S3 は数に入らない。書き忘れると読めない(読めなかった件数を出す) |
| C. アラームや Sentry から自動で | 人が書かなくてよい | 外のサービスの権限が要る。「変更が原因か」は人にしか分からない |

## 決めたこと

① は **C**、② は **B**。

- ラベル `ai:assisted` は `ai-label.yml` が本文の印(`docs/cost/people.yaml` の `ai_markers`)と AI のボットから付け、付けるだけで外さない。印の無い AI の PR は人が付ける。週の数字も費用のページの人の時間も、ラベルで AI の PR と見る(費用のページは本文の印でも見るまま)。
- 障害は振り返りのファイルの2行で読む。失敗したデプロイ(Environment `prod` の最後の状態が失敗)も変更の失敗に数える。
- そのほか(デプロイ・PR・コミット・仕様)は GitHub とリポジトリにある物だけで数え、新しい置き場を作らない。

## 結果として起きること

- 良くなること: 数え方が1つにそろう(週の数字と費用のページ)。人がラベルと振り返りで数を直せる。外のサービスや新しい権限が要らない。
- 我慢すること: ラベルを入れる前の PR は AI の PR に数えない(さかのぼらない)。S3 の障害は数に入らない。仕様の「作る待ち」は当てずっぽう(作った物から番号が指されているか)。
- 見直す合図: 印の無い AI の PR に人が付ける手間が増えた(AI の道具が増えた)・S3 の障害が多くて失敗率が実感と合わない・仕様を完了にし忘れて作る待ちが実感と合わない。
