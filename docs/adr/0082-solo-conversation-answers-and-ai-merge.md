# ADR 0082: 1人の間は、持ち主の会話の返事を答えにし、必須のチェックが緑なら AI がマージする

- 状態: 採用
- 日付: 2026-10-28
- 決めた人: @attumkwg(2026-10-28。会話で回答。仕様 0080 の「決めたこと」)

## 背景

- 目指す姿は「Slack でクラウドの AI に頼むと、AI が作って PR まで出し、人はマージの判断だけ」(仕様 0080)。
- 今のキットでは、AI の PR が3か所で人を呼ぶ: ① 未確定事項の答えは、人が GitHub に書いたコメントだけ(G-61・ADR なし・仕様 0061)② AI はマージしない(フックと設定)③ 作る前の対話と3段の PR(`/new-feature`)。
- 1人で回している間は、レビューする人も答える人も持ち主1人。答えは Slack かチャットで返すのが自然で、GitHub に書き直すのは手間だけが増える(持ち主の指摘)。
- 一方で、仮決めは必ず持ち主に「これでいいですか」と確かめる(持ち主の答え)。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A 今のまま(答えは GitHub のコメント・マージは人) | AI が答えを作れない | 頼むたびに GitHub を開いて書き、押す。「頼めば作る」にならない |
| B 1人の間だけ、会話の返事を答えにし、返事+必須のチェックが緑で AI がマージ | Slack の返事だけで終わる。人が増えれば自動で A に戻る | CI は会話の書き手を確かめられない。AI が「返事があった」と偽ると止められない |
| C いつでも B | 人が増えても速い | レビューの数とつり合わない。2人目の目を外すことになる |

## 決めたこと

**B**。1人の間(`.github/setup.yml` の `required_approvals: 0`)だけ:

- 未確定事項の状態に `Slack`・`チャット`・`会話` と書いた行は、`@持ち主` なら答えとして CI が通す(`scripts/decisions-lib.mjs`)。
- AI のマージは `pnpm pr:merge-when-green` だけ。持ち主がクラウドの環境に `KIT_AI_MERGE=slack` を入れた所だけで動き(手元とコマンドの中で入れたときはフックが止める)、必須のチェックが全部緑で、待つ間に push が無いときだけマージする。
- 合図は、その作業に持ち主が返した返事だけ(`/slack-request`)。

偽りの返事への守りは、マージの前に必須のチェックが全部通ること・PR とスレッドに返事の文が残ること・持ち主が依頼のチャンネルを自分だけにすることで受ける(1人の間の割り切り)。

## 見直し(2026-10-28)

キットを5人の AI でレビューしたとき、AI のマージが印(危険度「高」・テストを弱めた)を見ておらず、Slack の道では人が PR を開かないので、認証・移行・CI の変更が返事の一言で入りうると分かった。CI は PR 自身の版で動くので、`.github` を変える PR は自分のチェックを自分で緑にできる。

→ **危険度「高」・テストを弱めた印の PR と、危険度「高」の場所・守りの場所(`.github/**`・`.claude/**`・`CLAUDE.md`・検査とマージのスクリプト)に触る PR は、AI はマージしない**(`scripts/pr-merge-lib.mjs` の `humanOnlyReasons`。待つ前とマージの直前の2回見る)。人が GitHub で中身を見て押す。

## 結果として起きること

- 良くなること: Slack に1行 → 「これでいいですか」に返事 → マージ、で1件が終わる。
- 我慢すること: CI は会話の書き手を確かめない。AI が偽りの返事でマージした場合、気づくのはスレッドと PR を後で読んだとき。
- 見直す合図: 人が増えて承認数を 1 以上にしたとき(自動で止まる)・AI が返事なしにマージした・承認に書き換えたことが1度でもあったとき。
