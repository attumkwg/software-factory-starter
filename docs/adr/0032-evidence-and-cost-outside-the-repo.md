# ADR 0032: 証跡と費用の集計は、使う側の非公開の S3 に置き、費用は静的な HTML の1枚で見せる

- 状態: 提案
- 日付: 2026-10-25
- 決めた人: @attumkwg(提案は AI。承認待ち)

## 背景

- 認証(P マーク・ISMS)の審査では、「その月に、その設定だった」ことを**後から変えられない記録**で見せる必要がある。今は GitHub の画面・AWS のコンソールを、審査の前にスクショで集め直している。
- 持ち主は「今いくらかかっていて、動いている物ごとにいくら投入されているか」を1枚で見たい(仕様 0019)。費用は AWS・GitHub Actions・AI・そのほかの SaaS に散っている。
- キットは**公開のリポジトリ**。証跡(人の名前・権限・使っているサービス)と請求の詳細は、公開のリポジトリ・公開の Actions のログと成果物・GitHub Pages に出せない。使う側のリポジトリも公開かもしれない。
- 記録の置き場には、ほかに CloudTrail の S3 とバックアップの保管庫がある(どちらも別の用途で、書き込む主体も違う)。

## 選択肢

### 証跡の置き場

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 使う側の AWS の、証跡だけの S3(Object Lock・自前の鍵・公開を止める) | 消せない・書き換えられない(版が残る)。費用は月数円。審査に中身と SHA-256 で見せられる | AWS の apply と変数が要る(人がやる) |
| B. リポジトリにコミットする | 何も足さずに済む・差分が読みやすい | 公開のリポジトリに人の名前と権限が出る。履歴は強制 push で書き換えられる |
| C. Actions の成果物 | 簡単 | 公開のリポジトリでは誰でも落とせる。保存は最長90日(このキットは7日) |
| D. CloudTrail の S3 に相乗り | 置き場を増やさない | CloudTrail が書く場所に Actions の書き込みを許すと、記録の信用が下がる。保存の期間と鍵の決まりが違う |

### 費用の見せ方

| 案 | 良い所 | 弱い所 |
|---|---|---|
| E. 集めた JSON から静的な HTML の1枚を作り、非公開の S3 に置く(非公開のリポジトリなら成果物にも) | AWS・Actions・AI・SaaS を1枚に混ぜられる。見積もり(段階の表)と並べられる。依存を足さない。費用は Cost Explorer の呼び出し(1回 $0.01)だけ | 見るのに S3 のコンソールか期限つきの URL が要る。毎日の更新(リアルタイムではない) |
| F. CloudWatch のダッシュボード(Terraform) | AWS のコンソールでいつでも見られる。アラームと同じ所 | AWS の外の費用(Actions・AI・SaaS)を載せられない。費用の数字は請求の指標(毎日の EstimatedCharges・us-east-1 だけ)で粗い。3枚を超えると1枚 月 $3 |
| G. GitHub Pages | URL を開くだけ | 公開のリポジトリでは誰でも見える(非公開の Pages は Enterprise だけ) |
| H. QuickSight・外の BI | 見た目が良い・自由に切れる | 1人 月 数千円〜。設定が重い。PMF の前には過ぎる |
| I. Cost Explorer のコンソールだけ | 足す物が無い | AWS の外が見えない。「動いている物ごと」はタグを毎回選び直す |

## 決めたこと

- **証跡は A**。CloudTrail とは別の、証跡だけの S3(`modules/record-store` の `lock` つき)を prod のアカウントに置く。書くのは main からだけ引ける役割で、足すだけ(`s3:PutObject`。消す・古い版を消す権限は持たせない)。
- **費用は E**(② の PR で作る)。集めた JSON と HTML は、非公開の S3(`record-store` の `lock` なし。古い版は400日で消す)にだけ置く。Actions の成果物には、リポジトリが非公開のときだけ置く。**F(CloudWatch のダッシュボード)は足さない**: AWS の外の費用を載せられず、「何にいくら」の問いに答えられないため。AWS の中の急な変化は、Budgets(今ある)と Cost Anomaly Detection(② で足す)のアラームで知らせる。
- **AI の費用は API で取らない**。Anthropic の使用と費用の API は管理用の鍵(Admin API key)でしか読めず、この鍵は組織の人と鍵を作り・消せる。**管理用の鍵は GitHub(Actions の秘密)に置かない — 漏れると組織ごと取られる**(持ち主の答え 2026-10-25:「人が取った方がいい。管理用の鍵を GitHub に置く方が危険」)。AI の席・使用料の月額は、人が `docs/cost/saas.yaml` に手で書き、ページの AI の欄はそこから出す。
- 集める部品(AWS CLI の呼び出し・束ね方と SHA-256 の目録・ログに中身を出さない決まり)は、証跡と費用で同じ物(`scripts/evidence/lib.mjs`)を使う。
- ログ(公開されうる)には、集めた物の名前と件数だけを出す。アカウントの番号と ARN は伏せる。

## 結果として起きること

- 良くなること: 審査の前のスクショ集めが要らなくなる。毎月の設定が、消せない場所に日付つきで残る。費用が1枚で、見積もりと並んで見える。公開のリポジトリから証跡と請求の詳細が漏れない。
- 我慢すること: 使い始めに prod の apply と変数の設定が要る(人がやる)。費用のページは毎日の更新で、見るには S3 のコンソールか期限つきの URL が要る。Object Lock の向きと年数は、作った後に縮められない(設計書 0019 の U-1)。
- 見直す合図: AWS のアカウントが3つを超えて、まとめて見たくなった(Organizations の管理のアカウントから集める形に)/ 費用を毎日ではなく時間ごとに見たくなった / 人が増えて、ページを URL で配りたくなった(認証つきの置き場へ)。
