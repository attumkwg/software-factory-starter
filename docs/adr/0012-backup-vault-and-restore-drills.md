# ADR 0012: バックアップは消せない保管庫にも取り、「戻せる」を毎月確かめる

- 状態: 採用
- 日付: 2026-10-18
- 決めた人: @attumkwg

## 背景

DB のバックアップは Aurora の自動バックアップ(prod 14日・stg 7日。時点復元)だけだった。これは便利だが、(1) 35日より前には戻せない、(2) クラスターと同じ所にあり、権限のある人や乗っ取られた鍵なら消せる、(3) **戻したことが一度も無い**(戻し方の手順も無い)。「バックアップと、戻せることの確認」は PMF の前から雑にしてはいけない物の1つ(docs/concepts/stages.md の「雑にしてはいけない所」)。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. いまのまま(自動バックアップだけ) | 費用も手間も増えない | 上の (1)〜(3) が残る |
| B. **AWS Backup で毎日・毎月を、同じアカウントの消せない保管庫(Vault Lock)に** | 誤って・乗っ取られて消される、に強い。1年前の月初に戻せる。月 数百円から | アカウントごと失う事故には弱い。prod の compliance のロックは取り消せない |
| C. B に加えて、バックアップ専用の別アカウントへ写す | いちばん強い | Organizations の設定・鍵の共有が増える(PMF 後) |

戻せるかの確かめ方:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| 手順書だけ・四半期に人が | 仕組みが増えない | 忘れると、戻せないことに気づけない |
| **stg は毎月自動・prod は四半期に人が** | 手順と権限が壊れたら毎月分かる。prod のお客さんのデータを CI に触らせない | prod の自動の確かめは無い |
| stg も prod も毎月自動 | 確実 | CI から prod の DB に触れる入口が増える |

## 決めたこと

- **B**。stg は governance(外せる)、prod は **compliance**(3日の猶予の後、二度と外せない)。毎日 35日・毎月 365日。失敗は Slack へ。
- **stg は毎月自動・prod は四半期に人が**。自動の訓練(`restore-drill.yml`)は「名前が `-restore-drill-` で始まる一時の DB」しか触れない役割で、時点復元 → 表・移行・行の数 → 消す。かかった時間と戻せた時点を残す。自動の実行は、ほかの費用のかかるワークフローと同じく「有効にする日」を決めるまで手動(guides/automation.md)。
- 戻し方は3通り(1社分・表ごと・丸ごと)を手順書にする(`docs/runbooks/db-restore.md`)。1社分の手順は手元の DB で試した。

## 結果として起きること

- 良くなること: 「戻せる」が毎月の事実になる。戻すのにかかる時間の目安が手順書に入る。誤って消した1社のデータを、ほかの会社に触れずに戻せる。
- 我慢すること: prod の保管庫の設定(保存の期間)は、3日を過ぎると変えられない。保存の費用が少し増える。
- 見直す合図: 有料の顧客が付き、契約で「災害時の復旧」を約束するようになったら C(別アカウント・別リージョン)。解約した会社のデータを、バックアップの中からも消す約束が要るようになったら、保存の期間とテナントごとの鍵(docs/security.md の T-5)を見直す。
