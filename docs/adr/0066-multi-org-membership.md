# ADR 0066: 1人が複数の組織に所属する。組織を選び直すとセッションを出し直す(ADR 0001 の「1人 = 1組織」を置き換え)

- 状態: 提案
- 日付: 2026-10-25
- 決めた人: @attumkwg(承認待ち)

## 背景

ADR 0001 は「いまは1人 = 1組織」とし、見直す合図に「複数の組織に入る人が必要になった → 所属の表を足し、組織の切り替え(トークンは1社分だけ有効)」と書いた。複数の病院で働く医師・拠点や取引先をまたぐ人がいるお客さんで、その合図が来た(穴 G-21)。仕様は `docs/specs/0055-multi-org-membership.md`。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| **A. users の行を所属として使う(メールと sub の一意を組織ごとに)。選び直すと Cookie を出し直す** | セッション・関所・RLS・参照を変えない。組織ごとの名前・ロール・同意がそのまま使える | 人に1つの物(メール・二段階認証の写し・切った時刻)を全部の所属にそろえる関数が要る。一意を外すのは戻せない |
| B. 人の表(identities)を足し、users を所属の表に作り直す | 人と所属がはっきり分かれる | 全部の表の参照・監査ログの「誰が」・RLS の前提が変わる。移行が大きい |
| C. 1つのセッションで複数の組織を見る(組織を本文や URL で選ぶ) | 画面で並べて見られる | 「テナントはセッションからだけ」(ADR 0001 の 2)を崩す。書き忘れで漏れる |
| D. 組織ごとに別のアカウント(今のまま) | 何も作らない | 人がメールを組織の数だけ持つ。招待で他社の人を呼べない |

## 決めたこと

- **A**。ADR 0001 の決めたことの 2(テナントはセッションからだけ)はそのまま。置き換えるのは「1人 = 1組織」と、その見直す合図だけ。
- 組織を選び直す API(`POST /api/session/organization`)は本文に組織の ID を取るが、組織を決めるのは「セッションの人(Cognito の sub)がその組織に所属しているか」を DB の関数で確かめた結果で、ログインと同じ扱い。Cookie は1組織分だけ有効。
- 組織が決まる前に所属を引くのは、今と同じく SECURITY DEFINER の関数だけ。所属の一覧は本人にだけ返す。
- 人に1つの物(パスワード・二段階認証・メール・ほかの端末を切る)は Cognito が正で、users の写しは全部の所属に関数でそろえる。
- 移行は ① 拡張 → ② 両方 → ③ 縮小(全体の一意を外す。戻せない)。
- ADR 0001 は、この ADR が採用になったときに状態を「一部置き換え(→ 0066)」にする。

## 結果として起きること

- 良くなること: 1人が複数の組織で働ける。招待で他社の人を呼べる。分離の仕組み(セッション・関所・RLS)は今のまま。
- 我慢すること: 写しをそろえる関数と、Cognito を消すのは最後の所属のときだけ、の決まりが増える。全体の一意を外した後は戻せない。
- 見直す合図: 人に紐づく物(個人の設定・通知の受け方・SSO の人の結びつき)が増えた → B(人の表)。1つの画面で組織をまたいで見たい声が強い → 読むだけの横断の画面を、組織ごとの API を並べて作る(C にはしない)。
