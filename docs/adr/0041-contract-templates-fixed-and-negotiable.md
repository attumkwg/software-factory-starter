# ADR 0041: お客さんに出す取り決めは、文面ではなく「項目・既定・根拠」の型にし、変えない条件を先に分ける

- 状態: 採用
- 日付: 2026-10-25
- 決めた人: @attumkwg(2026-10-25。会話で回答)

## 背景

営業が申込書・SLA・個人データの取り扱いの取り決めを、お客さんごとに一から作っていた。中身の多く(バックアップの期間・戻せる時点・解約後に消えるまで・障害の連絡・再委託先・安全管理措置)はキットの作りからもう決まっているのに、散らばっていて営業の1枚になっていない。SLA は稼働率の数字だけを出しがちで、割ったときに「何を測ったか・どの停止を数えるか・補償・誰が決めるか」で揉める。大企業の個別の契約書では、仕組みで守れない約束(例: バックアップから30日で消す。prod の保管庫はロックで縮められない)を書いてしまう危うさがある。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 文面のひな形を書く | すぐ出せる | 法律の文は専門家が書く物で、キットが書くと誤りがそのまま広まる。業種・契約で文が変わる |
| B. **項目・キットの既定・根拠のファイル・使う人が決めること、の型**にし、条件を「変えない / 仕組みを変えれば変えられる / 契約だけで変えられる」に分ける | 仕組みの事実と約束がつながる。専門家に渡す材料になる。交渉で守れない約束を避けられる | 文面は使う人が専門家と作る。型の値と仕組みの値が食い違うおそれ |
| C. 何も足さず、根拠のファイルを営業に読ませる | 足す物が無い | 営業は手順書を読まない。SLA の測り方と補償は、どこにも無い |

型の値と仕組みの食い違いの防ぎ方:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| 型に値を写さず、リンクだけ | 食い違わない | 営業の1枚にならない |
| **値を並べ、横に根拠のファイルを置く。正は根拠** | 1枚で読める。どこを見れば正しいかが分かる | 仕組みを変えたときに型を直し忘れうる |
| 型を機械の読める形にして Terraform と照らす | 食い違いを CI で止められる | 型が読みにくくなる。照らす仕組みが要る |

## 決めたこと

- **B**。`docs/legal/` に README(キットの作りから決まる項目と、3つの分け)と、申込書・SLA・取り扱いの取り決めの型を1つずつ。文面は書かず、各型の頭と最後に「専門家に確かめる」。
- 値は型に並べ、**正は根拠のファイル**。根拠の元の表(`docs/guides/data-retention.md`)の頭で「期間を変えたら型も」を求める。機械の照らし合わせは、食い違いが起きてから。
- SLA は、測る物(外形監視と、それで見えない停止を振り返りの S1 で補う)・数える停止の区分・補償の段・義務か努力目標か・事実を確定する人(障害の指揮)と例外を認める人(責任者)を、数字と一緒に決める。停止の事実は振り返りの記録が正。
- 既定の数字(稼働率の線・補償・連絡の時間・削除までの日数・契約の期間・申し込む権限の確かめ方・委託先として扱うか)は、答えがプロダクトごとに変わるので、設計書 0028 の未確定事項に置く。

## 結果として起きること

- 良くなること: 営業が聞かれる仕組みの事実が1か所にそろい、根拠まで辿れる。SLA を割ったときに、測り方・区分・決める人が先に決まっている。個別の契約書の赤字を「変えない / 仕組みを変える / 契約だけ」で仕分けられる。
- 我慢すること: 文面は使う人が専門家と作る(キットはそこまで持たない)。月の稼働率は手で出す。外形監視が DB を見ないので、DB の停止は振り返りに頼る。
- 見直す合図: 型の値と仕組みの値の食い違いが1回でも見つかったら、型を機械の読める形にして CI で照らす。有料の顧客が「夜中も30分で連絡」を求めたら、当番を置いてから連絡の時間を変える。SLA の申し出が月に何件も来たら、稼働率の自動の計算と、補償を自動で当てる仕組み(プランと請求の表の後)。
