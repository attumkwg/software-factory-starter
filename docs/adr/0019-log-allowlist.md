# ADR 0019: ログは「出してよい項目だけ」を出す(許可リスト)

- 状態: 提案
- 日付: 2026-10-22
- 決めた人: @attumkwg(作者の希望「個人情報をログに出さないのを、初めからハーネスとして組み込む」から AI が案を書いた。承認待ち)

## 背景

Sentry に送る中身は、ログの1行から決めた項目だけを拾う許可リスト(ADR 0011・`packages/error-reporting/src/scrub.ts`)。一方、自分の AWS の中のログ(CloudWatch)は、pino の `redact` で**伏せる名前の一覧**(`password`・`token`・`email` など)を1段下まで伏せるだけだった。2026-10-21 の点検で、次が素通りすると分かった。

- 一覧に無い名前(`name`・`newEmail`・`staffName`・`title`)と、2段より深い所
- 画面のサーバーは `cookie` と `authorization` だけ。SSR の失敗(`{ err }`)は pino の既定の形で、失敗の文がそのまま
- API の `serializeError` は Drizzle の失敗の値は落とすが、ほかの失敗の文(SMTP の「550 <アドレス>」・pg の「invalid input syntax: "値"」)と原因はそのまま
- 送信待ちの `last_error` に生の失敗の文
- メールの中継(Postfix)のログに `to=<アドレス>`
- Semgrep の `no-whole-object-logging` は `{ title: body.title }`・`{ ...row }`・テンプレート文字列を通す

伏せる名前の一覧は、**AI が項目を足すたびに追いかける**必要があり、足し忘れは誰も気づかない。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 伏せる名前の一覧を増やす(いまの延長) | ログの中身が変わらない | 足し忘れが漏れになる。深さに上限がある |
| **B. 出してよい名前の一覧(許可リスト)。知らない名前は値を `[REDACTED]`** | 足し忘れは「ログに出ない」側に倒れる(漏れにならない)。Sentry と同じ考え方 | 新しい項目をログに出したいときは、一覧に足す(危険度「高」・人の確認)。それまで調べにくい |
| C. ログに書く前に、値を型で包む(`Redacted<string>`) | 型で止まる | 全部のコードを書き換える。ライブラリの失敗の文は包めない |

## 決めたこと

**B**。API と画面のサーバーは同じ部品 `packages/logging` を使う。

- 出してよい名前: `…Id` / `…Ids` と、`ALLOWED_KEYS`(状態・件数・時間・API の形・コードが決めた文字列)。初期値は今あるログの呼び出しを全部読んで決めた(設計書 0008 の U-3)
- **分類表で personal / sensitive の列の名前は、どの深さでも伏せる**(`ALWAYS_REDACTED`。許可リストより強い)。分類表に足して一覧に無いと、単体テストが落ちる
- 出してよい名前でも、文字列の値は伏せ字を通す。`…Id` は ID の形(英数字と `-` `.` `:`)の値だけ。パスは ID と英字の区切りだけ残す
- 失敗(`err`)は `serializeError` を通す: 種類・code・スタックの行・原因。文は Sentry と同じ伏せ字(`scrubMessage`)に、**区切りのある電話番号**と**日本語の並び**を足して伏せる(ライブラリの文は英語で、日本語はほぼ利用者の値。自分で投げた日本語の文も伏せられるが、種類とスタックで場所は分かる)
- ログの文(2つ目の引数)も伏せ字を通す(テンプレート文字列で値を入れても、メールアドレスや数字の並びは出ない)。書く所でも Semgrep が止める
- 送信待ちの `last_error` も同じ伏せ字を通してから書く(分類表で `internal` に下げた)
- Postfix のログは、名前付きのパイプと `sed` で、メールアドレスを `[email]` にしてから標準出力へ(Message-ID の行だけはそのまま。アプリのログと突き合わせる)
- 全部の API を、目印つきの値(名前・電話番号・病名に見立てた文・メールアドレス)で叩き、出たログの全行を調べる結合テスト `personal-data-logs.int.test.ts`

## 結果として起きること

- 良くなること: ログの項目を足し忘れても、個人情報は出ない。API と画面のサーバーの決まりが1か所。「全 API で出ていない」を毎 PR で確かめる。
- 我慢すること: ログに新しい名前を出すときは `ALLOWED_KEYS` に足す(人の確認)。失敗の文の日本語は読めない(種類・code・スタックの行で追う)。`[REDACTED]` が出たら「許可リストに無い名前を書いた」の合図。
- 見直す合図: `[REDACTED]` のせいで障害の調べがつかなかったことが続いた。ログに出したい項目が増えて、許可リストの PR が毎週出るようになった(項目の名前の付け方の決まりを見直す)。
