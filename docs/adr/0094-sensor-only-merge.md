# ADR 0094: 人が決めることの無い PR は、センサーが緑なら人を呼ばずに入れてよい(使う人が選ぶ・既定はオフ)

- 状態: 採用
- 日付: 2026-10-29
- 決めた人: AI(G-135・仕様 0095。キットの既定はオフなので、オンにするかは使う人が決める。持ち主の方針「人のレビューは極限まで絞る。人が判断するのはセンサーが正しいかの判定と、人が決めなきゃいけない所に端的に答えること」(ロードマップの 6)に沿う)
- ADR 0082・0085・0086 の条件(1人の間・`KIT_AI_MERGE=slack`・必須のチェックが全部緑・待つ間に push が無い)は変えない。返事が要らない範囲を足すだけ

## 背景

- AI のマージ(`pnpm pr:merge-when-green`)は、全部の PR で持ち主の会話の返事を待つ。センサーが緑で、人が決めること([../concepts/human-decisions.md](../concepts/human-decisions.md) の「強制」の行)が何も無い PR でも人を呼ぶ。週100〜200本では、返事の回数がそのまま流量の天井になる。
- 一方で、判断待ちの積み場(`pnpm queue`)は、印も問いも無い PR を載せない。返事を待っているのに積み場に出ない PR が黙って溜まる。
- 守る場所(センサーそのもの)・高の領域・印・問いの見分けは、G-130・G-132 で既にある。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A 今のまま(全部の PR で返事) | 人がすべてに「いいよ」と言う | 返事の回数が流量の天井。人を呼ぶ理由の無い PR では、返事は形だけになる |
| B 人を呼ぶ理由が無い PR は返事なし。使う人が `setup.yml` で選ぶ・既定はオフ | 人の出番が「決めること」だけになる。怖い人はオフのまま | オンの所では、低い PR の中身を人が見ずに入る(センサーの穴がそのまま入る) |
| C B を既定でオン | 何もせずに速い | 怖いと感じる人に、知らないうちに入る |

## 決めたこと

**B**。

- `setup.yml` の `ai_merge.sensors_only: true` にした所だけ、`pnpm pr:merge-when-green <番号> --sensors` が返事なしで入れる。`KIT_AI_MERGE=slack`(ADR 0086)も要る。
- 入れるのは、人を呼ぶ理由が1つも無い PR だけ: 守る場所・守りの場所(CI・フック・設定・このスクリプト)・高の領域に触らない / 印 needs-human・risk:high・tests:weakened が無い / 本文の「🧑‍⚖️」に問いが無い / 本文の危険度が「高」でない。緑になった後にもう一度見る。
- `setup.yml` は守る場所なので、`sensors_only` をオンにする PR は、それ自体が人を呼ぶ(AI が自分でスイッチを入れられない)。
- 入れたら PR に「センサーだけでマージ」の記録(当てた版・緑だった数・理由が無かったこと)を残す。おかしければ revert して、どのセンサーが足りなかったかを書く(センサーを足す PR は人を呼ぶ)。
- キットの既定はオフ(キット自身でもオフ)。
- ルートの `CLAUDE.md`(マージの例外の文)と `/slack-request`(仮決めが無いときも聞く)は、この ADR では書き換えない。AI の振る舞いの決まりなので、オンにする PR で持ち主の答えと一緒に `--sensors` の例外を1行ずつ足す([../guides/throughput.md](../guides/throughput.md) の 4)。

## 結果として起きること

- 良くなること: オンの所では、人が答えるのは「決めること」がある PR だけになる。背景の AI の上限も、人を待つ PR だけを数えられる(仕様 0095)。
- 我慢すること: オンの所では、低い PR の中身を人が読まない。センサーに無い誤りは、入った後に見つかる(戻すのは revert)。
- 見直す合図: センサーだけで入れた PR を revert した / 人が増えた(承認数 1 以上で AI はマージしない。G-133)/ 人を呼ぶ理由の見分けに当たらない「高」の変更が入った(守る場所か高の領域の表に足す)。
