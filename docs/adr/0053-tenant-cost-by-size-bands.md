# ADR 0053: 1社あたりの原価は、組織の大きさの帯ごとの合計を運営のコマンドで出し、3つの元で按分した幅にする

- 状態: 採用
- 日付: 2026-10-25
- 決めた人: @attumkwg(2026-10-25。会話で回答。原価に入れる物・按分の元・帯は既定として承認し、帯の区切りは使う人が導入時に決める)

## 背景

値段を決める・大きいお客さんの DB を分ける判断に、1社あたりの原価が要る(仕様 0042・穴 G-10)。けれども、① 組織ごとの使い方は本番の DB にしか無く、費用のページ(Actions)は DB に入れない ② 組織ごとの金額を出すと、組織と金額が結びつく ③ 何の割合で按分するかで数字が大きく変わる。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 費用のページが本番の DB を読み、組織ごとに按分する | 人の手が要らない | Actions に本番の DB の接続と秘密が要る(infra と守りが増える)。組織ごとの金額が出る |
| B. 運営のコマンドが組織ごとの数(ID なし)を出し、費用のページが按分する | 按分の自由が利く | 組織ごとの行は、ID が無くても大きさで個社が分かる |
| C. 運営のコマンドが**帯ごとの合計といちばん大きい組織の %**だけを出し、費用のページが帯ごとに按分する | 組織ごとの数が DB の外に出ない。今の非公開の入力の流れ(人が置く)に乗る | 帯の中の違い(帯の中で大きい組織・小さい組織)は見えない。月1回、人がコマンドを流して置く |

按分の元:

| 案 | 良い所 | 弱い所 |
|---|---|---|
| 1つ(例: データの行の数)に決める | 数字が1つで読みやすい | 何を重く見るかで値段が変わるのに、その選びが見えない |
| 3つ(人数・行の数・書き込み)で按分した**幅** | 選びの違いが幅として見える(費用のページの人の時間と同じ) | 幅が広いと決めにくい |

## 決めたこと

**C** と **3つの幅**。帯は人数(1〜5人・6〜20人・21〜100人・101人〜)・5組織未満の帯に印。按分するのは本番の AWS だけ。どれもキットの既定で、帯の区切りは使う人が自分の料金のプランに合わせて導入時に決める(設計書 0042 の U-1)。

## 結果として起きること

- 良くなること: 値段と DB を分ける判断に、組織の ID を出さない数で答えられる。外の権限・秘密が増えない。
- 我慢すること: 帯の中の違いは見えない。月1回、人が `tenant-shares` を流して置く。人の時間・SaaS は入らない。
- 見直す合図: いちばん大きい組織が全体の3割を超えて伸び続ける(帯でなくその組織だけを見たくなる)・料金のプランが人数でない物(機能・データ量)になった・組織が数千になって数えるのが重くなった。
