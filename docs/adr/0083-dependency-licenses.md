# ADR 0083: 依存のライセンスは決まりの台帳で分け、版を書かない一覧を CI で今の姿に保つ

- 状態: 採用
- 日付: 2026-10-29
- 決めた人: @attumkwg 2026-10-29 会話で回答「書いてあること全部アグリーです」(PR #159 の「人に判断してほしい所」の 1。分け方と注意5件の理由をそのまま)

## 背景

- キットを公開する(MIT・著作権 attumkwg。G-40)。外の会社の審査・DD・弁護士は「依存のライセンスに、MIT と合わない物(GPL・AGPL など)が無いか」を必ず聞く(穴 G-108。G-86・G-87・G-53 の依存のライセンスの一覧を束ねた)。
- 画面と API のイメージには SBOM を付けている(`deploy.yml` の `sbom: true`)が、ライセンスの一覧として読める形ではない。
- 依存は Renovate が毎週上げる。版つきの一覧をコミットすると、版が上がるたびに一覧が古くなり、Renovate の PR が赤くなる。
- 入る物が OS で違う(`@esbuild/linux-x64` と `@esbuild/win32-x64` など)。手元と CI で一覧が揺れる。

## 選択肢

| 案 | 良い所 | 弱い所 |
|---|---|---|
| A. 版つきの全部の一覧をコミットし、CI で古さを見る | 読めばすぐ全部が分かる | Renovate の PR が毎回赤くなる。OS で揺れる |
| B. 一覧はコミットせず、CI で GPL などだけを止める | 揺れない | 審査に渡す物が手元に無い。「注意」の物をなぜ使ってよいか、どこにも残らない |
| C. 決まりの台帳(許す・注意・入れない・注意の物の理由)を正にし、版と OS ごとの本体を除いた一覧をコミットして CI で古さを見る。版つきの全部は `--full` で必要なときに作る | 一覧が変わるのは、直接の依存を足したとき・新しい種類のライセンスや注意の物が出たときだけ。注意の物の理由が残る | 版つきの全部は、渡すたびに作る |

## 決めたこと

C。決まりは `docs/compliance/licenses.yaml`(危険度「高」。人の確認が要る)、人が読む一覧は `docs/compliance/licenses.md`(生成物)。`pnpm deps:licenses` が `pnpm licenses list` の結果と照らし合わせ、次で CI を落とす: 入れないライセンス(GPL・AGPL・SSPL・CC-BY-NC/ND/SA・UNLICENSED)/ 決まりに無いライセンス / 注意のライセンス(MPL・LGPL・CC-BY・FSL など)なのに理由が無い / 理由を書いた依存が消えた・ライセンスが変わった / 一覧の作り忘れ。

- 一覧に版を書かない(Renovate で揺れない)。OS・CPU ごとの本体(package.json に `os` か `cpu` がある物)は除く(中身は親と同じ作り手の物)。
- 間接の依存は、出てくるライセンスの種類だけ書く(数は書かない。依存の入れ替えで揺れる)。直接の依存は1件ずつ。
- `A OR B` はどれかが許せば許す(選べる)。`A AND B` は全部に従う。
- 版つきの全部(名前・版・ライセンス・分け方・本番か開発か・ホームページ)は `pnpm deps:licenses --full <ファイル>.csv`。DD・審査に渡すときに作る(コミットしない)。

## 結果として起きること

- 良くなること: 公開の前に「MIT と合わない依存は無い」と言える(2026-10-29 の時点: 入れない物 0件。注意 5件 — MPL-2.0 の `lightningcss`・`axe-core`・`@axe-core/playwright`、CC-BY-4.0 の `caniuse-lite`、FSL-1.1-Apache-2.0 の `sentry`)。新しい依存で GPL などが入ると CI が止める。
- 我慢すること: 直接の依存を足したら `pnpm deps:licenses --write` が要る。間接の依存に新しい種類のライセンスや注意の物が出ると、Renovate の PR が赤くなる(理由を台帳に書いてから通す。これは止めたい所)。台帳の理由は専門家の確認ではない(キットから作ったプロダクトを売る前は、`--full` の一覧を添えて専門家に確かめる)。
- 見直す合図: Renovate の PR が台帳の追記で月に2回以上止まる / 審査や DD で、この一覧では足りないと言われた(SBOM の形・版つきの一覧のコミットを考える)。
