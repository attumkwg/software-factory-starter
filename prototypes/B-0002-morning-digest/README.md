# 試作: 朝のまとめ(B-0002・見本)

> **見本**。賭け [B-0002](../../docs/product/bets/B-0002-morning-digest.md) の `psf`(この解決策で困りごとが消えるか)を確かめるための、押せる画面だけ。
> 会社・人・タスク・数字は**全部架空**。裏(API・DB)は無く、何も保存・送信しない。作り方と守りは [docs/guides/prototypes.md](../../docs/guides/prototypes.md)。

- 手元で開く: `pnpm prototype:dev B-0002` → http://localhost:5180/B-0002/
- 置いた後: `https://<CloudFront>/B-0002/`(合言葉つき。PR のコメントに URL が出る)

## 確かめること(賭けの「線と期限」から)

- 合格の線: 試作を触ってもらった5人中3人以上が、まとめだけで「誰に声をかけるか」を決められる(架空)
- 撤退の線: 5人中1人以下・「うるさい」が多い

## 画面の流れ(4枚)

| # | 画面 | 見ること |
|---|---|---|
| 1 | 朝のまとめ(メールの見た目) | 最初にどこを見るか。「過ぎた」「今日」の数で手が止まるか |
| 2 | まとめから開いた一覧 | 担当ごとに見て、声をかける相手を決められるか |
| 3 | まとめの設定 | 届く時間・プロジェクトのどれを外したがるか(外したい物 = うるさい物) |
| 4 | 申し込み(形の見本) | 利用目的を読むか・同意で手が止まるか(③ お金の段で使う形。どこにも送らない) |

## 台本(相手に何を頼み、何を見るか)

**試作は最後に見せる。** 先に過去の行動を聞く(`docs/guides/before-pmf.md` の「話の聞き方」)。

1. 過去の行動を聞く(5〜10分。試作はまだ見せない)
   - 「最後に、期限が近いタスクを探したのはいつですか。そのとき何を見て、何をしましたか」
   - 「催促の連絡は、週に何回くらいしていますか。どうやって相手を決めていますか」
2. 頼むこと(1つずつ。押す場所は教えない)
   - 「朝、このメールが届いたとします。最初に何をしますか」(画面 1)
   - 「今日、声をかける人を決めてください」(画面 2)
   - 「このメールが毎朝来るとしたら、何を変えたいですか」(画面 3)
3. 見ること
   - どこで止まったか・迷ったか・声に出したこと・押そうとして押せなかった所
   - 「誰に声をかけるか」を、まとめの画面だけで決められたか(合格の線)
   - 「うるさい」「多い」と言ったか・設定で外したがった物(撤退の線)
4. 聞かないこと: 「使いますか」「いくらなら払いますか」「良いと思いますか」
5. 記録と持ち帰り: その日のうちに `docs/product/interviews/`(名前・連絡先・会社名は書かない)→ `/bet` で B-0002 に小石を足す
