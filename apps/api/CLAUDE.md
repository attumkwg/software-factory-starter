# apps/api のルール

- 入口: `src/app.ts`(組み立て)・`src/index.ts`(起動と SIGTERM)・`src/cli.ts`(移行・種データ)
- リクエストの流れ: request ID → セッションを読む(`auth/`)→ **認可の関所**(`authz/middleware.ts`)→ ルート → リポジトリ
- 認可の決まりは `src/authz/policy.ts` の1か所だけ。ルートの中で `role` を見て分岐しない。
- 「このデータに触ってよいか」(自分が作った物だけ消せる、など)も `policy.ts` に足し、データを読んだ後に `can(actor, 操作, データ)` の形で聞く。足したら `docs/authz/matrix.yaml` に「自分の物 / 同じ会社の他人の物 / 他社の物」の答えも書く。
- **領域ごとに分ける**(ADR 0004): `src/domains/<領域>/{schema,repository,routes,index}.ts`。ほかの領域・共通部分からは `index.ts` だけを使う。使ってよい向きは `src/domains/dependencies.ts`(破ると `test/unit/domain-boundaries.test.ts` が落ちる)。表は領域の名前の Postgres のスキーマに置く。
- ルート(`routes.ts`)は入力と出力の形だけ。DB の読み書きは `repository.ts` に書き、`scopeOf(c)` を渡す。
- 共通の部品: `src/http/common.ts`(OpenAPI の応答・本文)・`src/db/`(接続・テナント・列の作り方)・`src/outbox/`(送信待ち)。
- **お金と時刻**(ADR 0005): 金額は最小単位の整数+通貨、単価・率は小数の文字列、計算は `@app/shared` の `money.ts`(丸め方を必ず渡す)。時刻は UTC で持ち、日付だけの値は `date`。「1日」の区切りは組織の時間帯(`tenants.time_zone`・`time.ts` の `localDayRange`)。
- **起きたことをほかへ知らせる**(ADR 0006): 外へ直接送らず、同じトランザクションで `enqueue()`。受け手は同じ出来事が2回届いても大丈夫に書く。
- **メール**(ADR 0008): リクエストの中で直接送らない。出来事を積み、受け手(`outbox/handlers.ts`)で組み立てて `mailer.send()`。宛先は送る直前に DB から読む(出来事にメールアドレスを入れない)。手順は `docs/guides/mail.md`。
- リポジトリは RLS に頼り切らず、`tenantId` でも絞る(層を重ねる)。
- 他社の物・無い物は 404。権限が無ければ 403。ログインしていなければ 401。
- 失敗は投げるだけ(`errors.ts` の関数)。ルートで try/catch して形を作らない。`onError` が code に直し、ログは `logger.error({ err }, "…")` の形だけ(SQL の値・失敗の文の値が落ちる)。ログの項目は許可リスト(`packages/logging`。ADR 0019)で、`…Id`・状態・件数・時間のほかは `[REDACTED]` になる。error 以上のログはそのまま Sentry にも行くので、Sentry を直接呼ばない。決まりは `docs/guides/error-handling.md`。
- **機能フラグ**(賭けの psf / rollout で一部の組織に出す): 機能の API のハンドラーの最初で `await requireFeature(c, "<名前>")`(入っていなければ 404)。名前は `@app/shared` の `FEATURE_FLAGS` に足す(賭けの ID つき)。切り替えは運営のコマンドだけ(API は作らない)。使ったことは `await recordUsage(c, "<名前>")`(`src/usage`。操作と同じトランザクションで1日1人1行。画面から送る API は作らない)。`docs/guides/feature-flags.md`
- **個人情報**: 列を足したら `src/db/classification.ts` に区分と目的を1行(`personal` / `sensitive` の値はログ・監査ログ・出来事の中身に入れない)。要配慮(`sensitive`)はスキーマ `sensitive` にだけ置ける(ADR 0018)。
- **要配慮個人情報**(ADR 0029): 読み書きは `src/sensitive/` の中だけ。表(`schema.ts`)と SQL もそこに書き、ルートからは `sensitiveOf(c).run(scopeOf(c), async (s) => …)` の形で `index.ts` の関数を呼ぶ。値は `s.seal("sensitive.<表>.<列>", 行の ID, 値)` で暗号化してから書き、読むときに `s.open(…)`(DB には暗号文だけ・列は text)。接続はアプリと別なので `c.var.tx` と1つのトランザクションにならない(ふつうの行を先に書く)。代理ログインの最中は 403。KMS を待つのはモジュールの中(トランザクションの外)だけ。
- 入力は Zod で検証(`@app/shared` のスキーマを使う)。`sql.raw` は使わない。
- **一覧は必ずページング**(全件を返さない)。`?cursor=&limit=`(`http/common.ts` の `PageQuery`)と `{ …, nextCursor }`。並びは「作った時刻+ID」で、同じ並びの索引を張る(`src/db/paging.ts`・`docs/guides/api-changes.md`)。
- DB の時間切れ(`src/db/client.ts` の `DB_TIMEOUTS`): 1つのクエリ 5 秒・トランザクションを開いたまま DB に何も頼まない時間 10 秒。**トランザクションの中で外(Cognito・メール・HTTP)を待たない**(認可の関所がリクエストごとに開いているので、ハンドラーの中は全部トランザクションの中)。0.5 秒を超えたクエリは warn のログに出る。
- テストは必ず2社で書く(`test/helpers/fixtures.ts` の `createTenantFixture`)。
- 単体は `test/unit`(DB 無し)、DB が要るものは `test/integration/*.int.test.ts`(Testcontainers)。
- 結合テストは全部のファイルが同じ DB を同時に使う。**全社分をまとめて扱う処理**(アウトボックスの送り出し `relayOnce`・`notifyLegalChange` など)を回すファイルは、`test/helpers/isolated-db.ts` の `createIsolatedDatabase` で自分だけの DB を使う(ほかのファイルの行を取り合って、流すたびに違う所で落ちる)。
