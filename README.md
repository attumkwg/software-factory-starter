# software-factory-starter

**AI に全速で作らせても、使う人を裏切らない。**
一言頼むと、AI が仕様を書き、PR を出し、テストで確かめます。あなたが決めるのは「やるか」と「マージするか」だけ。

会社向け SaaS を 1〜3人で始めるための、工場の雛形です。ログイン・他社とのデータの分離・SSO・監査ログ・CI・AWS が最初からそろっているので、初日から使う人の困りごとに取りかかれます。試すのは0円、本番は月 約8万円から。

🏭 **このリポジトリ自身が、この工場で作られました。** 13日で PR 149本。書いたのは全部 AI です。人が使ったのは 約43〜68時間(推定)で、ほとんどは PR を確かめることと、AI からの「どうしますか?」に答える時間でした(数の出どころは下の「🏭 何者か」)。

## 💡 なぜ作ったか(意義)

会社向け SaaS は、最初の数か月を土台づくりに取られます。そのあいだ、使う人は困ったまま待っています。その数か月を、**使う人に届けて「本当に使われたか」を確かめる時間**に変えるのが、この工場です。意義は作る人の楽さではなく、使う人の便利さにあります。

- 🚀 **早く届く**: 土台はもうある。AI が依頼を仕様から PR まで流す。
- 🔒 **壊さない**: 他社のデータが見える・鍵が漏れる・本番が壊れる、を「お願い」ではなく仕組み(16の必須のチェック・危ない場所のフック・人の答えが要るマージ)で止める。速く出しても、使う人の信頼を失わない。
- 📈 **使われたか分かる**: 作る前に「使う人の何が変わるか」を書き、使われ方・継続率・「無くなったら困るか」を測る。使われなければやめて、次の困りごとに回る。

## 🏭 何者か

**依頼を受けて、届くところまで流す工場です。** 一言の依頼を、AI が1問ずつ聞いて仕様と設計にし、1つ = 1 PR の大きさの子の Issue に割り、PR にし、受け入れで確かめます(`/new-feature` → `/accept`)。流れを止めるのは人の目ではなくセンサー(テスト・型・検査・E2E・計測)で、危険度「高」の場所・テストを弱めた PR・課金・個人データ・SSO・メールのセンサー(テスト)を変える PR は、人の答えが無いと AI がマージしません(1人の間(`.github/setup.yml` の `required_approvals: 0`)は、持ち主に領域の問いを会話で聞き、答えを PR に残してから工場がマージする。人が増えたら人の承認に戻る。文書の表と守る場所は `pnpm guards` が突き合わせる)。
人の仕事は2つに絞ります: **センサーが正しいかの判定**と、**人が決めなければならないことに端的に答えること**(いまは仕様の承認・レビュー・本番の承認の3か所で止まる。センサーが緑なら人を呼ばない範囲は、公開までに広げる)。

このキット自身が、この工場で作られています(2026-10-17〜10-29 の13日。出どころと前提は [docs/kit/roi.md](docs/kit/roi.md)):

| 何を | 数 |
|---|---|
| マージした PR(ボットを除く) | **149本。AI が書いた PR は149本(100%)**【実測】 |
| 人が使った工数 | **約43〜68時間**【推定】(AI の PR を確かめる15分 × 149本+コメント。問いに別に5分ずつかかったなら上の端。`docs/cost/people.yaml` の目安) |
| 無人化率(有人化率)。毎週いちばん目に入る数 | **約78〜86%(約14〜22%)**【推定】(全部を人が書いた場合の 約300時間 と比べて) |
| 人が答えた問い・人が手で直した PR | 問い 305(102本の PR)・手直し1本【実測】。人の介入が無かった AI の PR は47本(32%) |
| いちばん多い週 | 97本(2026-10-19〜25)【実測】 |

- 人が使った工数は、PR の履歴から出した推定。Claude Code への指示・会話の時間は履歴に残らないので入っていない。
- テストは462件が12秒で緑・1社が事前登録から解約までたどる E2E は18秒で緑【実測】。

📏 **物差し**: 毎週いちばん目に入る数は**無人化率**(人が使った工数の裏返し。入力の指標)。守りは**事故0件**と**センサーが正しいかの判定**。いちばんの物差し(北極星)は「意義があると判断した物が、使う人に届いて使われた数 ÷ 人の工数」= 人の1時間あたりに、使われる物をどれだけ届けたか。北極星を測る仕組みは、公開までに足す(すぐ下の「🔜 次に足す」)。

### 🔜 次に足す(公開までに)

まだ言い切らない物。公開(目安 2026-11-29)の前に「できるはず」まで入れる([docs/kit/roadmap.md](docs/kit/roadmap.md) の 6):

- ✅ 済み(2026-10-29): 人が決めることの一覧と、判断待ちの積み場(毎朝の Issue)・答えは会話で、工場が PR に記録してマージ([docs/concepts/human-decisions.md](docs/concepts/human-decisions.md))
- 依頼ごとの進み具合(n/m・依存の順番・止まった PR の見張り)と、週100〜200本を受ける流量の受け皿(マージキュー)
- 北極星(意義があると判断した物が、使う人に届いて使われた数 ÷ 人の工数)を測る・資産の累計と ROI を自動で出す・無人化率(有人の工数)を1つの数で週ごとに出す

## 🙋 誰のためか

- **1〜3人で、会社向け(B2B)の SaaS を始め、使う人に早く届けたい人**。15人ほどまでのチームでも使える。
- **AI に実装を任せたいが、使う人に迷惑をかける事故(他社のデータが見える・鍵が漏れる・本番を壊す)は起こしたくない人**。
- 持ち帰れる考え方(人と AI の分担・センサーで流す・作る前に賭けを決める)は、**AI の導入を支援する人・新規事業の EM** にも。

<details>
<summary>向いている・向いていない(詳しく)</summary>

| 向いている | 向いていない(いまは) |
|---|---|
| 会社向け(B2B)の SaaS を、1〜15人ほどで始める | 個人向けのアプリ・記事で人を集めるサイト(個人向けの型・SEO の型はまだ無い) |
| AI に実装を任せたいが、事故(他社のデータが見える・鍵が漏れる)は起こしたくない | スマホのネイティブアプリが最初から要る(スマホのブラウザなら動く) |
| 詳しい人がいなくても、点検や更新を回したい | 1,000人規模の開発の組織(作る側の会社か部門が100人までを狙っている。大きな会社の中の小さなチームなら当てはまる) |
| 1〜3人なら軽い型(`/tailor` の最初の問い)で部品を減らせる | **本番に出して月 約8万円**(AWS の本番 約5.3万円+AI の席 1人 3万円〜)を払えない。手元・試作・話を聞く段階は0円 |

</details>

## ✨ 何ができるか(できることのカタログ)

> 上の3つの手段の順。**状態**: ✅ 動く = 手元のテストか E2E で確かめた / 🧩 型まで = 使う側でつなぐ・決める(本物の AWS では確かめていない物を含む)。

| 手段 | 使う人に届く物・作る人が楽になる物 | 試し方 | 状態 |
|---|---|---|---|
| 🚀 早く届ける | 一言の依頼から、AI が仕様・設計・親子の Issue・実装・テスト・PR・受け入れまで。危険度は変えた場所で自動で付く | Claude Code で `/new-feature` → `/accept`。守りの一覧は `pnpm guards` | ✅ 動く |
| 🚀 早く届ける | 16の必須のチェック(型・2社の結合・E2E・秘密・脆弱性・移行・見た目)とブランチ保護が、GitHub に一括でそろう | `pnpm setup:github`(試し。差分だけ出る) | ✅ 動く |
| 🚀 早く届ける | 会社が来てから去るまで(事前登録 → 開通 → 招待 → プラン → 書き出し → 人を外す → 1人分の削除 → 解約)が最初から1本でつながる | `pnpm test:e2e journey.spec.ts`(18秒) | ✅ 動く |
| 🚀 早く届ける | 本番に乗せずに、押せる画面だけの試作で使う人に見せて話を聞ける | `/prototype`・`pnpm prototype:dev` | ✅ 手元 / 🧩 合言葉つきの URL は AWS で |

| 🔒 壊さない | 使う人のデータが他社に見えない。DB(RLS)と関所の二重で止め、全部の API を2社で叩くテストつき | `admin@globex.test` でログインし、Acme のデータが無いのを見る | ✅ 動く |

| 🔒 壊さない | 規約の同意と版・個人情報をログに出さない・要配慮個人情報を分けて暗号化 | 初めてのログインで同意の画面 | ✅ 動く |

## 👀 5分で見る(AWS も鍵も要らない)

要るもの: **Node.js 24**・**Docker**。

```bash
git clone https://github.com/attumkwg/software-factory-starter my-product && cd my-product
```

```bash
corepack enable
```

```bash
pnpm install && pnpm test
```

```bash
docker compose up --build
```

http://localhost:8080 を開いて、カタログの守りを3つ目で見る:

1. **他社のデータが見えない**: `admin@acme.test` でログイン(開発用。パスワードなし)→ `admin@globex.test` に替えると、Acme のデータが無い。
2. **招待が届く**: Acme の管理者で「設定」→「招待を開く」から人を招く → 招待のメールが Mailpit(http://localhost:8025)に届く。
3. **監査ログに残る**: 「設定」→「監査ログを見る」に、いまの招待が「誰が・いつ・何をした」で並ぶ。

【実測】`pnpm install` 32秒・`pnpm test` 12秒・起動 17〜37秒(イメージを一度作った後。最初はイメージの取得が足される)。1社の一周を自分の目で見たいときは、もう1つの端末で `pnpm test:e2e journey.spec.ts`。

## 🧾 できないこと・確かめていないこと

一覧は **[docs/kit/limits.md](docs/kit/limits.md)**(各行に、代わりにどうするか・穴の番号)。要約:

- **できない**: 部品だけを既存のリポジトリに持ち帰る道(G-51)・AWS や GitHub 以外への入れ替え(G-55)・保守の約束(MIT・無保証。[maintenance.md](docs/kit/maintenance.md))。
- **1人の間は**: 本番の承認も自分1人(G-64)・前の版に戻すのは `aws` のコマンド(G-65)・1人分の削除は手順書で(G-06)。AI のマージは既定でオフ(使う人が選ぶ。持ち主が `KIT_AI_MERGE` を入れたら、会話の答えと緑のチェックでマージする)。
- **確かめていない**: 本物の AWS の上(G-120。カタログの「🧩 AWS で」の行)・クラウドで Slack から頼む道(使う側でつなぐ)。

## 🚀 始め方

> 🧭 **最初の30分は、1 と 2 の一本道**(動かす → 2社のデータが分かれているのを見る → 自分のリポジトリにする)。経営・事業の方は、手順の前に下の「👥 立場ごとの入口」へ。

要るもの: **Node.js 24**・**Docker**・**GitHub のアカウント**(公開のリポジトリか Pro / Team / Enterprise Cloud。非公開の Free ではブランチ保護が使えない。非公開の Pro / Team では本番の承認者が働かない → [docs/guides/local-guards.md](docs/guides/local-guards.md) の表)・**Claude Code**。

**1. 手元で動かす(30分。自分のリポジトリはまだ要らない)**

上の「👀 5分で見る」のとおり(`git clone` → `pnpm install && pnpm test` → `docker compose up --build` → 2社のデータが分かれているのを見る)。

**2. 自分のリポジトリにして、GitHub を一括で整える(10分)**

```bash
git remote rename origin kit
```

```bash
gh repo create <自分か組織>/my-product --private --source . --push
```

```bash
pnpm setup:github
```

`kit` の名前でキットを残すと、後でキットの新しい版を取り込める([docs/kit/upgrade.md](docs/kit/upgrade.md))。`pnpm setup:github` は試し(差分だけ)。よければ `pnpm setup:github --apply`。ブランチ保護・ラベル・Environments・定期の点検がそろう。最後に「人がやること」が一覧で出る。

**3. 何を作るかを決める(半日〜)**

Claude Code でこのフォルダを開き、`/kickoff` と打つ。1問ずつ聞かれるので答えるだけ。話を聞く・画面だけで確かめる段階では AWS は要らない。

**4. 部品を選ぶ(30分〜)**

`/tailor` と打つ。会社向けか・個人情報・お金・メールなどを聞かれ、要らない部品を消す。**迷ったら残す**(1〜3人で PMF の前なら、最初の問いで「軽い型」を選ぶと、後から足せる部品をまとめて外せる)。

この先(題材の差し替え・AWS・Slack・毎週の運用)は **[docs/getting-started.md](docs/getting-started.md)** に順番どおりに書いてある。

## 🔁 1つの機能が出るまで(人が止まるのは3か所)

```
「これ作りたい」 → /new-feature(1問ずつ) → 仕様と設計の PR ──② 人が承認
  → AI が実装 → PR(危険度のラベルが自動で付く) → CI ──⑦ 人がレビュー(中は1人・高は2人)
  → stg → 本番 ──⑨ 人が承認 → 見守る(アラーム・手順書)
```

人が見るのは「判断が要る所」だけ(事業判断・利用者の挙動・他チームとの契約・戻せないリスク)。**1人の間**(`required_approvals: 0`)は、② と ⑦ は持ち主が会話で答え、工場がその答えを PR に残してマージする(危険度「高」も。先に領域の問いを聞く)。⑦ の「中は1人・高は2人」は人が増えてから。⑨ 本番の承認は GitHub の Environment で人が押す。PdM の受け入れ(`/accept`)は、仕様の承認の後の確かめで、止まる所には数えない。番号と詳しくは [docs/playbook.md](docs/playbook.md)。
